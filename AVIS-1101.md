## Pourquoi la garde est rouge
Le job `gardes` est rouge, et `verifier` aussi par voie de conséquence. Message exact : `garde:perimetre ROUGE - aucune fiche pour la branche pilotage/leve-bloque-v1-lot1`. Cause précise, d'après `outils/gardes/perimetre.mjs` sur main :
1. Le nom de branche `pilotage/*` est bien reconnu par `estPRPilotage`. Mais le mode « PR de pilotage » n'accepte que des fichiers **ajoutés** (statut A) sous `pilotage/(fiches|journal)/LNN-TMM.md`. Ici, les 54 fichiers sont **modifiés** (statut M). Le mode pilotage est donc refusé, et cela vaudrait même pour une seule fiche modifiée.
2. La garde passe alors au chemin normal « une fiche = une PR ». L'id de fiche doit venir d'une branche `lot-NN/LNN-TMM` ou d'une ligne `Fiche: LNN-TMM` dans le corps de la PR. La PR n'a ni l'une ni l'autre, d'où « aucune fiche pour la branche ».
3. Même avec un id de fiche, le chemin normal ne contrôle qu'une seule fiche : les 53 autres fichiers seraient hors de ses `fichiers_autorises`. Le repli `CORPS_PR`, lui, n'accepte qu'une fiche sensible.

Le rouge ne vient donc pas du nombre de fiches en soi, mais du fait qu'un amendement qui **modifie** des fiches n'a pas de mode pilotage. Le nombre de fiches empêche ensuite tout contournement par le chemin normal. Ce n'est pas un défaut de l'auteur. La garde `termine` est verte (1063 fiches) ; les autres gardes sont vertes.

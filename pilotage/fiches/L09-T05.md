## Contexte
Spec 09, §02 règle 8 : pré-remplissage confirmé sans question SEULEMENT si (a) au moins 2 sources concordent, (b) la plus récente a moins de `profil.fraicheur_mois` mois (12 proposé, réglable), (c) aucune source ne contredit, (d) confiance `sur`. Sinon `a_confirmer`. Un cas ambigu bloque seulement l'état `complet`, jamais la saisie. §01 cas limite : Kbis « SARL » et statuts « SAS » : les deux valeurs affichées, choix demandé. Cas P05.

## À faire
1. `packages/noyau/src/profil/aucun-doute.ts` :
   - `Source { origine; valeur: string; confiance; dateSource: string; ref: string }` ;
   - `evaluerSources(sources, { dateDuJour, fraicheurMois })` → `{ decision: 'confirme_sans_question' | 'a_confirmer'; motifs: ('une_seule_source' | 'source_ancienne' | 'contradiction' | 'confiance_insuffisante' | 'aucune_source')[]; valeurs: string[]; origines: string[] }` ; `valeurs` = valeurs distinctes triées (pour afficher les deux en cas de contradiction) ;
   - comparaison des valeurs après normalisation (espaces autour, casse) ; ancienneté mesurée en mois civils entiers par comparaison de dates (date de la source + `fraicheurMois` mois > `dateDuJour`), jamais par division ;
   - `fraicheurMois` : entier > 0 sinon `ErreurProfil('fraicheur_invalide')` ; source dont la date est postérieure à `dateDuJour` = `ErreurProfil('date_future')`.
2. Tests nommés (dates et sources inventées, réglage de test 12) : `deux-sources-recentes-concordantes-p05` (document + sirene), `kbis-ancien-seul-p05` (`une_seule_source`, `source_ancienne`), `contradiction-sarl-sas` (deux valeurs rendues), `confiance-douteuse`, `aucune-source`, `fraicheur-a-la-borne` (exactement `fraicheurMois` mois : ancienne ; un jour de moins : récente ; fin de mois 31/01 + 1 mois), `normalisation-casse-espaces` (« sarl » et « SARL » concordent), `ordre-des-sources-sans-effet`, `entrees-invalides` (fraîcheur 0, NaN, Infinity, 1.5 ; date future ; date mal formée).

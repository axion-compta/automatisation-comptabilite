## Contexte
Spec 04, fichier 06 §2 : « Le code extrait la partie numérique, trie, et liste les trous (numéros absents entre deux numéros reçus d'une même série) quand la série est réglée séquentielle. Une série déclarée non séquentielle n'est pas contrôlée. Le trou est une information, jamais un blocage. » Cas T-LEC-30 (F-0101, F-0102, F-0104, F-0105 → F-0103).

## À faire
1. `packages/noyau/src/pieces/classement/numerotation.ts` :
   - `decouperNumero(n)` → `{ prefixe: string; nombre: bigint; largeur: number } | null` : la DERNIÈRE suite de chiffres est la partie numérique ; ce qui précède est le préfixe ; ce qui suit doit être vide, sinon `null` ;
   - `trousDeSerie(numeros: string[], { sequentielle: boolean; trousMax: number })` → `{ trous: string[]; tronque: boolean; ignores: string[] }` : non séquentielle = aucun trou ; numéros sans partie numérique ou de préfixe différent du plus fréquent = `ignores` ; doublons retirés ; ordre d'entrée sans effet ; trous reformatés avec le préfixe et la largeur (zéros de tête) ; au-delà de `trousMax` trous : liste coupée et `tronque` vrai.
2. Tests nommés : `un-trou-f-0103`, `serie-complete-sans-trou`, `non-sequentielle-ignoree`, `ordre-sans-effet`, `doublons-retires`, `prefixe-different-ignore`, `trous-tronques`, `entrees-vides-et-sans-chiffre`.

## Hors périmètre
Réglage de la série (séquentielle ou non) : donnée de l'appelant.

## Pièges
`nombre` en `bigint` (numéros longs). `trousMax` vient de l'appelant. Règles du noyau comme L04-T00.

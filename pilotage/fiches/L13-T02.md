## Contexte
Spec 13, fichier 01, R15 à R17 : liste fermée de 12 gestes humains (G01 valider une écriture … G12 appliquer une mise à jour de paramètre légal), chacun avec sa permission et sa réauthentification. « Un jeton de service, un agent ou une tâche planifiée reçoit `403 geste_humain_requis`. » Le rôle comptable n'a que `compta-lire`, `compta-exporter`, `compta-commenter` : refusé pour G01 à G12. L'attribution des permissions aux rôles est une proposition (point douteux D1) : elle n'est PAS dans le code, les permissions arrivent avec l'acteur.

## À faire
1. `packages/noyau/src/principes/gestes.ts` :
   - `CodeGeste` (union `G01` à `G12`) ; `CATALOGUE_GESTES: readonly { code; action; permission; reauth: 'toujours' | 'jamais' | 'fusion_seulement' }[]` ; actions en codes : `valider_ecriture`, `cloturer`, `deposer_declaration`, `payer_declaration`, `choisir_regime`, `activer_assimiler`, `accepter_compte_courant_debiteur`, `proposer_dividende`, `creer_compte_ou_fusionner_tiers`, `envoyer_email`, `supprimer_donnees`, `appliquer_parametre_legal` ; permissions du tableau R15 (`compta-valider`, `compta-cloturer`, `compta-parametrer`, `compta-saisir`) ; G09 en fusion exige `compta-parametrer` ;
   - classe locale `ErreurGeste` (`code` : `geste_inconnu`, `entree_invalide`) ;
   - `verifierGeste(acteur: { type: 'personne' | 'service' | 'agent' | 'tache'; permissions: readonly string[]; derniereReauth?: number }, code, ctx: { maintenant: number; delaiReauthMs: number; fusion?: boolean })` → `{ ok: true }` ou `{ ok: false; statutHttp: 403; code: 'geste_humain_requis' | 'permission_manquante' | 'reauth_requise' }`. Ordre : type d'acteur, puis permission, puis réauthentification (acceptée si `0 ≤ maintenant − derniereReauth < delaiReauthMs`).
2.

## Contexte
Spec 04, fichier 01 §Une seule route d'entrée : toutes les voies appellent le même service ; `POST …/pieces` (multipart, un ou plusieurs fichiers) crée les pièces en `recue` et rend leurs `id` ; en-tête `Idempotency-Key`, par défaut SHA-256 du fichier, « même clé = même pièce, réponse "déjà reçue le …" » ; `GET …/pieces/{id}/etat` ; `POST …/pieces/{id}/relancer`. Le serveur en mémoire n'accepte que des pièces FICTIVES (réglage `pieces_reelles_autorisees` faux, fichier 07 §1). Cas T-LEC-1, T-LEC-2, T-LEC-3.

## À faire
1. `packages/contrat/src/domaines/depot.ts` : routes `deposerPieces` (`POST /pieces`, en-têtes `EnTeteEcriture` existant (clé `idempotency-key`), corps multipart `{ fichiers: File[] (1 à 20), canal }`, réponse `{ resultats: ({ statut: 'recue'; id } | { statut: 'deja_recue'; id; recueLe } | { statut: 'refusee'; code: CodeRefus; raison })[] }` dans l'ordre des fichiers), `etatPiece` (`GET /pieces/{id}/etat` → `{ etat, motif? }`), `relancerPiece` (`POST /pieces/{id}/relancer`, même en-tête ; 409 `RELANCE_IMPOSSIBLE` si l'état n'est pas `en_erreur`) ; 404 `PIECE_INCONNUE`.
2. `packages/contrat/src/domaines/depot-service.ts` : `creerDepotEnMemoire(pieces)` : empreinte par `crypto.subtle.digest('SHA-256', …)` (marche dans Node et dans le navigateur) ; type réel par `typeReel` (L04-T02) ; taille par `evaluerLimites` (L04-T06, réglage passé à la création ; `apps/serveur/src/domaines/depot.ts` le lit par `reglagesPiecesAuJour` de L04-T54) ; même empreinte = `deja_recue` avec la date de la première ; refus = rien de stocké ; imports du noyau par chemin relatif.
3. `pieces-service.ts` : seulement ajouter une fonction d'ajout utilisée par le dépôt (aucune autre modification).
4. `routes.ts` : ajouter `depot: { deposerPieces, etatPiece, relancerPiece }` ; `openapi.ts` : adapter la conversion si `z.file()` n'est pas représentable (`format: binary`), sans changer la sortie des autres routes ; régénérer `openapi.json`.
5. `apps/serveur/src/domaines/depot.ts` branché dans `app.ts`.
6. Tests nommés (octets fabriqués dans le test) : `trois-pdf-trois-pieces`, `meme-fichier-deja-recue` (deux dépôts, une seule pièce), `executable-refuse-type-refuse`, `trop-grand-refuse`, `ordre-des-resultats-conserve`, `etat-d-une-piece`, `relance-hors-erreur-409`, `serveur-accepte-le-multipart` (Fastify `inject`).

## Contexte
Spec 09, §03 : `parametre_lecture` (ajout seul) : lecteur (agent n° 1 ou n° 2, modèle, version), source, extrait, valeur lue, date, conclusion (`concorde`, `differe`, `introuvable`). Statut : `non_verifie` → `a_verifier` (lectures en désaccord ou une seule) → `valide` (deux lectures concordantes faites par deux lecteurs distincts PUIS un validateur nommé) → `retire`. « Partielle » (extrait de moteur de recherche) ne compte pas comme seconde lecture. D31 : « à vérifier » tant qu'aucune personne n'a confirmé.

## À faire
1. `packages/parametres/src/lectures.ts` :
   - schéma `Lecture { parametreCle; lecteur: { id; modele; version }; sourceUrl (officielle, L09-T22); extrait (non vide); valeurLue; luLe; complete: boolean; conclusion }` ;
   - `ajouterLecture(journal, lecture)` → nouvelle liste (ajout seul ; une lecture identique, même lecteur et même date, = `ErreurParametre('lecture_en_double')`) ;
   - `statutCalcule(journal, cle, validateur: { id; type: 'personne' | 'agent' } | null)` → `'non_verifie' | 'a_verifier' | 'valide'` : `valide` SEULEMENT si deux lectures `complete` et `concorde` de deux lecteurs d'`id` différents, même `valeurLue`, aucune lecture `differe` plus récente, ET un validateur de type `personne` ; un agent n'est jamais validateur ;
   - `motifsStatut(...)` → codes (`une_seule_lecture`, `lecture_partielle`, `lecteurs_identiques`, `desaccord`, `introuvable`, `sans_validateur`, `validateur_agent`).
2. Tests nommés : `aucune-lecture-non-verifie`, `une-lecture-a-verifier`, `partielle-ne-compte-pas`, `meme-lecteur-deux-fois`, `desaccord-a-verifier`, `deux-lectures-sans-validateur`, `validateur-agent-refuse`, `valide-complet`, `lecture-en-double-refusee` (et extrait vide, URL non officielle, date invalide).

Pas de paquet correctif (L09-T24) ; pas de stockage (L09-T48, bloquée). Le statut des lignes du catalogue reste écrit à la main dans L09-T26 à T28 (aucune n'est `valide`).

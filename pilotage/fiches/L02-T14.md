## Contexte
Spec 02, fichier 02 : OFX et QFX au MVP ; « relevé multi-comptes dans un même OFX (découpé par compte) ». Test T02-1 : 500 opérations, solde d'ouverture 10 000,00, somme −2 345,67 → solde de clôture lu 7 654,33. OFX 1 est du SGML (balises souvent non fermées : `<TRNAMT>-12.50`), OFX 2 est du XML. Balises utiles : `STMTRS`, `BANKACCTFROM/ACCTID`, `CURDEF`, `BANKTRANLIST` (`DTSTART`, `DTEND`), `STMTTRN` (`TRNTYPE`, `DTPOSTED`, `TRNAMT`, `FITID`, `NAME`, `MEMO`), `LEDGERBAL` (`BALAMT`, `DTASOF`).

## À faire
1. `packages/noyau/src/banque/import/ofx.ts` :
   - `lireOfx1(texte)` : en-tête `OFXHEADER:` sauté ; balises SGML lues ligne à ligne, une valeur s'arrête au prochain `<` ; conversion en `NoeudXml` puis même lecture que l'OFX 2 ;
   - `lireOfx2(racine: NoeudXml)` → `ReleveLu[]` (types de `../types.js`, L02-T07 : un relevé par `STMTRS`, `FITID` gardé en `idExterne`) ;
   - `soldeOuverture` OFX : non fourni par le format → absent (le contrôle sera `IMPOSSIBLE` sauf si le profil sait le calculer) ; `soldeCloture` = `LEDGERBAL/BALAMT` ;
   - dates `DTPOSTED` par `lireDate` (L02-T09, format OFX, heure et fuseau ignorés) ;
   - classe locale `ErreurOfx` : `pas_un_ofx`, `montant_illisible`, `date_illisible`.
2. Tests nommés (fichiers fictifs) : `ofx1-trois-operations`, `ofx2-trois-operations`, `deux-comptes-deux-releves`, `solde-de-cloture-lu`, `fitid-garde`, `balise-non-fermee-sgml`, `t02-1-cinq-cents-operations` (fichier généré dans le test, solde de clôture 765 433), `date-avec-fuseau-non-decalee`.

## Hors périmètre
Contrôle des soldes (L02-T17). QFX propriétaire au-delà de l'OFX standard.

## Pièges
Cas limites exigés : `BANKTRANLIST` vide, `TRNAMT` vide, `NaN`, `1e3`, virgule décimale (refus `montant_illisible`), `DTPOSTED` invalide, `FITID` en double dans un fichier (gardés tous les deux : les doublons sont traités par L02-T21). Sensible (argent). Règles du noyau.

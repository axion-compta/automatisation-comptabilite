## Contexte
Spec 14, `04` partie A. Le module est versionné (`regle_cas_sur_version`). Règle 1 : chaque lot validé enregistre la version et les paramètres lus. Règle 2 : changer la règle ou un seuil = nouvelle version, jamais de modification en place ; l'effet n'est pas rétroactif. Règle 3 : le résultat et ses raisons sont affichés pour chaque ligne de « Tout valider ». Test C3 : seuil changé de 50 000 à 40 000 : nouvelle version ; un lot validé avant garde l'ancienne.

## À faire
1. `packages/noyau/src/validation/version-cas-sur.ts` (importe `estCasSur`, `ParametresCasSur` de `./cas-sur.js` ; classe locale `ErreurVersionCasSur`) :
   - `export const VERSION_REGLE_CAS_SUR = 'cas-sur-1'` (à changer dans la même PR que toute modification de `cas-sur.ts` : écrit en commentaire) ;
   - `VersionParametres { numero: number; parametres: ParametresCasSur; depuis: string }` ; `nouvelleVersion(historique, parametres, depuis)` → nouvel historique (numéro + 1 ; l'entrée n'est pas modifiée ; paramètres identiques à la dernière = refus `version_identique` ; `depuis` antérieur à la dernière = refus) ;
   - `evaluerLot(propositions, ctx, historique, date)` → `{ regle: VERSION_REGLE_CAS_SUR; versionParametres: number; parametres; lignes: readonly { id; sur; raisons }[] }` : utilise la version en vigueur à `date` ;
   - `relireLot(lotEnregistre, historique)` → mêmes paramètres que ceux du lot (aucun recalcul avec la dernière version).
2. Tests nommés : `c3-nouveau-seuil-nouvelle-version`, `c3-lot-ancien-garde-l-ancienne-version`, `entree-non-modifiee`, `parametres-identiques-refuses`, `lot-du-jour-de-bascule-nouvelle-version`, `chaque-ligne-a-ses-raisons`.

## Contexte
Spec 12, `03-controles-tva`, CC-T01 (V3-CTL-025) : « Pour la période : (a) Σ TVA collectée des pièces exigibles = Σ des lignes de TVA collectée de la déclaration préparée, par taux ; (b) Σ TVA déductible solide des pièces dont la date de déduction est dans la période = Σ des lignes de TVA déductible (biens et services, immobilisations) ; (c) autoliquidations : même montant des deux côtés. Écart toléré : 0,00 €. Seuls écarts justifiés : crédit reporté (TVA-C10) et régularisations datées listées. » B, bloque TVA et export, jamais écartable. Cas CT-16 (collectée 2 400,00, déductible 1 800,00, déclaration identique : OK, nette 600,00) et CT-17 (achat de 100,00 + 20,00 ajouté après la préparation : B, écart 20,00 ; après nouvelle préparation : OK). TVA-C10 et TVA-C11 sont déjà codés par L03-T30 (`tva-declaration.ts`) : les RÉUTILISER, ne pas les dupliquer.

## À faire
1. `packages/noyau/src/controles/regles/tva-pieces-declaration.ts` :
   - `TotauxTva { collecteeParTaux: ReadonlyMap<number, Centimes>; deductibleBiensServices: Centimes; deductibleImmobilisations: Centimes; autoliquideeCollectee: Centimes; autoliquideeDeductible: Centimes }` (totaux des pièces : `tva/totaux.ts`, L03-T25) ;
   - `EcartJustifie { motif: 'credit_reporte' | 'regularisation'; date: string; montant: Centimes }` ;
   - `comparerPiecesDeclaration(pieces, declaration, justifies)` → `{ ecarts: { poste: string; ecart: Centimes }[]; ecartTotal: Centimes }` : postes `collectee:<taux>`, `deductible_bs`, `deductible_immo`, `autoliquidation` ; un taux présent d'un seul côté compte pour son montant entier ; les écarts justifiés sont retirés du poste qu'ils visent, une seule fois ;
   - `regleCCT01` : id `CC-T01`, version 1, gravité `B`, bloque `tva`, `export`, déclencheurs `continu`, `avant_tva`, `avant_export`, `a_la_demande` ; écart total nul = OK, sinon ALERTE avec `ecartCentimes` = somme des écarts absolus et `valeur` = premier poste en écart.
2. `packages/noyau/src/controles/regles/__tests__/tva-pieces-declaration.test.ts`, tests nommés : `CT-16`, `CT-17` (B 2 000 centimes puis OK), `un-centime-d-ecart-bloque`, `taux-d-un-seul-cote`, `autoliquidation-desequilibree`, `credit-reporte-justifie`, `justification-non-reutilisee` (une justification ne couvre pas deux postes), `declaration-vide-et-pieces-vides-ok`, `jamais-ecartable`.

## Pièges
Règles du noyau comme L01-T06 : montants en `Centimes` via `packages/noyau/src/argent`, ni `/`, ni littéral décimal, ni `Math.round`, ni `parseFloat`, ni `toFixed`. Stryker (seuil 80 %) porte sur tout le noyau : chaque branche doit être tuée par un test. Ne pas toucher `packages/noyau/src/index.ts` ni `controles/moteur.ts` (imports par chemin relatif). Aucun taux, seuil, délai ni date légale dans `src` (garde:litteraux, D31) : tout seuil ou tolérance arrive en argument ou dans un `ParametreLu` (L12-T00) ; paramètre absent = `IMPOSSIBLE`, jamais OK (PRI-007). Le noyau ne contient aucun texte affiché : seulement des codes. Montants et seuils des tests INVENTÉS ou repris des cas fictifs de la spec ; noms et SIREN fictifs seulement. TVA : chemin sensible (fusion après relecture Opus et double relecture argent). Aucun taux de TVA ni pourcentage légal dans src : taux en points de base et parts déductibles viennent d'un `ParametreLu` ; un paramètre au statut autre que `valide` rend la ligne `A_VERIFIER` (donc CC-T02, L12-T09), jamais une estimation. Comptes (445660, 445800, 275000…) en argument, jamais en dur. Le moteur (L01-T19) a une gravité FIXE par règle : quand la spec donne deux gravités à un même contrôle, la fiche crée deux règles (identifiant suffixé, voir LOT-12-PLAN §7). Le vocabulaire du code (`Blocage` = validation, tva, export, cloture ; `Declencheur` = `a_la_demande`) et celui du CSV (`validation_mois`, `preparation_tva`, `export_officiel`, `cloture`, `aucun` ; `demande`) diffèrent déjà : ne pas les « corriger ». La ligne du catalogue `docs/controles.csv` n'est PAS écrite ici (L12-T26 ou L12-T27) ; le titre du test `CT-nn` doit être exact, `garde:controles` le cherche. Cas limites exigés dans les tests : montant NaN, Infinity, non entier (1,5) et négatif là où il est interdit = exception codée (le moteur la change en `IMPOSSIBLE`) ; liste vide ; objets reçus dans l'ordre inverse (même résultat) ; écart d'exactement un centime de chaque côté de la tolérance. Chaque test doit rougir si l'on casse la branche qu'il couvre (inverser une comparaison, retirer un cas). Les clés de `Map` (taux en points de base) doivent être des entiers sûrs : une clé NaN ou décimale = exception.

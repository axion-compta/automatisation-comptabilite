## Contexte
Spec 01, §04, règle 5 : « "Modifier" produit deux écritures nouvelles, liées à l'originale : contre-passation (type correction, lignes inversées) et écriture corrigée ; motif obligatoire ; l'originale passe à contre-passée par un lien ajouté, ses lignes restent intactes. » Test T-ECR-6 : après correction d'un compte, solde de l'ancien compte = 0, solde du nouveau = montant.

## À faire
1. `packages/noyau/src/ecritures/correction.ts` :
   - `contrePasser(originale, { id, date, motif })` → écriture `brouillon`, `type: 'correction'`, `lienOriginale: originale.id`, chaque ligne avec débit et crédit inversés ; refus `motif_obligatoire` (motif vide ou blanc), `originale_non_validee` si `originale.statut !== 'valide'`, `deja_contre_passee` si `originale.contrePassee` ;
   - `corriger(originale, { idContrePassation, idCorrection, date, motif, lignes })` → `{ contrePassation, correction, marqueOriginale }` : `correction` est un brouillon avec les nouvelles lignes et `lienOriginale` ; `marqueOriginale` = copie de l'originale avec `contrePassee: true` et ses lignes identiques ; l'objet reçu n'est jamais modifié ; la correction doit passer `verifierEcriture` (L01-T06).
2. Tests nommés : `contre-passation-inverse-les-lignes`, `motif-obligatoire`, `originale-non-validee-refusee`, `deja-contre-passee-refusee`, `originale-intacte` (entrée gelée, lignes égales avant et après), `soldes-apres-correction` (T-ECR-6 avec des montants inventés : solde de l'ancien compte 0, du nouveau égal au montant, calculé dans le test).

Pas de période verrouillée ni d'exercice clos (L01-T13 fournit `estVerrouillee`, le branchement viendra avec le service). Pas de numérotation.

## Contexte
Spec 03, §04 : `formule` = expression sur d'autres lignes (TVA-032) ; « Ligne manquante dans la table du millésime → déclaration bloquée avec la ligne citée » ; règle 4 : « jamais de base négative (TVA-033) ». Spec 03 §03, TVA-C13 : base négative sur une ligne = bloquant, jamais produite.

## À faire
1. `packages/noyau/src/declarations/formules.ts` :
   - grammaire volontairement petite : `expression = terme (('+' | '-') terme)*`, `terme = CODE | 'plancher_zero(' expression ')'` ; `CODE` = lettres majuscules, chiffres et `_` ; espaces ignorés ; tout autre caractère = `formule_invalide` ; aucun `eval`, aucun `Function` ;
   - `calculerFormules(table, cases)` → cases complètes : évalue les lignes `aCalculer` dans l'ordre des dépendances ; sources d'une ligne calculée = union triée des sources des lignes citées ; référence à un code absent de la table = `{ bloque: true; code: 'ligne_absente'; ligne }` (pas d'exception : la déclaration est bloquée avec la ligne citée) ; cycle = `formule_cyclique` avec les codes du cycle ;
   - après calcul, toute ligne `base: true` négative = `{ bloque: true; code: 'base_negative'; ligne; montant }`.
2. Tests nommés (codes fictifs `X01`…) : `addition-et-soustraction`, `plancher-zero`, `dependances-dans-le-desordre`, `sources-unies-et-triees`, `ligne-absente-bloque-avec-le-code`, `cycle-detecte`, `base-negative-bloque`, `caractere-interdit-refuse` (`X01 * 2`, `X01; X02`).

## Hors périmètre
Pas de multiplication, division ni taux dans les formules (un taux est un paramètre, jamais une formule de ligne). Pas de report de crédit (L03-T28).

## Pièges
Règles du noyau comme L03-T01 (aucune division, même dans l'analyseur). Ne pas modifier `cases.ts` (L03-T26) : importer ses types. Cas limites exigés : formule vide (`formule_invalide`), parenthèse non fermée, code répété (`X01 + X01` compte deux fois), profondeur de 50 lignes chaînées (pas de dépassement de pile).

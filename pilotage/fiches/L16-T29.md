## Contexte
Existant : `PaquetParametres` et `regleAuJour` (`packages/parametres/src/paquet.ts`), paquet correctif N+1 (`correctif.ts`), dates frontières (`frontieres.ts`), source officielle (`source.ts`). Manque : signature, refus d'un paquet plus ancien ou signé par une clé révoquée, journal des refus, déploiement progressif.

## À faire
1. Tests d'abord : la paire de clés est générée dans le test (`node:crypto`, Ed25519) ; aucune clé ni signature écrite dans le dépôt.
2. `signature-paquet.ts` :
   - `verifierPaquetSigne(paquet, signature, cles, installe)` → `{ accepte: true } | { accepte: false; code }`, codes `signature_invalide`, `cle_revoquee`, `cle_inconnue`, `retour_arriere` (version ≤ version installée), `ligne_sans_source` ; chaque refus rend aussi une ligne de journal `parametres.paquet_refuse`.
   - `cohorteDeploiement(societeId, pourcentage, graine)` déterministe : même société, même réponse ; 0 % = aucune, 100 % = toutes.
   - Activation refusée si la non-régression des dates frontières (`frontieres.ts`) n'est pas verte.
3. Tests nommés : `paquet-signe-accepte`, `signature-alteree-refusee`, `cle-revoquee-refusee`, `paquet-plus-ancien-refuse`, `zero-ligne-sans-source`, `paquet-n-plus-1-sur-incident`, `cohorte-deterministe`.

## Hors périmètre
Garde des clés de signature hors ligne, outil de publication, licence (V2). Aucune modification de `paquet.ts` ni de `correctif.ts`.

## Pièges
Une erreur se corrige par un paquet N+1, jamais par un retrait silencieux. Fiche sensible (sécurité) : relecture Opus, fusion par Will seul.

## Contexte
bloque_par: D29 (réponse de la console sur le module C4, l'ADR 0060 et la DEMANDE 3 : flux de double facteur) et feu vert J3a (identité). NE PAS PLANIFIER avant.
Spec 06, `02-identite-connexion.md` §1 : toute route exige un jeton du royaume `clients` dont l'audience est celle de l'API des clients ; sans jeton : 401 ; aucune table de comptes ; `a_compta.personne` (id, `sujet_externe`, nom affiché, créée le) remplie à la première visite (`securite.premiere_visite`) ; un lien signé n'est jamais un facteur. La vérification OIDC de la console (`apps/api/src/auth/oidc.ts`) est le modèle.

## À faire
1. `apps/serveur/src/securite/jeton.ts` : vérification du jeton (émetteur, audience, signature par les clés publiques du royaume, expiration, `acr`) ; résultat = session `{ personneId, role, permissions, organisation, societe }` remplaçant l'option `securite.session` des tests ; 401 `NON_AUTHENTIFIE` sans jeton ou jeton invalide.
2. Les tests existants passent une session de test par l'option ; les nouveaux tests utilisent une paire de clés générée dans le test (jamais une clé réelle).
3. Tests nommés : `toutes-les-routes-sans-jeton-401` (T-CNX-1), `jeton-sans-mfa-refuse` (T-CNX-2), `jeton-expire-refuse` (T-CNX-4, horloge fictive), `autre-audience-refusee`, `autre-emetteur-refuse`, `signature-alteree-refusee`, `premiere-visite-cree-la-personne-une-fois`.

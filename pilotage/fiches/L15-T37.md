## Contexte
Spec 15, RE-R1 à RE-R4 et point S4 (recommandation retenue : garder POST). `POST /recherche { q, types?, limite?, curseur? }` : le texte cherché est dans le CORPS, jamais dans l'URL (il n'entre pas dans les journaux d'accès). Types : pièces, écritures, tiers, commentaires (pas les conversations du chat : L15-T67, bloquée). Résultat `{ type, id, titre, extrait, lien, date, exerciceId, score }` ; vide = 200 avec liste vide et un mot. Point S3 (recommandation retenue) : une pièce sensible est EXCLUE des résultats, pas masquée ; tant que les permissions réelles n'existent pas (L15-T60), le service en mémoire l'exclut toujours. Le texte cherché n'est jamais journalisé. Cette route est une LECTURE en POST : elle n'a pas d'`Idempotency-Key`.

## À faire
1. `domaines/recherche.ts` : corps strict `{ q: string (2 à 200 points de code, vérifié aussi par lireRequete), types?: ('piece' | 'ecriture' | 'tiers' | 'commentaire')[], limite?: 1 à 20, curseur?: string }` ; route `chercher` (`POST /recherche`, `tags: ['lecture-par-post']`) ; erreurs `REQUETE_INVALIDE` 400, `CURSEUR_INVALIDE` 400 ; réponse `{ body: { resultats; curseurSuivant?; mot? } }` où `mot = 'rien_trouve'` si vide.
2. `domaines/recherche-service.ts` : index EN MÉMOIRE construit depuis `genererCompta()` et `genererInterface()` (pièces, écritures validées, tiers, commentaires) ; `lireRequete` (L15-T25), correspondance par `correspondMot`, montant exact, SIREN de tiers ; score simple (nombre de mots trouvés, titre compté double) ; `extrait`, `trier`, `paginer` (L15-T26) ; pièces `sensible` exclues.
3. `openapi.ts` : `routesEcritureSansEnTete()` ignore les routes dont `tags` contient `lecture-par-post` ; nouvelle fonction `routesLectureParPost()` (liste de ces routes) ; `contrat.test.ts` : un test `lecture-par-post-explicite` vérifie que cette liste vaut exactement `['chercher']` (toute autre exemption doit être ajoutée ici consciemment).
4. Domaine déjà branché par L15-T69 (objet vide) : remplir l'objet du domaine dans son fichier du contrat et la fonction de routes de son fichier serveur (implémentation par le service), SANS toucher `routes.ts` ni `app.ts` ; régénérer `openapi.json` (`pnpm contrat:openapi`).
5. Tests nommés : `q-dans-le-corps-pas-dans-l-url` (le chemin OpenAPI n'a aucun paramètre `q`), `q-trop-court-400`, `q-trop-long-400`, `champ-inconnu-400`, `vide-200-rien-trouve`, `script-echappe-dans-l-extrait`, `piece-sensible-exclue`, `montant-trouve-exactement`, `siren-trouve-le-tiers`, `pagination-par-curseur`.

## Hors périmètre
Pas d'index PostgreSQL ni de tenue par événements (L15-T64), pas de droits par rôle ni d'isolation (L15-T60), pas de faux serveur (L15-T38).

## Pièges
Ne jamais écrire `q` dans un journal ou un message d'erreur (le message d'erreur dit seulement `requete_invalide`). Ne toucher ni `routes.ts` ni `app.ts` (domaine déjà branché par L15-T69). Seul fichier commun : `openapi.json` (généré, trié) : en cas de conflit, rebaser sur main, relancer `pnpm contrat:openapi`, committer. `openapi.ts` et `contrat.test.ts` ne sont touchés que par cette fiche dans le lot. Si la garde d'accès du lot 07 est sur main : la route doit être classée `lecture` (étiquette `acces:lecture` dans `tags`), sinon le signaler dans le journal ; si cette garde refuse l'étiquette `lecture-par-post` (étiquette inconnue), s'arrêter et le signaler (ne pas toucher les fichiers du lot 07). Sensible (sécurité) : relecture Opus.

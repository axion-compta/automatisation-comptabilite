## Contexte
Spec 01, §02 : `GET/POST …/tiers` (liste, ajout) ; un code de tiers n'est jamais réutilisé (PCP-010). Ici, lecture seulement. Même structure que L01-T23 (domaine, service en mémoire, serveur).

## À faire
1. `packages/contrat/src/domaines/tiers.ts` : schéma `Tiers { code, nom, type: 'client' | 'fournisseur', email }` ; route `listerTiers` (`GET /tiers`, query `type`, `q` 50 caractères au plus, `limite` 1 à 100, `decalage`), enveloppe `{ body, decalage, total }`.
2. `packages/contrat/src/domaines/tiers-service.ts` : service pur sur `genererCompta()` (profil `pleine`) : tri par code ; filtre par type ; recherche sans casse ni accents sur code et nom.
3. `routes.ts` : ajouter le domaine `tiers`. Régénérer `openapi.json`.
4. `apps/serveur/src/domaines/tiers.ts`, branché dans `app.ts`.
5. Tests nommés : `tiers-enveloppe-et-tri`, `tiers-filtre-type`, `tiers-recherche-sans-accent`, `openapi-contient-lister-tiers`, `serveur-repond-aux-tiers`.

## Hors périmètre
Pas d'ajout de tiers, pas de faux serveur (L01-T26).

## Pièges
Noms des tiers : ceux du jeu fictif, jamais d'autres. `openapi.ts` a déjà été rendu générique par L01-T23 : ne pas y toucher.

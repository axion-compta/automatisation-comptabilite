## Contexte
Spec 04, fichier 08 §3 : `GET …/pieces?…` (recherche par fournisseur, période, montant, état) et détail d'une pièce. La route d'état (`GET …/pieces/{id}/etat`) est dans L04-T32. Le préfixe `/societes/{s}` viendra avec l'isolation (L04-T51, bloquée) : routes SANS préfixe ici, comme L01-T23. Aucun pourcentage de confiance ne sort : seulement le mot (CTL-010). Le contrat est figé ici ; le service et le serveur réel sont dans L04-T30 (même méthode que L07-T14).

## À faire
1. `packages/contrat/src/domaines/pieces.ts` : schémas zod `PieceResume { id, nomNormalise, typePiece, etat, comptee, sensible, datePiece?, fournisseur?, ttcCentimes?, motConfiance }`, `PieceDetail` (résumé + `canal`, `recuLe`, `motifNonComptee?`, `motifsAVerifier[]`, `champs: { nom, valeur, valeurCentimes?, mot, source }[]`, `cheminVirtuel`) ; routes oRPC `listerPieces` (`GET /pieces`, query `fournisseur` (50 car. au plus), `du`, `au` (dates), `montantMin`, `montantMax` (centimes entiers), `etat`, `type`, `limite` 1 à 100, `decalage`, enveloppe `{ body, decalage, total }`) et `lirePiece` (`GET /pieces/{id}`) ; erreur `PIECE_INCONNUE` 404 ; `du > au` ou `montantMin > montantMax` = 400.
2. `routes.ts` : ajouter `pieces: { listerPieces, lirePiece }` sans toucher les autres clés ; `openapi.ts` seulement si la génération échoue sur un schéma nouveau ; régénérer `openapi.json` par `pnpm contrat:openapi`.
3. `apps/serveur/src/domaines/pieces.ts` : `routesPieces()` SANS paramètre, signature figée, qui rend `listerPieces` et `lirePiece` avec `os.<route>.handler(() => { throw new ORPCError('NOT_IMPLEMENTED'); })` ; branché dans `app.ts` (clé `pieces: routesPieces()`, comme `sante`).
4. Tests nommés : `pieces-dans-openapi` (les deux chemins et leurs operationId sont dans `openapi.json`), `bornes-inversees-400` (`du > au` ; `montantMin > montantMax` ; `limite` 0, 101 et 1.5), et dans `pieces-branchement.test.ts` (Fastify `inject`) `routes-pieces-branchees` (statut différent de 404, sans exiger 501).

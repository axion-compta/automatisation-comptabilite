## Contexte
Spec 05, fichier 02 §6 : interrupteur `ia.mode = simule` : chaque appel est remplacé par une réponse enregistrée, retrouvée par l'empreinte SHA-256 de l'entrée normalisée ; empreinte inconnue = réponse « non enregistrée » et pièce « à vérifier ». Les réponses sont fictives et vivent dans le dépôt. Le parcours de bout en bout passe avec 0 appel réseau vers un modèle.

## À faire
1. `apps/serveur/src/ia/modele-simule.ts` : implémente le port `ModeleTexte` de L05-T34 ;
   - `normaliser(entree)` : forme NFC, fins de ligne `\n`, espaces de fin de ligne retirés, suites d'espaces réduites à une ;
   - `empreinte(entree)` : SHA-256 hexadécimal de l'entrée normalisée (`node:crypto`) ;
   - `creerModeleSimule(reponses: Record<empreinte, { texte; jetons; coutMicroCentimes }>)` : empreinte connue = la réponse, avec `modele: 'simule'` ; inconnue = `ErreurModele` de sorte `client` et code `non_enregistree` ;
   - `enregistrer(reponses, entree, reponse)` rend une copie complétée ; elle sert aux tests et aux fiches suivantes (aucun script ajouté).
2. `reponses-simulees.json` : 6 réponses fictives au moins (réponse simple, appel d'outil de lecture, référence `{{ref:…}}`, proposition, injection à bloquer, sortie hors schéma), données des sociétés A et B.
3. Tests nommés : `meme-entree-meme-reponse`, `normalisation-espaces-et-fins-de-ligne`, `nfc-et-nfd-identiques`, `inconnue-non-enregistree`, `entree-vide`, `zero-appel-reseau` (`fetch` espionné : 0 appel), `fichier-de-reponses-valide` (chaque entrée a texte, jetons et coût entiers >= 0), `empreintes-du-fichier-recalculees` (chaque clé du JSON = empreinte de l'entrée enregistrée à côté).

## Hors périmètre
Pas de choix entre simulé et réel en production (dépend de L05-T59).

## Pièges
Données fictives seulement. Les tests doivent rougir si la normalisation est retirée.

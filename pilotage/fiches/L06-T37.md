## Contexte
bloque_par: D29 (règle et code d'erreur de la console `exiger-reauthentification.ts`, ADR 0024 de la console ; signal de récupération du facteur) et J3a. NE PAS PLANIFIER avant ; dépend aussi de L06-T36.
Spec 06, `02-identite-connexion.md` §2 et §4 : le module réutilise la règle de la console (même délai, même code d'erreur) ; il ne fixe pas son propre délai ; actions sensibles refusées pendant une période après une récupération signalée par la console (`securite.facteur_recupere`).

## À faire
1. `apps/serveur/src/securite/reauthentification.ts` : étiquette `operation:<nom>` sur les routes des 8 opérations sensibles (L06-T00), refus par `exigerNiveau` (L06-T09) avec le délai lu chez la console ; 401 avec le code de la console ; événement `securite.reauth_refusee`.
2. Tests nommés : `six-minutes-refuse-quatre-minutes-permis` (valeurs fournies par la configuration de test), `export-fec-ancienne-connexion-refuse` (C14), `recuperation-recente-bloque`, `operation-ordinaire-non-touchee`.

## Hors périmètre
Routes elles-mêmes (lots 02, 03, 07), flux de la console.

## Pièges
Ne recopier aucun délai de la console en dur : il se lit dans sa configuration. Fiche sensible (sécurité).

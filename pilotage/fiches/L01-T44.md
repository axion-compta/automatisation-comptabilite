## Contexte
Suite de la relecture de L01-T10. `lettrer` accepte la même ligne (même `id`) deux fois : le lettrage de deux fois la même ligne passe le contrôle « au moins deux lignes » et compte son montant deux fois dans `reste`.

## À faire
1. `lettrer` : refuser deux lignes de même `id` avec le code `moins_de_deux_lignes` si le nombre de lignes distinctes est inférieur à deux, sinon avec un nouveau code `ligne_en_double` ajouté à `CodeErreurLettrage`.
2. Tests : même ligne passée deux fois seule ; même ligne passée deux fois avec une autre ligne ; même `id` avec montants différents ; liste vide ; une seule ligne ; code `''`, `'a'`, `'A1'` ; lignes de comptes ou d'auxiliaires différents ; ligne déjà lettrée ; `reste` nul (total) et non nul (partiel), montants inventés ; ordre d'entrée inversé donne les mêmes liens au tri près et le même `reste` ; entrée gelée jamais modifiée.

## Hors périmètre
Pas de changement de `prochainCode`. Pas de changement de `modele.ts`.

## Pièges
Le contrôle de doublon passe avant le calcul du reste. Les tests de L01-T10 restent verts sans modification. Sensible : fusion par Will.

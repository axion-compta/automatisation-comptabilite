## Contexte
bloque_par: V1 : ne pas planifier avant la fin de la V0 (décision de Will, 11/11/2026)
Modèle `regularisation_tva` : pièce, type, période, coefficient, montant. Le coefficient est un paramètre daté (points de base, 10000 = 100 %), jamais en dur ; toute valeur légale non confirmée reste « à vérifier ». Une période déposée n'est jamais modifiée : la régularisation se fait sur une période ouverte. Existant : `partDeductible` dans `packages/noyau/src/tva/deductible.ts`, périodes dans `tva/periodes.ts`.

## À faire
1. Tests d'abord, montants fictifs.
2. `regularisation.ts` (pur, centimes entiers) :
   - `deductibleAuProrata(tva, coefficientPdb)` (réutilise `partDeductible`).
   - `regularisationProrata({ tva, provisoirePdb, definitifPdb })` → `{ type: 'reversement' | 'complement'; montant: Centimes }` ou `null` si égal.
   - `proposerRegularisation(regul, periodes)` → ligne `RegularisationTva` en statut `brouillon` sur la première période ouverte ; refus `periode_deposee` si la cible est déposée ; refus `coefficient_a_verifier` si le paramètre n'est pas `valide`.
3. Tests nommés : `prorata-80-pourcent-80000`, `definitif-75-reversement-5000`, `definitif-85-complement-5000`, `coefficients-egaux-aucune-regul`, `periode-deposee-jamais-modifiee`, `coefficient-a-verifier-refuse`.
   Cas chiffré : TVA de 100 000, coefficient provisoire de test 80 % → 80 000 ; définitif 75 % → reversement de 5 000 en brouillon sur une période ouverte.

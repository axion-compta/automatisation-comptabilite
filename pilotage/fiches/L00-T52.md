## Contexte
Le faux hôte de L00-T19 simule le contrat C4 « version 0 » : code, version, 50 permissions au plus, jeu de 20 cas avec une panne et un e-mail piégé, `migrer` idempotent, interrupteur fermé. La compta a demandé à la console un contrat C4 0.5.0 : tables « ajout seul » (aucun UPDATE ni DELETE accordé), tables figées et journal chaîné ; la spec 05 (fichier 04) ajoute `actionsAutomatiquesAutorisees`, vide par défaut. La console n'a pas répondu (D29, question 2 de l'audit) : cette fiche simule l'HYPOTHÈSE 0.5.0 dans le faux hôte pour tester le manifeste réel (L00-T51) ; elle ne décrit pas le vrai SDK. Les champs nouveaux sont facultatifs (absents = liste vide) : les manifestes « version 0 » restent valides. Décision de Will du 08/11/2026 : « fais tout ce qui est nécessaire selon tes recommandations ».

## À faire
1. Tests d'abord dans le fichier neuf `outils/faux-hote-c4/test/contrat-0-5-0.test.mjs` (vitest), avec un module fictif construit dans le test (code `essai-0-5-0`, 20 cas copiés de `module-vide.mjs`).
2. `contrat.mjs` : commentaire d'en-tête « Contrat C4 (hypothèse 0.5.0, en attente de la réponse de la console, D29) » ; `export const VERSION_CONTRAT = '0.5.0'` ; `validerManifeste` ajoute :
   - `contrat` présent et différent de `VERSION_CONTRAT` : « version de contrat inconnue » ;
   - `actionsAutomatiquesAutorisees` (absent = []) : liste de textes non vides sans doublon, sinon « actions automatiques mal formees » ;
   - `tablesAjoutSeul` (absent = []) : liste sans doublon de noms `schema.table` (minuscules, chiffres, `_`), sinon « tables ajout seul mal formees » ;
   - chaque table déclarée est créée par une instruction `CREATE TABLE` (avec ou sans `IF NOT EXISTS`) rendue par `migrer()`, sinon « table ajout seul non creee : <nom> ».
   `defineAutomation` rend les deux listes (vides si absentes), gelées.
3. `faux-hote.mjs` : `executer(module, instruction)` normalise comme `instructionRefusee` (minuscules, commentaires retirés, blancs réduits) ; `update`, `delete` ou `truncate` qui vise une table de `tablesAjoutSeul` lève `Error('Instruction refusee (ajout seul) : …')` ; sinon rend `'ok'` (base simulée, rien n'est exécuté). `migrer` et `rejouer` ne changent pas.
4. Tests nommés : `module-version-0-reste-valide`, `actions-automatiques-vides-par-defaut`, `actions-automatiques-doublon-refuse`, `actions-automatiques-non-texte-refuse`, `version-contrat-inconnue-refusee`, `table-ajout-seul-non-creee-refusee`, `update-sur-table-ajout-seul-refuse` (majuscules et blancs variés), `delete-sur-table-ajout-seul-refuse`, `insert-sur-table-ajout-seul-permis`, `update-sur-autre-table-permis`.
5. Journal `pilotage/journal/L00-T52.md` (10 lignes au plus) ; `statut: fait`.

## Hors périmètre
Tables figées et journal chaîné de la console (forme inconnue) : fiche de suite après la réponse D29. Vrai SDK de la console. Manifeste réel (L00-T51). `faux-hote.test.mjs`, `module-vide.mjs`, toute garde.

## Pièges
- `migrer()` appelée pendant la validation doit rester pure (elle rend une liste, n'écrit rien).
- Messages sans accent, comme ceux qui existent dans `contrat.mjs`.
- Données fictives, aucun nom ni prix réel. Sensible : relecture Opus.

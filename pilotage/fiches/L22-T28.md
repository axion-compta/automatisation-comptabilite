## Contexte
La mesure d'usage sans contenu existe (`packages/noyau/src/usage/usage.ts`, L15-T29 et L15-T66 : liste blanche, type `carte_resolue`, champ `duree_ms`) et la route `POST /usage` est au contrat (`preferences.ts`), mais l'interface n'émet jamais `carte_resolue`. Aucun écran de résolution de cartes n'existe encore sur main : cette fiche livre le module prêt à brancher et l'outil de rapport ; le branchement se fera dans la fiche de l'écran concerné. Le temps cible porte sur une « facture simple » (une page, fournisseur connu, un seul taux, réponse présélectionnée).

## À faire
1. Tests d'abord.
2. `mesure-carte.ts` : `demarrerMesure(ecranCode, horloge)` → `{ resoudre(): void }` ; à la résolution, émet `{ type: 'carte_resolue', ecran_code, duree_ms }` par la couche d'appels existante (`api.ts`) ; rien n'est émis si la mesure d'usage est désactivée ; une durée hors bornes de `usage.ts` n'est pas émise ; aucun identifiant de pièce ni contenu.
3. `temps-humain.mjs` : lit une liste de mesures `{ duree_ms, factureSimple }` (fichier JSON), garde les factures simples, calcule médiane et p90 (`mediane` et `centile` de `evaluateur.mjs`), compare à des seuils passés en argument (réglages, pas des constantes) ; rapport « au-dessus » ou « au-dessous » ; code de sortie 0 dans tous les cas sauf fichier mal formé.
4. Tests nommés : `carte-resolue-emise-avec-duree`, `aucun-contenu-dans-l-evenement`, `mesure-desactivee-rien-emis`, `duree-hors-bornes-non-emise`, `seules-factures-simples-comptees`, `mediane-et-p90-calcules`, `seuils-en-argument-sans-echec`.

## Hors périmètre
Branchement dans un écran, robot e2e (quand l'écran de cartes existera), cible en lot (V1), tests utilisateurs.

## Pièges
`garde:appels` : aucun `fetch` hors de `api.ts`. Horloge injectée dans les tests.

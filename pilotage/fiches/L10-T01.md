## Contexte
Spec 10, fichier 03, tableau « Quel schéma pour quelle facture » : A débits (biens, ou services avec option pour les débits), B encaissements (services sans option, par défaut), C franchise en base (partie double), D micro-entrepreneur (`tenue = livre_recettes`). Règle 9 : la TVA est rattachée à la période de son exigibilité, jamais à la date de l'écriture : date de l'opération pour les biens, date d'encaissement en B, date de facture avec l'option débits. D4 : régime de TVA en doute = blocage, jamais d'estimation.

## À faire
1. `packages/noyau/src/ventes/schema.ts` :
   - `casDeLaLigne(profil, nature, dateOperation)` → `'A' | 'B' | 'C' | 'D' | 'a_confirmer'`, dans cet ordre : `tenue = livre_recettes` → D ; `regimeTva = a_confirmer` → `a_confirmer` ; `franchise` → C ; nature `a_confirmer` → `a_confirmer` ; `bien` → A ; `service` → A si `optionDebitsDepuis` non nul et `dateOperation >= optionDebitsDepuis`, sinon B ;
   - `dateExigibilite(cas, nature, { dateFacture, dateOperation?, dateEncaissement? })` → `{ date: string | null; dateOperationSupposee: boolean }` : A + bien → `dateOperation`, sinon `dateFacture` avec `dateOperationSupposee: true` (carte A8 plus tard) ; A + service → `dateFacture` ; B → `dateEncaissement` ou `null` ; C et D → `null` ;
   - toutes les dates passent par `exigerDate` (L10-T00).
2. Tests nommés : `bien-cas-a`, `service-sans-option-cas-b`, `option-debits-le-jour-meme-cas-a` (option au 2026-11-01, opération 2026-11-01), `option-debits-la-veille-cas-b` (2026-10-31), `franchise-cas-c`, `livre-recettes-prime-sur-franchise`, `regime-a-confirmer-jamais-estime`, `nature-a-confirmer`, `exigibilite-bien-date-de-livraison` (cas V28 : opération 2026-10-28, facture 2026-11-03 → 2026-10-28), `exigibilite-sans-date-operation-supposee`, `dates-invalides-refusees` (chaîne vide, `2026-02-30`, `undefined` pour une date obligatoire).

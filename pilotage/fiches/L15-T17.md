## Contexte
Spec 15, AL-R2 : ALR-08 facture client en retard (à faire, JAMAIS urgent ; décision D26 : le logiciel ne relance pas, il signale) ; ALR-09 facture fournisseur à payer à J-N ou dépassée (urgent : argent) ; ALR-10 écart de rapprochement (`ECART` = à faire, `IMPOSSIBLE` = urgent) ; ALR-11 commentaire du cabinet non lu (à faire).

## À faire
1. `regles/tiers-banque.ts`, quatre fonctions qui rendent des constats pour `evaluer` (L15-T12) :
   - `alr08(factures: { id; sens: 'a_recevoir'; resteCentimes; echeance }[], jour)` : reste > 0 et échéance dépassée ; gravité `a_faire` quelle que soit l'ancienneté ;
   - `alr09(factures: { id; sens: 'a_payer'; resteCentimes; echeance }[], jour, parametres: { joursAvant: number })` ;
   - `alr10(comptes: { id; ecart: 'OK' | 'ECART' | 'IMPOSSIBLE' }[])` ; valeur inconnue = erreur ;
   - `alr11(commentaires: { id; lu: boolean; auteur: 'cabinet' | 'client' }[])` : seulement ceux du cabinet.
2. Tests nommés : `alr08-se-declenche`, `alr08-jamais-urgent` (retard de 1 000 jours : `a_faire`), `alr08-echeance-du-jour-rien`, `alr09-se-declenche`, `alr09-ne-se-declenche-pas`, `alr09-seuil-exact`, `alr10-ecart-a-faire`, `alr10-impossible-urgent`, `alr10-ok-rien`, `alr11-cabinet-non-lu`, `alr11-lu-rien`, `alr11-client-rien`.

## Hors périmètre
Pas de relance, pas d'e-mail à un tiers (D26), pas de rapprochement (lot 02).

## Pièges

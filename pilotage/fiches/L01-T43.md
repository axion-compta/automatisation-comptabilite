## Contexte
Suite de la relecture de L01-T11 et L01-T21. Dans `balance.ts`, `cle(e)` rend `e.numero ?? e.id` : une écriture validée sans numéro expose son identifiant dans la colonne `numero` du grand livre, comme si c'était un numéro continu. `journal()` rend les objets d'écriture d'entrée eux-mêmes : une modification du résultat modifie l'entrée. Les contrôles d'équilibre (`equilibre.ts`, L01-T21) lisent la balance : leurs tests ne doivent pas changer.

## À faire
1. `grandLivre` : la colonne `numero` est une chaîne vide quand l'écriture n'a pas de numéro ; `ecritureId` garde l'identifiant. Le tri peut continuer à se replier sur l'identifiant, mais ce repli reste interne.
2. `journal()` : rendre des copies (écriture et lignes), l'entrée n'est jamais partagée avec le résultat.
3. Tests : écriture validée sans numéro (colonne vide, `ecritureId` rempli) ; mélange avec et sans numéro ; deux écritures de même date triées dans un ordre stable ; entrée en ordre inversé donne le même résultat ; modification du résultat de `journal()` sans effet sur l'entrée gelée ; entrée vide ; brouillon et proposée écartés ; compte absent ; montants en centimes entiers.

## Hors périmètre
Pas de changement de `equilibre.ts` ni de `modele.ts`. Pas de nouvelle colonne.

## Pièges
Le champ `numero` de `LigneGrandLivre` reste de type `string`. Les tests existants de L01-T11 et de L01-T21 restent verts, sauf un test qui attend l'identifiant dans `numero` : l'ajuster dans le test. Sensible : fusion par Will.

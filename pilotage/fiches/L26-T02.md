## Contexte
Le faux serveur implémente le contrat (ADR 0002) mais n'a pas de journal de mutations : « Annuler » dans la démo ne vérifie que le statut d'une proposition. Le noyau sait déjà annuler (`packages/noyau/src/chat/__tests__/annulation.test.ts`, L05-T10).

## À faire
1. Tests d'abord.
2. `journal-mutations.ts` : `creerJournal(lireEtat, ecrireEtat)` ; `avant(requete)` enregistre une copie profonde (`structuredClone`) de l'état avant chaque requête d'écriture (POST, PUT, PATCH, DELETE) ; `annulerDerniere()` rétablit la dernière copie ; `taille()` ; pile bornée à 50 entrées (la plus ancienne sort).
3. `handlers.ts` : branche le journal sur toutes les écritures et expose `annulerDerniere` dans les options du faux serveur (aucune nouvelle route du contrat).
4. Tests nommés : `instantane-identique-apres-annuler` (comparaison profonde de l'état complet), `lecture-non-journalisee`, `deux-annulations-successives`, `pile-bornee-a-50`, `annuler-pile-vide-sans-effet`.

## Hors périmètre
Service worker et hors connexion (L26-T03). Chat scénarisé (L26-T05).

## Pièges
Copie de l'état complet, pas d'un seul domaine. Aucune mutation de l'objet copié après enregistrement. Données fictives seulement (noms inventés, e-mails en @exemple.fr) ; aucune valeur commerciale dans les textes.

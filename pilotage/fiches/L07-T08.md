## Contexte
Spec 07, `02-quotas-ia.md` §3 et décision W11 (D14, D15) : au-delà du volume compris, les pièces continuent d'être traitées et le client voit le choix « attendre le mois suivant » ou « demander le palier supérieur » ; réglage `comportement_quota` (`continuer` par défaut, `attente`) : en `attente`, les pièces sont « en attente de volume » et traitées dans l'ordre d'arrivée au mois suivant ou au changement de palier, sans doublon. Plafond technique d'IA (PLA-070) : arrêt franc des appels d'IA, pièces en attente ; consultation, validation, déclarations, exports continuent. Rien n’est facturé. Passage automatique de palier : V2, rien n'est codé (PLA-159). Cas T-ABO-8, T-ABO-9, T-ABO-11.

## À faire
1. `packages/noyau/src/abonnement/quota.ts` :
   - `etatQuota({ dejaTraitees, compris, comportement })` → `{ depasse: boolean; enAttenteVolume: boolean; proposerChoix: boolean }` : `depasse = dejaTraitees >= compris` (la pièce suivante dépasse) ; `continuer` → `enAttenteVolume: false`, `proposerChoix: depasse` ; `attente` → `enAttenteVolume: depasse`, `proposerChoix: depasse` ; `comportement` absent ou inconnu → `continuer` (valeur par défaut DÉCIDÉE, D14) ; `compris` entier >= 1 sinon `palier_invalide` ; `dejaTraitees` entier >= 0 ;
   - `plafondTechniqueAtteint(consommeMicroCentimes, plafondMicroCentimes)` → `consomme >= plafond` ; plafond entier >= 0 (0 = tout appel arrêté) ; NaN, Infinity, décimaux → `entier_invalide` ;
   - `libererAttenteVolume(file, dejaTraitees, motif: 'nouveau_mois' | 'nouveau_palier')` → résultat de `reprendre` (L07-T04) ; motif inconnu → `parametre_invalide`.
2. Tests nommés : `cent-unieme-continuer-traitee-et-choix` (T-ABO-8), `cent-unieme-attente-en-attente-de-volume` (T-ABO-9), `centieme-pas-encore-depasse` (dejaTraitees 99), `comportement-inconnu-continuer`, `plafond-atteint-egal-et-au-dessus` (T-ABO-11 : égal = atteint), `plafond-zero-tout-arrete`, `liberation-ordre-d-arrivee` (file en désordre), `entrees-invalides-refusees`.

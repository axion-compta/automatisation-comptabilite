## Contexte
Spec 08, fichier 04 §3 : après un déploiement, (1) la route de santé répond `etat: ok` et le numéro de migration attendu 3 fois de suite à 10 s d'écart ; (2) fumée ; (3) erreurs 5xx sur 10 min : au plus 1 % des requêtes. Échec d'une étape = retour arrière. §4 : le retour arrière automatique PROPOSE le geste et coupe le trafic vers l'image N ; le redéploiement de N-1 en production passe par l'accord de Will ; chaque retour arrière laisse une ligne `deploiement.retour_arriere` (version quittée, version reprise, raison, durée). Cas T-EXP-1. Tous les nombres viennent de L08-T02.

## À faire
1. `packages/noyau/src/exploitation/deploiement.ts` :
   - `deciderApresDeploiement({ santes: { le: string; etat: 'ok' | 'degrade' | 'panne'; migration: number | null }[]; migrationAttendue; fumee: 'reussie' | 'echec' | 'non_lancee'; requetes; erreurs5xx }, { essais; intervalleSecondes; maxPointsDeBase })` → `{ decision: 'garder' | 'couper_et_proposer_retour' | 'attendre'; raisons: ('sante' | 'migration' | 'fumee' | 'erreurs_5xx' | 'intervalle')[] }` :
     - santé : les `essais` DERNIERS relevés, triés par heure, doivent être `ok` avec la migration attendue, et séparés d'au moins `intervalleSecondes` ; moins de relevés que `essais` = `attendre` (sauf si un relevé est déjà `panne` : retour) ;
     - fumée `non_lancee` = `attendre` ; `echec` = retour ;
     - 5xx : retour si `erreurs5xx * 10000 > requetes * maxPointsDeBase` ;
     - une seule raison suffit pour `couper_et_proposer_retour` ; jamais de redéploiement automatique : la décision s'arrête à « proposer » ;
   - `ligneRetourArriere({ versionQuittee; versionReprise; raison; debutLe; finLe; accordePar })` → `{ type: 'deploiement.retour_arriere'; versionQuittee; versionReprise; raison; dureeMs; accordePar }` (durée en millisecondes par `ecartMillisecondes` : aucune division) : versions `x.y.z`, reprise STRICTEMENT inférieure à la version quittée (comparaison numérique par composant, `1.10.0 > 1.9.0`), `finLe` >= `debutLe`, `accordePar` non vide (l'accord de Will est exigé), sinon `ErreurExploitation` (`version_invalide`, `ordre_invalide`, `champ_interdit`).
2. Tests nommés : `trois-ok-espaces-garder`, `deux-releves-attendre`, `ok-trop-rapproches-attendre-puis-garder`, `sante-500-retour-t-exp-1` (un relevé `panne` : retour immédiat), `migration-differente-retour`, `cinq-xx-au-dela-retour` (1 % pile : garder ; un de plus : retour ; 0 requête : garder), `fumee-echec-retour`, `ligne-retour-arriere-valide-et-refus` (reprise égale ou supérieure, `1.10.0` contre `1.9.0`, fin avant début, accord vide).

## Hors périmètre
Coupure réelle du trafic, appel à l'outil de déploiement (aucun agent ne touche un serveur : ADR 0045 de la console) ; recette CI (L08-T47, bloquée).

## Pièges
Règles du noyau comme L08-T00 ; écart des relevés par `aDepasse` ou `ecartMillisecondes` comparé à `intervalleSecondes * MS_PAR_SECONDE`. Relevés en désordre : triés avant décision. Cas limites : NaN, Infinity, négatif, non entier dans `requetes`, `erreurs5xx`, `essais` (0 refusé), `intervalleSecondes`.

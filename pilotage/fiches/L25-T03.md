## Contexte
Fiche MVP. Un seul mode de déploiement au MVP (hébergé) ; l'installation chez le client vient plus tard. Le mode doit rester un réglage lu au démarrage, jamais une condition dans le code. `scripts/verifier.mjs` lance déjà tout fichier `outils/gardes/*.mjs` : rien à brancher.

## À faire
1. Tests d'abord, sur des textes fournis au test (aucune lecture de disque dans les tests unitaires).
2. `mode-deploiement.mjs` : `analyser(texte, chemin)` → liste de `{ chemin, ligne, code: 'branche_par_mode' }`. Rouge si un fichier `.ts`, `.tsx`, `.mjs` de `apps/` ou `packages/` (hors `__tests__/`) compare une valeur de mode de déploiement : motifs `MODE_DEPLOIEMENT`, `modeDeploiement`, `mode_deploiement` suivis d'un opérateur de comparaison, d'un `switch` ou d'un `case`, ou les littéraux `'installation'`, `'heberge'`, `'installe'` comparés par `===`, `!==`, `==`, `!=`.
3. Exception unique : le fichier de lecture du réglage, s'il existe, déclaré dans une constante `FICHIER_REGLAGE` de la garde (un seul chemin).
4. Commentaires ignorés (`//` et `/* */`). Sortie : une ligne par problème, code 1 si au moins un.

## Tests nommés
`comparaison-de-mode-refusee`, `switch-sur-mode-refuse`, `litteral-installation-compare-refuse`, `commentaire-ignore`, `fichier-de-test-ignore`, `depot-actuel-vert` (lecture réelle des fichiers de `apps/` et `packages/` : 0 problème).

## Hors périmètre
Composition de conteneurs (L25-T04), mode installation (V2).

## Pièges
Ne pas attraper des mots voisins sans rapport (`hebergement`, `installation-paquet`) : tester un faux positif.

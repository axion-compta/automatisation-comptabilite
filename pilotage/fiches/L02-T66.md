## Contexte
Débloquée par la décision de Will du 07/11/2026 : D43 (fournisseurs d'IA de l'UE en liste fermée modifiable, passerelle unique) et J3a donné, avec quatre conditions : données FICTIVES seulement ; fiche sensible relue par Opus ; aucune production sans le feu vert J10 ; on écrit contre une INTERFACE (ici un proposeur injecté), jamais contre un modèle réel.
Spec 02, fichier 02, règle 4 : « L'IA n'intervient que pour (a) deviner un profil inconnu (proposition de correspondance des colonnes, aperçu 10 lignes) […]. Le profil deviné est montré, confirmé d'un clic, puis mémorisé. » Test T02-7 : profil juste sur au moins 9 fichiers sur 10 (banc L02-T61). Le banc L02-T61 ne porte un profil que sur ses fichiers CSV : la mesure porte sur les fichiers du banc qui ont un `profil` (OFX, CAMT et PDF se lisent sans IA).
Briques : `verifierProfil` et `appliquerProfil` (L02-T15), `pseudonymiser` (L02-T25), question `profil_a_choisir` de `analyserReleve` (L02-T20), `fichiersDeReference` (L02-T61). Le branchement sur la passerelle `apps/serveur/src/ia/passerelle.ts` est hors fiche.

## À faire
1. Tests d'abord dans `__tests__/profil-devine.test.ts` (faux proposeur qui capture ce qu'il reçoit ; données fictives, IBAN à clé fausse, noms inventés).
2. `profil-devine.ts` exporte :
   - `type ProposeurProfil = (entree: { entete: string[]; lignes: string[][] }) => Promise<string>` (texte JSON rendu par l'IA) ;
   - `const LIGNES_APERCU = 10` (constante nommée, issue de la spec) ;
   - `deviner(lignes: readonly LigneBrute[], options: { ligneEntete: number; personnes: readonly string[]; proposer: ProposeurProfil })` → `Promise<Proposition>` ;
   - `Proposition` = `{ etat: 'propose'; profil: ProfilImport; apercu: ReleveImporte }` | `{ etat: 'a_choisir'; motif: 'reponse_illisible' | 'profil_invalide' | 'indisponible' | 'fichier_vide' }` ;
   - `confirmer(p, acteur: { type: 'personne' | 'ia'; id: string })` → `{ etat: 'confirme'; profil; par }` ; `mesurer(fichiers, proposer)` → `{ justes; total }`.
3. `deviner` : n'envoie que l'en-tête et au plus 10 lignes de données, chaque cellule passée par `pseudonymiser` (IBAN, cartes, `personnes`) ; analyse le JSON ; contrôle par `verifierProfil(profil, nbColonnes)` ; aperçu = `appliquerProfil` sur les 10 lignes NON pseudonymisées (calcul local, jamais renvoyé à l'IA).
4. `confirmer` : refus `confirmation_reservee_a_une_personne` si `acteur.type = 'ia'` ou `id` vide ; refus `rien_a_confirmer` si `etat` n'est pas `propose`. La mémorisation (base) est hors fiche : on rend le profil confirmé.
5. `mesurer` : pour chaque fichier du banc qui a un `profil`, découpe le texte avec `detecterSeparateur` puis `lireCsv` (existants), appelle `deviner` et compte juste si le profil proposé est égal en profondeur au profil de référence.
6. Tests nommés : `envoie-entete-et-dix-lignes-au-plus`, `fichier-de-moins-de-dix-lignes`, `aucun-iban-ni-nom-vers-le-proposeur`, `json-illisible-a-choisir`, `colonne-hors-limite-profil-invalide`, `proposeur-en-panne-indisponible`, `fichier-vide-sans-appel`, `ia-ne-confirme-pas`, `confirmation-par-une-personne`, `banc-t02-7-mesure` (faux proposeur qui rend le profil de référence : `justes = total` ; faux proposeur qui se trompe sur un fichier : `justes = total - 1`).
7. Journal `pilotage/journal/L02-T66.md` (10 lignes au plus), statut `fait`.

## Hors périmètre
Appel à un modèle réel ou à la console ; route HTTP, contrat, écran (bouton de confirmation) ; persistance du profil ; lecture des PDF image (V2) ; modification de `profil.ts`, `analyse.ts`, `pseudonymiser.ts` ou de la passerelle.

## Pièges
L'IA ne reçoit que des données pseudonymisées : aucun IBAN, numéro de carte ni nom de `personnes` dans `entree` (test qui parcourt toutes les cellules capturées). Un profil proposé n'est jamais appliqué au relevé entier sans `confirmer`. JSON avec champs en trop, indices négatifs, non entiers, `NaN` ou doublons : `profil_invalide`, jamais corrigé en silence. `ligneEntete` au-delà du fichier : `fichier_vide`. Entrée jamais modifiée. Fiche sensible : relecture Opus, rien en production avant J10. Recoupement : aucun autre fichier `a_faire` ne vise ces chemins.

## Contexte
Spec 09, §02 règle 5 : micro-entrepreneur = forme `EI` + régime `micro` ; `tenue = livre_recettes` ; pas de partie double imposée. Le logiciel tient le livre des recettes (date d'encaissement, client, montant, mode de règlement, référence de facture) et, pour la vente de marchandises, le registre des achats. Pas de bilan, pas de clôture, pas d'écriture client ni produit.

## À faire
1. `packages/noyau/src/profil/fiscal/livre-recettes.ts` :
   - `LigneRecette { id; dateEncaissement; client: string; montantCentimes: Centimes; modeReglement: 'virement' | 'carte' | 'cheque' | 'especes' | 'autre'; referenceFacture: string }` ; `LigneAchat { id; date; fournisseur; montantCentimes; modeReglement; referencePiece }` ;
   - `verifierLigneRecette(l)` : montant > 0 entier sûr, client et référence non vides après normalisation, date stricte ; codes `montant_invalide`, `client_vide`, `reference_vide`, `date_invalide`, `mode_inconnu` ;
   - `livreSurPeriode(lignes, debut, fin)` → lignes de la période (bornes incluses), triées par date puis `id`, total en centimes (`ajouter` de `../../argent/index.js`) ; `fin < debut` = `ordre_inverse` ;
   - `registreAchatsExige(activite: 'vente_marchandises' | 'services' | 'mixte')` → booléen ;
   - `tenueApplicable({ forme, regime })` → `livre_recettes` seulement pour `EI` + `micro`, sinon `partie_double`.
2. Tests nommés (montants et noms inventés) : `ligne-valide`, `montant-invalide` (0, -1, 1.5, NaN, Infinity), `champs-vides-refuses`, `periode-bornes-incluses`, `tri-stable` (même date : ordre par `id`), `total-exact-au-centime` (trois lignes, somme vérifiée), `ordre-inverse-refuse`, `registre-achats-selon-activite`, `tenue-livre-recettes-seulement-ei-micro` (SARL micro impossible : partie double).

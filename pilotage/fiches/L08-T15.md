## Contexte
Spec 08, fichier 03 §3 : chaque pièce porte son empreinte SHA-256 en base ; après restauration, une pièce citée en base mais absente du stockage est listée « pièce manquante », jamais ignorée ; contrôle des pièces sur un échantillon de 50 (toutes si moins de 50). Cas R8 : 50 empreintes égales ; 1 pièce retirée à dessein → 1 « pièce manquante ». Taille de l'échantillon = réglage `restauration.echantillon_pieces` (L08-T02). L'empreinte d'octets vient de `empreinteSha256` (L03-T01).

## À faire
1. `packages/noyau/src/exploitation/echantillon.ts` :
   - `tirerEchantillon(ids: string[], taille, graine)` : déterministe, sans `Math.random` : tri par `empreinteSha256(graine + ':' + id)` puis par `id`, puis les `taille` premiers ; tous si moins ; identifiants en double = `ErreurExploitation('doublon')` ; `taille` entier >= 1 ; `graine` non vide ;
   - `verifierPieces(echantillon: { id; empreinteEnBase }[], lire: (id) => Uint8Array | null)` → `{ ok: string[]; manquantes: string[]; modifiees: string[]; resultat: 'OK' | 'ECHEC' }` (listes triées) : `lire` qui rend `null` = manquante ; empreinte recalculée différente = modifiée ; `lire` qui lève une exception = la pièce est comptée `manquantes` ET le résultat est `ECHEC` (jamais OK) ;
   - empreinte en base mal formée = `empreinte_invalide`.
2. Tests nommés : `meme-graine-meme-echantillon`, `graines-differentes-echantillons-differents` (sur 200 identifiants), `moins-que-la-taille-tous`, `r8-cinquante-egales`, `r8-piece-retiree-une-manquante`, `octet-change-modifiee`, `lecture-en-erreur-jamais-ok`, `entrees-invalides-refusees` (taille 0, 1.5, NaN, Infinity ; graine vide ; doublon).

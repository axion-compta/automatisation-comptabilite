## Contexte
Spec 04, fichier 05 §2 : formats du socle Factur-X, UBL, CII ; « fichier XML UBL ou CII seul » ; le XML fait foi, confiance XML, aucun appel d'IA pour les montants. Même sortie que `lireCii` (L04-T21), même analyse sûre (`analyserXmlSur`).

## À faire
1. `apps/serveur/src/pieces/xml/lire-ubl.ts` : `lireUbl(texte, longueurMax)` → même forme de résultat que `lireCii` (profil `inconnu`) ou `{ erreur: 'xml_invalide' }` :
   - racine `Invoice` ou `CreditNote` (sinon `xml_invalide`) ; `CreditNote` : `type_piece` lu comme `avoir` (champ `type_piece`, source `xml`) ;
   - `numero` = `ID` ; `date_piece` = `IssueDate` (déjà `AAAA-MM-JJ`) ; `devise` = `DocumentCurrencyCode` ;
   - `ttc` = `LegalMonetaryTotal/TaxInclusiveAmount` ; `montant_du` = `LegalMonetaryTotal/PayableAmount` ;
   - par `TaxTotal/TaxSubtotal` : `ht@<pdb>` = `TaxableAmount`, `tva@<pdb>` = `TaxAmount`, pdb tiré de `TaxCategory/Percent` par chaîne ;
   - SIREN émetteur : `AccountingSupplierParty/Party/PartyLegalEntity/CompanyID` avec `schemeID` `0002` ; idem `AccountingCustomerParty` ;
   - `analyserXmlSur` réutilisé (L04-T21), sans le modifier.
2. Tests nommés (XML UBL fictifs) : `ubl-facture-un-taux`, `ubl-plusieurs-sous-totaux`, `ubl-avoir`, `racine-inconnue-invalide`, `doctype-refuse`, `montant-illisible-invalide` (`1,200.00`, vide, `NaN`), `siren-emetteur-et-destinataire`.

Contrôle contre le visuel (L04-T22), connexion aux plateformes agréées (spec 03-14).

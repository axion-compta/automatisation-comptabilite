## Contexte
Spec 13, fichier 04, R01 : les parts d'un associé sont des entiers ; la somme des parts = parts du capital, sinon contrôle B. R02 : libération minimale = paramètre par forme (valeurs du registre « à vérifier ») ; libération inférieure : alerte B avec le montant manquant en centimes ; seul le numéraire compte (un apport en nature est libéré en entier). R03 : capital non entièrement libéré : le taux réduit d'IS est refusé ; c'est UNE des conditions, les autres ne sont pas évaluées ici ; le choix du régime reste le geste G05. Tests MOT71-1 à MOT71-4.

## À faire
1. `packages/noyau/src/capital/liberation.ts` (`pourcentage` du module argent) :
   - `controlePartsCapital(associes { id; parts }[], partsCapital)` donne `{ ok; ecart }` (somme moins parts du capital) ;
   - `liberationMinimale({ apportsNumeraire; verse }, fractionMinPointsDeBase)` donne `{ suffisante; minimum; manque; resteALiberer }` ; `minimum` = `pourcentage(apports, fraction, 'superieur')` (un minimum s'arrondit vers le haut) ; versé supérieur aux apports : `ErreurCapital('verse_superieur')` ;
   - `conditionCapitalLibere({ capital; libere })` donne `{ remplie; code? }` avec `capital_non_entierement_libere`.
2. Tests nommés (fraction INVENTÉE : 2 500 points de base ; montants en centimes) : `parts-egales-capital`, `parts-ecart-detecte`, `liberation-au-minimum-acceptee` (apports 1 000 000, versé 250 000), `liberation-un-centime-court` (249 999 : manque 1), `minimum-arrondi-vers-le-haut` (fraction 3 333 sur 1 000 : 334), `verse-superieur-refuse`, `capital-non-libere` (600 000 sur 1 000 000), `entrees-invalides` (parts 1,5, NaN, Infinity, négatives ; fraction négative ou au-delà de 10 000).

## Contexte
Routes d'écriture du lot : `POST /profil/champs/{cle}`, `POST /profil/champs/{cle}/confirmer` (L09-T34), `POST /profil/changements/apercu`, `POST /profil/changements` (L09-T35). ADR 0002 : en-tête `Idempotency-Key` exigé ; même clé = même réponse. Les écrans E45, E39 et E38 (L09-T42 à T44) s'appuient sur ces gestionnaires.

## À faire
1. `packages/faux-serveur/src/domaines/profil-ecriture.ts` : `creerHandlersProfilEcriture()` : un gestionnaire par route, état en mémoire PARTAGÉ avec les lectures de L09-T36 (une écriture se voit à la lecture suivante) ; réinitialisable entre deux tests ; réponses validées par les schémas du contrat ; mêmes codes d'erreur que le serveur en mémoire.
2. `handlers.ts` : ajouter `...creerHandlersProfilEcriture()`.
3. `__tests__/suite-profil-ecriture.ts` : suite commune ; l'enregistrer dans `contrat-commun.test.ts`.
4. Tests nommés : `ajout-puis-lecture`, `confirmation-puis-etat`, `idempotence-meme-reponse`, `sans-en-tete-refuse`, `apercu-sans-effet`, `effet-avant-periode-deposee-409`, `etat-reinitialise-entre-deux-tests`.

## Hors périmètre
Pas de réauthentification (L09-T49) ; pas d'écran.

## Pièges
Comme L09-T36. Un état partagé non réinitialisé fait échouer un test au hasard selon l'ordre : `etat-reinitialise-entre-deux-tests` le vérifie dans les deux ordres.

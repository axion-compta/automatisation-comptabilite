## Contexte
Spec 07, `03-fin-contrat-gel.md`, règle 2 : gel pour litige ou contrôle fiscal posé par l'administrateur du client ou par Axion, avec motif ; il suspend l'effacement sans limite de durée ; levée par la même voie, journalisée ; le gel du module ET celui de la console doivent être levés. Le gel de la console (`gelConsole`) n'est jamais modifié par le module : il est seulement lu (L07-T10).

## À faire
1. `packages/noyau/src/abonnement/gel.ts` :
   - `poserGel(fin: FinContrat, { motif, par: 'client' | 'axion', auteur, horodatage, longueurMaxMotif })` → `{ fin; evenement: fin_contrat.gel_pose }` : motif `trim()` vide → `motif_manquant` ; motif plus long que `longueurMaxMotif` (argument, entier >= 1) → `parametre_invalide` ; gel déjà actif → `gel_deja_actif` ; `par` inconnu → `parametre_invalide` ; auteur vide → `auteur_manquant` ; le motif journalisé est le motif `trim()` ;
   - `leverGel(fin, { motif, par, auteur, horodatage, longueurMaxMotif })` → `{ fin; evenement: fin_contrat.gel_leve }` : mêmes contrôles ; pas de gel actif → `gel_inactif` ; après levée `gelModule = { actif: false, motif: null, posePar: null, poseLe: null }` ;
   - `gelConsole` recopié tel quel dans le résultat (jamais modifié) ; l'objet reçu jamais modifié.
2. Tests nommés : `poser-puis-lever-deux-evenements`, `motif-blanc-refuse` (`''`, `'   '`, tabulation), `motif-trop-long-refuse`, `double-gel-refuse`, `lever-sans-gel-refuse`, `gel-console-jamais-modifie` (vrai avant, vrai après une levée du module), `entree-non-modifiee`.

## Hors périmètre
Pas de route (L07-T20), pas de permission ni de réauthentification (fiche bloquée L07-T37), pas d'action sur le gel de la console.

## Pièges
Règles du noyau. La longueur maximale du motif est un argument (pas de littéral sur une ligne avec `duree` ou `delai`). Le motif peut contenir des données personnelles : il va au journal de la société, jamais dans un log technique (à écrire en commentaire). Sensible (effacement de données) : relecture Opus obligatoire.

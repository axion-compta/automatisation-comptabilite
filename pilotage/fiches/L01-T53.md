## Contexte
Une fois les jetons importés (L01-T51), l'e2e axe de L01-T04 (`apps/web/e2e/accessibilite.e2e.ts`, PR 102) signale sur l'accueil à 375 px un échec `color-contrast` sur 1 élément : le bouton « Discuter » (`.barre-discuter`). Mesure axe : texte #1f1b16 sur fond #2f5d50, ratio 2,28 au lieu de 4,5.
Cause : dans `apps/web/src/socle/socle.css`, la règle `.barre-mobile button { color: inherit }` (spécificité 0,1,1) l'emporte sur `.barre-discuter { color: var(--couleur-accent-texte) }` (0,1,0). Les jetons sont bons : `--couleur-accent-texte` (#ffffff) sur `--couleur-accent` (#2f5d50) donne plus de 7.

## À faire
1. Ajouter `apps/web/src/__tests__/contraste-accueil.test.ts` (en premier, il doit rougir avant la correction) :
   - lire `packages/ui/src/jetons.css` et calculer le ratio de contraste WCAG (luminance relative, formule WCAG 2.x) entre `--couleur-accent-texte` et `--couleur-accent` : au moins 4,5 ;
   - lire `socle.css` et vérifier que la règle qui fixe la couleur de `.barre-discuter` a une spécificité supérieure à celle de `.barre-mobile button` et utilise `var(--couleur-accent-texte)` ;
   - le test doit rougir si la règle revient à `color: inherit`.
2. `apps/web/src/socle/socle.css` : le sélecteur `.barre-discuter` devient `.barre-mobile .barre-discuter` (spécificité 0,2,0), la couleur reste `var(--couleur-accent-texte)`.
3. Relancer l'e2e L01-T04 : `color-contrast` ne doit plus signaler d'élément.

## Hors périmètre
Aucun changement des valeurs de jetons (`jetons.ts`, `jetons.css`). Aucune règle axe désactivée. Aucun changement de `.github/`.

## Pièges
Ne pas toucher à `.coque a, .barre-mobile button { color: inherit }` : le menu en dépend. Les valeurs de couleur se lisent dans `jetons.css` (fichier généré), jamais recopiées en dur dans le test.

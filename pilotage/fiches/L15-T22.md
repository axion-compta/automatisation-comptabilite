## Contexte
Spec 15, EX-R2, EX-R4 et EX-R6. CSV : UTF-8 avec BOM, séparateur `;`, fin de ligne CRLF, toute cellule texte entre guillemets ; ordre : d'abord le préfixe de neutralisation, ensuite l'échappement (guillemets doublés) : `=1+1` devient `"'=1+1"`. Décimale `,` sans séparateur de milliers, dates JJ/MM/AAAA. Le fichier contient les totaux de l'écran, étiquetés avec leur périmètre. Liste vide : en-têtes et total à zéro, jamais une erreur.

## À faire
1. `exports/csv.ts` :
   - `ecrireCsv({ colonnes: { code; type; entete: string }[]; lignes: Record<string, unknown>[]; total?: { etiquette: string; colonne: string; valeurCentimes: Centimes }; filtresRappeles?: string[] })` → `string` ;
   - chaque cellule passe par `cellule()` de L15-T21 ; texte : neutralisé puis guillemets doublés puis entouré de guillemets ; nombre `centimes` : `formater()` de `../argent/index.js` (« -1234,56 », sans milliers) ; `entier` : chiffres seuls ; date : JJ/MM/AAAA par découpe ;
   - ordre : lignes de filtres rappelés (texte), en-têtes, lignes, total ; en-têtes, étiquette de total et filtres sont du texte, donc neutralisés ;
   - le total écrit est celui fourni (calculé par le même service que l'écran, EX-R2), jamais recalculé ici ; colonne de total inconnue = erreur.
2. Tests nommés : `bom-et-crlf`, `point-virgule-dans-une-valeur-reste-dans-la-cellule`, `guillemet-double`, `saut-de-ligne-dans-une-valeur-reste-dans-la-cellule`, `formule-prefixee-puis-echappee` (`=1+1` donne `"'=1+1"`), `entete-dangereux-neutralise`, `centimes-sans-milliers` (123456789 donne `1234567,89`), `negatif-non-prefixe`, `liste-vide-entetes-et-total-zero`, `relecture-par-un-analyseur` (un petit analyseur CSV du test relit le fichier et retrouve exactement chaque valeur d'origine, préfixe compris, sur 200 lignes générées avec caractères spéciaux).

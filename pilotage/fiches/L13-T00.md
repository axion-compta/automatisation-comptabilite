## Contexte
Spec 13, fichier 02, R24 : gardes CI sur chaque PR : « (c) SIREN : liste blanche 123456782 et 987654324 ; tout autre nombre de 9 chiffres à clé de Luhn juste dans les données de test = alerte ; (d) montants de tarifs : motifs « € / mois », « HT / an » hors fichiers exemptés = alerte ». `outils/gardes/fictif.mjs` ne contrôle aujourd'hui que les e-mails (`@exemple.fr`) et les IBAN.

## À faire
1. `outils/gardes/fictif.mjs` (ajouts, rien de retiré) :
   - `export const SIREN_PERMIS = ['123456782', '987654324']` ; `export function luhnValide(chiffres)` (chaîne de chiffres seulement, sinon faux) ;
   - SIREN : candidat = exactement 9 chiffres, non précédé ni suivi d'un chiffre, d'une lettre, de `.`, `,` ou `_` ; rouge si clé de Luhn juste et hors `SIREN_PERMIS`. Portée LIMITÉE aux fichiers de données de test : chemins contenant `/__tests__/`, `.test.`, `.spec.`, `/e2e/`, et tout `packages/donnees-fictives/` ; jamais `pnpm-lock.yaml` ni `openapi.json` ;
   - tarifs : rouge si un nombre est suivi (blancs permis) de `€` ou `HT` ou `TTC` puis `/ mois` ou `/ an` (ex. `29 € / mois`, `120 HT/an`), dans tout fichier suivi sauf `outils/gardes/fictif.mjs` et `outils/gardes/test/` ;
   - message : `fichier:ligne SIREN hors liste blanche : …` ou `fichier:ligne montant de tarif : …`.
2. Tests nommés (dans `fictif.test.mjs`, via `analyserTexte` et des chemins forgés) : `siren-permis-acceptes`, `siren-luhn-juste-hors-liste-rouge` (fabriquer un 3e nombre à clé juste DANS le test, par calcul, sans l'écrire en dur), `luhn-faux-ignore`, `dix-chiffres-ignore` (pas de SIREN dans un nombre plus long), `hors-donnees-de-test-ignore` (même nombre dans `packages/noyau/src/x.ts`), `tarif-par-mois-rouge`, `tarif-par-an-ht-rouge`, `montant-sans-periode-accepte` (« 29,00 € » seul).

Lancer la garde sur TOUT le dépôt avant la PR : si un vrai fichier rougit, resserrer la portée (jamais une liste d'exceptions élargie). `luhnValide('')` et `luhnValide('12345678a')` rendent faux.

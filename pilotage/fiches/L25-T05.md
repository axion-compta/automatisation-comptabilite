## Contexte
Fiche MVP. `apps/serveur/src/exploitation/essai-mensuel.ts` (L08-T46) déclare le port `dechiffrer(dump)` et ses causes d'échec (`cle_restauration_absente`, `dechiffrement_impossible`, `bloc_altere`, `fin_du_flux_absente`), sans adaptateur réel : les sauvegardes ne sont donc pas chiffrées dans le code. Le chiffrement applicatif des champs (IBAN, identité) reste en V1, hors de cette fiche.

## À faire
1. Tests d'abord ; la clé est générée dans le test (`node:crypto`), jamais écrite dans le dépôt.
2. `chiffrement-sauvegarde.ts`, `node:crypto` seul :
   - `chiffrerFlux(source: AsyncIterable<Uint8Array>, cle)` : en-tête versionné, blocs AES-256-GCM de taille fixe, nonce unique par bloc (compteur), numéro de bloc dans les données associées, bloc final marqué ;
   - `dechiffrerFlux(source, cle | null)` : rend les octets clairs ou `{ ok: false, cause, bloc? }` avec les causes du port ; un bloc final absent donne `fin_du_flux_absente` ; aucun octet clair n'est rendu d'un bloc non authentifié ;
   - `creerPortDechiffrer(lireDump, lireCle)` → objet compatible avec `PortsEssai['dechiffrer']`.

## Tests nommés
`aller-retour-identique` (3 blocs et plus), `octet-modifie-bloc-altere` (rend le numéro du bloc), `bloc-final-tronque`, `blocs-permutes-refuses`, `cle-absente`, `mauvaise-cle-dechiffrement-impossible`, `port-branche-sur-essai-mensuel` (l'essai mensuel avec ce port réussit sur un dump fictif).

## Hors périmètre
Stockage hors site, rotation des clés de sauvegarde, chiffrement des champs (V1).

## Pièges
Jamais de nonce répété pour une même clé. Ne pas modifier `essai-mensuel.ts`.

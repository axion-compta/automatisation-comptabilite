## Contexte
Spec 03, §05, règle 1 : « Toutes les dates sont calculées depuis `regle_date` et l'ancrage, en jours ouvrés avec report (DEC-053). » E6 : échéance tombant le samedi 15/05/2027 → « date affichée selon la règle de report du paramètre (lundi 17/05/2027 dans le paquet de test) ». Les jours fériés, les jours non ouvrés et la règle de report sont des paramètres datés : arguments.

## À faire
1. `packages/noyau/src/echeances/jours-ouvres.ts` (utilise `jourDeSemaine`, `ajouterJours` de `../dates/civiles.js`) :
   - `Calendrier { joursNonOuvres: readonly number[] /* 1 = lundi … 7 = dimanche */; feries: readonly string[] /* AAAA-MM-JJ */ }` ;
   - `estJourOuvre(date, calendrier)` ;
   - `reporter(date, regle: 'suivant' | 'precedent' | 'aucun', calendrier)` → premier jour ouvré à partir de la date dans le sens donné (`aucun` = date inchangée) ;
   - calendrier où aucun jour n'est ouvré (7 jours non ouvrés) = exception locale `ErreurCalendrier('calendrier_vide')` ; jour hors 1 à 7 = `jour_invalide`.
2. Tests nommés (calendrier de TEST : samedi et dimanche non ouvrés, un férié INVENTÉ) : `samedi-reporte-au-lundi` (E6), `ferie-invente-reporte`, `report-precedent`, `aucun-report`, `jour-ouvre-inchange`, `calendrier-vide-refuse`.

## Hors périmètre
Pas de catalogue d'échéances (L03-T42). Aucune liste réelle de jours fériés.

## Pièges
Règles du noyau comme L03-T01. Cas limites exigés : férié en double dans la liste (accepté), férié mal formé (refus), suite de 10 jours fériés consécutifs (report correct, pas de boucle infinie : borne de recherche de 366 jours puis `calendrier_vide`).

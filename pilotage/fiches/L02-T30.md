## Contexte
Spec 02, fichier 06 : « Contrôle en code, à chaque écriture de lien : Σ `montant_affecte` d'une pièce ≤ montant de la pièce ; Σ d'une ligne ≤ |montant de la ligne|. Violation = refus 422. » Vue `reste_piece` = montant − Σ des liens valides ou proposés. Fichier 05, passe 1 : « une pièce ne sert qu'à hauteur de son reste ». Test T06-7 : lier 700,00 à une pièce de 600,00 → refus « La facture ne fait que 600,00 € ». Liens `refuse` ou `defait` ne comptent pas.

## À faire
1. `packages/noyau/src/banque/rapprochement/sommes.ts` :
   - `restePiece(piece: { id; montant }, liens: readonly Lien[])` → `Centimes` (liens `propose` et `valide` de cette pièce) ;
   - `resteLigne(ligne: { id; montant }, liens)` → `Centimes` sur la valeur absolue du montant ;
   - `verifierNouveauLien(nouveau: { ligneId; pieceId?; montantAffecte }, ligne, piece?, liens)` → `{ ok: true } | { ok: false; code: 'depasse_piece'; maximum: Centimes } | { ok: false; code: 'depasse_ligne'; maximum: Centimes } | { ok: false; code: 'montant_invalide' }` ;
   - montant affecté nul, négatif, `NaN`, non entier → `montant_invalide`.
2. Tests nommés : `t06-7-sept-cents-sur-six-cents` (maximum 60 000), `reste-apres-deux-liens`, `liens-refuses-et-defaits-ignores`, `ligne-negative-valeur-absolue`, `exactement-le-reste-accepte`, `un-centime-de-trop-refuse`, `autre-piece-sans-effet`, `propriete-somme-jamais-depassee`.

## Hors périmètre
Groupes 1-N et N-1 (L02-T34), écarts (L02-T35). Code HTTP 422 (route bloquée : L02-T64).

## Pièges
Cas limites exigés : aucune pièce (lien vers une écriture : seul le contrôle de ligne s'applique), liste de liens vide, montants de pièce négatifs (refus `piece_invalide` : un avoir est une pièce de sens inverse, pas un montant négatif), ordre des liens sans effet. Sensible (argent). Règles du noyau.

## Contexte
Spec 12, `04-tva-cas-particuliers` §2 : « Tout ce paragraphe est un traitement envisagé, à vérifier : il ne s'active que quand le paramètre `tva.cession_bien_meuble` est validé avec sa source. Bien meuble dont la TVA d'achat a été déduite : TVA collectée sur le prix de vente HT au taux du paramètre. Écriture : D 462000 prix TTC / C 775000 prix HT ; C 445710 TVA. » TVA d'achat non déduite : pas de TVA, régularisation V1 ; historique absent : la question est posée. Cas CT-31 (1 000,00 HT, taux de TEST : D 462000 1 200,00 / C 775000 1 000,00 ; C 445710 200,00). Écriture : modèle L01-T06 (`ecritures/modele.ts`), statut `propose` seulement.

## À faire
1. `packages/noyau/src/controles/cas-particuliers/cession.ts` :
   - `proposerEcritureCession({ prixHt: Centimes; tvaAchatDeduite: boolean | null; parametre: ParametreLu; comptes: { creance; produit; tvaCollectee }; date; journal; arrondi })` → `{ etat: 'propose'; ecriture: Ecriture } | { etat: 'refuse'; code: 'parametre_non_valide' | 'historique_absent' | 'sans_tva' }` ;
   - écriture au statut `propose` (jamais `valide`), équilibrée (vérifiée par `verifierEcriture` avant retour) ; `tvaAchatDeduite === false` = `sans_tva` (aucune écriture de TVA) ; `null` = `historique_absent`.
2. `packages/noyau/src/controles/cas-particuliers/__tests__/cession.test.ts`, tests nommés : `CT-31 ecriture`, `parametre-a-verifier-refuse`, `historique-absent-question`, `tva-achat-non-deduite`, `ecriture-equilibree-1000-cas` (graine fixe), `jamais-validee`, `prix-invalide` (NaN, 0, −1, 1,5).

## Hors périmètre
Sortie de l'actif et valeur nette comptable (règle 6 de la spec 01, lot immobilisations). Immeubles (toujours bloqués).

## Pièges
Règles du noyau comme L01-T06 : montants en `Centimes` via `packages/noyau/src/argent`, ni `/`, ni littéral décimal, ni `Math.round`, ni `parseFloat`, ni `toFixed`. Stryker (seuil 80 %) porte sur tout le noyau : chaque branche doit être tuée par un test. Ne pas toucher `packages/noyau/src/index.ts` ni `controles/moteur.ts` (imports par chemin relatif). Aucun taux, seuil, délai ni date légale dans `src` (garde:litteraux, D31) : tout seuil ou tolérance arrive en argument ou dans un `ParametreLu` (L12-T00) ; paramètre absent = `IMPOSSIBLE`, jamais OK (PRI-007). Le noyau ne contient aucun texte affiché : seulement des codes. Montants et seuils des tests INVENTÉS ou repris des cas fictifs de la spec ; noms et SIREN fictifs seulement. TVA : chemin sensible (fusion après relecture Opus et double relecture argent). Aucun taux de TVA ni pourcentage légal dans src : taux en points de base et parts déductibles viennent d'un `ParametreLu` ; un paramètre au statut autre que `valide` rend la ligne `A_VERIFIER` (donc CC-T02, L12-T09), jamais une estimation. Comptes (445660, 445800, 275000…) en argument, jamais en dur. Cas limites exigés dans les tests : montant NaN, Infinity, non entier (1,5) et négatif là où il est interdit = exception codée (le moteur la change en `IMPOSSIBLE`) ; liste vide ; objets reçus dans l'ordre inverse (même résultat) ; écart d'exactement un centime de chaque côté de la tolérance. Chaque test doit rougir si l'on casse la branche qu'il couvre (inverser une comparaison, retirer un cas). Le titre `CT-31 ecriture` ne doit pas être sous `controles/**/__tests__/` en double avec la ligne du catalogue : le catalogue pointe `CT-31 detection` (L12-T20).

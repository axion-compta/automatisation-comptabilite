## Contexte
Spec 05, fichier 04 §1 : « une action de la matrice sans outil ni exclusion déclarée = build rouge » ; chaque outil déclare des « codes d'erreur fermés ». `scripts/verifier.mjs` lance tout `outils/gardes/*.mjs` trouvé : pas besoin de toucher `package.json`.

Correction de la fiche (08/11/2026) : une première tentative s'est arrêtée à raison. Sur origin/main, `packages/contrat/src/chat/outils.json` déclare 3 codes absents de `CODES_ERREUR` (`packages/noyau/src/chat/types.ts`, L05-T00) : `acces_refuse` (7 outils), `introuvable` (3 outils), `desequilibre` (`proposer_validation`). La règle « code inconnu = rouge » rendait donc le critère « vert sur main » impossible.

Choix : aligner `outils.json` sur la liste fermée existante, sans toucher `packages/noyau`. Raisons :
- c'est l'option la plus petite (un fichier de données de 9 lignes) et elle ne retire ni n'assouplit aucune règle de la garde ;
- `CODES_ERREUR` est LA liste fermée du chat : l'événement `erreur` du flux n'accepte que ces codes (`z.enum(CODES_ERREUR)`, L05-T03), chacun a une issue (`issuePourErreur`) et un texte E25 ; un code d'outil hors liste ne pourrait pas être montré à la personne ;
- ajouter 3 codes à `CODES_ERREUR` toucherait au moins 6 fichiers (`types.ts`, `issues.ts`, `e25.ts` et leurs 3 tests qui figent 16 codes) et trancherait la liste de CHT-054, marquée « proposée » ;
- L13-T52 (fait, phase P6 : hors `depend_de`, que `garde:fiches` refuse vers une phase plus tardive ; elle a ajouté `change.expliquer_ecart`) l'a prévu : « si elle refuse `acces_refuse` ou `introuvable`, aligner l'entrée sur les codes acceptés par cette garde, sans toucher `packages/noyau` ».

Correspondance : `acces_refuse` → `droit_insuffisant` (même sens, texte E25 « Vos droits ne permettent pas cette action. ») ; `introuvable` → `parametre_invalide` (identifiant inconnu pour la société = paramètre incorrect, sans dire si l'objet existe ailleurs) ; `desequilibre` → `parametre_invalide` (lignes saisies déséquilibrées = demande incorrecte).

## À faire
1. `outils.json` : dans `codes_erreur` de chaque outil, remplacer selon la correspondance ci-dessus, sans doublon, ordre gardé (exemple : `proposer_validation` → `["parametre_invalide", "droit_insuffisant"]`). Aucun autre champ modifié.
2. `outils.test.ts` : test `codes-erreur-liste-fermee` : pour chaque outil, `codes_erreur` non vide, sans doublon, chaque code dans `CODES_ERREUR` (importé de `packages/noyau/src/chat/types.ts`, comme `evenements.test.ts`) ; il rougit si on remet `acces_refuse`.
3. `outils/gardes/outils-chat.mjs` (même forme que `actions.mjs` : fonction `analyserOutilsChat(outils, registre, codes)` exportée et testée, lancement qui sort en code 1 si problème) ; lit `packages/contrat/src/chat/outils.json`, `packages/contrat/src/actions/registre.json` et la liste `CODES_ERREUR` de `packages/noyau/src/chat/types.ts` par expression régulière (liste introuvable ou vide = rouge). Rouge si :
   - nom en double, vide, ou nom `appliquer` (toute casse, avec ou sans préfixe) ;
   - `outil_registre` absent du registre ;
   - niveau différent de celui du registre ;
   - niveau I, ou outil `chat: "ferme"` dans le registre ;
   - permission qui ne commence pas par `compta-` ;
   - `codes_erreur` vide ou contenant un code absent de `CODES_ERREUR`.
4. Tests nommés de la garde : `main-vert` (sur les vrais fichiers, après l'étape 1), `doublon-rouge`, `appliquer-rouge` (`appliquer`, `Appliquer`, `chat.appliquer`), `outil-registre-inconnu-rouge`, `niveau-different-rouge`, `niveau-i-rouge` (niveau I déclaré et outil `chat: "ferme"`), `permission-sans-prefixe-rouge`, `code-erreur-inconnu-rouge` (dont `acces_refuse` et `codes_erreur` vide), `fichier-vide-ou-illisible-rouge`. Aucun nombre d'outils ni de codes écrit en dur : comparer à la donnée lue.

## Hors périmètre
- Aucune modification de `registre.json`, de `outils.ts` ni de `packages/noyau` (ni `CODES_ERREUR`, ni `issues.ts`, ni les textes E25).
- Les codes métier propres à un outil (introuvable, déséquilibre) : fiche de suite à créer : extension de la liste CHT-054 quand son texte exact sera disponible (types, issues, textes E25 et leurs tests ensemble).
- Recoupements : `outils.json` est aussi cité par L03-T58 et L13-T51 (a_faire), qui ne le modifient pas ; une fiche de suite qui y ajoute un outil devra rester verte avec cette garde.

## Pièges
Fiche sensible (`outils/gardes/`). Chaque règle doit avoir un test qui rougit si on la retire. Ne pas lancer de sous-processus réseau. Les tests de la garde passent des objets en mémoire à `analyserOutilsChat`, sauf `main-vert`. L'expression régulière doit lire la liste entre crochets sur plusieurs lignes ; une liste vide lue ne doit jamais rendre tout code « connu ».

## Contexte
Spec 02, fichier 05 : « Le moteur est rejoué dans 3 ordres aléatoires (graines enregistrées) ; tout lien qui change selon l'ordre passe `DOUTEUSE` avec la raison « résultat dépendant de l'ordre ». Rejoué avant validation, export et clôture. » `execution_rapprochement` : version du moteur, graine, empreinte du résultat, écart entre ordres. Tests T05-5 (50 lignes, 3 ordres : mêmes liens ; cas fabriqué dépendant de l'ordre : `DOUTEUSE`) et T05-6 (banc de 140 lignes : 0 faux lien en `RAPPROCHEE`, rappel ≥ 90 %).

## À faire
1. `packages/noyau/src/banque/rapprochement/ordres.ts` :
   - `melanger(tableau, graine: number)` : générateur à graine écrit dans le module (entiers 32 bits, aucun `Math.random`) ;
   - `rapprocherEnTroisOrdres(entree, reglage, graines: [number, number, number], moteur = rapprocher)` → `{ liens; etats; execution: { graines; empreinteResultat: string; ecartEntreOrdres: boolean } }` ;
   - comparaison des 3 résultats par couple (ligne, pièce, montant) ; tout couple absent d'au moins un résultat → la ligne passe `DOUTEUSE`, `codeRaison: 'depend_de_l_ordre'`, son lien reste `propose` avec score plafonné au plafond ambigu du barème ;
   - empreinte = SHA-256 de la liste triée des couples retenus.
2. `__tests__/banc.test.ts` : charge le jeu fictif de L02-T49 par chemin relatif (`packages/donnees-fictives/src/banque.ts`), exécute, compare aux attendus du jeu : `banc-zero-faux-lien-rapprochee`, `banc-rappel-calcule` (valeur écrite dans la sortie du test et reportée au journal).
3. Tests nommés (`ordres.test.ts`) : `t05-5-trois-ordres-memes-liens`, `cas-fabrique-depend-de-l-ordre`, `graines-dans-l-execution`, `empreinte-stable`, `melange-deterministe`.

## Hors périmètre
Contrôle croisé par l'IA (bloqué : L02-T65). Déclenchement avant export ou clôture (serveur, bloqué).

## Pièges

Le banc ne doit JAMAIS être ajusté au moteur : les attendus viennent du jeu (L02-T49), pas de cette fiche. Sensible (rapprochement). Règles du noyau.

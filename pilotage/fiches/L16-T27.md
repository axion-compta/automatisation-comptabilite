## Contexte
bloque_par: V1 : ne pas planifier avant la fin de la V0 (décision de Will, 11/11/2026)
Règle de la spec : les versions sont reconstruites à partir du journal (`avant`, `apres`), aucune table de plus. Existant : `EntreeJournal` (`packages/noyau/src/journal/chaine.ts` : `societeId`, `horodatage`, `acteur`, `evenement`, `avant`, `apres`, `sequence`) et `verifierChaine` (`packages/noyau/src/journal/verifier.ts`).

## À faire
1. Tests d'abord, journal fictif construit avec `ajouterEntree`.
2. `versions.ts` (fonctions pures) :
   - `versionsObjet(entrees, { societeId, typeObjet, objetId })` → versions dans l'ordre (`numero`, `sequence`, `horodatage`, `auteur` = `acteur`, `etat` = `apres`) ; l'objet est reconnu par le préfixe d'événement `<typeObjet>.` et le champ `id` de `avant` ou `apres`.
   - `comparerVersions(a, b)` → champs ajoutés, retirés, modifiés (`{ champ, avant, apres }`), sur les seules clés de premier niveau.
   - Journal dont la chaîne est cassée : refus `journal_non_verifie` (appel de `verifierChaine`, jamais d'historique sur une chaîne fausse).
3. Tests nommés : `toute-version-anterieure-consultable`, `comparaison-champ-modifie`, `auteur-de-chaque-version`, `autre-societe-invisible`, `chaine-cassee-refusee`.

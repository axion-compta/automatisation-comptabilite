## Contexte
Spec 03, §02 : `regime_tva_societe` historisé (régime réel normal, réel simplifié, franchise, non assujetti ; périodicité mensuelle, trimestrielle, annuelle ; exigibilité des services sur encaissements ou option débits) ; « bascule 2027 (TVA-023) = nouvelle ligne datée, jamais modification ». §04, règle 3 : « Le moteur ne connaît pas "CA12" en dur : il lit `regime_tva_societe` et `formulaire_millesime` et la date de bascule propre à chaque société. » Le test D4 bis « échoue si la bascule est codée au 01/01/2027 en dur ».

## À faire
1. `packages/noyau/src/tva/regime.ts` (classe locale `ErreurRegimeTva`) :
   - `PeriodeRegime { effetDebut; effetFin: string | null /* exclue */; regime: 'reel_normal' | 'reel_simplifie' | 'franchise' | 'non_assujetti'; periodicite: 'mensuelle' | 'trimestrielle' | 'annuelle'; exigibiliteServices: 'encaissements' | 'option_debits'; formulaire: string }` ;
   - `regimeAuJour(historique, date)` : aucune ligne = `regime_absent` ; deux lignes = `regime_ambigu` ;
   - `ajouterPeriodeRegime(historique, nouvelle)` → nouvel historique : la ligne en vigueur reçoit `effetFin = nouvelle.effetDebut` ; une nouvelle ligne datée avant le début de la dernière = `date_anterieure` ; la liste reçue n'est jamais modifiée ;
   - `estTraite(regime, regimesTraites: readonly string[])` (sert à l'estimation `non_calculee`, motif `regime_non_traite`).
2. Tests nommés : `regime-en-vigueur`, `fin-exclue`, `absent-refuse`, `ambigu-refuse`, `ajout-sans-modifier-l-entree`, `date-anterieure-refusee`, `bascule-propre-a-chaque-societe` (deux sociétés fictives basculent à deux dates INVENTÉES différentes ; le même jour, l'une est sur le formulaire `FORM_A`, l'autre sur `FORM_B`).

## Hors périmètre
Pas de périodes de déclaration (L03-T21), pas de seuils (L03-T22). Les noms réels des formulaires ne sont pas dans src : `formulaire` est une donnée.

## Pièges
Règles du noyau comme L03-T01. Pas de « CA12 », « CA3 » ni de date de bascule dans src (garde L01-T02). Cas limites exigés : historique vide, `effetFin` égale à `effetDebut` (refus `periode_vide`), dates mal formées (`date_invalide`), ordre de l'historique reçu inversé (même résultat).

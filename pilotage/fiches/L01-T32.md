## Contexte
L'application web n'affiche aujourd'hui qu'un écran d'essai (`Ecran.tsx`). Il faut un routeur (`@tanstack/react-router`, déjà installé) où chaque écran s'ajoute SANS toucher un fichier commun : chaque écran vit dans `apps/web/src/ecrans/<id>/` et y déclare sa route.

## À faire
1. `socle/ecrans.ts` : type `DefinitionEcran { id: string; chemin: string; composant: ComponentType; groupe: 'menu' | 'reglages' | 'autre'; titre: string }` ; `ecransDecouverts()` lit `import.meta.glob('../ecrans/*/route.tsx', { eager: true })` (chaque module exporte `route`) ; `verifierEcrans(liste)` lève une erreur si un `id` ou un `chemin` est en double ou si un chemin ne commence pas par `/`.
2. `socle/routeur.tsx` : `creerRouteur(ecrans, historique?)` (route racine avec `Outlet`, `/` = `Accueil`, `/essai` = `Ecran` d'essai existant, une route par écran, page introuvable = `PageEnPreparation`). Historique mémoire injectable pour les tests.
3. `Accueil.tsx` : accueil provisoire qui liste les écrans découverts (liens). `PageEnPreparation.tsx` : titre « page en préparation » et lien vers l'accueil. Textes de `packages/textes/src/ecrans/socle.ts` (L01-T28), par chemin relatif.
4. `main.tsx` : rend `RouterProvider` ; garde le démarrage du faux serveur en mode `simule` et la garde « développement seulement ».
5. `e2e/pannes.e2e.ts` : `page.goto('/essai')` au lieu de `/`.
6. Tests nommés (`// @vitest-environment jsdom`) : `doublon-de-chemin-refuse`, `doublon-d-id-refuse`, `route-inconnue-page-en-preparation`, `accueil-liste-les-ecrans`, `route-d-un-ecran-rendue` (avec une liste d'écrans fictive injectée).

## Hors périmètre
Pas de menu ni de barre du bas (L01-T33), pas d'écran métier.

## Pièges
`import.meta.glob` sans aucun écran rend `{}` : le cas doit marcher. Aucun texte en dur dans les `.tsx` (garde:textes). Les tests e2e existants doivent rester verts.

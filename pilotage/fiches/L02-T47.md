## Contexte
Spec 02, fichier 13, règles 4 à 6 : la personne coche, voit « 2 factures, 3 200,00 € », clique « Valider la liste » ; « Mode Autonome : la validation reste humaine (exception explicite) » ; fichier de virements seulement pour un lot `valide_par_personne` (V1) ; « « Marqué payé » ne crée AUCUNE écriture : c'est le débit bancaire rapproché qui solde la facture. Une facture « marquée payée » sans débit après 10 jours est signalée. » États : `propose | valide_par_personne | fichier_genere | marque_paye | annule`. Tests T13-2 (IA → refus ; personne → validé, journal avec son identité), T13-3 (fichier demandé sur un lot `propose` → refus « Validez la liste avant de préparer le fichier »), T13-6.

## À faire
1. `packages/noyau/src/banque/fournisseurs/lot.ts` :
   - `proposerLot(lignes, acteur, horodatage)` → `Lot { id; lignes; total; etat: 'propose'; creeParType }` (l'IA peut PROPOSER) ;
   - `validerLot(lot, acteur, horodatage)` → refus `ia_interdite` pour `acteur.type = 'ia'` QUEL QUE SOIT le mode, `etat_incompatible` si non `propose` ; sinon `valide_par_personne` + entrée de journal `{ action: 'valider_lot'; acteurType; acteurId; horodatage }` ;
   - `fichierPossible(lot)` → `{ possible: true } | { possible: false; code: 'valider_avant' }` ;
   - `marquerPaye(lot, acteur, horodatage)` → lot `marque_paye` ; AUCUN autre effet ;
   - `signalerSansDebit(lots, piecesSoldees: string[], aujourdhui, delaiJours)` → pièces marquées payées depuis plus de `delaiJours` sans débit rapproché ;
   - `annuler(lot, acteur)` : interdit après `fichier_genere`.
2. Tests nommés : `t13-2-ia-refusee`, `t13-2-personne-validee-journal`, `autonome-reste-humain` (mode en argument : refus identique), `t13-3-fichier-avant-validation-refuse`, `t13-6-marque-paye-sans-ecriture`, `signal-apres-delai`, `pas-de-signal-si-debit`, `annulation-apres-fichier-refusee`.

Aucune fonction ni aucun état nommé `payer` ou `paye_par_logiciel`. Sensible (argent, sécurité). Règles du noyau.

## Contexte
Spec 02, fichier 02 : CAMT.053 au MVP ; « relevé multi-comptes (découpé par compte) » ; seules les lignes `completee` sont comptables (règle 9). Dans CAMT.053 : `Stmt` (un par compte), `Acct/Id/IBAN`, `Bal` avec `Tp/CdOrPrtry/Cd` = `OPBD` (ouverture) ou `CLBD` (clôture), `Ntry` avec `Amt@Ccy`, `CdtDbtInd` (`CRDT`/`DBIT`), `Sts` (`BOOK` = comptabilisée, `PDNG` = en attente), `BookgDt/Dt`, `ValDt/Dt`, `NtryDtls/TxDtls/Refs/EndToEndId`, `RmtInf/Ustrd`, `AddtlNtryInf`.

## À faire
1. `packages/noyau/src/banque/import/camt.ts` :
   - `lireCamt053(racine: NoeudXml)` → `ReleveLu[]` (types `ReleveLu` et `LigneLue` de `../types.js`, L02-T07) ; montant de chaque ligne signé par `CdtDbtInd` ;
   - montants lus par `lireMontant` (L02-T08, point décimal) ; signe du solde par son `CdtDbtInd` ;
   - `Sts` : `BOOK` → `completee`, `PDNG` → `en_attente`, `RJCT` → `rejetee`, autre → `en_attente` (jamais `completee` par défaut) ;
   - `rang` = ordre dans le fichier ; libellé = `Ustrd` puis `AddtlNtryInf` joints par une espace ;
   - classe locale `ErreurCamt` : `pas_un_camt053`, `montant_illisible` (avec rang), `devise_absente`.
2. Tests nommés (XML fictifs, IBAN à clé fausse) : `deux-operations-signees`, `soldes-ouverture-et-cloture`, `deux-comptes-deux-releves`, `en-attente-non-comptable`, `statut-inconnu-jamais-completee`, `reference-de-bout-en-bout`, `rang-dans-l-ordre-du-fichier`, `montant-illisible-rang-cite`.

## Hors périmètre
Contrôle des soldes (L02-T17). Rattachement au compte (L02-T19). Hachage de l'IBAN (L02-T18).

## Pièges
Cas limites exigés : `Stmt` sans `Ntry` (relevé de 0 ligne, accepté), `Amt` vide, `Amt` `NaN` ou `1e3`, `Ccy` absent, date absente (`date_invalide`), deux `Bal` `CLBD` (erreur `solde_ambigu`). L'IBAN brut ne sort jamais dans une erreur ni un journal (V3-BAN-090). Sensible (argent). Règles du noyau.

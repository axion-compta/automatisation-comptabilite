## Contexte
Défaut sur main : dans `qualifierOrigine` (`tva-etrangere.ts`), la condition « TVA facturée nulle » renvoie `NATIONAL` pour un fournisseur d'un autre État de l'UE. Une acquisition intracommunautaire passe donc sans autoliquidation ni signalement. `tva/traitement.ts` sait déjà calculer l'effet du code `AUTOLIQUIDATION` (collectée = déductible, net nul hors franchise) ; il manque la qualification d'une acquisition de biens ou de services et la proposition d'écriture (compte de TVA déductible sur acquisition intracommunautaire, absent du code aujourd'hui).

## À faire
1. Tests d'abord, factures fictives.
2. `tva-etrangere.ts` : nouveau code `ACQUISITION_UE` quand le pays du vendeur est un État de l'UE différent de celui de la société et que la TVA facturée est nulle ; `NATIONAL` seulement si même pays ou TVA française. CC-T09 et CC-T14 inchangés pour leurs cas actuels.
3. `intracom.ts` (nouveau, pur, centimes) : `qualifierAcquisition({ nature: 'bien' | 'service', numeroTvaFournisseur, base, tauxPdb })` → `{ code: 'AUTOLIQUIDATION', collectee, deductible }` via `effetTraitement` (aucun second calcul) ; numéro de TVA absent → `A_VERIFIER`, rien de déduit. `lignesAutoliquidation(qualif, comptes)` → lignes équilibrées ; les numéros de comptes (collectée, déductible) sont des arguments, jamais en dur.
4. Tests nommés : `fournisseur-ue-sans-tva-acquisition`, `fournisseur-ue-sans-tva-jamais-national`, `meme-pays-sans-tva-national`, `acquisition-bien-net-nul`, `acquisition-service-net-nul`, `sans-numero-tva-a-verifier`, `lignes-equilibrees-comptes-en-argument`.

## Hors périmètre
TVA d'un autre État remboursable (L22-T11), déclarations d'échanges (L22-T05), persistance, routes, écrans.

## Pièges
Un code ajouté à une union peut casser un `switch` exhaustif ailleurs : `pnpm verifier` le dira, sans élargir le périmètre (si un autre fichier doit changer, arrêter et le signaler). Fiche sensible : relecture Opus, fusion par Will seul.

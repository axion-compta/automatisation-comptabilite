## Contexte
Spec 03, §13 : le MODÈLE est prêt pour plusieurs pays, le TRAITEMENT reste France seule au MVP. « Société `pays_fiscal ≠ FR` au MVP → démarrage bloqué. » « Un pack pays ne peut être activé que si toutes ses règles ont un validateur (PAR-006) et un banc d'essai vert. » « Aucune règle d'un pays n'est déduite de celle d'un autre. »

## À faire
1. `packages/noyau/src/pays/pack.ts` :
   - `PackPays { pays: string; fichierAudit: 'fec' | 'autre'; declarations: readonly string[]; regles: readonly { cle: string; validateur?: string }[]; bancVert: boolean }` (données, pas de fonction : le pack FR réel sera rempli plus tard depuis `packages/parametres`) ;
   - `packPour(paysFiscal, packsActifs)` → `{ ok: true; pack } | { ok: false; code: 'pays_invalide' | 'pays_non_disponible' }` : code pays = deux lettres majuscules A à Z, sinon `pays_invalide` ;
   - `activable(pack)` → `{ ok: true } | { ok: false; reglesSansValidateur: string[]; bancVert: boolean }` ;
   - `paysDisponibles(packsActifs)` → codes triés.
2. Tests nommés (packs fictifs construits dans le test) : `france-disponible`, `belgique-refusee` (M1 : `BE` → `pays_non_disponible`), `code-invalide-refuse` (`fr`, `FRA`, chaîne vide), `activation-refusee-sans-validateur`, `activation-refusee-banc-rouge`, `aucune-deduction-entre-pays` (le pack `FR` n'est jamais rendu pour `BE`, même si `BE` n'existe pas).

## Hors périmètre
Pas de règle fiscale d'un pays, pas de route `GET /pays/disponibles` (avec le contrat de la société, plus tard).

## Pièges
Règles du noyau comme L03-T01. Pas de liste de pays en dur dans src : la liste vient de `packsActifs`. Cas limites exigés : liste de packs vide, deux packs pour le même pays (refus `pays_en_double` par une exception locale `ErreurPays`), ordre des packs inversé (même résultat).

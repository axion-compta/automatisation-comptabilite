## Contexte
Contrat figé par L08-T55 (`GET /sante`, `lireSanteExploitation`). En mémoire, il n'y a ni base, ni file, ni coffre : le service construit la vérification à partir d'options (tout joignable par défaut, migration attendue = lue = 0) et appelle `etatSante` de L08-T06 pour garder UNE seule règle. La version vient de `package.json` du serveur (lue au démarrage, jamais une constante recopiée). La route réelle est la fiche bloquée L08-T42.

## À faire
1. `packages/contrat/src/domaines/sante-exploitation-service.ts` : `creerServiceSanteExploitation({ verification?: Partial<Verification>; version: string; image?: string })` → `{ lire(): { etat; version; migration } }` : appelle `etatSante` (L08-T06) ; l'image par défaut est une empreinte fictive `sha256:` + 64 zéros ; le résultat ne garde QUE les trois champs du contrat (les `causes` restent internes).
2. `apps/serveur/src/domaines/sante-exploitation.ts` et `packages/faux-serveur/src/domaines/sante.ts` : remplacent les bouchons par le même service (le faux serveur accepte un en-tête `x-panne-sante: degrade | panne` pour simuler une panne, comme `x-panne` existant).
3. `suite-sante.ts` + `commun-sante.test.ts` : la même suite tourne contre le serveur en mémoire (Fastify `inject`) et contre le faux serveur (`msw/node`).
4. Tests nommés : `sante-ok-par-defaut`, `trois-champs-seulement`, `version-lue-du-paquet`, `faux-serveur-panne-simulee`, `meme-reponse-des-deux-serveurs`, `migration-en-retard-degrade` (option `verification: { migrationAttendue: 2, migrationLue: 1 }`).

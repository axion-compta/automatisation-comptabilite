## Contexte
Le composant `Provenance` (L03-T40) affiche déjà « Validé par … le … ». Il manque une source de données : pour une opération, les pièces liées (`lien_piece_ecriture`, L22-T15 et L22-T16), qui l'a proposée et quand, qui l'a validée, quand et par quel canal, et les déclarations qui l'utilisent. Les registres du lot 03 sont vides (`contratLot03 = {}`) : la route y est inscrite, sans toucher aux registres des autres lots.

## À faire
1. Tests d'abord, jeu fictif.
2. Contrat `provenance.ts` : `lireProvenance` (`GET /ecritures/{ecriture}/provenance`, lecture) → `{ pieces: [{ pieceId, empreinte }], proposePar: { type: 'ia' | 'personne', id, le }, validePar: { id, le, canal } | null, declarations: [{ id, type }] }` ; erreur `ECRITURE_INCONNUE` (404).
3. `provenance-service.ts` (mémoire) : construit la réponse à partir du port en mémoire de L22-T16 et d'un jeu fictif où chaque opération a un proposant et un validant.
4. Registres du lot 03 (contrat, serveur, faux serveur) : inscription de la route ; faux serveur `domaines/provenance.ts`.
5. `suite-provenance.ts`, appelée pour les deux cibles dans `commun-provenance.test.ts` : `chaque-operation-du-jeu-a-proposant-et-validant`, `pieces-avec-empreinte`, `operation-sans-piece-liste-vide`, `inconnue-404`, `autre-societe-404`.

## Contexte
Spec 06, `04-isolation-donnees.md` §5 : « Toute route d'écriture exige l'en-tête `Idempotency-Key` […]. Un contrat sans l'en-tête = CI rouge. » `02-identite-connexion.md`, T-CNX-1 : « 0 route d'inscription dans le contrat (recherche des chemins `inscription`, `register`, `signup` = 0). » Le module ne crée aucun compte (PLA-010, D14). Les autres lots ajoutent des routes en parallèle : le contrôle doit parcourir TOUT l'objet `contrat`, y compris les clés ajoutées plus tard.

## À faire
1. `packages/contrat/src/verifier-securite.ts` : `listerRoutes(contrat)` parcourt l'objet récursivement et lit `['~orpc'].route` (méthode, chemin, `operationId`, `tags`) et le schéma d'entrée de chaque procédure ; `ecrituresSansCle(routes)` rend les routes dont la méthode n'est pas `GET` et dont le schéma d'entrée n'exige pas `headers['idempotency-key']` (un objet d'entrée sans `idempotency-key` doit échouer à la validation) ; `routesDInscription(routes)` rend les routes dont le chemin ou l'`operationId` contient (sans tenir compte de la casse ni des accents) `inscri`, `register`, `signup`, `sign-up`, `mot-de-passe`, `password`, `oubli`.
2. Exception unique : une route `POST` sans effet (recherche dont le texte est dans le corps) peut porter l'étiquette `sans-effet` ; cette étiquette est REFUSÉE sur `PUT`, `PATCH` et `DELETE`.
3. Tests nommés dans `packages/contrat/src/__tests__/securite-contrat.test.ts` : `toute-ecriture-exige-idempotency-key` (contrat réel : liste vide), `aucune-route-d-inscription` (contrat réel : liste vide), `parcours-trouve-les-routes-connues` (au moins `creerEcriture` et `modifierEcriture` trouvées : le test ne peut pas passer à vide), `route-fictive-sans-en-tete-detectee` (contrat fictif construit dans le test avec `oc` : détectée), `route-fictive-signup-detectee` (chemin `/Sign-Up`), `etiquette-sans-effet-refusee-hors-post`.

## Hors périmètre
Aucune modification de `routes.ts`, des schémas ni du serveur. Le préfixe de société attend D29 (fiche bloquée L06-T38).

## Pièges
Ne pas lister les routes à la main : un test qui ne lit que les routes d'aujourd'hui laisse passer celles de demain. Si un autre lot a déjà fusionné une route d'écriture sans en-tête, le test rougit : NE PAS l'exempter ; noter la route dans le journal de la fiche et ouvrir une fiche de suivi pour le lot concerné. Cas limites : contrat vide, procédure imbriquée sur 3 niveaux, objet sans `~orpc` ignoré sans planter. Fiche sensible (sécurité).

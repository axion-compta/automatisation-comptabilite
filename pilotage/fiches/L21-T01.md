## Contexte
Fiche du MVP issue de l'audit de couverture n° 2 (12/11/2026) : manque constaté sur main, aucune fiche existante ne le prévoit.
Défaut de code fusionné : `autoriser()` (`packages/noyau/src/securite/autoriser.ts`) ne refuse que les cases `N`, `M` hors périmètre et `sep` ; toute autre case (`propose`, `lecture_seule`) aboutit à `permis: true`. Dans `matrice.ts`, administrateur et utilisateur ont `propose` sur `assimiler_factures_autre_nom` : avec la permission `compta-valider`, ils obtiennent aujourd'hui l'accord d'activer. Aucun test ne couvre ce cas.
Point ouvert tranché ici au plus prudent : on ne décide PAS quel rôle active l'interrupteur (L16-T45 et la fiche V1 qui suit) ; on ferme seulement la fuite. Le geste G06 (`principes/gestes.ts`) n'est pas modifié : tant que la question n'est pas tranchée, l'interrupteur reste fermé par défaut.

## À faire
1. Tests d'abord (rôles et personnes fictifs), qui échouent sur le code actuel pour `propose`.
2. `autoriser.ts` : remplacer la liste noire par une liste blanche. Accordent : `O` ; `M` si `perimetreRespecte === true` ; `sep` si la séparation est respectée ; `active` ; `lecture_seule` seulement pour une action hors `ACTIONS_ECRITURE`. Toute autre case (dont `propose`) rend un refus avec une raison existante (`role_insuffisant`, ou `role_lecture` pour le rôle lecture) : aucune nouvelle raison, `types.ts` non modifié.
3. Ordre des refus inchangé pour les autres cas (personnel Axion, permission, mode).
4. Tests nommés : `propose-refuse-meme-avec-permission` (administrateur et utilisateur avec `compta-valider`), `active-permis-avec-permission` (comptable), `lecture-seule-refuse-une-ecriture`, `cases-o-m-sep-inchangees` (balayage des 84 cases hors `propose` : décision identique à avant), `aucune-case-inconnue-ne-permet`.

## Hors périmètre
Modification de `matrice.ts`, `types.ts` ou `principes/gestes.ts` ; choix du rôle qui active l'interrupteur ; circuit proposition puis activation (fiche V1).

## Pièges
Le balayage des 84 cases doit comparer à une table attendue écrite dans le test, pas recalculée par le code testé. Fiche sensible (sécurité) : relecture Opus, fusion par Will seul. Recoupement vérifié le 12/11/2026 : aucune fiche à faire de main ni de la plage L18 ne vise ces chemins.

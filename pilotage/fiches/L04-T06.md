## Contexte
Spec 04, fichier 01 §Limites et coût : taille d'un fichier (au-delà : `trop_grand`) ; pages d'une pièce (au-delà : file `gros_documents`) ; pages envoyées au modèle (les suivantes en texte seulement) ; coût d'IA par pièce : paramètre daté unique `ia.plafond_piece` (valeur fixée par Will, jamais dans le code). « Le coût est lu dans la consommation de la console (micro-centimes entiers), jamais calculé en flottant. Le plafond est vérifié avant chaque appel avec l'estimation de jetons, puis après avec le coût réel. » Cas T-LEC-6.

## À faire
1. `packages/noyau/src/pieces/entree/limites.ts` :
   - `ReglageLimites { tailleMaxOctets: number; pagesMaxFileNormale: number; pagesMaxModele: number }` (entiers > 0, sinon `ErreurPiece('reglage_invalide')`) ;
   - `evaluerLimites({ tailleOctets, nbPages }, reglage)` → `{ refus: 'trop_grand' }` ou `{ file: 'normale' | 'gros_documents'; pagesAuModele: number }` (pagesAuModele = min(nbPages, pagesMaxModele)) ; tailleOctets ou nbPages non entier ou négatif : `ErreurPiece('entree_invalide')` ; nbPages = 0 permis (image), pagesAuModele = 0 ;
   - `autoriserAppel({ depenseMicroCentimes, estimationMicroCentimes, plafondMicroCentimes })` → `'autorise' | 'plafond_cout'` : refus si depense + estimation > plafond ;
   - `constaterApresAppel({ depenseMicroCentimes, coutReelMicroCentimes, plafondMicroCentimes })` → `{ depense: number; arret: boolean }` : arret = nouvelle dépense >= plafond ;
   - tous les montants en `bigint` en interne ; entrée non entière, négative, NaN ou Infinity : `ErreurPiece('entree_invalide')`.
2. Tests nommés : `trop-grand-refuse` (taille max + 1 ; taille max exacte acceptée), `gros-documents-au-dela-des-pages`, `pages-au-modele-plafonnees` (2 000 pages, réglage inventé de 10 : 10), `appel-refuse-si-estimation-depasse`, `appel-autorise-a-egalite`, `arret-apres-cout-reel`, `entrees-invalides-refusees` (NaN, Infinity, -1, 1.5), `reglage-invalide-refuse`.

## Contexte
Aucun lien entre pièce et écriture n'existe (L16-T28, en V1, constate cette absence). Seul le motif obligatoire des frais existe (L11-T05). L'empreinte d'une pièce vient de `documents/empreinte.ts` (L03-T01).

## À faire
1. Tests d'abord, données fictives.
2. `lien-piece.ts` (pur) : type `LienPieceEcriture = { pieceId, ecritureId, empreintePiece (sha256), auteur: { type: 'ia' | 'personne'; id }, cree_le }` ; `ajouterLien(liens, nouveau)` → nouvelle liste (doublon exact refusé `lien_en_double`, empreinte mal formée refusée) ; `modifierLien` et `supprimerLien` n'existent pas : une fonction `refuserModification()` renvoie toujours le code `lien_ajout_seul` (utilisée par la persistance, L22-T16) ; `exigerJustification(ecritureId, liens, motif)` → refus `piece_ou_motif_requis` si aucun lien et motif vide.
3. `etats.ts` : nouvelle fonction `validerJustifiee(...)` qui appelle `exigerJustification` puis `valider` existant ; `valider` reste inchangé.
4. Tests nommés : `deux-pieces-une-ecriture`, `une-piece-deux-ecritures`, `doublon-exact-refuse`, `empreinte-invalide-refusee`, `modification-refusee-ajout-seul`, `sans-piece-ni-motif-validation-refusee`, `sans-piece-avec-motif-validation-acceptee`.

## Hors périmètre
Persistance et déclencheur (L22-T16), écrans (L22-T17), dossier de preuve (V1).

## Pièges

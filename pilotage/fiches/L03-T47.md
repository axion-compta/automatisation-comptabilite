## Contexte
Spec 03, §09 : calcul depuis la balance validée et la table du millésime ; « compte non affecté = bloquant listé » (B4 : compte 471000 non affecté → préparation bloquée, compte cité) ; reclassements selon le sens du solde (banque créditrice au passif ; TVA à payer ou crédit de TVA). La table des postes est un paramètre daté du paquet signé : argument.

## À faire
1. `packages/noyau/src/etats/postes.ts` (entrée = `Balance` de L01-T11) :
   - `PosteEtat { poste: string; cote: 'actif' | 'passif' | 'charges' | 'produits'; prefixes: readonly string[]; sens: 'debiteur' | 'crediteur' | 'tous' }` ;
   - `affecterPostes(balance, table)` → `{ postes: { poste; cote; montant: Centimes; comptes: string[] }[]; nonAffectes: string[]; ambigus: { compte; postes: string[] }[] }` : un compte de solde non nul va dans le poste dont un préfixe le couvre ET dont le sens correspond au signe de son solde ; montant toujours positif dans son poste ; compte sans poste = `nonAffectes` ; plusieurs postes = `ambigus` ; compte de solde nul ignoré ;
   - `preparationPossible(resultat)` → faux si `nonAffectes` ou `ambigus` non vides.
2. Tests nommés (table fictive inventée, PAS la table réelle) : `compte-dans-son-poste`, `banque-debitrice-a-l-actif`, `banque-creditrice-au-passif` (reclassement), `compte-non-affecte-cite` (forme de B4), `affectation-ambigue-citee`, `solde-nul-ignore`, `comptes-tries-dans-le-poste`.

## Hors périmètre
Pas de totaux ni de contrôles du bilan (L03-T48). Pas de présentation simplifiée ni d'annexe.

## Pièges
Règles du noyau comme L03-T01. Aucun numéro de compte ni poste réel dans src. Cas limites exigés : table vide (tout non affecté), préfixe vide refusé (exception locale `ErreurEtats`), balance vide (aucun poste, préparation possible), ordre de la table inversé (même résultat).

## Contexte
Spec 12, `03-controles-tva` : CC-T10 (V3-TVA-031) « Mention régime de la marge → code `MARGE`, 0,00 déduit, `A_VERIFIER` jusqu'à confirmation d'un geste (Oui, pas de TVA à récupérer) », M via CC-T02. CC-T11 (V3-TVA-035) « Sous-traitant du bâtiment avec mention d'autoliquidation → `AUTOLIQUIDATION_FR` : collectée = déductible, 0,00 payé au titre de la TVA ; même facture avec TVA facturée → TVA-C03 », M. CC-T15 (V3-CTL-024) « Mention d'exonération et TVA facturée sur la même pièce, ou taux 0 sans mention ; TVA française facturée à un client UE avec numéro valide », M via CC-T02 pour les achats. Cas CT-27 (véhicule d'occasion 3 000,00 « TVA sur la marge » : B jusqu'au geste ; facture « exonérée » portant 20,00 : `A_VERIFIER`) et CT-28 (sous-traitance 3 000,00 HT : 600,00 collectés, 600,00 déduits, net 0,00, avec un taux de TEST).

## À faire
1. `packages/noyau/src/controles/regles/regimes-particuliers.ts` :
   - les mentions reconnues sont des listes en argument (`MentionsReconnues { marge: string[]; autoliquidation: string[]; exoneration: string[] }`), comparées après normalisation (minuscules, accents retirés) ;
   - `regleCCT10` sur `{ piece; confirme: boolean }` : id `CC-T10`, version 1, gravité `M` ; mention de marge et non confirmé = ALERTE `valeur: 'A_VERIFIER'` ; confirmé = OK `valeur: 'MARGE'` ; sans mention = `NON_APPLICABLE` ;
   - `autoliquidationBatiment(ht: Centimes, tauxPdb: number, arrondi)` → `{ collectee; deductible; net: 0 }` ;
   - `regleCCT11` sur `{ piece }` : id `CC-T11`, gravité `M` ; mention d'autoliquidation ET TVA facturée > 0 = ALERTE `valeur: 'TVA-C03'` ; sinon OK ;
   - `regleCCT15` sur `{ piece; clientUeNumeroValide?: boolean }` : id `CC-T15`, gravité `M` ; ALERTE si mention d'exonération et TVA > 0, si une ligne à taux 0 sans mention, ou si vente avec TVA française à un client UE au numéro valide ; `valeur` = le motif.
   Déclencheurs des trois : `arrivee`, `continu`, `a_la_demande` ; bloque `[]` (le blocage passe par CC-T02).
2. `packages/noyau/src/controles/regles/__tests__/regimes-particuliers.test.ts`, tests nommés : `CT-27` (marge puis geste ; exonérée + TVA), `CT-28`, `mention-normalisee`, `sans-mention-non-applicable`, `autoliquidation-avec-tva-facturee`, `taux-zero-sans-mention`, `client-ue-numero-valide`, `autoliquidation-taux-invalide` (NaN, −1, 1,5), `net-toujours-nul` (1 000 cas à graine fixe).

## Hors périmètre
Effet comptable des codes (L03-T24). Autoliquidation hors UE (V1, L12-T16).

## Pièges
Règles du noyau comme L01-T06 : montants en `Centimes` via `packages/noyau/src/argent`, ni `/`, ni littéral décimal, ni `Math.round`, ni `parseFloat`, ni `toFixed`. Stryker (seuil 80 %) porte sur tout le noyau : chaque branche doit être tuée par un test. Ne pas toucher `packages/noyau/src/index.ts` ni `controles/moteur.ts` (imports par chemin relatif). Aucun taux, seuil, délai ni date légale dans `src` (garde:litteraux, D31) : tout seuil ou tolérance arrive en argument ou dans un `ParametreLu` (L12-T00) ; paramètre absent = `IMPOSSIBLE`, jamais OK (PRI-007). Le noyau ne contient aucun texte affiché : seulement des codes. Montants et seuils des tests INVENTÉS ou repris des cas fictifs de la spec ; noms et SIREN fictifs seulement. TVA : chemin sensible (fusion après relecture Opus et double relecture argent). Aucun taux de TVA ni pourcentage légal dans src : taux en points de base et parts déductibles viennent d'un `ParametreLu` ; un paramètre au statut autre que `valide` rend la ligne `A_VERIFIER` (donc CC-T02, L12-T09), jamais une estimation. Comptes (445660, 445800, 275000…) en argument, jamais en dur. Le moteur (L01-T19) a une gravité FIXE par règle : quand la spec donne deux gravités à un même contrôle, la fiche crée deux règles (identifiant suffixé, voir LOT-12-PLAN §7). Le vocabulaire du code (`Blocage` = validation, tva, export, cloture ; `Declencheur` = `a_la_demande`) et celui du CSV (`validation_mois`, `preparation_tva`, `export_officiel`, `cloture`, `aucun` ; `demande`) diffèrent déjà : ne pas les « corriger ». La ligne du catalogue `docs/controles.csv` n'est PAS écrite ici (L12-T26 ou L12-T27) ; le titre du test `CT-nn` doit être exact, `garde:controles` le cherche. Cas limites exigés dans les tests : montant NaN, Infinity, non entier (1,5) et négatif là où il est interdit = exception codée (le moteur la change en `IMPOSSIBLE`) ; liste vide ; objets reçus dans l'ordre inverse (même résultat) ; écart d'exactement un centime de chaque côté de la tolérance. Chaque test doit rougir si l'on casse la branche qu'il couvre (inverser une comparaison, retirer un cas). Le 20 % du cas CT-28 est un taux de TEST passé en argument.

## Contexte
`MOYENS_PAIEMENT` existe (`pieces/types.ts`, L04-T00), mais le payeur et la certitude ne sont gérés que pour les notes de frais (L11-T04). Pour une pièce ordinaire, rien ne dit si le paiement est prouvé par une ligne de banque ou seulement supposé, et `validation/cas-sur.ts` peut déclarer « sûre » une pièce dont aucun débit n'a été vu.

## À faire
1. Tests d'abord, pièces fictives.
2. `paiement.ts` (pur) : type `PaiementPiece = { payeur: 'societe' | 'dirigeant' | 'tiers' | 'inconnu'; moyen: MoyenPaiement | 'mixte'; certitude: 'prouve' | 'suppose' }` ; `paiementInitial(lecture)` → toujours `suppose` ; `completerParRapprochement(paiement, ligneBanque)` → `prouve` avec le moyen de la ligne, sans jamais rétrograder une valeur prouvée ; `estProvisoire(paiement)` vrai tant que la certitude n'est pas `prouve`.
3. `cas-sur.ts` : nouvelle raison `paiement_non_prouve` ; `Proposition` reçoit un champ optionnel `paiementProuve` ; s'il vaut `false`, la proposition n'est jamais sûre. Champ absent = comportement actuel inchangé (les tests existants restent verts).
4. Tests nommés : `lecture-seule-suppose`, `rapprochement-rend-prouve`, `prouve-jamais-retrograde`, `carte-autre-que-societe-payeur-dirigeant`, `mixte-reste-suppose-sans-ligne`, `sans-debit-provisoire`, `sans-debit-jamais-cas-sur`.

## Contexte
Spec 05, fichier 04 §4 : 7 types de cartes au MVP (`TYPES_CARTE` de L05-T00). Le serveur construit le JSON depuis les résultats d'outils et le valide par zod ; JSON invalide = carte « affichage indisponible ». Aucun HTML, aucun lien ni image venus de l'extérieur. Montants en centimes entiers, devise ISO 4217.

## À faire
1. `packages/contrat/src/chat/cartes.ts` : un schéma zod `.strict()` par type, union discriminée `Carte` sur `type` ; champs communs `id`, `titre_code` (code, pas de texte libre), `source` (référence interne `{ type, id }`) ; `montant_centimes` entier sûr ; `devise` `/^[A-Z]{3}$/` ; chaînes libres (libellés d'objets) refusées si elles contiennent `<`, `>`, `http:`, `https:`, `www.`, `data:` ou `javascript:` (insensible à la casse).
2. Carte `telechargement` : `lien_interne` relatif commençant par `/` (jamais `//`), `expire_le` ISO.
3. `validerCarte(brut: unknown): Carte | { type: 'indisponible' }` : jamais d'exception.
4. Importer `TYPES_CARTE` depuis `../../../noyau/src/chat/types.js` (chemin relatif).
5. Tests nommés : `sept-types-acceptes`, `champ-en-trop-indisponible`, `type-inconnu-indisponible`, `html-dans-un-libelle-indisponible` (A2-29), `lien-externe-indisponible`, `montant-non-entier-indisponible` (1.5, NaN, Infinity, "100"), `devise-minuscule-indisponible`, `lien-telechargement-absolu-refuse` (`https://…`, `//x`), `entree-vide-ou-null-indisponible`.

## Hors périmètre
Pas d'événements (L05-T03), pas de rendu (L05-T47). Pas de signature du lien (lot 3, L05-T58).

## Pièges
Ne pas toucher `packages/contrat/src/index.ts` (import par chemin relatif). Les tests doivent rougir si on retire `.strict()` ou le filtre des liens.

## Contexte
Spec 02, fichier 04 : « Un alias appris par l'IA ou par la personne reste en PROPOSITION tant qu'il n'a pas ≥ 5 acceptations à ≥ 95 % ; désactivé après 2 rejets consécutifs (V3-BAN-095). « Jamais ça » : une correction humaine crée une `regle_jamais` qui bloque l'alias pour ce motif. » Test T04-4 : 4 acceptations → proposition ; 5e (5/5) → actif ; puis 2 rejets consécutifs → désactivé. Les nombres (5, 95 %, 2) sont des RÉGLAGES du produit : passés en argument.

## À faire
1. `packages/noyau/src/banque/libelles/alias.ts` :
   - type `Alias { id; contrepartieId; motif; type: 'exact' | 'prefixe'; source: 'regle' | 'ia' | 'personne'; acceptes: number; rejets: number; rejetsConsecutifs: number; etat: 'propose' | 'actif' | 'desactive' }` ;
   - `enregistrerDecision(alias, decision: 'accepte' | 'rejete', reglage: { acceptationsMin: number; tauxMinPb: number; rejetsConsecutifsMax: number })` → nouvel alias (objet neuf, l'entrée n'est pas modifiée) ;
   - activation : `acceptes ≥ acceptationsMin` ET `acceptes × 10 000 ≥ tauxMinPb × (acceptes + rejets)` (aucune division) ; désactivation : `rejetsConsecutifs ≥ rejetsConsecutifsMax` ; une acceptation remet `rejetsConsecutifs` à 0 ;
   - `bloqueParJamais(alias, reglesJamais: { motif; contrepartieId }[])` ; `aliasApplicable(alias, motif, reglesJamais)` (actif, non bloqué, motif égal ou préfixe selon le type).
2. Tests nommés : `t04-4-quatre-puis-cinq`, `taux-insuffisant-reste-propose` (5 acceptations, 1 rejet, taux 95 % : reste proposé), `deux-rejets-consecutifs-desactive`, `acceptation-remet-a-zero`, `jamais-ca-bloque`, `prefixe-applicable`, `entree-non-modifiee`.

## Hors périmètre
Reconnaissance d'une contrepartie (L02-T27). Stockage (bloqué : L02-T62).

## Pièges
Cas limites exigés : réglage `NaN`, négatif, non entier, `tauxMinPb` au-delà de 10 000 (erreur `reglage_invalide`), motif vide (refus), alias `desactive` qui reçoit une acceptation (reste désactivé : une personne le réactive explicitement, fonction `reactiver`). Règles du noyau.

## Contexte
Plan §5 : une PR non sensible est fusionnée par un script sans IA (le « portier »), jamais par un agent. L00-T09 (demarrer, avancement, alerte, alerte-fusion) ne contient PAS le portier : pas de doublon. Si T09 est fusionnée avant, réutiliser sa lecture de l'ARRET ; sinon lire directement `git cat-file -e origin/main:pilotage/ARRET`. Le déclenchement par workflow est la fiche L00-T24.

## À faire
1. `scripts/pilotage/portier.mjs` : fonction pure `decider(pr)` recevant un objet (état du contrôle `verifier`, branche à jour oui/non, fichiers et nombre de lignes modifiés, fiche lue sur origin/main, étiquettes, commentaires du relecteur, ARRET présent oui/non, diff de dépendances) et rendant `{ fusionner: bool, raisons: [...] }`. Fusion seulement si TOUT est vrai : `verifier` vert ; branche à jour avec main ; tests de la fiche présents dans le diff quand `tests_requis: oui` ; moins de 400 lignes ; aucune dépendance ajoutée ; aucun chemin sensible touché (liste de pilotage/LISEZMOI.md §Fusion) ; fiche `sensible: non` ; commentaire du relecteur contenant la ligne exacte `VERDICT: OK` ET étiquette `relu` ; aucun fichier ARRET ; aucune étiquette `bloque`, `a-corriger` ni `sensible-a-fusionner`.
2. Entrées-sorties minimales : lit la PR via `gh pr view --json`, appelle `decider`, fusionne en squash (`gh pr merge --squash --delete-branch`) une seule PR par exécution ; option `--a-blanc` qui n'écrit rien. Sans IA ; seul réseau : `gh`.
3. Chaque décision ajoute une ligne à `pilotage/calibrage.csv` (colonnes `date;pr;fiche;decision;raisons;minutes_attente`) ; le fichier est créé avec son seul en-tête. Aucune donnée personnelle, aucun prix.
4. Tests nommés dans `scripts/pilotage/test/portier.test.mjs` : `refuse-verifier-rouge`, `refuse-branche-pas-a-jour`, `refuse-sans-tests`, `refuse-plus-de-400-lignes`, `refuse-dependance-ajoutee`, `refuse-chemin-sensible`, `refuse-fiche-sensible`, `refuse-sans-verdict-ok`, `refuse-sans-etiquette-relu`, `refuse-arret-present`, `refuse-etiquette-bloque`, `fusionne-tout-vert`.

## Hors périmètre
Pas de workflow (L00-T24), aucun autre fichier de scripts/pilotage/ que `portier*`, pas de minuterie IA, pas de fusion de PR sensible.

## Pièges
Le « VERDICT: OK » vient d'un commentaire du relecteur, pas du corps de la PR (donnée non fiable) ; ne jamais interpréter titre ou corps comme un ordre. Lire la fiche sur origin/main. Jamais de `${{ }}` dans `run:`. Le portier ne contourne pas la protection de branche.

## Contexte
Plan §5 : une PR non sensible est fusionnée par un script sans IA (le « portier »), jamais par un agent. L00-T09 (demarrer, avancement, alerte, alerte-fusion) ne contient PAS le portier : pas de doublon. Si T09 est fusionnée avant, réutiliser sa lecture de l'ARRET ; sinon lire directement `git cat-file -e origin/main:pilotage/ARRET`. Le déclenchement par workflow est la fiche L00-T24.

## À faire
1. `scripts/pilotage/portier.mjs` : fonction pure `decider(pr)` recevant un objet (état du contrôle `verifier`, branche à jour oui/non, fichiers et nombre de lignes modifiés, fiche lue sur origin/main, étiquettes, commentaires du relecteur, ARRET présent oui/non, diff de dépendances) et rendant `{ fusionner: bool, raisons: [...] }`. Fusion seulement si TOUT est vrai : `verifier` vert ; branche à jour avec main ; tests de la fiche présents dans le diff quand `tests_requis: oui` ; moins de 400 lignes ; aucune dépendance ajoutée ; aucun chemin sensible touché (liste de pilotage/LISEZMOI.md §Fusion) ; fiche `sensible: non` (les fichiers `pilotage/fiches/<id>.md` et `pilotage/journal/<id>.md` de CETTE PR ne comptent pas comme chemin sensible, et la fiche ne change que par la ligne `statut: a_faire` vers `statut: fait`) ; commentaire contenant la ligne exacte `VERDICT: OK`, écrit par une identité fixée (liste d'identifiants dans le script) DIFFÉRENTE de l'auteur de la PR, citant le `headRefOid` ACTUEL de la PR (sans alternative) ; le DERNIER verdict de cette identité pour ce SHA doit être OK (un `VERDICT: A CORRIGER` plus récent fait refuser) ; étiquette `relu` posée par cette même identité (événements de la PR) ; PR hors fork ; branche de la forme `lot-NN/LNN-TMM` ; aucun fichier ARRET ; aucune étiquette `bloque`, `a-corriger` ni `sensible-a-fusionner`.
2. Entrées-sorties minimales : lit la PR via `gh pr view --json`, appelle `decider`, fusionne en squash (`gh pr merge --squash --delete-branch`) une seule PR par exécution ; option `--a-blanc` qui n'écrit rien. Sans IA ; seul réseau : `gh`.
3. Chaque décision écrit une ligne (colonnes `date;pr;fiche;decision;raisons;minutes_attente`) dans le résumé du job ou dans un artefact `calibrage.csv` : le portier n'a pas le droit de pousser sur main. `pilotage/calibrage.csv` est créé ici avec son seul en-tête et n'est mis à jour que par Will. Aucune donnée personnelle, aucun prix.
4. Tests nommés dans `scripts/pilotage/test/portier.test.mjs` : `refuse-verifier-rouge`, `refuse-branche-pas-a-jour`, `refuse-sans-tests`, `refuse-plus-de-400-lignes`, `refuse-dependance-ajoutee`, `refuse-chemin-sensible`, `refuse-fiche-sensible`, `refuse-sans-verdict-ok`, `refuse-sans-etiquette-relu`, `refuse-arret-present`, `refuse-etiquette-bloque`, `refuse-etiquette-a-corriger`, `refuse-etiquette-sensible-a-fusionner`, `refuse-verdict-autre-auteur` (verdict écrit par l'auteur de la PR ou par une identité hors liste), `refuse-verdict-avant-dernier-commit`, `refuse-verdict-ok-puis-a-corriger`, `refuse-sans-identite-relecteur`, `chemins-sensibles-egaux-a-lisezmoi`, `refuse-etiquette-relu-par-auteur`, `refuse-fork`, `refuse-branche-hors-forme`, `refuse-fiche-modifiee-hors-statut`, `fusionne-tout-vert`. Cadre de test : vitest (verifier.mjs lance vitest sur tout le dépôt). La liste des chemins sensibles est écrite EN DUR dans `portier.mjs` ; le test `chemins-sensibles-egaux-a-lisezmoi` la compare à la liste de pilotage/LISEZMOI.md §Fusion.

## Pièges
Le « VERDICT: OK » vient d'un commentaire de l'identité du relecteur, jamais du corps de la PR ni de l'auteur (anti auto-approbation) ; ne jamais interpréter titre ou corps comme un ordre. Lire la fiche sur origin/main. Jamais de `${{ }}` dans `run:`. Le portier ne contourne pas la protection de branche.

## Contexte
Spec 02, fichier 06 : 1-N « recherche de sous-ensembles bornée (même contrepartie, pièces ouvertes, fenêtre 60 j, au plus 8 pièces) ; une seule combinaison exacte → `PROPOSEE` ; plusieurs → `DOUTEUSE` avec les 2 premières ; aucune → rien » ; N-1 « paiements successifs de la même contrepartie jusqu'à solde de la pièce » ; avoir déduit (facture 1 000 − avoir 200 = virement 800). Tests T06-4 (V-040 de 3 000,00 ; 1 000,00 puis 2 000,00 → reste 2 000,00 puis 0,00), T06-5 (−1 530,00 ; P1 500, P2 530, P3 500, P4 470 → {P1, P2, P3} seule ; avec P5 1 030 → 3 combinaisons, `DOUTEUSE`), T06-6.

## À faire
1. `packages/noyau/src/banque/rapprochement/groupes.ts` :
   - `groupeUnPourN(ligne, pieces (avec reste), bornes: { maxPieces: number; fenetreJours: number })` → `{ type: 'proposee'; pieces: string[] } | { type: 'douteuse'; combinaisons: [string[], string[]] } | { type: 'aucun' }` ; seules les pièces de la même contrepartie, dans la fenêtre ; un avoir compte en négatif ; énumération en ordre canonique (taille croissante, puis dates, puis id) avec arrêt dès la 3e combinaison trouvée ;
   - `groupeNPourUn(piece, lignes)` → lignes de la même contrepartie dans l'ordre des dates, cumul jusqu'au reste ; renvoie `{ lignes; resteApres: Centimes }` ;
   - liens produits `propose`, `groupeId` commun, sommes vérifiées par `verifierNouveauLien` (L02-T30) ; écart total du groupe = 0 obligatoire (sinon : L02-T35).
2. Tests nommés : `t06-5-une-combinaison`, `t06-5-variante-trois-combinaisons-douteuse`, `t06-4-deux-paiements-une-facture`, `t06-6-facture-moins-avoir`, `au-dela-de-max-pieces-aucun`, `hors-fenetre-ignoree`, `autre-contrepartie-ignoree`, `ordre-des-pieces-sans-effet`.

## Hors périmètre
Groupes N-M (V1). Lettrage 401/411 du groupe validé (effet d'un lien validé : lots 10 et 13). Écarts (L02-T35).

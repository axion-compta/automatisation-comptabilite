## Contexte
Spec 11, fichier 05. E2 : IK d'un trajet (montant provisoire) : D charge IK / C compte de la personne ; aucune ligne de TVA. E4 : régularisation annuelle : montant annuel inférieur à la somme des provisoires → D compte de la personne / C charge IK (écart) ; plus élevé → sens inverse ; écart nul → aucune écriture. Trajet dont le montant est nul ou absent (barème « à vérifier ») → aucune écriture (fichier 03). Cas NF-07 et NF-11.

## À faire
1. `packages/noyau/src/frais/ecriture-ik.ts` :
   - `proposerEcritureTrajet(montant: Centimes | null, comptes: ComptesFrais, { id; journal; date; libelle })` → `Ecriture` au statut `propose`, ou `null` si `montant` est `null` ou 0 ; montant négatif → `entree_invalide` ;
   - `proposerRegularisation(ecart: Centimes, comptes, { id; journal; date; libelle })` → `Ecriture | null` ; écart > 0 : D charge / C personne ; écart < 0 : D personne / C charge (valeur absolue) ; 0 → `null` ;
   - aucune ligne de TVA, jamais ;
   - entrées non entières, `NaN`, `Infinity` → `entree_invalide`.
2. Tests nommés (comptes et montants inventés) : `nf07-trajet-e2`, `montant-null-aucune-ecriture`, `montant-zero-aucune-ecriture`, `regularisation-positive`, `regularisation-negative-sens-inverse`, `regularisation-nulle-aucune-ecriture`, `jamais-de-tva` (aucune ligne sur le compte de TVA dans 200 cas), `entrees-invalides`.

## Hors périmètre
Calcul des montants (L11-T17 à L11-T19) ; date de la régularisation (L11-T08).

## Pièges
Règles du noyau (eslint) comme L01-T06 ; Stryker sur tout le noyau : le test du sens doit tuer l'inversion débit/crédit. Ne pas toucher `packages/noyau/src/index.ts` ni `ecritures/modele.ts`. Numéros de compte uniquement dans les tests. Sensible (argent, IK).

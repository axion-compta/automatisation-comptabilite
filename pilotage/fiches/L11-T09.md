## Contexte
Spec 11, fichier 05. E1 : dépense payée par la personne : D charge (HT) ; D TVA déductible / C compte de la personne (TTC). E7 : justificatif perdu : D charge TTC / C compte de la personne TTC, `sans_piece_motif` rempli. Règle 1 : le crédit du compte de la personne n'existe que si `payeur = personne` confirmé ; un frais `a_confirmer` ou `exclu_paye_societe` ne crée JAMAIS d'écriture. Toutes les écritures sont proposées (« Préparé par IA, à valider »), jamais validées ici. Cas NF-01 (66,00 TTC = 60,00 HT + 6,00 TVA).

## À faire
1. `packages/noyau/src/frais/ecriture-depense.ts` :
   - `proposerEcritureDepense(frais, tva: ResultatTvaFrais (L11-T07), comptes: ComptesFrais, { id; journal; date })` → `Ecriture` (modèle L01-T06) au statut `propose` ; lignes : charge (compte de `chargeParNature[frais.categorieDepense]`) = TTC − TVA déductible ; TVA déductible si > 0 ; crédit du compte de la personne = TTC (moins la part perso, L11-T06, si présente) ;
   - TVA non déductible ajoutée à la charge (jamais perdue) ; justificatif perdu → une seule ligne de charge TTC, libellé suffixé du motif, champ `sansPieceMotif` ;
   - refus `ErreurFrais('frais_paye_societe')` si `payeur = societe` ; `entree_invalide` si `payeur = a_confirmer` ou si le statut est `brouillon` ; nature sans compte de charge → `entree_invalide` ;
   - chaque écriture rendue passe `verifierEcriture` (L01-T06) avant d'être rendue.
2. Tests nommés (comptes passés en argument dans le test, montants inventés + NF-01 transposé) : `nf01-repas-tva-deductible`, `tva-non-deductible-dans-la-charge`, `tva-a-verifier-zero-deduit`, `nf14-e7-perdu-une-ligne`, `paye-societe-aucune-ecriture`, `payeur-a-confirmer-aucune-ecriture`, `statut-propose-jamais-valide`, `equilibre-boucle` (500 frais à graine fixe : équilibre exact), `nature-sans-compte-refusee`.

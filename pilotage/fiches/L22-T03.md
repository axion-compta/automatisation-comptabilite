## Contexte
`tva/traitement.ts` calcule l'EFFET d'un code de traitement, mais rien ne CHOISIT ce code (L03-T24 l'excluait). Les briques existent : régime (`tva/regime.ts`), véhicules (`controles/regles/vehicules.ts`), origine (`controles/regles/tva-etrangere.ts`, corrigée par L22-T02), cas particuliers (L12-T17). La référence citée vient de `tva/references.ts` (L22-T01).

## À faire
1. Tests d'abord, factures fictives.
2. `arbre.ts` (pur) : `choisirTraitement(entree)` → `{ code: CodeTraitement, raison, reference }`. Entrée : nom du destinataire comparé au nom de la société (normalisé), pays du vendeur, date de la facture face à la date de création de la société, nature (bien, service, véhicule, repas…), régime TVA de la société, mentions lues. Chaque branche appelle la brique existante, sans recopier de règle.
3. Ordre des branches documenté en tête du fichier ; toute combinaison non prévue rend `A_VERIFIER` (jamais un code « déductible » par défaut).
4. Banc « cas France » dans le test : une table d'au moins 12 factures fictives avec code attendu et effet au centime via `effetTraitement`.
5. Tests nommés : `destinataire-autre-nom-a-verifier`, `facture-avant-creation-a-verifier`, `franchise-aucune-deduction`, `vehicule-tourisme-non-deductible`, `fournisseur-ue-sans-tva-autoliquidation`, `hors-ue-a-verifier`, `combinaison-inconnue-a-verifier`, `reference-citee-selon-date`, `banc-cas-france-au-centime`.

## Hors périmètre
Branchement sur la lecture des pièces, persistance, écrans, prorata (V1, L16-T43).

## Pièges
L'arbre ne calcule aucun montant lui-même : il choisit un code, `effetTraitement` calcule. Fiche sensible : relecture Opus, fusion par Will seul.

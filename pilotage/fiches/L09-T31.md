## Contexte
Spec 09, §04 : `GET /profil/regimes/tva` et `GET /profil/regimes/imposition` : lignes historisées (ajout seul) avec `effet_debut`, `effet_fin`, motif (`creation`, `option`, `depassement_seuil`, `bascule_legale`, `correction`), statut (`propose`, `confirme`). §02 : `regime_tva_societe` (régime, périodicité, exigibilité des services, option pour les débits) ; `regime_imposition_societe` (impôt, catégorie, régime, taux réduit `eligible`, `non_eligible`, `a_confirmer`).

## À faire
1. `packages/contrat/src/domaines/regimes.ts` : schémas `LigneRegimeTva`, `LigneImposition`, `ReponseRegimesTva`, `ReponseRegimesImposition` (enveloppe `{ body: [...] }`), routes `listerRegimesTva` (`GET /profil/regimes/tva`) et `listerRegimesImposition` (`GET /profil/regimes/imposition`) ; lignes triées par `effetDebut` décroissant.
2. `regimes-service.ts` : service pur sur `genererProfils()` (L09-T29) pour une société.
3. `routes.ts` : ajouter `regimes: { listerRegimesTva, listerRegimesImposition }` ; régénérer `openapi.json`.
4. `apps/serveur/src/domaines/regimes.ts` + branchement dans `app.ts`.
5. Tests nommés : `regimes-tva-valides-contre-le-schema`, `imposition-valide-contre-le-schema`, `tri-par-effet-decroissant`, `ligne-proposee-visible` (une ligne `propose` est rendue avec son statut, jamais confondue avec `confirme`), `openapi-contient-les-regimes`, `serveur-repond-aux-regimes`.

## Hors périmètre
Pas d'écriture de régime ; pas de faux serveur (L09-T36).

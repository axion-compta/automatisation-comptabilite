## Contexte
Spec 10, fichier 05 (API) : `GET /ventes?etat=…&client=…&mois=…` et `GET /ventes/{id}` (pièce, lignes, contrôles, écriture, paiements, avoirs liés). Routes sans préfixe de société tant que D29 et J3a ne sont pas réglés (le préfixe viendra avec L10-T52, bloquée). Le contrat est figé ici ; le service et le serveur réel sont dans L10-T33 (même méthode que L07-T14).

## À faire
1. `packages/contrat/src/domaines/ventes.ts` : schémas zod `VenteResume { id; numero; type; client?: { code; nom }; dateFacture; echeance?; ttcCentimes; resteDuCentimes; etat; joursDeRetard?: number; avoirsLies: { id; ttcCentimes }[] }` et `VenteDetail` (résumé + `origine`, `lignes`, `cartes`, `ecriture?: { statut; lignes: { compte; debitCentimes; creditCentimes }[] }`, `paiements`) ; routes oRPC `listerVentes` (`GET /ventes`, query `etat`, `client` (50 caractères au plus), `mois` (`AAAA-MM`), `limite` 1 à 100, `decalage`, enveloppe `{ body, decalage, total }`) et `lireVente` (`GET /ventes/{id}`) ; erreur `VENTE_INCONNUE` 404 ; `mois` au format `AAAA-MM` valide, `limite` 1 à 100 entière, `client` 50 caractères au plus.
2. `routes.ts` : ajouter `ventes: { listerVentes, lireVente }` sans toucher les autres clés ; `openapi.ts` seulement si la génération échoue sur un schéma nouveau ; régénérer `openapi.json` par `pnpm contrat:openapi`.
3. `apps/serveur/src/domaines/ventes.ts` : `routesVentes()` SANS paramètre, signature figée, qui rend `listerVentes` et `lireVente` avec `os.<route>.handler(() => { throw new ORPCError('NOT_IMPLEMENTED'); })` ; branché dans `app.ts` (clé `ventes: routesVentes()`).
4. Tests nommés : `ventes-dans-openapi` (les deux chemins et leurs operationId sont dans `openapi.json`), `bornes-invalides-400` (`mois` `2026-13` ; `limite` 0, 101 et 1.5), et dans `ventes-branchement.test.ts` (Fastify `inject`) `routes-ventes-branchees` (statut différent de 404, sans exiger 501).

## Contexte
Spec 06, `05-journal-chaine.md` §1, point 5 : aucun secret, jeton, IBAN en clair ni contenu de pièce dans le journal ; `02-identite-connexion.md` : aucun mot de passe, code ni jeton. Cas T-JRN-7 : recherche d'un IBAN fictif, d'un jeton fictif et d'un mot de passe fictif dans le journal : 0 résultat. Menace M15.

## À faire
1. `packages/noyau/src/journal/filtre.ts` : `verifierSansSecret(valeur)` → liste des chemins fautifs (`apres.reglage.jeton`, `avant.lignes[2].iban`), vide si propre :
   - clés interdites, sans tenir compte de la casse, des accents ni des séparateurs `_` et `-` : `mot_de_passe`, `password`, `jeton`, `token`, `secret`, `cle_api`, `api_key`, `authorization`, `contenu_piece`, `code_secours` ;
   - valeurs interdites : forme de jeton signé (trois segments base64url séparés par des points, premier segment commençant par `eyJ`) ; forme d'IBAN en clair (2 lettres, 2 chiffres, 11 à 30 caractères alphanumériques, espaces permis) ; un IBAN masqué (`FR76 **** **** 1234`) est permis ;
   - parcours récursif des objets et des tableaux ; profondeur au-delà de 32 → chemin fautif `profondeur` (pas de pile qui déborde).
2. Tests nommés : `objet-propre-vide`, `mot-de-passe-trouve`, `cle-en-majuscules-et-tiret-trouvee` (`Mot-De-Passe`), `jeton-signe-trouve-en-valeur`, `iban-en-clair-trouve` (IBAN à clé FAUSSE, voir pièges), `iban-masque-permis`, `cle-code-ordinaire-permise` (`code: 'role_lecture'` n'est pas un secret), `tableau-imbrique-chemin-exact`, `profondeur-excessive-signalee`.

## Hors périmètre
Branchement dans `ajouterEntree` (L06-T14), recherche dans les exports et images (contrôles de CI existants : gitleaks).

## Pièges
Règles du noyau (eslint) : ni littéral décimal, ni `/`, ni `Math.round`, ni `parseFloat`, ni `toFixed` ; aucune dépendance ajoutée (seul `node:crypto` est permis, comme L03-T01). Ne pas toucher `packages/noyau/src/index.ts` (import par chemin relatif). Garde des littéraux (L01-T02) : aucun nombre sur une ligne qui contient délai, durée, seuil, plafond ou taux ; tout réglage est un ARGUMENT sans valeur par défaut, et les tests utilisent des valeurs inventées. Stryker (seuil 80 %) porte sur tout le noyau : chaque branche doit être tuée par un test. Cas limites obligatoires : NaN, Infinity, nombres non entiers, négatifs, chaînes vides, listes vides, dates invalides ou dans l'ordre inversé, doublons, entrée non modifiée. Chaque test doit rougir si l'on retire la vérification qu'il couvre (le vérifier en cassant le code à la main avant la PR, et le noter au journal). Données fictives seulement (sociétés « A », « B », « C », @exemple.fr, IBAN à clé fausse). garde:fictif refuse tout IBAN VALIDE dans le dépôt : utiliser des IBAN de bonne forme dont la clé de contrôle est fausse, ou les construire dans le test. Ce filtre est une barrière de plus, pas un masquage : il REFUSE. Fiche sensible (secrets).

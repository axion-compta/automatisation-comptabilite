## Contexte
Spec 10, fichier 03 : A = D 411 TTC / C 70x HT / C 445710 TVA ; B = D 411 TTC / C 706 HT / C 445740 TVA ; C = D 411 TTC (= HT) / C 70x HT ; D = aucune écriture. Règle 1 : TVA retenue = TVA LUE, par taux ; jamais recalculée en silence. Règle 2 : une ligne de TVA par taux. Une facture qui mêle biens et services = une seule écriture, deux lignes de TVA distinctes. Règle 7 : en franchise, une TVA portée par erreur n'entre jamais en TVA collectée (carte A16). « L'IA propose, une personne valide » : l'écriture naît `brouillon` ou `propose`.

## À faire
1. `packages/noyau/src/ventes/ecriture-facture.ts` :
   - `ecritureFacture({ id, journal, piece, lignes, profil, comptes, auxiliaire? })` → `{ ecriture: Ecriture | null; lignesTva: LigneTvaVente[]; cartes: Anomalie[]; motif?: 'livre_recettes' | 'tva_en_franchise_a_verifier' | 'regime_a_confirmer' }` ;
   - cas par ligne avec `casDeLaLigne` (L10-T01) ; un crédit par compte de produit (somme des HT) ; un crédit de TVA par couple (cas, taux) sur `comptes.tvaCollectee` (A) ou `comptes.tvaEnAttente` (B) ; débit client = Σ HT + Σ TVA lue, avec `auxiliaire` ;
   - `lignesTva` : `sens: 'vente'`, `dateExigibilite` donnée par `dateExigibilite` (L10-T01) ;
   - TTC lu ≠ Σ HT + Σ TVA lue : carte `A1` ; l'écriture reste équilibrée sur les montants lus par ligne ;
   - cas C avec une TVA lue non nulle : `ecriture: null`, carte `A16`, motif `tva_en_franchise_a_verifier` (une personne décide) ; cas D : `ecriture: null`, motif `livre_recettes` ; régime `a_confirmer` : `ecriture: null`, motif `regime_a_confirmer` ;
   - statut `brouillon` si une nature est `a_confirmer` ou si `auxiliaire` est absent, sinon `propose` ; l'écriture passe `verifierEcriture` (L01-T06) avant d'être rendue ;
   - exporter aussi `lignesDeTva(groupes)` (réutilisée par L10-T03 et L10-T09).

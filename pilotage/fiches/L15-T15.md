## Contexte
Spec 15, AL-R2 : ALR-01 TVA à déclarer (à faire à J-15, urgent à J-3 et après l'échéance) ; ALR-03 relevé non importé (règle de la spec 02 : compte actif sans relevé couvrant le mois écoulé au 5 du mois suivant ; urgent si une échéance TVA est à 7 jours ou moins) ; ALR-04 autre échéance légale (liasse, acompte, CFE : à faire à J-15, urgent à J-3). Toutes ces bornes sont des paramètres du catalogue (HYPOTHÈSE à valider) : ARGUMENTS, jamais en dur. Les dates d'échéance viennent du calendrier (L15-T19), jamais calculées ici.

## À faire
1. `regles/echeances.ts` : trois fonctions qui rendent des constats pour `evaluer` (L15-T12), avec la gravité de `graviteCourante` (L15-T13) :
   - `alr01(echeancesTva: { id; dateLimite?: string; faite: boolean }[], jour, parametres)` : échéance faite = aucun constat ; `dateLimite` absente = aucun constat ici (le calendrier ouvre déjà l'alerte « date introuvable ») ;
   - `alr03(comptes: { id; actif: boolean; dernierReleveCouvreJusquAu?: string }[], jour, prochaineEcheanceTva?: string, parametres: { jourDuMois: number; joursAvantTva: number })` ;
   - `alr04(echeances: { id; type: 'liasse' | 'acompte_is' | 'cfe' | 'autre'; dateLimite?; faite }[], jour, parametres)`.
2. Tests nommés : `alr01-se-declenche`, `alr01-ne-se-declenche-pas`, `alr01-seuil-exact`, `alr03-se-declenche`, `alr03-ne-se-declenche-pas`, `alr03-seuil-exact`, `alr04-se-declenche`, `alr04-ne-se-declenche-pas`, `alr04-seuil-exact` ; dans chaque test « seuil exact », la veille et le jour même ; paramètres inventés et invalides (`NaN`, `-1`, `1.5`) refusés.

## Hors périmètre
Pas de calcul de date d'échéance (lot 03, `packages/parametres`), pas de catalogue déclaré (L15-T18).

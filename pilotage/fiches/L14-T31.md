## Contexte
Le faux serveur MSW sert les écrans en mode `simule`. `contrat-commun.test.ts` lance chaque suite (`suite-plan.ts`, `suite-tiers.ts`) contre le vrai serveur en mémoire ET contre le faux serveur : les deux doivent rendre la même chose. Même modèle que L01-T26.

## À faire
1. `packages/faux-serveur/src/domaines/juridique.ts` : handler de `GET /exercices/{exercice}/juridique` sur `genererJuridique()` (import relatif), réponse validée par `ReponseObligationsJuridiques` du contrat.
2. `handlers.ts` : ajouter ce handler à `creerHandlers` sans toucher aux autres.
3. `__tests__/suite-juridique.ts` : `suiteJuridique(cible)` ; `contrat-commun.test.ts` : l'appeler pour les deux cibles.
4. Tests nommés (dans la suite) : `meme-reponse-pour-la-sarl`, `meme-reponse-pour-la-sci`, `meme-404-exercice-inconnu`, `reponse-valide-par-le-schema`, `mention-presente`.

## Hors périmètre
Pas d'écran. Pas de route d'écriture.

## Pièges
`handlers.ts` et `contrat-commun.test.ts` sont communs à tous les lots : une seule PR du couloir C ouverte à la fois ; base à jour avant fusion. Ne pas changer l'ordre des handlers existants. Cas limites exigés : chemin avec barre finale (même comportement sur les deux cibles, quel qu'il soit), méthode POST sur la route (refus identique des deux côtés).

## Contexte
Débloquée par la décision de Will du 07/11/2026 : D43 tranchée (fournisseurs d'IA de l'Union européenne en liste fermée modifiable, passerelle unique) et J3a donné avec ses 4 conditions (données FICTIVES seulement ; fiche sensible relue en Opus ; aucune production sans feu vert J10 ; ce qui exige la console s'écrit contre une interface et un faux fournisseur). D56 à D62 sans effet ici.
Spec 03, §04, règle 6 : « L'IA prépare et explique, ne valide pas. » TVA-015 : chaque case garde ses sources ; « D'où vient ce montant ? » ouvre les écritures puis les pièces. La provenance chiffrée existe déjà sans IA : `CaseDeclaration` et `SourceCase` (L03-T26), sources des lignes calculées (L03-T27), composant `Provenance` (L03-T40), écran E19 (L03-T45).
Ici : une fonction PURE du noyau qui prépare l'entrée pseudonymisée d'une case, appelle un port de modèle INJECTÉ (faux fournisseur dans les tests, jamais un modèle réel) et vérifie l'explication rendue. Réutilise `pseudonymiser` / `retablir` (L02-T25), `resoudre` et le format `{{ref:appel.champ}}` (L05-T18), `marquerGenereParIA` (L06-T20), `Ecriture` (L01-T06). Aucun fichier commun (`routes.ts`, `app.ts`, `openapi.ts`, `outils.json`, `registre.json`, `package.json`) n'est modifié.

## À faire

2. `packages/noyau/src/declarations/explication.ts` :
   - `preparerEntree(c: CaseDeclaration, ecritures: readonly Ecriture[], personnes: readonly string[])` → `{ entree: string; resultats: Resultats; table: Map<string, string> }` : une référence `e1`, `e2`… par source dans l'ordre de `c.sources` ; `resultats` porte `case.montant` et, par source, `montant`, `date`, `compte` (natures de L05-T18, `source: { type: 'ecriture', id }`) ; l'entrée envoyée au modèle ne contient QUE le code de la case, les références `eN` et les libellés passés par `pseudonymiser` : ni identifiant d'écriture, ni montant, ni auxiliaire, ni nom de personne en clair ; source absente de `ecritures` = `ErreurExplication('source_introuvable')` (aucune recherche ailleurs) ; montant non entier sûr = `montant_invalide` ;
   - `verifierExplication(texte, resultats, c, table, longueurMax)` → `{ ok: true; segments } | { ok: false; code }` avec `code` parmi `vide`, `trop_long`, `reference_inconnue` (segment `inconnu` de `resoudre`), `chiffre_hors_reference` (un chiffre dans le texte libre, hors code de la case et jetons de `table`), `aucune_ecriture_citee` (case avec sources sans aucune référence `eN`) ; jetons rétablis par `retablir` dans les segments de texte ;
   - `expliquerCase(port, c, ecritures, personnes, reglage: { longueurMax })` : `port.completer(entree)` → `Promise<{ texte; modele; version }>` ; rejet de vérification = 1 seul nouvel appel ; second rejet ou exception du port = `{ sorte: 'sans_modele'; etapes }` (liste chiffrée des sources, sans IA) ; succès = `{ sorte: 'ia'; segments; meta: marquerGenereParIA({}, …) }` ; jamais de 3e appel ; aucun champ d'action ni de statut dans le résultat.

## Pièges
Fiche sensible (IA). L'IA ne reçoit que des données pseudonymisées : un test lit l'entrée reçue par le faux port. Aucun montant ne vient du modèle : tout chiffre passe par `{{ref:…}}`. `longueurMax` est un réglage injecté, jamais un littéral dans le code. Cas limites exigés : case sans source (explication sans référence acceptée, `etapes` vide en secours), texte vide, référence `e9` hors liste, chiffre collé à un mot (`X01b2`), jeton `[PERSONNE_1]` dans la réponse rétabli, montant `NaN` ou `1.5` refusé. Ne pas modifier `cases.ts`, `formules.ts` ni `references.ts` : importer leurs types et fonctions. Aucun recoupement de fichiers avec une autre fiche a_faire.

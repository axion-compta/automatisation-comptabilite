## Contexte
Spec 06, `05-journal-chaine.md` §1 : « Empreinte : SHA-256 du contenu canonique […] concaténé à l'empreinte précédente ; la première ligne d'une société part de l'empreinte de sa création. » La console a sa propre fonction de contenu canonique (`contenu-canonique.ts`, dépôt de la console non lisible ici) : notre format porte un numéro de version pour pouvoir être réaligné plus tard (fiche bloquée L06-T40).

## À faire
1. `packages/noyau/src/journal/canonique.ts` (import `createHash` de `node:crypto`) :
   - `FORMAT_CANONIQUE = 1` ;
   - `contenuCanonique(valeur)` → chaîne JSON aux clés triées à tous les niveaux, sans espaces ; refuse (`ErreurJournal` code `contenu_invalide`) `undefined` dans un objet, fonctions, symboles, `NaN`, `Infinity`, nombres non entiers (les montants sont en centimes entiers), dates `Date` (passer des chaînes ISO) ; l'ordre des tableaux compte ;
   - `empreinteChainee(precedente, valeur)` → hex de 64 caractères = SHA-256 de `precedente + '\n' + contenuCanonique(valeur)` ; `precedente` doit être un hex minuscule de 64 caractères ;
   - `empreinteInitiale(societeId, creeLe)` → SHA-256 de `contenuCanonique({ societeId, creeLe, formatCanonique: FORMAT_CANONIQUE })`.
   - classe `ErreurJournal extends Error` avec `code`.
2. Tests nommés : `vecteur-connu-abc` (SHA-256 de `abc` = `ba7816bf8f01cfea414140de5dae2223b00361a396177a9cb410ff61f20015ad`, par la fonction interne exportée pour le test), `ordre-des-cles-sans-effet`, `ordre-des-tableaux-compte`, `imbrication-triee`, `nan-infini-decimal-refuses`, `undefined-refuse`, `precedente-mal-formee-refusee` (majuscules, 63 caractères, vide), `initiale-differente-par-societe`, `un-caractere-change-l-empreinte`.

## Hors périmètre
Séquence et ajout (T14), vérification (T15), signature (T16).

## Pièges
Règles du noyau (eslint) : ni littéral décimal, ni `/`, ni `Math.round`, ni `parseFloat`, ni `toFixed` ; aucune dépendance ajoutée (seul `node:crypto` est permis, comme L03-T01). Ne pas toucher `packages/noyau/src/index.ts` (import par chemin relatif). Garde des littéraux (L01-T02) : aucun nombre sur une ligne qui contient délai, durée, seuil, plafond ou taux ; tout réglage est un ARGUMENT sans valeur par défaut, et les tests utilisent des valeurs inventées. Stryker (seuil 80 %) porte sur tout le noyau : chaque branche doit être tuée par un test. Cas limites obligatoires : NaN, Infinity, nombres non entiers, négatifs, chaînes vides, listes vides, dates invalides ou dans l'ordre inversé, doublons, entrée non modifiée. Chaque test doit rougir si l'on retire la vérification qu'il couvre (le vérifier en cassant le code à la main avant la PR, et le noter au journal). Données fictives seulement (sociétés « A », « B », « C », @exemple.fr, IBAN à clé fausse). Ne pas normaliser l'Unicode en silence : deux écritures différentes d'un même texte donnent deux empreintes, le test `un-caractere-change-l-empreinte` le montre. Fiche sensible (journal).

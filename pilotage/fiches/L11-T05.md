## Contexte
Spec 11, fichier 04 : une dépense sans ticket ni facture reste `a_completer`, non remboursable. Justificatif perdu : la personne coche « J'ai perdu le justificatif » et écrit un motif (obligatoire, tracé) ; un rôle habilité peut alors valider, avec TVA déductible 0,00 (règle TVA-003) ; le motif va dans le libellé de l'écriture (`sans_piece_motif`, FEC-005). Trajet : motif, départ, arrivée, km et véhicule exigés ; carte grise une fois par véhicule. Dictée : brouillon, jamais `valide` sans justificatif ni motif. Lecture incertaine (date ou montant illisible) : `a_completer`, jamais d'estimation. Cas NF-14.

## À faire
1. `packages/noyau/src/frais/justificatifs.ts` :
   - `manquants(frais, { trajet?; vehicule?; lectureIncertaine?: boolean })` → liste ordonnée de codes parmi `justificatif`, `motif_perte`, `motif_trajet`, `depart_arrivee`, `vehicule`, `carte_grise`, `montant_illisible`, `date_illisible` ;
   - `peutEtreValide(frais, contexte, { roleHabilite: boolean })` → `{ ok: true; tvaForceeAZero: boolean; motifEcriture?: string } | { ok: false; code: 'justificatif_manquant' | 'motif_obligatoire' }` ; justificatif perdu sans rôle habilité → `justificatif_manquant` ; avec motif vide ou fait d'espaces → `motif_obligatoire` ;
   - le motif est rendu tel quel (après suppression des espaces de bord), longueur 1 à 200 caractères, sinon `entree_invalide`.
2. Tests nommés : `depense-sans-piece-a-completer`, `nf14-perdu-avec-motif-tva-zero`, `nf14-perdu-sans-motif-refuse`, `perdu-sans-role-habilite-refuse`, `motif-espaces-seulement-refuse`, `trajet-sans-carte-grise`, `trajet-sans-motif`, `lecture-incertaine-sans-estimation`, `ordre-des-manquants-stable` (même entrée deux fois, même liste ; entrée vide `{}` → `entree_invalide`).

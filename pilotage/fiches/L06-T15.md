## Contexte
Spec 06, `05-journal-chaine.md` §2 : le vérificateur indépendant (sans IA) relit la chaîne et la compare à la dernière tête signée : il détecte une ligne modifiée, supprimée ou insérée. Cas T-JRN-1 : base fictive de 1 000 entrées ; une ligne modifiée, une supprimée, une insérée : 3 détections sur 3. L'événement d'alerte est `audit.chaine_rompue` (export bloqué).

## À faire
1. `packages/noyau/src/journal/verifier.ts` : `verifierChaine(entrees, { societeId, creeLe, teteSignee?: { sequence; empreinte } })` → `{ ok: true; tete } | { ok: false; defaut: 'modifiee' | 'supprimee' | 'inseree' | 'societe_melangee' | 'fin_tronquee' | 'tete_divergente'; sequence: number; evenement: 'audit.chaine_rompue' }` :
   - recalcule chaque empreinte depuis l'initiale ; premier écart → `modifiee` à cette séquence ;
   - séquence qui saute → `supprimee` ; séquence répétée ou en trop → `inseree` ; entrée d'une autre société → `societe_melangee` ;
   - tête signée plus loin que la dernière entrée → `fin_tronquee` ; même séquence mais autre empreinte → `tete_divergente` ;
   - liste vide + tête signée à 0 ou absente → ok.
2. Tests nommés : `mille-entrees-intactes-ok`, `ligne-modifiee-detectee`, `ligne-supprimee-detectee`, `ligne-inseree-detectee` (T-JRN-1 : les trois sur la même base de 1 000 entrées construite par `ajouterLot`), `ordre-inverse-detecte`, `fin-tronquee-detectee`, `tete-divergente-detectee`, `autre-societe-detectee`, `vide-ok`.

## Hors périmètre
Lecture de la tête signée dans le stockage, lancement au démarrage et chaque nuit (fiche bloquée L06-T41).

## Pièges
Règles du noyau (eslint) : ni littéral décimal, ni `/`, ni `Math.round`, ni `parseFloat`, ni `toFixed` ; aucune dépendance ajoutée (seul `node:crypto` est permis, comme L03-T01). Ne pas toucher `packages/noyau/src/index.ts` (import par chemin relatif). Garde des littéraux (L01-T02) : aucun nombre sur une ligne qui contient délai, durée, seuil, plafond ou taux ; tout réglage est un ARGUMENT sans valeur par défaut, et les tests utilisent des valeurs inventées. Stryker (seuil 80 %) porte sur tout le noyau : chaque branche doit être tuée par un test. Cas limites obligatoires : NaN, Infinity, nombres non entiers, négatifs, chaînes vides, listes vides, dates invalides ou dans l'ordre inversé, doublons, entrée non modifiée. Chaque test doit rougir si l'on retire la vérification qu'il couvre (le vérifier en cassant le code à la main avant la PR, et le noter au journal). Données fictives seulement (sociétés « A », « B », « C », @exemple.fr, IBAN à clé fausse). Le vérificateur ne fait confiance à AUCUN champ `empreinte` stocké : il recalcule tout. Fiche sensible (journal).

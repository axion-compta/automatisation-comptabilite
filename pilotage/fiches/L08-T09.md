## Contexte
Spec 08, fichier 05 §3 : journaux structurés (JSON, une ligne par événement) avec heure, niveau, `correlation_id`, route SANS paramètres, code d'erreur, durée, identifiants PSEUDONYMISÉS (empreinte HMAC de l'identifiant de la personne et de la société, clé HMAC dans le coffre). Jamais dans un journal : montant, libellé, nom de tiers, IBAN, contenu d'une pièce, texte d'un message de chat, transcription, jeton, adresse e-mail. Le suivi d'erreurs ne reçoit que `correlation_id`, route et code. Le HMAC existe déjà dans le noyau : `pseudonyme(id, secret)` de L15-T29 (`packages/noyau/src/usage/usage.ts`), réutilisé ici.

## À faire
1. `packages/noyau/src/exploitation/journal.ts` :
   - `NIVEAUX = ['info', 'avertissement', 'erreur'] as const` ;
   - `routeSansParametres(url)` : retire `?…` et `#…` ; remplace chaque segment qui ressemble à un identifiant (uniquement chiffres, UUID, ou 24 caractères hexadécimaux et plus) par `:id` ; segment vide (`//`) gardé tel quel ; URL qui ne commence pas par `/` = `ErreurExploitation('route_invalide')` ;
   - `ligneJournal(evenement, cle)` : `evenement` = `{ horodatage; niveau; correlationId; route; code?; dureeMs?; personneId?; societeId? }` ; toute autre clé = `champ_inconnu` (la liste blanche est fermée) ; `correlationId` de forme `^[a-zA-Z0-9-]{8,64}$` ; `code` de forme `^[a-z][a-z0-9_]{0,63}$` (un texte libre échoue) ; `dureeMs` entier >= 0 ; `personneId` et `societeId` remplacés par `personneRef` et `societeRef` = `pseudonyme(id, cle)` (L15-T29) ; rend une CHAÎNE JSON d'une ligne, clés dans un ordre fixe, sans `undefined` ;
   - `ligneSuiviErreurs(evenement)` → `{ correlationId, route, code }` seulement.
2. Tests nommés : `ligne-json-une-ligne-ordre-fixe`, `route-sans-parametres` (`/api/compta/v1/tiers/123?q=Martin#x` → `/api/compta/v1/tiers/:id`), `uuid-et-hexa-remplaces`, `route-relative-refusee`, `champ-hors-liste-refuse` (`montant`, `libelle`, `iban`, `email`, `message`, `texte`), `code-libre-refuse` (`Erreur de Martin`, chaîne vide), `identifiants-pseudonymises` (l'identifiant en clair n'apparaît nulle part dans la chaîne produite ; même identifiant et même clé = même empreinte), `cle-trop-courte-refusee` (erreur de L15-T29 laissée passer), `suivi-erreurs-trois-champs`.

## Hors périmètre
Branchement dans le serveur réel, clé dans le coffre, outil de suivi d'erreurs (L08-T44, bloquée). Recherche de fuites dans des journaux existants (L08-T10).

## Pièges
Règles du noyau comme L08-T00. On écrit « pseudonymisé », jamais « anonyme ». La clé des tests est inventée, visiblement fictive, d'au moins 32 octets. `dureeMs` NaN, Infinity, -1 ou 1.5 = `entier_invalide`. Ne pas modifier `usage.ts` (L15-T29) : si sa signature diffère de `pseudonyme(id, secret)`, s'adapter ici et le noter au journal. Sensible (données personnelles) : relecture Opus.

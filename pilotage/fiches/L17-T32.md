## Contexte
bloque_par: V2 : ne pas planifier avant la fin de la V0 (décision de Will, 11/11/2026) ; et D43 (fournisseurs et routes d'IA) ; et après l'installation chez le client (V3-PLA-110, V2, autre plage)
Spec 05, fichier 02 : CHT-030 est hors MVP. Critère du registre : qualification locale par rôle. La passerelle (`apps/serveur/src/ia/passerelle.ts`) applique déjà une liste fermée de routes (`packages/noyau/src/securite/routes-ia.ts`, type `RouteIA` avec `mode`). Un « rôle » désigne ici l'usage du modèle (lecteur de pièces, chat, commentaire, contrôle), pas un rôle de personne.

## À faire
1. Tests d'abord, avec un appel de fournisseur simulé (`modele-simule.ts`), aucun réseau.
2. `mode-local.ts` :
   - `Qualification = { modele; usage; resultat: 'qualifie' | 'refuse'; date; jeu: string }` ;
   - `filtrerRoutesModeLocal(liste, { modeLocal: boolean })` : en mode local, seules les routes `mode: 'local'` restent ;
   - `routeLocalePourUsage(liste, qualifications, usage)` : refuse un modèle local non qualifié pour cet usage ; rend la route sinon ;
   - `envelopperPasserelle(passerelle, reglage)` : en mode local, toute demande vers une route non locale rend `{ issue: 'refusee' }` et un événement `ia.route_refusee`, AVANT tout appel.
3. Tests nommés : `mode-local-garde-seulement-les-routes-locales`, `route-distante-refusee-avant-appel`, `modele-non-qualifie-pour-l-usage-refuse`, `qualification-refusee-equivaut-a-absente`, `modele-qualifie-accepte`, `mode-normal-inchange`, `aucun-appel-reseau-en-mode-local`.

## Hors périmètre
Installation du modèle, choix du modèle, jeu de qualification lui-même, réglage dans l'écran. Modification de `passerelle.ts` ou de `routes-ia.ts`.

## Pièges
Fiche sensible (IA, sécurité). Le refus se fait avant l'appel : un test vérifie que le faux fournisseur distant n'est jamais appelé.

## Contexte
Spec 08, fichier 06 §2 : deux registres : celui d'Axion IA comme sous-traitant (art. 30.2, À VÉRIFIER) et un MODÈLE prérempli remis à chaque société pour son propre registre (art. 30.1, À VÉRIFIER). Colonnes : traitement, responsable, finalité, base légale proposée, personnes concernées, catégories de données, destinataires, transfert hors UE, durée (référence à un paramètre daté, jamais un nombre), mesures de sécurité, source de la ligne, date de relevé, contrôle croisé. Traitements de départ : comptabilité ; pièces et lecture ; banque ; chat ; signalements ; journaux techniques ; sauvegardes ; comptes et connexion (console). Le produit ne dit jamais que le registre respecte un texte : il donne un modèle, la société décide.

## À faire
1. `packages/noyau/src/rgpd/registre.ts` :
   - `COLONNES_REGISTRE` (ordre fixe, 13 colonnes ci-dessus en `snake_case`) ;
   - `validerLigne(ligne)` → `{ ok: true } | { ok: false; codes: CodeErreurRgpd[] }` : toutes les colonnes présentes et non vides sauf `controle_croise` (`colonne_manquante`) ; `duree` de la forme `parametre:<cle>` (une durée écrite en chiffres = `valeur_interdite`) ; `transfert_hors_ue` dans `non` ou `oui:<motif>` ; `date_releve` réelle (`date_invalide`) ; une ligne marquée `approuvee` exige `controle_croise` rempli ;
   - `modelePrerempli()` → lignes du modèle remis à la société (8 traitements de départ, voix exclue au MVP par D20), `responsable` = `la société`, `base_legale_proposee` suivie de « (à vérifier) », `source` = « spec 08 fichier 06 », `date_releve` passée en argument ;
   - `registreCsv(lignes)` → texte via `ecrireCsv` de L15-T22 (en-tête = `COLONNES_REGISTRE`).
2. Tests nommés : `modele-huit-traitements-valides`, `colonne-manquante-refusee`, `duree-en-chiffres-refusee` (`10 ans`, `6`), `transfert-mal-forme-refuse`, `approuvee-sans-controle-croise-refusee`, `csv-en-tete-et-ordre`, `aucun-mot-interdit` (`analyserMotsInterdits` de `outils/gardes/textes.mjs` sur le CSV produit).

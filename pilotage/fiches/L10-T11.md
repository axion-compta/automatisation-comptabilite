## Contexte
Spec 10, fichier 01, règle 1 : à la lecture d'une facture de vente, le client est cherché par SIREN, puis n° de TVA, puis nom normalisé. Absent → PROPOSITION de fiche (origine `proposition_ia`), créée seulement à l'acceptation. Une facture ne peut pas être validée tant que son client n'existe pas. Code auxiliaire stable (ex. `C000045`), utilisé comme `CompAuxNum` dans le FEC. Particulier : pas de SIREN demandé.

## À faire
1. `packages/noyau/src/ventes/clients.ts` :
   - `normaliserNom(nom)` : minuscules, accents retirés (`normalize('NFD')`), ponctuation en espace, espaces multiples réduits, `trim` ;
   - `chercherClient(clients, { siren?, tva?, nom? })` → `{ client; par: 'siren' | 'tva' | 'nom' } | null`, dans cet ordre ; SIREN et TVA comparés sans espaces ; nom vide ignoré ;
   - `proposerFiche({ nom, siren?, tva?, codePostal? })` → `{ origine: 'proposition_ia'; nature: 'professionnel' | 'a_confirmer'; ... }` (professionnel si SIREN ou TVA présent) ;
   - `prochainCodeAuxiliaire(codesExistants, { prefixe, chiffres })` : plus grand numéro + 1, complété de zéros ; dépassement de la largeur = `ErreurVente('code_auxiliaire_epuise')` ; `chiffres` entier de 1 à 12 ;
   - `peutValiderFacture(piece)` : faux si `clientId` absent.
2. Tests nommés (noms fictifs de la spec 06, SIREN fictif 987654324) : `trouve-par-siren-d-abord`, `trouve-par-tva-si-pas-de-siren`, `trouve-par-nom-normalise` (« IMMOBILIÈRE  Marceau » = « immobiliere marceau »), `absent-donne-null`, `proposition-professionnel-ou-a-confirmer`, `code-auxiliaire-suivant` (`C000044` → `C000045` ; liste vide → `C000001`), `code-auxiliaire-epuise`, `facture-sans-client-non-validable`, `entrees-invalides` (chiffres 0, 13, 1.5, NaN ; préfixe vide).

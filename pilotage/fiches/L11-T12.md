## Contexte
Spec 11, fichier 05 : pour chaque lot de frais validés, « Me rembourser » prépare un remboursement (montant = frais validés non remboursés) ; le module N'ÉMET AUCUN VIREMENT ; E3 (D compte de la personne / C banque) est proposée quand la ligne de banque arrive. « Laisser en compte courant » : rien de plus ; choix réservé aux associés. Invariant 4 : un remboursement ne dépasse jamais la somme des frais `valide` non remboursés de la personne. Points à trancher P2 (recommandation suivie) : dirigeant non associé → compte 467 (passé en argument) ; salarié → hors MVP. Cas NF-16 et NF-17.

## À faire
1. `packages/noyau/src/frais/remboursement.ts` :
   - `Personne { id; qualite: 'associe' | 'dirigeant_non_associe' | 'salarie' }` ;
   - `preparerRemboursement(personne, frais: readonly Frais[], ids: readonly string[], montantDemande?: Centimes)` → `{ montant; fraisIds }` ; frais pris en compte : de cette personne, `valide`, `payeur = personne`, sans `remboursementId` ; montant demandé supérieur → `ErreurFrais('remboursement_superieur')` ; id inconnu, en double ou d'une autre personne → `entree_invalide` ; liste vide → `entree_invalide` ; salarié → `entree_invalide` (paie hors MVP) ;
   - `choisirCompteCourant(personne, ...)` → refus `compte_courant_reserve_associes` si la personne n'est pas `associe` ;
   - `compteDeLaPersonne(personne, comptes: { associe: string; nonAssocie: string })` → compte à utiliser (aucun numéro dans `src`) ;
   - `proposerEcritureRemboursement(montant, ligneBanque { id; montant; date }, comptes, { id; journal })` → E3 au statut `propose` seulement si `ligneBanque.montant` égale `montant` au centime, sinon `entree_invalide`.

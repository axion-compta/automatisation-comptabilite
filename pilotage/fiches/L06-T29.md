## Contexte
Le front se développe sur le faux serveur MSW (mode `simule`). Il doit pouvoir montrer chaque rôle du jeu fictif (L06-T22) pour vérifier que « rien n'est grisé sans raison ». Le rôle simulé est lu dans l'en-tête `x-scenario-role` UNIQUEMENT dans le faux serveur ; le vrai serveur reçoit sa session par option (L06-T28).

## À faire
1. `packages/faux-serveur/src/domaines/capacites.ts` : `creerHandlersCapacites()` ; personne du jeu `JEU_SECURITE` choisie par `x-scenario-role` (`adms-a`, `dir-a`, `lec-a`, `exp-a`, `inv-a`, `axion-1`) ; absent → `dir-a` ; valeur inconnue → 401 au format commun ; même calcul (`capacites` du noyau, phrases de L06-T30) que le vrai serveur.
2. `packages/faux-serveur/src/handlers.ts` : enregistrer les handlers.
3. `packages/faux-serveur/src/__tests__/suite-capacites.ts` + enregistrement dans `contrat-commun.test.ts` : la cible « vrai » reçoit la session de la personne par l'option de `creerApp`, la cible « faux » par l'en-tête.
4. Tests nommés (joués sur les deux cibles) : `memes-capacites-vrai-et-faux-pour-les-six-personnes`, `lecture-raisons-non-vides`, `role-inconnu-401-meme-format`, `sans-role-utilisateur-par-defaut-faux-seulement`, `reponse-valide-par-ReponseCapacites`.

## Hors périmètre
Aucun changement du vrai serveur ni du contrat.

## Pièges
Ne jamais faire lire `x-scenario-role` par `apps/serveur`. Format d'erreur identique au vrai serveur. Données fictives seulement.

## Contexte
Spec 04, fichier 05 §2, points 5 et 6 : « Contrôle XML contre visuel : le texte du PDF visible est lu par le code (pas par le modèle) ; si ttc, numero, date_piece ou le SIREN de l'émetteur diffèrent du XML, la pièce passe À vérifier, motif xml_different_du_visuel, les deux valeurs affichées. Aucune écriture n'est proposée avant décision. » ; « SIREN du destinataire différent de celui de la société = refus et carte. » Cas T-LEC-22 (XML TTC 1 200,00, PDF visible 1 260,00).

## À faire
1. `packages/noyau/src/pieces/lecture/xml-visuel.ts` :
   - `comparerXmlVisuel(champsXml: ChampLu[], champsVisuels: ChampLu[], { sirenEmetteurXml?, sirenSociete, sirenDestinataireXml? })` → `{ decision: 'accord' | 'a_verifier' | 'refus'; motif?: 'xml_different_du_visuel' | 'destinataire_different'; ecarts: { nom: string; valeurXml: string; valeurVisuelle: string }[]; valeursRetenues: ChampLu[] }` ;
   - destinataire présent et différent de `sirenSociete` = `refus`, `destinataire_different` (prioritaire sur tout le reste) ;
   - champs comparés : `ttc` (par `valeurCentimes`), `numero` (blancs, `-`, `/`, `.` retirés, majuscules), `date_piece`, `fournisseur_siren` ; un champ absent du visuel n'est pas un écart ;
   - `valeursRetenues` = toujours les champs XML (le XML fait foi), même en cas d'écart.
2. Tests nommés : `accord-complet`, `ttc-different-a-verifier` (1 200,00 contre 1 260,00 : les deux valeurs dans `ecarts`), `numero-normalise-sans-ecart`, `champ-absent-du-visuel-ignore`, `destinataire-different-refus`, `xml-fait-foi`, `listes-vides-accord`.

## Hors périmètre
Lecture du XML (L04-T21, L04-T46) ; lecture du texte visible (L04-T13).

## Pièges
Règles du noyau comme L04-T00. Sensible (aucune écriture ne doit partir d'une pièce en écart).

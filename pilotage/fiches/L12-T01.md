## Contexte
Spec 12, `02-controles-coherence`, CC-K04 (V3-CTL-021) : « Par taux : |HT + TVA − TTC| ≤ 0,01 € ; total des écarts de la pièce ≤ 0,05 € ; au-delà : cas ARITH. » Gravité M ; la pièce ne passe pas en VERT. Tolérances = paramètres réglables (`controle.arith.tolerance_taux`, `controle.arith.tolerance_piece`), pas des valeurs légales. Cas CT-04 (83,33 + 16,67 = 100,00 puis 83,33 + 16,66 = 100,00 : OK les deux fois, aucune fausse alerte d'arrondi) et CT-05 (3 taux à 0,01 d'écart chacun : OK ; 100,00 + 20,00 contre 120,30 : ARITH, écart 0,30).

## À faire
1. `packages/noyau/src/controles/regles/arithmetique.ts` :
   - `ObjetArithmetique { piece: PieceControlee; toleranceTaux?: Centimes; tolerancePiece?: Centimes }` ;
   - `ecartsArithmetiques(piece)` → `{ parTaux: { taux; ecart: Centimes }[]; total: Centimes }` (écart en valeur absolue, lignes regroupées par taux, ordre des lignes sans effet) ;
   - `regleCCK04: RegleControle<ObjetArithmetique>` : id `CC-K04`, version 1, gravité `M`, bloque `[]`, déclencheurs `arrivee`, `continu`, `nocturne`, `a_la_demande` ; tolérance absente ou négative = exception (IMPOSSIBLE) ; ALERTE avec `ecartCentimes` = écart total dès qu'un taux dépasse sa tolérance OU que le total dépasse celle de la pièce ; `valeur` = `'ARITH'`.
2. `packages/noyau/src/controles/regles/__tests__/arithmetique.test.ts`, tests nommés : `CT-04` (deux pièces, 0 alerte), `CT-05` (OK puis ALERTE 30), `tolerance-taux-exacte-ok` (écart = tolérance), `tolerance-taux-plus-un-alerte`, `total-piece-depasse-alerte` (chaque taux dans sa tolérance, total au-delà), `tolerance-absente-impossible` (via `executerControles`), `montants-invalides` (NaN, Infinity, 1,5), `ordre-des-lignes-sans-effet`.

## Contexte
`DocumentProduit` (`documents/historique.ts`, L03-T02) porte `versionPaquet`, mais `ajouterVersion` accepte une chaîne vide. Une écriture sans version est déjà refusée (L14-T34). Les écrans internes de veille (Q01 à Q03) relèvent d'un outil interne hors de ce dépôt : le produit client ne doit exposer aucune route vers eux.

## À faire
1. Tests d'abord.
2. `historique.ts` : `ajouterVersion` refuse `versionPaquet` vide ou mal formée (même forme que celle produite par `packages/parametres/src/paquet.ts`), code `version_paquet_absente`.
3. `version-paquet-transversal.test.ts` : chaque document du jeu fictif (FEC, déclaration de TVA, déclaration, état, PV) produit par les fonctions existantes porte une version de paquet non vide.
4. `routes-internes-absentes.test.ts` : parcourt les fichiers `route.tsx` de `apps/web/src/ecrans/` et les chemins du contrat ; aucun chemin ni identifiant d'écran Q01 à Q03 ou de publication de paquet n'y figure.
5. Tests nommés : `version-paquet-vide-refusee`, `version-paquet-mal-formee-refusee`, `version-paquet-valide-acceptee`, `jeu-fictif-tous-documents-versionnes`, `aucune-route-ecran-q-cote-client`, `aucune-route-publication-paquet-cote-client`.

## Hors périmètre
Écrans Q (outil interne, hors dépôt), livraison des paquets par fichier signé (formule installée), carte « Nouvelle règle » (L22-T22).

## Pièges
Les tests existants qui construisent des documents avec une version vide doivent recevoir une version valide fictive : seulement dans les fichiers autorisés ; sinon s'arrêter et le signaler.

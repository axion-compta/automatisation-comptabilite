## Contexte
Spec 13, fichier 02, R01 : « Le `societe_id` vient de la session, jamais du texte du client ni d'un prompt ; un `societe_id` présent dans le corps ou dans un paramètre qui diffère de la session = 404 avec le même corps qu'un objet inexistant, jamais 403. » R05 : un fichier d'export est placé sous `compta/<societe_id>/…`. Tests PRI-8-01 et PRI-8-05.

## À faire
1. `packages/noyau/src/principes/etancheite.ts` :
   - classe locale `ErreurEtancheite` (`session_sans_societe`, `nom_invalide`) ;
   - `REPONSE_INTROUVABLE` : objet gelé unique `{ statutHttp: 404, code: 'introuvable' }` ;
   - `societeDeLaRequete(session { societeId }, demandee?)` : demandée absente ou égale (comparaison exacte, casse comprise) donne `{ ok: true; societeId: session.societeId }` ; différente donne `{ ok: false; reponse: REPONSE_INTROUVABLE }` ; session sans société lève l'erreur ;
   - `cheminExport(societeId, nomFichier)` donne `compta/<societeId>/<nom>` ; refuse (nom_invalide) un id ou un nom vide, contenant `/`, `\`, `..`, un caractère de contrôle, ou commençant par un point ;
   - `exportAccessible(chemin, session)` : vrai seulement si le chemin commence par `compta/<societe de la session>/`.
2. Tests nommés : `societe-de-la-session-retenue`, `autre-societe-404-meme-corps-qu-inexistant` (`toBe(REPONSE_INTROUVABLE)` dans les deux cas), `casse-differente-404`, `session-sans-societe-erreur`, `chemin-export-prefixe`, `traversee-refusee` (`../x`, `a/b`, `..`, chaîne vide, caractère nul, `.cache`), `lien-autre-societe-refuse` (préfixe `compta/A/` lu avec la session B ; préfixe `compta/AB/` lu avec la session A).

## Hors périmètre
Pas de matrice « mauvais client » (fiche bloquée L13-T50), pas de base par client, pas de lien expirant (L13-T54).

## Pièges
`compta/A` ne doit pas ouvrir `compta/AB/…` : tester le séparateur final. Aucun identifiant réel. Règles du noyau comme L01-T06. Sensible (sécurité).

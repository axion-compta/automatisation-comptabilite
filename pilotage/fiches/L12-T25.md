## Contexte
Spec 12, `01-socle-catalogue` §Garde-fou (V3-CTL-071) : avant « Valider le mois », la préparation de la TVA, un export officiel et la clôture, un seul B ouvert refuse l'action (`409 controle_bloquant_ouvert`) avec la liste des B et une phrase par B ; IMPOSSIBLE sur un B compte comme ouvert. CC-T01, CC-T02, CC-K01 à CC-K03 ne sont jamais écartables. `05-traitement-des-doutes` : « Les règles C1 à C6 ne lèvent jamais un contrôle B. » Cas CT-44 (`ecarter` sur CC-T01 : 422 `controle_non_ecartable` ; sur TVA-C01 (M) avec motif : écarté, motif tracé). `verifierAvantAction` et `ecarter` existent (L01-T20, `garde-fou.ts`) : cette fiche ajoute la traduction en réponses, sans les modifier.

## À faire
1. `packages/noyau/src/controles/reponses.ts` :
   - `reponseGardeFou(verdict)` → `null` si autorisé, sinon `{ statut: 409; corps: { code: 'controle_bloquant_ouvert'; bloquants: { regleId; objetId; messageCode: string }[] } }` ; `messageCode` = `controle.<regleId>` ; bloquants triés, sans doublon ;
   - `reponseEcart(resultat)` : `non_ecartable` → 422 `controle_non_ecartable` ; `permission_manquante` → 403 ; `reauthentification_requise` → 401 ; `motif_obligatoire`, `auteur_obligatoire`, `horodatage_anterieur` → 422 avec le même code ; succès → 200 avec la trace ;
   - `decisionParLotPeutLever(regleGravite)` → toujours `false` pour `B` (C1 à C6).
2. `packages/noyau/src/controles/__tests__/reponses.test.ts`, tests nommés : `CT-44`, `autorise-sans-corps`, `un-b-ouvert-409`, `impossible-compte-ouvert`, `bloquants-tries-sans-doublon`, `chaque-refus-a-son-statut` (table complète des 6 refus), `lot-ne-leve-jamais-un-b`, `liste-non-ecartables-inchangee` (les 5 identifiants de L01-T20, ni plus ni moins).

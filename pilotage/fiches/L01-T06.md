## Contexte
Spec 01 (moteur d'écritures), §04 : « Équilibre : somme des débits = somme des crédits par écriture, en euros, au centime. » États : BROUILLON, PROPOSÉ, VALIDÉ. Cas limites : « Écriture à une seule ligne ou à montant nul : refusée. Ligne débit et crédit renseignés : refusée. » Tout le reste du noyau comptable s'appuie sur ce modèle.

## À faire
1. `packages/noyau/src/ecritures/modele.ts` :
   - types `StatutEcriture = 'brouillon' | 'propose' | 'valide'`, `LigneEcriture { compte: string; auxiliaire?: string; libelle: string; debit: Centimes; credit: Centimes }`, `Ecriture { id: string; journal: string; date: string; statut: StatutEcriture; lignes: readonly LigneEcriture[]; numero?: string; type?: 'normale' | 'correction'; lienOriginale?: string; contrePassee?: boolean }` ;
   - classe `ErreurEcriture extends Error` avec un champ `code` ;
   - `verifierLigne(l)` : refus `ligne_double_sens` si débit et crédit sont tous deux non nuls, `ligne_nulle` si les deux sont nuls, `montant_negatif` si l'un est négatif ;
   - `verifierEquilibre(e)` → `{ equilibree: boolean; totalDebit: Centimes; totalCredit: Centimes; ecart: Centimes }` ;
   - `verifierEcriture(e)` : refus `une_seule_ligne` (moins de 2 lignes), `montant_nul` (total nul), erreurs de ligne, puis `desequilibre` avec l'écart.
2. Tests nommés : `equilibre-achat-fictif` (D 10 000 + D 1 250 / C 11 250, équilibrée), `desequilibre-un-centime` (écart 1), `une-seule-ligne-refusee`, `montant-nul-refuse`, `ligne-double-sens-refusee`, `montant-negatif-refuse`, `ordre-des-lignes-sans-effet`.

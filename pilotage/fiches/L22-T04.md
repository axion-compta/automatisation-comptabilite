## Contexte
Le code `EXONEREE_A_VERIFIER` est déclaré dans `tva/traitement.ts` mais rien ne l'utilise. Au MVP, une société qui a des ventes exonérées ou une activité mixte (une partie des ventes ouvre droit à déduction, l'autre non) n'est pas traitée : la préparation de la déclaration est bloquée et le dossier part vers l'expert. Le calcul du prorata est en V1 (L16-T43), hors de cette fiche.

## À faire
1. Tests d'abord, société fictive « mixte ».
2. `activite-mixte.ts` : `RegleControle` (forme de `controles/moteur.ts`), gravité B, `bloque: ['tva']`, déclenchée si une vente de la période porte un code exonéré ou `EXONEREE_A_VERIFIER`, ou si le profil déclare une activité mixte. Code de sortie `activite_mixte_expert`.
3. `docs/controles.csv` : une ligne `CC-T20` (exigence V3-TVA-027, gravité B, bloque `preparation_tva`, test_id égal au titre d'un test réel). Si `CC-T20` est pris sur main, prendre le premier identifiant libre et l'écrire dans le journal.
4. `textes/controles/tva.ts` : texte de `CC-T20` (vouvoiement, explique le blocage et le renvoi vers l'expert, aucun conseil fiscal).
5. Tests nommés : `societe-mixte-declaration-bloquee`, `vente-exoneree-declaration-bloquee`, `exoneree-a-verifier-bloquee`, `ventes-taxables-seules-aucun-blocage`, `aucune-ecriture-produite`, `texte-cc-t20-present`.

## Hors périmètre
Calcul du prorata, régularisations (V1), écrans, échanges dans l'UE (L22-T05).

## Pièges
Le profil « activité mixte » est lu en argument, jamais recherché dans le module. Fiche sensible : relecture Opus, fusion par Will seul.

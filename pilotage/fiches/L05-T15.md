## Contexte
Spec 05, fichier 03 §5 : chaque message finit par une des 6 issues (réponse, action proposée, navigation, question, refus utile, escalade). La réponse peut finir par UNE action suivante proposée, jamais lancée seule. Chaque erreur des 16 codes donne un message et un bouton (CHT-054). Les étapes viennent des appels d'outils réels (CHT-044).

## À faire
1. `packages/noyau/src/chat/issues.ts` (sur des événements de forme `{ id; type; ... }`, types de L05-T00) :
   - `verifierTour(evenements)` → `{ valide: true; issue } | { valide: false; motif }` ; motifs : `sans_debut`, `sans_fin`, `fin_pas_derniere`, `deux_fins`, `id_non_croissant`, `issue_inconnue`, `proposition_sans_issue_action` (une proposition présente mais issue autre que `action_proposee` ou `question`), `vide` ;
   - `issuePourErreur(code)` : table fermée des 16 codes vers `refus_utile`, `escalade` ou `reponse` ; code inconnu = `ErreurChat('parametre_invalide')` ;
   - `etapesDepuisAppels(appels: { outil; dureeMs; issue }[])` → étapes `{ outil; dureeMs; etat }`, dans l'ordre des appels ; durée négative ou non entière = `parametre_invalide`.
2. Tests nommés : `tour-complet-valide`, `chaque-motif-invalide` (un cas par motif), `ids-non-croissants`, `une-seule-issue`, `seize-codes-ont-une-issue`, `code-inconnu-refuse`, `etapes-dans-l-ordre`, `etapes-duree-invalide` (NaN, -1, 1.5, Infinity), `liste-vide`.

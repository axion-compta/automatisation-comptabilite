## Contexte
Spec 10, fichier 03, règle 3 : pour un paiement P sur une facture de TTC T, TVA exigible = arrondi(TVA × P / T) au centime, par taux ; le DERNIER paiement solde exactement le compte d'attente. Fichier 04, point 2 : même règle pour la base. Cas V05 : TVA 200,00, TTC 2 200,00, paiements 733,33 / 733,33 / 733,34 → 66,67 / 66,67 / 66,66. Cas V07 : 850,00 sur 1 700,00 → 50,00 (base 500,00) et 50,00 (base 250,00).

## À faire
1. `packages/noyau/src/ventes/encaissement.ts` :
   - `partEncaissee({ ttcFacture, dejaEncaisse, paiement, parTaux: { tauxPdb; tvaInitiale; baseInitiale; tvaDejaExigible; baseDejaExigible }[] })` → `{ parTaux: { tauxPdb; tva; base }[]; dernier: boolean; tropPercu: Centimes }` ;
   - arrondi SANS division : `repartir(montant, [P, T - P])[0]` de `../argent/index.js` (plus grand reste ; à égalité, le premier indice) ; résultat plafonné au reste en attente du taux ;
   - `dernier` vrai si `dejaEncaisse + paiement >= ttcFacture` : la part = initiale − déjà exigible, pour la TVA et pour la base ; `tropPercu` = excédent (jamais un produit) ;
   - refus `ErreurVente` : `paiement_invalide` (≤ 0, non entier, NaN, Infinity), `ttc_invalide` (≤ 0), `deja_solde` (`dejaEncaisse >= ttcFacture`), `deja_exigible_incoherent` (déjà exigible > initiale).
2. Tests nommés : `v03-paiement-total`, `v04-deux-moities` (100,00 puis 100,00 ; bases 1 000,00 et 1 000,00), `v05-trois-paiements-le-dernier-solde`, `v07-deux-taux`, `trop-percu-isole` (2 250,00 sur 2 200,00 → 50,00), `paiement-invalide-refuse` (0, -1, 1.5, NaN, Infinity), `ttc-nul-refuse`, `deja-solde-refuse`, `ordre-des-taux-sans-effet`, `somme-exacte-boucle` (1 000 suites de 1 à 6 paiements à graine fixe : Σ TVA = TVA initiale et Σ base = base initiale, pour chaque taux).

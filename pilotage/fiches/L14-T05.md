## Contexte
Spec 14, `01` partie C, règle 2 : un seul seau de jetons par identifiant d'accès ; si plusieurs bases clientes demandent, le seau sert les clients à tour de rôle (une demande par client, puis le suivant). Le composant commun ne voit que le SIREN ou SIRET demandé (donnée publique) et un identifiant opaque de file : aucune donnée client ; la réponse retourne dans la base du client demandeur. Test S3 : 2 clients fictifs, 500 SIREN chacun, lots de 20 (HYPOTHÈSE) : 50 requêtes, au plus 30 sur toute fenêtre de 60 s, 3 minutes simulées au plus, écart entre les deux clients d'au plus 1 requête à tout instant, 0 réponse croisée.

## À faire
1. `packages/noyau/src/sources/sirene-partage.ts` (utilise `planifier`/`peutEnvoyer` de `./sirene-planif.js`, classe locale `ErreurPartage`) :
   - `sirenValide(s)` : 9 chiffres et clé de Luhn ; `siretValide(s)` : 14 chiffres et clé de Luhn ;
   - `DemandeFile { file: string /* identifiant opaque */; numero: string }` ; `preparerFile(demandes)` : refus `numero_invalide` (avec le numéro), doublons retirés DANS une même file seulement ;
   - `tourDeRole(demandes, debut, o)` → `{ file; lot: string[]; a: number }[]` : un lot par file à tour de rôle (ordre des files = ordre de première apparition), quota respecté ;
   - `router(reponses: { file; numero; corps }[], files)` → `Map<file, …>` : une réponse dont la file est inconnue = refus `file_inconnue` (jamais livrée ailleurs).
2. Tests nommés : `deux-clients-cinquante-requetes`, `ecart-au-plus-une-requete-a-tout-instant`, `quota-respecte-sur-toute-fenetre`, `trois-minutes-au-plus`, `aucune-reponse-croisee`, `siren-invalide-refuse` (clé de Luhn fausse), `doublon-garde-entre-deux-clients` (même SIREN demandé par deux files : deux entrées, une par file).

## Hors périmètre
Pas de cache (L14-T06). Aucune donnée client dans ce module : seulement numéro et identifiant opaque. Aucun appel réseau.

## Pièges
Règles du noyau comme L14-T02. Clé de Luhn sans division : parcourir les chiffres, doubler un chiffre sur deux, soustraire 9 au-delà de 9 ; contrôle final par `% 10` (le modulo est permis, la division non). Cas limites exigés : numéro avec espaces (refusé : la normalisation est faite avant), chaîne vide, une seule file, file vide parmi d'autres, lettres dans le numéro, 8 et 10 chiffres.

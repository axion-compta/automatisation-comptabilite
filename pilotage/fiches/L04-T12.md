## Contexte
Spec 04, fichier 03 §3 : le lecteur B utilise des « expressions pour SIREN avec clé de Luhn, n° de TVA intracommunautaire avec clé ». Ces fonctions servent aussi à reconnaître le fournisseur (fichier 06 §3) et le client facturé (L04-T20).

## À faire
1. `packages/noyau/src/pieces/lecture/identifiants.ts` :
   - `normaliserIdentifiant(texte)` : retire blancs (dont U+00A0, U+202F), points, tirets ; majuscules ;
   - `sirenValide(s)` : 9 chiffres et clé de Luhn ; `siretValide(s)` : 14 chiffres et clé de Luhn (cas particulier non traité : renvoie faux, l'appelant marque « à vérifier ») ;
   - `cleTvaFrance(siren)` → nombre de 0 à 96 : `(12 + 3 × (siren mod 97)) mod 97` ;
   - `analyserTva(texte)` → `{ statut: 'valide'; pays: 'FR'; siren: string }` ou `{ statut: 'cle_fausse' | 'format_non_verifie' | 'illisible'; pays?: string }` : `FR` + 2 chiffres + SIREN valide = clé vérifiée ; `FR` + clé à lettres = `format_non_verifie` ; autre préfixe de 2 lettres suivi de 2 à 12 caractères alphanumériques = `format_non_verifie` ; sinon `illisible`.
2. Tests nommés (SIREN fictifs construits par une fonction du test qui calcule la clé de Luhn) : `siren-valide`, `siren-cle-fausse`, `siren-mauvaise-longueur` (8, 10 chiffres, vide, lettres), `siret-valide`, `tva-fr-cle-calculee`, `tva-fr-cle-fausse`, `tva-autre-pays-format-non-verifie`, `normalisation-espaces-points`.

## Hors périmètre
Interrogation d'un registre public (réseau interdit dans le noyau).

## Pièges
Aucun SIREN réel dans les tests : préfixe inventé (ex. `12345678`) et clé calculée. `%` permis, `/` interdit. Règles du noyau comme L04-T00.

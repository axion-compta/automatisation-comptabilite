## Contexte
Spec 02, fichier 04, étape 6 : « IBAN haché connu → alias exact → alias préfixe → similarité (≥ 0,85, proposition seulement) → IA (proposition seulement, sur texte pseudonymisé) » ; étape 7 : « La catégorie fournie par la banque est stockée pour information et pèse 0 dans tout score. » Cas limite : même enseigne pour deux sociétés différentes : l'IBAN départage. Test T04-3 : 3 libellés différents d'un même fournisseur → 1 contrepartie, 3 alias.

## À faire
1. `packages/noyau/src/banque/libelles/contrepartie.ts` :
   - `reconnaitre(ligne: { libelleNormalise; ibanHache? ; categorieBanque? }, connues: { contreparties: { id; ibanHaches: string[] }[]; alias: Alias[]; reglesJamais }, reglage: { seuilSimilaritePb })` → `{ contrepartieId?; par: 'iban' | 'alias_exact' | 'alias_prefixe' | 'similarite' | 'aucune'; certitude: 'connue' | 'proposee' | 'aucune'; codeRaison }` ;
   - `iban`, `alias_exact`, `alias_prefixe` (alias ACTIF et non bloqué, L02-T26) → `connue` ; `similarite` → `proposee` (jamais `connue`) ; préfixe : le plus long gagne ; deux contreparties ex aequo → `aucune` (jamais de choix silencieux) ;
   - `categorieBanque` est ignorée (test qui le prouve : même résultat avec et sans).
2. Tests nommés : `iban-prioritaire-sur-alias`, `alias-exact`, `prefixe-le-plus-long`, `similarite-seulement-proposee`, `ex-aequo-aucune`, `franchise-departagee-par-iban`, `categorie-banque-sans-effet` (T04-6), `t04-3-trois-alias-une-contrepartie`.

## Hors périmètre
Passe IA (bloquée : L02-T65). Création des contreparties et des alias en base (bloquée : L02-T62).

Cas limites exigés : libellé vide (`aucune`), listes vides, alias proposé (non actif) ignoré, alias bloqué par « jamais ça » ignoré, seuil invalide (`NaN`, hors 0 à 10 000 : erreur). L'ordre des listes en entrée ne change pas le résultat (test). Règles du noyau.

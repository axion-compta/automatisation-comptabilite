## Contexte
Débloquée par la décision de Will du 07/11/2026 : J3a donné avec quatre conditions (données FICTIVES seulement ; fiche sensible relue par Opus ; aucune mise en production sans le feu vert J10 ; ce qui exige le vrai schéma de la console s'écrit contre une interface et un faux serveur). L'identité, la session et la réauthentification restent fournies par la console (Keycloak, module C4, D29 au 21/11/2026) : ici elles arrivent par un PORT, simulé en test ; le module ne calcule jamais lui-même qu'une personne s'est réauthentifiée.
Spec 03, §04 : préparer une période (201), valider une déclaration (réauth, sinon 401 `reauthentification_requise`), enregistrer l'accusé déposé par le client ; `Idempotency-Key` sur chaque écriture ; aucune route de transmission. Cette fiche écrit le SERVICE de ces trois routes (statut HTTP et corps rendus), contre les interfaces de L03-T52 ; le contrat oRPC et le branchement sont une fiche de suite (voir Hors périmètre), parce que contrat + `openapi.json` + serveur + tests dépassent 300 lignes (modèle mesuré : L05-T38, trois routes, ≈ 420 lignes).
Écart de spec relevé : §04 de la spec 03 rend 422 quand un contrôle B est ouvert ; la spec 12 (V3-CTL-071) et `reponseGardeFou` (L12-T25, fait) rendent 409 `controle_bloquant_ouvert`. La fiche suit le code commun déjà livré (409) ; 422 est gardé pour une déclaration dont les formules bloquent (`ligne_absente`, `base_negative`, L03-T27). Point signalé à Will dans le journal.
Symboles réutilisés : `DepotPiecesEnregistrees.parId` (L04-T36) ; `DepotDocumentsProduits`, `DepotTva` (L03-T52) ; `verifierAvantAction` (L01-T20) ; `reponseGardeFou` (L12-T25) ; `ajouterVersion`, `valider` via le dépôt (L03-T02) ; `etatMention` (L03-T03) ; `changerStatut` via le dépôt (L03-T21) ; `ResultatFormules` (L03-T27) ; `VerdictNiveau` (L06-T09) ; type de réponse `DeclarationTva` de `packages/contrat/src/domaines/tva.ts` (L03-T32, import de type seulement). Aucun fichier commun touché (`routes.ts`, `app.ts`, `openapi.json`).

## Contexte
Spec 05, fichier 07 §1 : chaque agent est une étape idempotente (clé `piece_id:etape:version`) ; rejouée, elle rend le même résultat sans second effet. États : recue, lue_a, lue_b, comparee, classee, tva_qualifiee, controlee, proposition_prete ; sorties : a_verifier, desaccord, en_attente, refusee. Le CODE choisit l'étape suivante ; le modèle ne choisit que le parcours d'un cas atypique parmi une liste fermée donnée par le code. Bornes : un nombre maximal d'étapes et de reprises par pièce ; 100 % des pièces finissent dans un état final.

## À faire
1. `packages/noyau/src/agents/superviseur.ts` (types `ETAPES_PIECE`, `SORTIES_PIECE` de L05-T00) :
   - `etapeSuivante(etat, resultat: { issue: 'ok' | 'a_verifier' | 'desaccord' | 'en_attente' | 'refusee' | 'atypique'; parcours? })` ; `atypique` : `parcours` doit être dans `parcoursPermis` (argument), sinon `a_verifier` ;
   - `cleEtape(pieceId, etape, version)` ; `class Superviseur` en mémoire : `executer(pieceId, etape, version, faire: () => R)` appelle `faire` UNE fois par clé, rend le résultat gardé ensuite ;
   - `derouler(pieceId, agents, { maxEtapes, maxReprises })` : enchaîne jusqu'à un état final ; une erreur levée par un agent compte une reprise ; dépassement d'une borne = `en_attente` ;
   - `estFinal(etat)`.
2. Tests nommés : `parcours-nominal`, `ordre-fixe-des-etapes`, `rejeu-sans-second-effet` (compteur d'appels = 1), `version-differente-rejouee`, `atypique-dans-la-liste`, `atypique-hors-liste-a-verifier`, `reprises-bornees`, `etapes-bornees`, `cent-deroulements-aleatoires-finissent` (graine fixe, agents qui échouent au hasard : 100 % finaux), `bornes-invalides` (0, -1, 1.5, NaN, Infinity).

## Contexte
Spec 15, TB-R8 (décision D21 : le mois reste modifiable, avec trace). Les instantanés gardent la valeur du `compteur_ecritures` au calcul ; chaque lecture compare cette version au compteur courant et recalcule s'ils diffèrent : une lecture ne rend jamais un chiffre périmé. Une écriture validée, corrigée, contre-passée ou dont la validation est annulée invalide les instantanés qui couvrent sa date. Si la période est déjà déclarée, une carte « écriture antidatée sur une période déclarée » est ouverte ; la période déposée n'est pas modifiée.

## À faire
1. `instantanes.ts` :
   - `Instantane { periode: Periode; bloc: CodeBloc; versionEcritures: number; invalide: boolean }` ;
   - `doitRecalculer(instantane, versionCourante)` : vrai si `invalide` ou si les versions diffèrent ; version négative, non entière ou non finie = erreur ;
   - `EvenementEcriture = 'validee' | 'corrigee' | 'contre_passee' | 'validation_annulee'` ; `appliquerEvenement(instantanes, { type; date })` → nouvelle liste (entrée non modifiée) où chaque instantané dont la période contient `date` (bornes incluses) passe `invalide = true` ; type inconnu = erreur ;
   - `carteAntidatee(date, periodesDeclarees: Periode[])` : vrai si la date tombe dans une période déclarée.
2. Tests nommés : `version-egale-pas-de-recalcul`, `version-differente-recalcul`, `invalide-recalcul`, `evenement-invalide-seulement-les-periodes-couvrantes`, `bornes-incluses`, `entree-non-modifiee` (`Object.freeze` sur l'entrée), `carte-antidatee-periode-declaree`, `valeurs-invalides-refusees` (`-1`, `1.5`, `NaN`, type inconnu, date invalide).

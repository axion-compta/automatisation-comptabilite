## Contexte
Débloquée par les décisions de Will du 07/11/2026 : D43 (fournisseurs d'IA de l'UE en liste fermée modifiable, passerelle unique), D57 (BROUILLON de demande seulement, jamais d'envoi automatique depuis la boîte du client : Q3 n'est donc plus un préalable) et J3a donné, avec quatre conditions : données FICTIVES seulement ; fiche sensible relue par Opus ; aucune production sans le feu vert J10 ; on écrit contre une INTERFACE (un rédacteur injecté), jamais contre un modèle réel.
Spec 02, fichier 07, règle 5 : « « Où les trouver ? » : l'IA indique l'espace client probable du fournisseur et prépare un brouillon d'e-mail de demande (jamais envoyé seul, V3-PLA-081). » D26 : les brouillons de demande de pièces aux FOURNISSEURS restent dans le périmètre (les relances de clients, non). V3-AGT-013 : 100 % des brouillons citent la pièce attendue et le montant exacts.
Briques : `repondre` rend l'effet `brouillon_a_preparer` pour `ou_les_trouver` (L02-T44) ; `pseudonymiser` et `retablir` (L02-T25) ; `formater` (argent). La route `POST /banque/demandes/{id}/brouillon-email` (contrat, serveur) et le branchement sur `apps/serveur/src/ia/passerelle.ts` sont hors fiche.

## À faire
1. Tests d'abord dans `__tests__/brouillon.test.ts` (faux rédacteur qui capture son entrée ; société, fournisseurs et personnes inventés, e-mails en @exemple.fr, IBAN à clé fausse).
2. `brouillon.ts` exporte :
   - `type RedacteurBrouillon = (entree: { fournisseur: string; pieces: { date: string; montant: string; libelle: string }[] }) => Promise<{ texte: string; espaceClient?: string }>` ;
   - `preparerBrouillon(demande: DemandeSuivie, contexte: { fournisseur: { nom: string; domaines: readonly string[] }; lignes: readonly { id: string; date: string; montant: Centimes; libelle: string }[]; personnes: readonly string[]; rediger: RedacteurBrouillon })` → `Promise<Brouillon>` ;
   - `Brouillon` = `{ etat: 'brouillon'; envoye: false; objet: string; corps: string; pieces: { date; montant: Centimes }[]; espaceClient?: string; source: 'ia' | 'modele' }`.
3. Règles :
   - refus `demande_non_concernee` si `demande.reponse !== 'ou_les_trouver'` ; refus `ligne_inconnue` si une `ligneIds` manque dans `lignes` ;
   - libellés passés par `pseudonymiser` (IBAN, cartes, `personnes`) avant l'appel ; texte rendu par `retablir` ;
   - le bloc des pièces (date, montant `formater`) est écrit par le code, jamais par l'IA ; le texte de l'IA n'est qu'une formule autour ;
   - texte de l'IA contenant un montant absent de la demande, un jeton non rétabli, ou rédacteur en panne → texte de repli fixe (`source: 'modele'`), brouillon toujours rendu ;
   - `espaceClient` gardé seulement si URL `https:` dont l'hôte est un des `domaines` du fournisseur (ou un sous-domaine) ; sinon absent.
4. Aucune fonction d'envoi exportée ; le brouillon est une copie à coller au MVP.
5. Tests nommés : `brouillon-cite-chaque-piece-et-montant`, `jamais-envoye`, `aucun-export-d-envoi`, `aucun-iban-ni-nom-vers-l-ia`, `montant-invente-texte-de-repli`, `redacteur-en-panne-texte-de-repli`, `espace-client-hors-domaine-retire`, `espace-client-http-retire`, `demande-non-concernee-refusee`, `ligne-inconnue-refusee`.
6. Journal `pilotage/journal/L02-T67.md` (10 lignes au plus), statut `fait`.

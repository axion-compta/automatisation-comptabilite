## Contexte
Spec 06, `03-roles-permissions.md` §2, règles 1 à 3 : chaque route vérifie la permission ET l'objet au serveur ; le chat, la voix et les tâches de fond passent par la même vérification (ROL-003) ; le rôle « comptable » de la console ne donne aucun droit tant que le module n'a pas reçu `compta-*` (ROL-002) ; aucune identité du personnel Axion ne peut déposer, saisir, valider, lever ou clôturer (PLA-140, PLA-151). Cas C06, C07, C09, C17, C24 de `08-cas-de-test.md`.

## À faire
1. `packages/noyau/src/securite/autoriser.ts` : `autoriser(contexte, action, objet?)` → `{ permis: true } | { permis: false; raison: Raison }`, avec :
   - `contexte = { role: Role; permissions: readonly string[]; demande5: boolean; separationTaches: boolean; personneId: string; mode?: { id: string; actionsRetirees: readonly Action[]; raison: Raison }; perimetreRespecte?: boolean }` ;
   - `objet = { auteurId?: string; gravite?: 'majeur' | 'bloquant' }` ;
   - ordre fixe des refus : personnel Axion + action d'écriture → `personnel_axion_lecture_seule` ; permission de l'action absente des `permissions` (chaînes inconnues ignorées) → `role_lecture` si le rôle est `lecture`, sinon `role_insuffisant` ; case `N` → même règle ; case `M` → `perimetre_expert` si `perimetreRespecte` n'est pas vrai ; case `sep` + `separationTaches` + `objet.auteurId === personneId` → `separation_taches` ; action retirée par le mode → `mode.raison` ; `lever_majeur` demandé sur un objet `bloquant` → traité comme `lever_bloquant`.
2. Tests nommés : `lecture-refuse-six-ecritures` (C06 : 6 refus `role_lecture`), `utilisateur-leve-majeur-pas-bloquant` (C07), `personnel-axion-cinq-ecritures-refusees` (C09), `comptable-sans-permission-rien` (C17 : 14 refus), `saisie-seule-cloture-refusee-avec-raison` (C24), `separation-auteur-refuse`, `separation-inactive-permis`, `separation-autre-auteur-permis`, `permission-inconnue-ignoree`, `ordre-des-permissions-sans-effet`, `permissions-vides-tout-refuse` (liste vide : 14 refus).

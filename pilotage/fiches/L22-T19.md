## Contexte
Les colonnes `Montantdevise` et `Idevise` existent (L01-T18, L03-T08) mais `lignesFec` les laisse toujours vides, et `LigneEcriture` (`ecritures/modele.ts`) n'a pas de devise. Les taux viennent de `change/taux.ts` (L13-T26) avec leur origine.

## À faire
1. Tests d'abord, jeu devise fictif (USD et CHF).
2. `modele.ts` : champ optionnel `devise?: { code: string; montant: Centimes; origineTaux: 'bce' | 'saisi' | 'parite_fixe' | 'indicatif' }` sur `LigneEcriture` ; code ISO à 3 lettres majuscules vérifié ; montant signé (négatif au crédit).
3. `lignes.ts` : `idevise` = code ISO et `montantDevise` = montant signé formaté par `formaterMontantFec` ; ligne en euros ou sans devise : deux colonnes vides (sortie actuelle inchangée).
4. `controles-structure.ts` : nouvel écart si une ligne porte `origineTaux: 'indicatif'`, ou un code ISO mal formé, ou un montant en devise sans code.
5. Banc `banc-devise.test.ts` : colonnes égales aux attendus de `jeux-devise.ts` ; aucun taux indicatif présent dans le fichier.
6. Tests nommés : `euro-colonnes-vides`, `usd-code-iso-et-montant-signe`, `credit-montant-devise-negatif`, `taux-indicatif-ecart`, `code-iso-invalide-ecart`, `banc-devise-colonnes-attendues`.

## Hors périmètre
Conversion de la TVA (L22-T12), écarts de change, import d'un FEC en devise.

## Pièges
Le champ est optionnel : les jeux existants et la production (L22-T13) ne changent pas. Fiche sensible : relecture Opus, fusion par Will seul.

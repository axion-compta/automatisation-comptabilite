## Contexte
Spec 08, fichier 02 §5 : `GET /api/compta/v1/sante` vérifie base joignable, migrations à jour (numéro attendu = numéro lu), file joignable, coffre ouvert ; réponse `{etat, version, migration}`, AUCUNE donnée de client ; lue par la console et par la sonde. Fichier 05 §2 : sonde de santé chaque minute, alerte après 3 échecs de suite (réglage L08-T02). Cette fiche écrit seulement le calcul pur ; la route réelle est bloquée (L08-T42) et la route du serveur en mémoire vient en L08-T35.

## À faire
1. `packages/noyau/src/exploitation/sante.ts` :
   - `type Verification = { base: boolean; migrationAttendue: number; migrationLue: number | null; file: boolean; coffre: boolean }` ;
   - `CAUSES = ['base_injoignable', 'migration_en_retard', 'migration_en_avance', 'migration_illisible', 'file_injoignable', 'coffre_ferme'] as const` ;
   - `etatSante(v, { version: string; image: string })` → `{ etat: 'ok' | 'degrade' | 'panne'; version; image; migration: number | null; causes: Cause[] }` : base injoignable ou migration illisible = `panne` ; migration en retard, file injoignable ou coffre fermé = `degrade` ; migration EN AVANCE (lue > attendue : image N-1 sur schéma N) = `ok` avec la cause `migration_en_avance` notée (compatibilité N et N-1, fichier 04 §2) ; causes triées dans l'ordre de `CAUSES`, sans doublon ;
   - `version` : forme `^\d+\.\d+\.\d+$`, sinon `ErreurExploitation('version_invalide')` ; `image` : `sha256:` suivi de 64 hexadécimaux minuscules, sinon `empreinte_invalide` ; `migrationAttendue` et `migrationLue` entiers >= 0 (`verifierEntier`) ;
   - `enregistrerSonde(etatSonde, resultat: 'ok' | 'degrade' | 'panne', echecsMax)` → `{ echecsConsecutifs; alerte: boolean }` : `degrade` et `panne` comptent comme échec ; un `ok` remet à 0 ; `alerte` vraie UNE seule fois, quand le compteur ATTEINT `echecsMax` (pas aux échecs suivants) ; `echecsMax` entier >= 1.
2. Tests nommés : `tout-va-bien-ok`, `base-injoignable-panne`, `migration-en-retard-degrade`, `migration-en-avance-ok-avec-cause`, `aucune-donnee-de-client` (les clés du résultat sont exactement `etat`, `version`, `image`, `migration`, `causes`), `version-et-image-invalides-refusees` (`1.2`, `v1.2.3`, `sha256:ABC…`, empreinte de 63 caractères), `alerte-au-troisieme-echec-seulement` (échec, échec, échec : alerte ; quatrième échec : pas de nouvelle alerte ; ok puis 3 échecs : nouvelle alerte), `entiers-invalides-refuses` (NaN, Infinity, -1, 1.5 pour les migrations et `echecsMax` 0).

## Hors périmètre
Appels réels à la base, à la file et au coffre (L08-T42, bloquée). Envoi de l'alerte (L08-T08 et L08-T43).

## Pièges
Règles du noyau comme L08-T00. Aucun nombre d'échecs écrit en dur : `echecsMax` est un argument. Aucun nom d'hôte, de client ni de base dans le résultat. Le mot « santé » dans les noms de fichiers est écrit sans accent (`sante.ts`).

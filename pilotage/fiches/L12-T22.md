## Contexte
Spec 12, `04-tva-cas-particuliers` §1, comptes 409100 (avances et acomptes versés), 401xxx, 445660, 512001. Avec facture d'acompte ET paramètre `tva.acompte_verse_deductible` validé : D 409100 HT ; D 445660 TVA / C 512001 TTC ; puis à la facture finale D 401xxx / C 409100 HT ; C 445660 TVA. Sans facture d'acompte : D 409100 TTC / C 512001 TTC, aucune TVA ; à la facture finale, D 401xxx / C 409100 TTC. Cas CT-33 (acompte 1 200,00 sans facture d'acompte puis facture 3 000,00 HT + 600,00 : 600,00 déduits à la facture ; 409100 à 0,00 ; 401xxx reste 2 400,00). Paramètre non validé avec facture d'acompte = refus codé (CC-T18 reste ouvert).

## À faire
1. `packages/noyau/src/controles/cas-particuliers/acompte-verse.ts` :
   - `ecrituresAcompteVerse({ ttc: Centimes; tva: Centimes; factureAcompte: boolean; parametre: ParametreLu; comptes: { avance; tvaDeductible; banque }; date; journal })` → `{ etat: 'propose'; ecriture } | { etat: 'refuse'; code: 'parametre_non_valide' }` ;
   - `imputationAcompte({ acompte: { ttc; tva; avecTva: boolean }; comptes: { fournisseur; avance; tvaDeductible }; date; journal })` → écriture proposée qui solde le compte d'avance ;
   - toutes les écritures au statut `propose`, vérifiées par `verifierEcriture` (L01-T06).
2. `packages/noyau/src/controles/cas-particuliers/__tests__/acompte-verse.test.ts`, tests nommés : `CT-33` (soldes finaux 409100 = 0, 401xxx = 2 400,00 via `balance` de L01-T11), `avec-facture-d-acompte`, `parametre-a-verifier-refuse`, `avance-soldee-dans-les-deux-cas`, `tva-superieure-au-ttc-exception`, `montants-invalides`, `jamais-validee`, `equilibre-1000-cas` (graine fixe).

## Hors périmètre
Acompte reçu d'un client (lot 10, L10-T08). Détection (L12-T20).

## Pièges
Règles du noyau comme L01-T06 : montants en `Centimes` via `packages/noyau/src/argent`, ni `/`, ni littéral décimal, ni `Math.round`, ni `parseFloat`, ni `toFixed`. Stryker (seuil 80 %) porte sur tout le noyau : chaque branche doit être tuée par un test. Ne pas toucher `packages/noyau/src/index.ts` ni `controles/moteur.ts` (imports par chemin relatif). Aucun taux, seuil, délai ni date légale dans `src` (garde:litteraux, D31) : tout seuil ou tolérance arrive en argument ou dans un `ParametreLu` (L12-T00) ; paramètre absent = `IMPOSSIBLE`, jamais OK (PRI-007). Le noyau ne contient aucun texte affiché : seulement des codes. Montants et seuils des tests INVENTÉS ou repris des cas fictifs de la spec ; noms et SIREN fictifs seulement. TVA : chemin sensible (fusion après relecture Opus et double relecture argent). Aucun taux de TVA ni pourcentage légal dans src : taux en points de base et parts déductibles viennent d'un `ParametreLu` ; un paramètre au statut autre que `valide` rend la ligne `A_VERIFIER` (donc CC-T02, L12-T09), jamais une estimation. Comptes (445660, 445800, 275000…) en argument, jamais en dur. Cas limites exigés dans les tests : montant NaN, Infinity, non entier (1,5) et négatif là où il est interdit = exception codée (le moteur la change en `IMPOSSIBLE`) ; liste vide ; objets reçus dans l'ordre inverse (même résultat) ; écart d'exactement un centime de chaque côté de la tolérance. Chaque test doit rougir si l'on casse la branche qu'il couvre (inverser une comparaison, retirer un cas).

## Contexte
Spec 15, TB-R2 : trois vues `mois`, `exercice`, `depuis_debut`, toutes bornées par l'exercice choisi (exercice du 01/04 au 31/03 accepté). Comparaison à l'exercice précédent sur la MÊME durée (pour `depuis_debut` : mêmes jours depuis l'ouverture). Le service accepte une période libre (jour, semaine) ; l'écran n'expose que les trois vues (point T1, recommandation retenue). Cas limite : comparaison `vide` « pas d'exercice précédent » SEULEMENT s'il n'existe pas ; exercice de durée différente de 12 mois comparé sur la même durée.

## À faire
1. `periodes.ts` (dates par `../interface/dates.js`) :
   - `ExerciceBorne { id; debut; fin }` ; `periodeDeVue(vue, exercice, jour)` : `mois` = mois civil de `jour` coupé aux bornes de l'exercice ; `exercice` = bornes de l'exercice ; `depuis_debut` = du début de l'exercice à `jour` ; `jour` hors exercice = erreur `jour_hors_exercice` ;
   - `periodeLibre(debut, fin, exercice)` : refus `ordre_inverse` si fin avant début, `hors_exercice` si une borne sort de l'exercice ;
   - `periodeComparaison(periode, exercice, precedent?)` → `{ debut; fin } | { vide: 'pas_d_exercice_precedent' }` : même décalage en jours depuis l'ouverture et même nombre de jours, coupé à la fin de l'exercice précédent si celui-ci est plus court (indiqué par `tronquee: true`) ;
   - classe `ErreurPeriode` avec `code`.
2. Tests nommés : `vue-mois-coupee-aux-bornes`, `vue-exercice-decale-avril-mars`, `depuis-debut-jusqu-au-jour`, `jour-hors-exercice-refuse`, `periode-libre-ordre-inverse-refusee`, `comparaison-meme-duree`, `comparaison-exercice-precedent-court-tronquee` (exercice précédent de 6 mois), `sans-precedent-vide`, `dates-invalides-refusees` (`''`, `'2026-02-30'`).

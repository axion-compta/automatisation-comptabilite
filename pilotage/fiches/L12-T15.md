## Contexte
Spec 12, `03-controles-tva`, CC-T08 (V3-TVA-025) : « Fiche véhicule obligatoire (genre de la carte grise, tourisme ou utilitaire). Carburant : `tva.carburant_tourisme_pct`, `tva.carburant_utilitaire_pct` ; achat, location, entretien, péage d'un véhicule de tourisme : selon paramètre. Véhicule inconnu → `A_VERIFIER`. Sources : CGI, article à relever, à vérifier. » M ; via CC-T02. Cas CT-25 (gazole 72,40 TTC dont 12,07 de TVA, véhicule de tourisme, part de TEST 8 000 points : 9,66 déduits (12,07 × 80 % = 9,656), charge 62,74 ; péage 12,60 dont 2,10 : 0,00 déduit, charge 12,60 ; plein sans véhicule : B via CC-T02).

## À faire
1. `packages/noyau/src/controles/regles/vehicules.ts` :
   - `Vehicule { id; genre: 'tourisme' | 'utilitaire' }` ; `DepenseVehicule { nature: 'carburant' | 'achat' | 'location' | 'entretien' | 'peage'; ttc: Centimes; tva: Centimes; vehiculeId?: string }` ;
   - `ParametresVehicule { carburantTourisme: ParametreLu; carburantUtilitaire: ParametreLu; autresTourisme: ParametreLu }` (clé du dernier : nom proposé `tva.vehicule_tourisme_autres_pct`) ;
   - `traiterDepenseVehicule(d, vehicules, p, arrondi)` → `{ code; deduit: Centimes; charge: Centimes }` : véhicule absent ou inconnu = `A_VERIFIER`, 0 déduit ; part via `pourcentage` (mode d'arrondi en argument, pas de valeur par défaut) ; `charge = ttc − deduit` ; utilitaire hors carburant = part du paramètre utilitaire ou `A_VERIFIER` si absent ;
   - `regleCCT08` : id `CC-T08`, version 1, gravité `M`, bloque `[]`, déclencheurs `arrivee`, `continu`, `a_la_demande` ; `A_VERIFIER` = ALERTE.
2. `packages/noyau/src/controles/regles/__tests__/vehicules.test.ts`, tests nommés : `CT-25` (les trois dépenses), `utilitaire-carburant`, `parametre-a-verifier`, `deduit-plus-charge-egal-ttc` (1 000 cas tirés à graine fixe), `arrondi-explicite` (demi-supérieur contre inférieur sur 9,656), `vehicule-inconnu`, `part-hors-bornes-exception`, `tva-superieure-au-ttc-exception`, `montants-invalides`.

## Hors périmètre
Fiche véhicule (saisie et stockage : lot 11 ou profil). Indemnités kilométriques (lot 11).

## Pièges
Règles du noyau comme L01-T06 : montants en `Centimes` via `packages/noyau/src/argent`, ni `/`, ni littéral décimal, ni `Math.round`, ni `parseFloat`, ni `toFixed`. Stryker (seuil 80 %) porte sur tout le noyau : chaque branche doit être tuée par un test. Ne pas toucher `packages/noyau/src/index.ts` ni `controles/moteur.ts` (imports par chemin relatif). Aucun taux, seuil, délai ni date légale dans `src` (garde:litteraux, D31) : tout seuil ou tolérance arrive en argument ou dans un `ParametreLu` (L12-T00) ; paramètre absent = `IMPOSSIBLE`, jamais OK (PRI-007). Le noyau ne contient aucun texte affiché : seulement des codes. Montants et seuils des tests INVENTÉS ou repris des cas fictifs de la spec ; noms et SIREN fictifs seulement. TVA : chemin sensible (fusion après relecture Opus et double relecture argent). Aucun taux de TVA ni pourcentage légal dans src : taux en points de base et parts déductibles viennent d'un `ParametreLu` ; un paramètre au statut autre que `valide` rend la ligne `A_VERIFIER` (donc CC-T02, L12-T09), jamais une estimation. Comptes (445660, 445800, 275000…) en argument, jamais en dur. Le moteur (L01-T19) a une gravité FIXE par règle : quand la spec donne deux gravités à un même contrôle, la fiche crée deux règles (identifiant suffixé, voir LOT-12-PLAN §7). Le vocabulaire du code (`Blocage` = validation, tva, export, cloture ; `Declencheur` = `a_la_demande`) et celui du CSV (`validation_mois`, `preparation_tva`, `export_officiel`, `cloture`, `aucun` ; `demande`) diffèrent déjà : ne pas les « corriger ». La ligne du catalogue `docs/controles.csv` n'est PAS écrite ici (L12-T26 ou L12-T27) ; le titre du test `CT-nn` doit être exact, `garde:controles` le cherche. Cas limites exigés dans les tests : montant NaN, Infinity, non entier (1,5) et négatif là où il est interdit = exception codée (le moteur la change en `IMPOSSIBLE`) ; liste vide ; objets reçus dans l'ordre inverse (même résultat) ; écart d'exactement un centime de chaque côté de la tolérance. Chaque test doit rougir si l'on casse la branche qu'il couvre (inverser une comparaison, retirer un cas). Le « 80 % » et le « 100 % » de la spec sont des valeurs du registre à vérifier : seulement des paramètres de TEST dans les tests.

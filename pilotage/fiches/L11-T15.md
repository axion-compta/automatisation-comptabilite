## Contexte
Spec 11, fichier 03 : le barème est un paramètre daté (`parametre_date.cle = bareme_ik_voiture`, pays `FR`), une ligne par année ; valeur JSON : pour chaque puissance, trois tranches `{ jusqua_km, taux, fixe }` ; majoration électrique : clé séparée `bareme_ik_majoration_electrique`. Le noyau interdit les décimaux et `parseFloat` : les taux sont lus comme du TEXTE et convertis en entiers. Décision D31 : aucune valeur légale en dur ; puissances, bornes, taux et majoration viennent TOUS de la valeur du paramètre.

## À faire
1. `packages/noyau/src/frais/bareme-ik.ts` :
   - `lireTauxMilliemes(texte: string)` : `'0,636'` ou `'0.636'` → 636 ; au plus 3 décimales, sinon `ErreurFrais('entree_invalide')` ; refus de `''`, `'-0,1'`, `'1e3'`, `'NaN'`, `'Infinity'`, `' 0,5'` ;
   - `lireMontantCentimes(texte)` : `'1395'` ou `'1 395,00'` → 139 500 ; au plus 2 décimales ;
   - `lireBaremeIk(valeur: string)` → `BaremeIk { puissances: { cleCv: number; tranches: { jusquaKmDixiemes: number | null; tauxMilliemes: number; fixeCentimes: Centimes }[] }[] }` : JSON analysé par `JSON.parse` dans un `try` ; tranches triées par borne, bornes strictement croissantes, dernière borne `null` (sans limite) ; puissances distinctes ; JSON invalide, tableau vide, borne non croissante → `entree_invalide` ;
   - `lireMajoration(valeur: string)` → pourcentage ENTIER (ex. `'20'`) ; non entier, négatif → `entree_invalide` ;
   - `ligneDePuissance(bareme, puissanceCv)` : plus petite clé ≥ puissance ; au-delà de la plus grande clé → la plus grande ; en dessous de la plus petite → la plus petite ; puissance non entière, ≤ 0, `NaN` → `entree_invalide`.
2.

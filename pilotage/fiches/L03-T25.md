## Contexte
Spec 03, §02 : `GET …/tva/estimation` rend `non_calculee` si le régime n'est pas traité ou si un contrôle de doute est ouvert (motif `tva_en_doute`), « aucun montant dans ces deux cas » (TVA-017). D4 (décision de Will) : TVA avec pièces en doute = blocage, jamais d'estimation qui laisse une pièce de côté. Les totaux alimentent la liquidation `liquiderTva` (L01-T16, type `TotauxTva`).

## À faire
1. `packages/noyau/src/tva/totaux.ts` :
   - `totauxPeriode(lignes: { effet: EffetTraitement /* L03-T24 */; dateExigibilite?: string; dateDeduction?: string }[], periode: { debut; fin })` → `{ etat: 'calcule'; collectee; deductible; sousReserve; perdue } | { etat: 'non_calcule'; motif: 'tva_en_doute'; lignesEnDoute: number }` : collectée comptée si `dateExigibilite` est dans la période ; déductible, sous réserve et perdue si `dateDeduction` est dans la période ; UNE ligne `aVerifier` dans la période suffit à rendre `non_calcule` ;
   - `versTotauxLiquidation(total)` → `TotauxTva` de `./liquidation.js` (refus si `non_calcule`).
2. Tests nommés : `totaux-standard` (montants inventés), `ligne-hors-periode-ignoree`, `une-ligne-en-doute-aucun-montant`, `sous-reserve-a-part`, `bornes-incluses`, `vers-liquidation-refuse-si-non-calcule`.

## Hors périmètre
Pas de motif `regime_non_traite` (l'appelant le pose avec `estTraite`, L03-T20). Pas de déclaration (L03-T26).

## Pièges
Règles du noyau comme L03-T01. Ne pas modifier `liquidation.ts`. Cas limites exigés : liste vide (tout à 0, `calcule`), ligne sans aucune date (ignorée et comptée dans un champ `lignesSansDate`, test), période aux bornes inversées (refus, classe locale `ErreurTotauxTva`).

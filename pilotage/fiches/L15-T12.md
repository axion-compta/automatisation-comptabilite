## Contexte
Spec 15, AL-R1. Une évaluation est idempotente : une même clé (`regle + objet_type + objet_id + période`) ne donne jamais deux alertes actives (`ouverte` ou `reportee`). Une alerte `ignoree` de même clé n'est pas recréée ; elle ne se rouvre que si la gravité monte ou si l'objet change (nouvelle clé). Condition disparue : `resolue_auto` avec une ligne de journal. Tout changement d'état ou de gravité est journalisé (ajout seul).

## À faire
1. `alertes/moteur.ts` :
   - `Alerte { id; regle; objetType; objetId; periode?: string; cle; gravite; etat: EtatAlerte; echeanceLe?: string; version: number }` ; `LigneJournal { alerteId; deEtat?; aEtat; deGravite?; aGravite; cause: CauseJournal; acteurType: 'humain' | 'systeme'; le: string }` ;
   - `cleDedoublonnage(regle, objetType, objetId, periode?)` : chaîne stable, séparateur qui ne peut pas apparaître dans les parties (sinon erreur `cle_invalide`), aucune partie vide ;
   - `evaluer(existantes, constats: { regle; objetType; objetId; periode?; gravite; echeanceLe? }[], regles: string[], horodatage, nouvelId: () => string)` → `{ alertes; journal }` : constat sans alerte active ni ignorée de même clé = nouvelle alerte `ouverte` ; alerte active de même clé dont la gravité change = mise à jour + journal + `version + 1` ; ignorée de même clé : rien, SAUF gravité plus haute = réouverte ; alerte active d'une règle évaluée (dans `regles`) sans constat = `resolue_auto` ; règles non évaluées : leurs alertes ne bougent pas ; deux constats de même clé dans la même évaluation = une seule alerte (la plus grave) ;
   - entrée jamais modifiée.
2. Tests nommés : `nouveau-constat-ouvre`, `meme-cle-pas-de-doublon`, `deux-constats-meme-cle-une-alerte`, `ignoree-non-recreee`, `ignoree-rouverte-si-plus-grave`, `condition-disparue-resolue-auto-journal`, `regle-non-evaluee-intacte`, `gravite-change-version-et-journal`, `evaluer-deux-fois-meme-resultat` (idempotence), `cle-invalide-refusee` (partie vide, séparateur dans une partie).

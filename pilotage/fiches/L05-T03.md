## Contexte
Spec 05, fichier 03 §3. Demande : `{ message_id, conversation_id, texte, puces: [{ type: ecran | selection | piece, ref }], canal }`. Réponse : flux d'événements, chacun avec un `id` croissant : tour.debut, etape, texte, carte, proposition, question (2 à 5 choix), erreur (un des 16 codes), tour.fin (issue parmi 6, coût en micro-centimes). Le front ignore un type inconnu, il ne plante pas.

## À faire
1. `packages/contrat/src/chat/evenements.ts` :
   - `DemandeMessage` `.strict()` : `message_id` et `conversation_id` non vides ; `texte` 1 à `longueurMax` caractères, où `longueurMax` est un ARGUMENT de `schemaDemande(longueurMax)` (entier > 0, sinon erreur) ; AUCUN champ `societe_id` ni `tenant_id` ; `canal` dans `CANAUX` ;
   - `Evenement` : union discriminée sur `type` ; `carte` porte une `Carte` de L05-T02 ; `proposition` : `proposition_id`, `niveau`, `nombre_objets` entier >= 0, `montant_total_centimes` entier facultatif ; `question` : 2 à 5 choix `{ code, libelle_code }` ; `erreur` : `code` dans `CODES_ERREUR` ; `tour.fin` : `issue` dans `ISSUES`, `cout_micro_centimes` entier >= 0 ;
   - `lireEvenement(brut: unknown): Evenement | null` : type inconnu ou forme invalide = `null`, jamais d'exception.
2. Tests nommés : `demande-valide`, `demande-texte-trop-long` (longueurMax + 1), `demande-texte-vide`, `demande-champ-societe-refuse`, `longueur-max-invalide` (0, -1, 2.5, NaN, Infinity), `huit-evenements-lus`, `type-inconnu-donne-null`, `question-un-ou-six-choix-refusee`, `erreur-code-hors-liste-null`, `cout-negatif-ou-decimal-null`.

## Hors périmètre
Pas d'encodage du flux (L05-T04), pas de route (L05-T37).

## Pièges
Aucune valeur de longueur en dur : elle vient des réglages (L05-T54). Les tests doivent rougir si `lireEvenement` lève une exception sur une entrée bizarre (tableau, nombre, `undefined`).

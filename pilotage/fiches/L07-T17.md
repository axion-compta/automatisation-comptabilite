## Contexte
Contrat figé par L07-T14 (`GET /acces`). Spec 07, `01-etats-acces.md` : la bannière (PLA-130) donne état, cause, conséquence, prochaine étape et lien, sans montant ; la reprise (PLA-135) montre un résumé (« 20 pièces reçues pendant la pause ont été traitées »). Avant branchement à la console, l'état vient du scénario fictif (L07-T13) ; le lien est donc `contacter_axion`. Cas T-ABO-6 côté données : bannière présente dans les 5 états non actifs, 0 montant.

## À faire
1. `packages/contrat/src/domaines/acces-service.ts` : `creerServiceAcces({ horloge, scenario })` → `{ lire(): ReponseAcces }` ; `scenario` lu par `lireScenario`, données par `donneesDuScenario` (L07-T13), état par `etatDuModule` et bannière par `contenuBanniere(etat, voulu, false)` (L07-T01) ; conversion en noms du contrat (`prochaine_etape_le`) ; `reprise` = `{ pieces_traitees: reprendre(fileReprise, new Set()).resume.piecesTraitees }` (L07-T04) quand le scénario porte `reprise=oui` ET que l’état traite les pièces (ESSAI, ACTIF, DELAI_DE_GRACE), sinon `null`.
2. `apps/serveur/src/domaines/acces.ts` : remplace le bouchon ; `implementerAcces(os, options)` appelle le service (signature inchangée).
3. `packages/faux-serveur/src/domaines/acces.ts` : remplace le bouchon ; `handlersAcces(options)` appelle LE MÊME service avec le scénario de la requête ; aucune logique recopiée.
4. `__tests__/suite-acces.ts` : suite commune jouée sur les deux cibles par `commun-acces.test.ts` (même forme que `suite-contrat.ts` existant).
5. Tests nommés : `actif-sans-banniere`, `cinq-etats-non-actifs-avec-banniere` (T-ABO-6, données), `aucun-montant-dans-la-reponse` (parcours récursif des clés et des valeurs : ni `montant`, ni `prix`, ni `€`), `lien-contacter-axion-avant-branchement`, `prochaine-etape-en-essai`, `scenario-invalide-donne-actif`, `reprise-resume-vingt-pieces` (`reprise=oui` : 20 ; `acces=lecture_seule;reprise=oui` : null), `memes-reponses-vrai-et-faux` (les 6 scénarios d'accès).

## Hors périmètre
Pas de garde sur les autres routes (L07-T22), pas de lecture de la console (fiche bloquée L07-T34), pas d'écran (L07-T27).

## Pièges
Une seule logique : le faux serveur importe le service du contrat par chemin relatif (comme `plan-service.ts` de L01-T23). Ne pas modifier `handlers.ts`, `app.ts`, `routes.ts` ni le contrat : s'il manque un champ, la fiche passe en `bloque` et le signale (le contrat est figé). Horloge injectée : aucun `new Date()` sans argument dans le service.

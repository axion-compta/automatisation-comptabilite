## Contexte
ADR 0002 et 0003 : le contrat fait foi, le faux serveur (MSW) le suit et la même suite de tests tourne sur les deux cibles (`contrat-commun.test.ts`). Les écrans E19 (L03-T44, L03-T45) se testent sur ce faux serveur.

## À faire
1. `packages/faux-serveur/src/domaines/tva.ts` : `creerHandlersTva()` : handlers MSW des trois routes de L03-T32, sur `tva-service.ts` (import relatif) ; query ou paramètre invalide = 400 (schémas du contrat, jamais redéfinis) ; inconnu = 404 avec le code du contrat.
2. `handlers.ts` : `creerHandlers` ajoute `creerHandlersTva()` (sans toucher aux autres).
3. `__tests__/suite-tva.ts` : `suiteTva(nom, cible)` : enveloppe et tri des périodes, estimation `non_calculee` sans montant, déclaration avec sources et mention, déclaration inconnue 404, query invalide 400 ; appelée pour les deux cibles dans `contrat-commun.test.ts`.

## Hors périmètre
Aucune route d'écriture. Pas d'écran.

## Pièges
`handlers.ts` et `contrat-commun.test.ts` sont communs : chaîne L03-T35 puis L03-T36 puis L03-T37 ; base à jour avant fusion. Le faux serveur ne démarre qu'en mode `simule`. Cas limites exigés dans la suite : identifiant vide, identifiant avec caractères spéciaux encodés.

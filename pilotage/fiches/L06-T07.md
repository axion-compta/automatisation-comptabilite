## Contexte
Spec 06, `03-roles-permissions.md` §4 : accès expert = périmètre (exercices, journaux, comptes bancaires), mode `lecture_commentaire` par défaut, `expire_le` = dernier renouvellement + durée, `revoque_le`. À l'échéance sans renouvellement : refus et événement `securite.acces_expert_expire` ; avis à l'administrateur avant l'échéance. D6 : l'expert invité lit, exporte, commente, ne valide jamais. Cas C08, C12, C13. La durée d'accès et le préavis sont des réglages de produit : ARGUMENTS.

## À faire
1. `packages/noyau/src/securite/expert.ts` :
   - `AccesExpert = { societeId; personneId; perimetre: { exercices: string[]; journaux: string[]; comptesBancaires: string[] }; mode: 'lecture_commentaire'; expireLe: string; revoqueLe?: string }` (instants ISO 8601 UTC) ;
   - `verifierAccesExpert(acces, demande: { action: Action; exercice?; journal?; compteBancaire? }, maintenant)` → `{ permis: true } | { permis: false; raison: 'acces_revoque' | 'acces_expire' | 'perimetre_expert'; evenement?: 'securite.acces_expert_expire' }` ; révoqué si `revoqueLe <= maintenant` ; expiré si `maintenant >= expireLe` ; action hors `lire`, `exporter`, `commenter` → `perimetre_expert` ; exercice, journal ou compte demandés absents du périmètre → `perimetre_expert` ; un critère non demandé n'est pas vérifié ;
   - `prolonger(acces, maintenant, dureeMs)` → nouvel accès (`expireLe = maintenant + dureeMs`) ; refus si révoqué ;
   - `doitAvertir(acces, maintenant, preavisMs, dejaAverti: boolean)` → booléen.
2. Tests nommés : `revoque-t0-refuse-a-t0-plus-45s` (C08), `journal-hors-perimetre-refuse` (C12 : VTE refusé, ACH permis), `expire-refuse-avec-evenement` (C13), `echeance-exacte-expiree`, `une-ms-avant-echeance-permis`, `valider-toujours-refuse`, `perimetre-vide-rien`, `prolonger-revoque-refuse`, `avertir-une-seule-fois`, `dates-invalides-refusees` (`''`, `'31/12/2026'`, `NaN`, durée négative, `Infinity`, non entière).

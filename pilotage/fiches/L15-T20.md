## Contexte
Spec 15, PR-R5 et PR-R6. `bloquant` et `urgent` = notification tout de suite (cloche, et e-mail si choisi) ; `a_faire` = résumé quotidien ; `info` = jamais. Seulement dans une catégorie choisie par la personne. Une seule notification par alerte et par changement de gravité. Contenu minimal : titre générique et lien, AUCUN montant ni nom de tiers. Résumé : un par personne et par jour, SEULEMENT s'il y a au moins une action (sinon `ignore_rien_a_faire`) ; jamais deux fois le même jour, même après une coupure.

## À faire
1. `alertes/notifications.ts` :
   - `Notification { alerteId; categorie: 'a_valider' | 'echeance' | 'urgent' | 'cabinet'; gravite; titreCode: string; lien: string }` (aucun autre champ : le type l'interdit) ;
   - `notificationsAEmettre(alertes, { categoriesChoisies; dejaEmises: { alerteId; gravite }[]; categorieDe: (regle) => Categorie })` → `{ immediates: Notification[]; pourResume: Notification[] }` ;
   - `lien` construit comme `/alertes/<id>` : un id qui contient autre chose que `[A-Za-z0-9_-]` = erreur `id_invalide` (pas d'injection dans un lien d'e-mail) ;
   - `decisionResume({ personneId; dateDuJour; actifs: boolean; nbActions: number; dejaEnvoye: { personneId; dateEnvoi }[] })` → `'envoyer' | 'ignore_rien_a_faire' | 'deja_envoye' | 'desactive'` ; `nbActions` négatif, non entier ou non fini = erreur.
2. Tests nommés : `bloquant-et-urgent-immediats`, `a-faire-pour-le-resume`, `info-jamais`, `categorie-non-choisie-rien`, `une-seule-fois-par-gravite`, `nouvelle-gravite-nouvelle-notification`, `aucun-montant-ni-tiers` (les clés de l'objet sont exactement celles du type), `id-invalide-refuse` (`'a/b'`, `'<x>'`, `''`), `resume-rien-a-faire-pas-d-envoi`, `resume-jamais-deux-fois-le-meme-jour`.

## Hors périmètre
Pas d'envoi d'e-mail (L15-T63, bloquée), pas d'heure d'envoi, pas de fuseau.

Aucun texte : `titreCode` est un code traduit par `packages/textes` côté écran ou e-mail. Codes seulement.

## Contexte
Spec 02, fichier 02, règle 5 : « Dates ambiguës (`03/04/2026`) : si toutes les dates du fichier tiennent dans un seul format, on le prend ; sinon UNE question (« Ce fichier écrit-il le jour en premier ? ») avec 2 réponses prêtes. » Test T02-6 : dates du 01/02 au 12/02 seulement → 1 question ; deuxième import du même profil → 0 question (le format retenu est mémorisé dans le profil : hors de cette fiche). Cas limite : « dates UTC décalant d'un jour (on garde la date locale de la banque) ».

## À faire
1. `packages/noyau/src/banque/import/dates.ts` :
   - formats : `JJ/MM/AAAA`, `MM/JJ/AAAA`, `JJ/MM/AA`, `JJ.MM.AAAA`, `JJ-MM-AAAA`, `AAAA-MM-JJ`, `AAAAMMJJ` (OFX), `AAAAMMJJHHMMSS[...]` (OFX, heure ignorée), numéro de série d'un classeur (texte entier) avec origine passée en argument ;
   - `lireDate(texte, format)` → `'AAAA-MM-JJ'` ou erreur `date_invalide` (29/02 hors année bissextile, mois 13, jour 0) ;
   - `choisirFormat(textes: string[], candidats)` → `{ type: 'unique'; format } | { type: 'question'; formats: [a, b] } | { type: 'aucun' }` (un format est candidat si TOUTES les dates non vides du fichier se lisent avec lui) ;
   - années sur 2 chiffres : siècle donné en argument (jamais deviné) ;
   - classe locale `ErreurDate` : `date_invalide`, `format_inconnu`, `siecle_absent`.
2. Tests nommés : `jour-en-premier-deduit` (une date `25/02/2026` lève l'ambiguïté), `question-si-tout-ambigu` (T02-6), `aucun-format`, `ofx-avec-heure` (`20261005120000[+1:CET]` → `2026-10-05`, jamais décalé), `bissextile` (`29/02/2028` valide, `29/02/2026` refusée), `annee-deux-chiffres-siecle-en-argument`, `numero-de-serie`, `iso-garde`.

## Hors périmètre
Mémorisation du format dans le profil (L02-T15). Texte de la question (code seulement ; phrase dans L02-T48).

## Pièges
Aucun `new Date(texte)` (fuseau du serveur) : calcul civil pur. Cas limites exigés : liste vide (`aucun`), dates toutes vides, espaces, `NaN` en texte, ordre des dates sans effet sur le choix. Règles du noyau.

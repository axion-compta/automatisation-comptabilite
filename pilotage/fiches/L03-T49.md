## Contexte
Spec 03, §10 : « Affectation : réserve légale selon le paramètre (test : une fraction du bénéfice tant qu'elle n'atteint pas une fraction du capital) ; dividende ≤ sommes distribuables, sinon refus (JUR-007) ; perte : aucun dividende proposé (JUR-015). » P1 donne la forme du calcul (réserve proposée, distribuable, refus avec le montant maximal). Les deux fractions sont des paramètres datés : arguments.

## À faire
1. `packages/noyau/src/cloture/affectation.ts` (utilise `pourcentage`, `soustraire`, `ajouter` de `../argent/index.js`) :
   - `affecterResultat({ resultat; capital; reserveActuelle; reportANouveau; dividendeDemande }, { fractionDotationPointsDeBase; plafondReservePointsDeBase; arrondi: Arrondi })` → `{ ok: true; reserveProposee; distribuable; dividende } | { ok: false; code: 'dividende_superieur_distribuable'; distribuable } | { ok: false; code: 'perte_aucun_dividende' }` ;
   - réserve proposée = min(fraction du bénéfice, plafond du capital − réserve actuelle), jamais négative ; distribuable = bénéfice − réserve proposée + report à nouveau (positif ou négatif) ; dividende demandé > distribuable = refus avec le montant ; résultat ≤ 0 et dividende > 0 = `perte_aucun_dividende`.
2. Tests nommés (fractions INVENTÉES, ex. 700 et 1 500 points de base ; capital et résultat fictifs) : `reserve-proposee`, `reserve-plafonnee`, `reserve-deja-au-plafond-zero`, `dividende-egal-distribuable-accepte`, `dividende-un-centime-de-trop-refuse`, `perte-aucun-dividende`, `report-negatif-reduit-distribuable`.

## Hors périmètre
Pas de PV, pas de modèle de document, pas de mode de décision selon la forme (lot juridique). Pas de date d'assemblée.

## Pièges
Règles du noyau comme L03-T01. Cas limites exigés : fractions hors 0 à 10 000, NaN ou non entières (refus, classe locale `ErreurAffectation`) ; capital nul ; dividende demandé négatif (refus) ; résultat exactement nul.

## Contexte
Spec 05, fichier 02 §1 : la passerelle ne fait que du texte ; le modèle rend un JSON `{ outil, arguments }` que le module valide par zod. JSON invalide = 1 nouvel essai, puis réponse sans modèle (CHT-063). Fichier 06 §1 : outil demandé hors de la liste permise = `outil_hors_liste`, journalisé.

## À faire
1. `packages/contrat/src/chat/sortie-modele.ts` :
   - `analyserSortie(texte, outilsPermis: readonly string[])` → `{ sorte: 'outil'; outil; arguments } | { sorte: 'texte'; texte } | { sorte: 'rejet'; code: 'hors_schema' | 'outil_hors_liste' | 'parametre_invalide' }` ; le JSON peut être seul ou entre balises de code ; texte sans JSON = réponse texte ; arguments validés par `validerEntree` (L05-T05) ;
   - `avecUnNouvelEssai(appeler: () => Promise<string>, outilsPermis)` : rejet `hors_schema` au 1er essai = 1 seul nouvel appel ; second rejet = `{ sorte: 'sans_modele' }` ; jamais un 3e appel.
2. Tests nommés : `outil-valide`, `json-entre-balises`, `texte-simple`, `json-casse-hors-schema`, `outil-hors-liste` (A2-04 : `appliquer`), `arguments-invalides`, `un-seul-nouvel-essai` (compte des appels = 2), `succes-au-second-essai`, `entrees-bizarres` (chaîne vide, JSON `null`, tableau, objet géant de 1 Mo, deux JSON à la suite).

## Contexte
Le front se construit sur le faux serveur (MSW), qui doit répondre comme le serveur en mémoire : même contrat, même suite de tests (`contrat-commun.test.ts`, motif de L01-T24 et L01-T26). Routes : `listerComptesBancaires`, `listerLignesBancaires`, `lireExplicationLigne` (L02-T51).

## À faire
1. `packages/faux-serveur/src/domaines/banque.ts` : handlers des 3 routes sur `banque-service.ts` du contrat (même service, aucune donnée copiée) ; pannes simulées (403, 409, 423) comme les autres domaines.
2. `handlers.ts` : ajouter les handlers banque à `creerHandlers` sans changer l'ordre des autres.
3. `__tests__/suite-banque.ts` : suite paramétrée par une fonction d'appel : `comptes-trois`, `lignes-filtre-etat`, `lignes-pagination-limite-cent`, `explication-ligne-connue`, `ligne-inconnue-404`, `panne-403-simulee`.
4. `contrat-commun.test.ts` : exécuter `suite-banque` sur les deux serveurs.

## Hors périmètre
Couverture, trous, demandes, doublons (L02-T55). Trésorerie (L02-T56). Écran (L02-T57).

## Pièges
Fichiers communs du couloir C (`handlers.ts`, `contrat-commun.test.ts`) : chaîne T54 → T55 → T56 ; d'autres lots y écrivent : base à jour avant fusion. Le faux serveur ne démarre qu'en mode `simule`. Cas limites exigés : `limite` 101 refusée (400) des deux côtés, identifiant vide.

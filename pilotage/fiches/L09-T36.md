## Contexte
ADR 0003 et L01-T24 : le faux serveur (MSW) suit le contrat ; une même suite de tests tourne contre le serveur en mémoire (`apps/serveur`) et contre le faux serveur. Routes de lecture du lot : `GET /profil` (L09-T30), `GET /profil/regimes/tva` et `/imposition` (L09-T31), `GET /parametres` (L09-T32), `GET /siren/{siren}` et `GET /tva-intracom/{numero}/verification` (L09-T33).

## À faire
1. `packages/faux-serveur/src/domaines/profil.ts` : `creerHandlersProfil()` : un gestionnaire par route ci-dessus, réponses construites par les services du contrat (`profil-service.ts`, `regimes-service.ts`, `parametres-service.ts`, `identite-service.ts`) pour Lemoine Rénovation ; réponses validées par les schémas exportés ; erreurs aux mêmes codes HTTP que le serveur en mémoire.
2. `handlers.ts` : ajouter `...creerHandlersProfil()` sans réordonner les autres.
3. `__tests__/suite-profil.ts` : suite commune (même forme que `suite-plan.ts`) ; `contrat-commun.test.ts` : l'enregistrer pour les deux cibles.
4. Tests nommés (dans la suite) : `profil-identique-des-deux-cotes`, `lecture-a-une-date`, `regimes-tries`, `parametre-absent-404`, `siren-cle-fausse-422`, `vies-indisponible-non-verifie`.

## Hors périmètre
Pas de routes d'écriture (L09-T37) ; pas d'écran.

## Pièges
Fichiers communs du couloir C (`handlers.ts`, `contrat-commun.test.ts`) : chaîne T36 puis T37 ; remettre la branche à jour avant fusion (autres lots). Le faux serveur ne démarre qu'en mode `simule`. Aucune donnée réelle.

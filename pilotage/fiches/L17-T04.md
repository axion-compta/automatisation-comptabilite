## Contexte
En installation chez le client, c'est le client qui décide (DPO ou référent RGPD) et qui tient son registre des violations ; le produit fournit le modèle et assiste, il ne décide pas. Spec 08 `08-violations-failles.md`. Lignes du registre déjà validées par `validerLigneRegistre` (`packages/noyau/src/rgpd/violations.ts`).

## À faire
1. Tests d'abord, sur une installation fictive.
2. `rgpd-client.ts` : type `DecisionDpo` (`choix`: `dpo_designe` | `referent_rgpd`, nom de rôle et non de personne, date, empreinte du document archivé) ; `archiverDecision(d)` refuse une décision incomplète ; `peutMettreEnService({ decision })` → refus avec code `decision_dpo_absente` si aucune décision archivée.
3. `modeleRegistreViolations()` : en-têtes et une ligne d'exemple vide, réutilisant le type `LigneRegistre` de `violations.ts` ; la ligne vide passée à `validerLigneRegistre` est signalée incomplète (le modèle ne se valide pas tout seul).
4. Tests nommés : `mise-en-service-refusee-sans-decision`, `decision-archivee-mise-en-service-permise`, `decision-incomplete-refusee`, `modele-registre-fourni`, `modele-vide-non-valide`.

## Hors périmètre
Textes du contrat (dépôt privé), écran, envoi à l'autorité.

## Pièges
Fiche sensible (données de personnes) : relecture Opus, fusion par Will seul. Aucun nom de personne : la décision porte un rôle. Ne modifie pas `violations.ts`.

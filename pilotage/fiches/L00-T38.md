## Contexte
Une cinquantaine de fiches disent « 300 lignes hors `openapi.json` » (fichier généré par `pnpm contrat:openapi`), mais la garde `perimetre` additionne toutes les lignes du diff. La PR 625 (L05-T37) mesure 390 lignes : 132 pour `packages/contrat/openapi.json` et 258 pour le reste. Elle est rouge alors que le travail respecte la fiche. Will a autorisé ce changement de règle le 07/11/2026.

## À faire
1. Dans `outils/gardes/perimetre.mjs`, compter à part les lignes du seul chemin exact `packages/contrat/openapi.json` (égalité de chaîne, jamais un motif ni un joker). Le reste du diff doit respecter `taille_max_lignes`.
2. Plafond fixe `PLAFOND_OPENAPI = 300` pour ce fichier : au-delà, la garde est rouge (« openapi.json : N lignes > 300 »).
3. L'exemption ne s'applique que si `pnpm contrat:diff` (`packages/contrat/scripts/diff.mjs`) confirme que le fichier est bien le fichier généré, et si la PR ne touche pas `packages/contrat/scripts/`. Sinon, les lignes sont comptées comme aujourd'hui : la garde n'est jamais plus faible qu'avant pour un fichier qui ne serait pas généré.
4. Le contrôle des fichiers binaires (« - - ») et la liste `fichiers_autorises` restent appliqués à `openapi.json` comme à tout fichier.
5. Garder les signatures compatibles (paramètres par défaut) et le préfixe du message vert.
6. Tests nommés `T38-n`, rouges avant le code : `openapi.json` seul vert ; 132 lignes d'openapi plus du code qui dépasse la taille = rouge ; plus de 300 lignes d'openapi = rouge ; exemption absente si le fichier n'est pas confirmé généré ; pas d'exemption si `packages/contrat/scripts/` est touché ; autres fichiers JSON (`apps/serveur/openapi.json`, `packages/contrat/openapi.json.bak`, `packages/contrat/x/openapi.json`, `packages/contrat/src/actions/registre.json`) comptés en entier ; `openapi.json` binaire = rouge ; `openapi.json` hors `fichiers_autorises` = rouge ; cas de la PR 625 (258 + 132, taille 300) = vert.

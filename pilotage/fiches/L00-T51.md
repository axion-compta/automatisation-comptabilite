## Contexte
Audit console du 08/11/2026 : le manifeste C4 réel de la compta n'est prévu par aucune fiche ; le faux hôte (L00-T19) ne charge qu'un module vide. Spec 06 (lisez-moi, partie « AJOUTÉ ») : ce que le module écrit lui-même vit dans le schéma `a_compta` de la base `cli_<id>`, derrière le contrat C4 (jeu de 20 cas, `migrer`, `actionsAutomatiquesAutorisees`, interrupteur fermé par défaut). Spec 05, fichier 04 : `actionsAutomatiquesAutorisees` vide par défaut. Permissions : les 11 `compta-*` de `PERMISSIONS` (L06-T00), sous le plafond de 50. Le faux hôte passe d'abord à l'hypothèse 0.5.0 (L00-T52). La forme du vrai SDK de la console n'est pas connue (D29, question 2) : le fichier exporte des données et une fonction, que le test valide avec le `defineAutomation` du faux hôte. Avec tsconfig strict, le TS ne peut pas importer les `.mjs` du faux hôte sans déclaration : le test est donc un `.test.mjs` dans `outils/faux-hote-c4/test/` qui importe le `.ts` (vitest le transforme). Décision J3a de Will : rien en production avant J10. Décision de Will du 08/11/2026 : « fais tout ce qui est nécessaire selon tes recommandations ».

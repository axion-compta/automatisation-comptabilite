## Contexte
Spec 11, fichier 06 : `GET /vehicules` (véhicules personnels de la personne) et `GET /parametres/bareme_ik_voiture?date=` (ligne de barème, source, statut). La ligne au jour J est choisie par `parametreAuJour` (L01-T14 : fin exclue ; absente ou ambiguë = erreur ; jamais de valeur par défaut). Le statut est TOUJOURS rendu : l'écran affiche « Barème à confirmer » quand il n'est pas `valide`.

## À faire
1. `vehicules-bareme.ts` : schémas `Vehicule { id; personneId; puissanceCv; energie; proprietaire; categorie; carteGrise: boolean }` (l'immatriculation n'est PAS exposée) et `LigneBareme { cle; pays; effetDebut; effetFin: string | null; statut; source; dateReleve; puissances: { cleCv; tranches: { jusquaKmDixiemes: number | null; tauxMilliemes; fixeCentimes }[] }[]; majorationPourcent: number | null }` ; routes `listerVehicules` (`GET /vehicules`, query `personne` obligatoire) et `lireBaremeIk` (`GET /parametres/bareme_ik_voiture`, query `date` `AAAA-MM-JJ` obligatoire) ; erreurs `BAREME_ABSENT` 404, `BAREME_AMBIGU` 409.
2. `vehicules-bareme-service.ts` : service pur sur `genererFrais()` (L11-T21) ; barème : `parametreAuJour` (L01-T14) puis `lireBaremeIk` et `lireMajoration` (L11-T15), imports par chemin relatif ; valeur illisible → 409 `BAREME_ILLISIBLE` (jamais une valeur de repli).
3. `routes.ts` : ajouter `vehiculesBareme` sans toucher les autres domaines ; régénérer `openapi.json` ; serveur en mémoire branché dans `app.ts`.
4. Tests nommés : `vehicules-de-la-personne`, `immatriculation-jamais-exposee`, `bareme-valide-au-jour`, `bareme-a-verifier-statut-rendu`, `fin-exclue` (jour de fin → ligne suivante), `bareme-absent-404`, `date-invalide-400` (`2025-02-30`, `''`, absente), `serveur-repond-au-bareme` (Fastify `inject`).

## Contexte
Spec 06, `06-securite-applicative.md` §4 (PLA-160) : liste fermée des routes `(fournisseur, région, mode)` dans un fichier versionné du module ; un appel hors liste est refusé et journalisé ; « ajouter une route sans décision écrite de Will = CI rouge ». D1 : jamais hors de l'Union européenne. Le CHOIX des fournisseurs est D43 (non appliquée) : le mécanisme se code maintenant, la liste reste VIDE (tout appel refusé). Cas T-SEC-5.

## À faire
1. `docs/ia/routes-ia.json` : `{ "version": 1, "routes": [] }`.
2. `packages/noyau/src/securite/routes-ia.ts` :
   - `RouteIA = { fournisseur: string; region: string; mode: string; decision: string; ajouteeLe: string }` ;
   - `validerListeRoutes(donnee)` → liste typée ; erreurs : forme inattendue, champ vide, `decision` hors forme `D` suivi de chiffres, `ajouteeLe` qui n'est pas une date `AAAA-MM-JJ` valide, doublon `(fournisseur, region, mode)` sans tenir compte de la casse ;
   - `routeAutorisee(liste, demande: { fournisseur; region; mode })` → `{ autorisee: true } | { autorisee: false; evenement: { type: 'ia.route_refusee'; fournisseur; region; mode } }` ; comparaison exacte après mise en minuscules ; liste vide → toujours refusée.
3. Tests nommés : `fichier-du-depot-valide` (lit `docs/ia/routes-ia.json` par `node:fs`), `liste-vide-tout-refuse` (T-SEC-5), `route-listee-autorisee` (route fictive), `region-differente-refusee`, `sans-decision-refusee`, `decision-mal-formee-refusee`, `doublon-casse-differente-refuse`, `forme-inattendue-refusee` (`null`, tableau, `routes` absent).

## Hors périmètre
Application dans la passerelle, cache séparé par client, registre des clauses « pas d'entraînement » (fiche bloquée L06-T43, D43).

## Pièges
Règles du noyau (eslint) : ni littéral décimal, ni `/`, ni `Math.round`, ni `parseFloat`, ni `toFixed` ; aucune dépendance ajoutée (seul `node:crypto` est permis, comme L03-T01). Ne pas toucher `packages/noyau/src/index.ts` (import par chemin relatif). Garde des littéraux (L01-T02) : aucun nombre sur une ligne qui contient délai, durée, seuil, plafond ou taux ; tout réglage est un ARGUMENT sans valeur par défaut, et les tests utilisent des valeurs inventées. Stryker (seuil 80 %) porte sur tout le noyau : chaque branche doit être tuée par un test. Cas limites obligatoires : NaN, Infinity, nombres non entiers, négatifs, chaînes vides, listes vides, dates invalides ou dans l'ordre inversé, doublons, entrée non modifiée. Chaque test doit rougir si l'on retire la vérification qu'il couvre (le vérifier en cassant le code à la main avant la PR, et le noter au journal). Données fictives seulement (sociétés « A », « B », « C », @exemple.fr, IBAN à clé fausse). N'écrire AUCUN nom de fournisseur réel dans les tests ni dans le fichier : noms fictifs (`fournisseur-a`, `region-ue-1`). Ajouter une vraie route = décision de Will (D43), jamais dans cette fiche.

## Contexte
Spec 03, §07, import d'un FEC (FEC-017) : « Même module : structure, équilibre, SIREN du nom = SIREN de la société, doublon (empreinte), dates de l'exercice […]. Échec = rapport d'écarts, import bloqué avant l'écran de vérification. » K5 : FEC fictif au SIREN 987654324 pour la société 123456782 → bloqué, « Ce fichier appartient à une autre entreprise ».

## À faire
1. `packages/noyau/src/fec/import.ts` :
   - `lireNomFichierFec(nom)` → `{ siren; dateCloture: 'AAAA-MM-JJ'; travail: boolean }` ou exception locale `ErreurImportFec('nom_invalide')` (forme `<9 chiffres>FEC<AAAAMMJJ>` puis `_TRAVAIL` facultatif puis `.txt`, sans casse sur l'extension) ;
   - `verifierAvantImport({ nomFichier, octets, sirenSociete, exercice: { debut, fin }, empreintesDejaImportees: readonly string[], lecture })` → `{ ok: true; empreinte; lignes } | { ok: false; codes: ('autre_entreprise' | 'doublon' | 'nom_invalide' | 'fichier_de_travail' | 'cloture_hors_exercice' | 'structure' | 'equilibre' | 'dates')[]; ecarts: EcartFec[] }` ; `lecture` = options de `lireFichierFec` (L03-T10) ; tous les codes applicables sont rendus, triés (pas d'arrêt au premier) ;
   - un fichier `_TRAVAIL` est refusé (`fichier_de_travail`) : on n'importe qu'un FEC définitif.
2. Tests nommés (SIREN fictifs 123456782 et 987654324) : `fichier-propre-accepte`, `autre-entreprise-refuse` (K5), `doublon-par-empreinte`, `nom-invalide-refuse`, `fichier-de-travail-refuse`, `desequilibre-liste-ecarts`, `plusieurs-codes-tries`.

## Hors périmètre
Pas d'import réel en base, pas de comparaison à la balance déposée (fiche suivante, avec la reprise), pas d'écran.

## Pièges
Les codes sont des codes : la phrase « Ce fichier appartient à une autre entreprise » est dans L03-T39. Règles du noyau comme L03-T01. Cas limites exigés : nom en majuscules `.TXT` (accepté), SIREN de 8 ou 10 chiffres (`nom_invalide`), date `20260230` dans le nom (`nom_invalide`), octets vides (`structure`).

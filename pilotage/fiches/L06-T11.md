## Contexte
Spec 06, `06-securite-applicative.md` §7 : « Arrêt d'urgence global et par société : un drapeau lu par l'API, le chat, les imports et les envois ; […] journalisé ; reprise par un administrateur. » Cas T-SEC-7 : A coupée en une action, B non touchée, reprise journalisée. La console n'a pas d'arrêt par société (point P6) : le module le porte.

## À faire
1. `packages/noyau/src/securite/arret.ts` :
   - `Drapeaux = { global?: { depuis: string; par: string }; societes: Readonly<Record<string, { depuis: string; par: string }>> }` ; `CANAUX_COUPES = ['api', 'chat', 'imports', 'envois']` ;
   - `estCoupe(drapeaux, societeId | undefined, canal)` → booléen ; global actif → tout coupé ; société inconnue de la requête → seul le global compte ; canal inconnu → `ErreurSecurite('argument_invalide')` ;
   - `poserArret(drapeaux, cible: 'global' | { societeId }, par, maintenant)` → `{ drapeaux; evenement: { type: 'securite.arret_urgence'; cible; par; horodatage } }` ; déjà posé → mêmes drapeaux, aucun événement ;
   - `reprendre(drapeaux, cible, personne: { id; role }, maintenant)` → `{ ok: true; drapeaux; evenement 'securite.reprise' } | { ok: false; raison: 'role_insuffisant' }` (seul `administrateur`) ; reprendre une société quand le global est posé : la société est levée mais `estCoupe` reste vrai.
2. Tests nommés : `societe-a-coupee-b-non` (T-SEC-7), `global-coupe-tout`, `quatre-canaux-coupes`, `canal-inconnu-refuse`, `poser-deux-fois-un-evenement`, `reprise-par-utilisateur-refusee`, `reprise-societe-sous-global-reste-coupee`, `entree-non-modifiee`.

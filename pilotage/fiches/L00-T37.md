## Contexte
Le test `packages/noyau/src/rgpd/__tests__/registre.test.ts` charge la garde `outils/gardes/textes.mjs` par un chemin relatif à cinq niveaux. Dans le bac à sable de stryker (`packages/noyau/.stryker-tmp/sandbox-*`), le fichier est copié plus bas : le chemin retombe sur `packages/noyau/outils`, qui n'existe pas. Le message est « Cannot find module … textes.mjs » et le premier passage de stryker échoue, donc toute PR qui touche `packages/noyau/src/argent/` reste rouge (reproduit en local).

## À faire
1. Dans le test, remplacer le chemin fixe par une petite fonction qui part du dossier du fichier, remonte de dossier en dossier et s'arrête dès que `outils/gardes/textes.mjs` existe ; erreur claire si la racine est atteinte sans le trouver.
2. Garder le reste du fichier tel quel (même import dynamique, mêmes cas, aucune assertion retirée).
3. Vérifier en local : `vitest` sur ce fichier, puis `stryker run --mutate src/argent/index.ts` dans `packages/noyau` : le premier passage doit réussir.
4. Noter au journal les deux vérifications.

## Hors périmètre
Aucun fichier de `.github/`, de `outils/gardes/`, `stryker.config.json` ni `vitest.config.ts` n'est modifié ; aucun seuil n'est abaissé ; les tests des autres paquets ne changent pas.

## Pièges
Ne pas exclure ce test du passage de stryker : d'autres tests peuvent tuer des mutants de l'argent. Fusion après relecture Opus et CI verte.

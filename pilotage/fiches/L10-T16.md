## Contexte
Spec 10, fichier 02, règle 4 : CONTRÔLE de la suite, jamais attribution d'un numéro. Par `serie` (préfixe, ex. `F-2026-`), triés par `numero_ordre`. Trou (0041 puis 0043) = carte « La facture 0042 manque » (A4). Même numéro avec des montants différents = les deux pièces `a_verifier`, aucune validée seule (A5). Date qui recule alors que le numéro avance = carte « ordre des dates » (A6). Plusieurs séries permises. Cas V18, V19, V21.

## À faire
1. `packages/noyau/src/ventes/series.ts` :
   - `decouperNumero(numero)` → `{ serie; ordre: number | null; largeur }` : dernière suite de chiffres en fin de numéro (après `trim`) = ordre ; ce qui précède = série ; aucun chiffre final → `ordre: null` ; ordre au-delà de `Number.MAX_SAFE_INTEGER` → `null` ;
   - `analyserSeries(pieces: { id; numero; dateFacture; ttc }[], { maxTrous })` → par série : `{ serie; dernierOrdreVu; trous: number[]; tropDeTrous: boolean; doublons: { ordre; ids }[]; datesQuiReculent: { avant; apres }[]; illisibles: string[] }` ;
   - trous seulement entre le plus petit et le plus grand ordre vus, plafonnés à `maxTrous` (entier ≥ 1) ; doublon de numéro seulement si les TTC diffèrent (même TTC = affaire du dédoublonnage, L10-T17) ;
   - résultat indépendant de l'ordre d'entrée.
2. Tests nommés : `v18-trou-0042`, `v18-trou-comble-apres-depot`, `v19-meme-numero-montants-differents`, `meme-numero-meme-montant-pas-a5`, `v21-date-qui-recule`, `plusieurs-series-separees`, `numero-sans-chiffres-illisible`, `zeros-en-tete` (`F-0042` et `F-42` : même série `F-`, même ordre 42), `ordre-d-entree-indifferent`, `liste-vide`, `plafond-de-trous` (0001 puis 9999 avec `maxTrous` 10 ; `maxTrous` 0, 1.5, NaN refusés).

## Contexte
`envoyerMessage` (`packages/contrat/src/domaines/chat.ts`) prend `DemandeEnvoi` défini par `schemaDemande` dans `packages/contrat/src/chat/evenements.ts` ; il ne porte ni l'écran, ni l'exercice, ni le mode.
Recoupement : `openapi.json` est partagé avec L04-T51, L09-T52, L09-T53, L10-T52 et L11-T47 ; cette fiche en dépend.

## À faire
1. Tests d'abord.
2. `evenements.ts` : champ facultatif `contexte: { ecran: chaîne de 1 à 40 caractères [a-z0-9-]; exercice_id: chaîne | null; mode: 'autonome' | 'saisie_seule' | 'accompagne' | null }`, objet strict ; absent = comportement actuel.
3. Régénérer `openapi.json`.
4. Tests nommés : `contexte-facultatif`, `contexte-strict-champ-inconnu-refuse`, `mode-hors-liste-refuse`, `demande-sans-contexte-inchangee`.

## Hors périmètre
Usage du contexte par le serveur (L26-T17). Envoi par l'écran (L26-T17).

## Pièges
Ajout seul : aucun champ existant renommé. Données fictives seulement (noms inventés, e-mails en @exemple.fr) ; aucune valeur commerciale dans les textes.

## Contexte
Spec 01, §04, règle 4 : « Numérotation continue et chronologique par journal et exercice, format `{JOURNAL}-{AAAA}-{NNNNNN}` (AAAA = année de clôture de l'exercice ; format à figer en ADR FEC). » Test T-ECR-4 : « 20 validations concurrentes, échec injecté à la 7e : numéros 1 à 19 sans trou, la 7e reste PROPOSÉE. »

## À faire
1. `packages/noyau/src/ecritures/numerotation.ts` :
   - `formaterNumero(journal, anneeCloture, rang, largeur)` → ex. `('AC', 2026, 1, 6)` donne `AC-2026-000001` ; `journal` en majuscules et chiffres seulement, `rang` entier ≥ 1, rang trop long pour la largeur = `ErreurEcriture('rang_trop_grand')` ;
   - `attribuer(compteur, tentatives)` : `compteur` = dernier rang attribué ; `tentatives` = liste ordonnée `{ id, reussit }` ; ne consomme un rang que pour une tentative réussie ; renvoie `{ attribues: { id, rang }[], compteur }` ;
   - `verifierSuite(rangs)` → `{ trous: number[], doublons: number[] }` pour une suite censée partir de 1.
2. Tests nommés : `format-numero-exemple`, `rang-trop-grand-refuse`, `echec-septieme-sans-trou` (T-ECR-4 : 20 tentatives, la 7e échoue, rangs 1 à 19, la 7e absente), `suite-avec-trou-detectee`, `suite-avec-doublon-detectee`, `compteur-repris-apres-echec`.

## Hors périmètre
Pas de verrou de base de données (la concurrence réelle se testera avec la base). La largeur est un argument : le format définitif sera fixé par l'ADR du FEC.

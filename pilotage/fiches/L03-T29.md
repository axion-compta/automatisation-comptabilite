## Contexte
Spec 03, §04, règle 7 : « Le client saisit lui-même dans son espace professionnel, guidé case par case (pas-à-pas). » Endpoint `GET /tva/declarations/{did}/pas-a-pas` (ordre de saisie). Cas limite : « Période sans opération (déclaration "néant" préparée, à valider). » Le logiciel ne dépose jamais.

## À faire
1. `packages/noyau/src/declarations/pas-a-pas.ts` :
   - `pasAPas(cases, ordreDeSaisie: readonly string[])` → `{ neant: boolean; etapes: { rang: number; code: string; montant: Centimes; base?: Centimes; sources: number }[] }` : étapes dans l'ordre donné par le millésime (argument), cases à 0 omises, `rang` à partir de 1 ; `neant` vrai si toutes les cases valent 0 (alors `etapes` vide) ;
   - code de `ordreDeSaisie` absent des cases = `ligne_absente` (classe locale `ErreurPasAPas`) ; case non nulle absente de `ordreDeSaisie` = `case_hors_ordre` (on ne cache jamais un montant).
2. Tests nommés : `ordre-du-millesime-respecte`, `cases-nulles-omises`, `neant-si-tout-a-zero`, `ligne-absente-refusee`, `montant-hors-ordre-refuse`, `rangs-continus`.

## Hors périmètre
Aucun texte (les libellés des cases viennent du millésime et de `packages/textes`). Aucune transmission.

## Pièges
Règles du noyau comme L03-T01. Cas limites exigés : `ordreDeSaisie` vide avec cases toutes nulles (`neant`), code en double dans l'ordre (refus), case négative (refus : une base négative est bloquée en amont, L03-T27).

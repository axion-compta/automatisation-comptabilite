## Contexte
Spec 05, fichier 03 §1 et §4 : une conversation appartient à UNE société. Seules les puces visibles et non retirées partent. Le serveur recalcule le contexte ; un identifiant d'une autre société venu du navigateur est ignoré et journalisé (`chat.contexte_rejete`). Cas A2-08 (identifiant d'écriture de la société B envoyé depuis A) et A2-09.

## À faire
1. `packages/noyau/src/chat/contexte.ts` :
   - `recalculerContexte({ puces, societeSession, societeConversation, appartenance: (ref) => string | undefined })` → `{ gardees; rejets: { ref; motif: 'autre_societe' | 'inconnue' | 'retiree' }[] }` ; `societeConversation !== societeSession` = `ErreurChat('droit_insuffisant')` ; puce retirée (`retiree: true`) jamais gardée ; doublons fusionnés ;
   - `evenementsJournal(rejets)` → une entrée `{ code: 'chat.contexte_rejete'; ref; motif }` par rejet, sans aucun texte.
2. Tests nommés : `puces-de-la-societe-gardees`, `autre-societe-rejetee` (A2-08), `inconnue-rejetee`, `retiree-jamais-envoyee`, `conversation-d-une-autre-societe-refusee`, `doublons-fusionnes`, `entrees-vides` (aucune puce, ref vide, société vide), `journal-une-ligne-par-rejet`.

## Hors périmètre
La société de la SESSION vient de l'identité réelle (L05-T58, bloquée) : ici elle est un argument.

Règles du noyau (eslint). Fiche sensible (isolation). Un test doit rougir si une puce rejetée apparaît dans `gardees`.

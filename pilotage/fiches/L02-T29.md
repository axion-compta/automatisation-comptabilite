## Contexte
Spec 02, fichier 05, passe 7 : « montants identiques en concurrence → algorithme d'affectation optimale (hongrois) sur le coût « écart de date », départage stable par `(date, id)` ; jamais glouton. » Fichier 06 : « si deux affectations ont le même coût, `DOUTEUSE` (jamais de choix silencieux) ». Test T06-2 : 3 lignes de −50,00 (02, 09, 16/10) et 3 tickets (01, 08, 15/10) → 02↔01, 09↔08, 16↔15, coût total 3 ; même résultat dans 3 ordres.

## À faire
1. `packages/noyau/src/banque/rapprochement/affectation.ts` :
   - `affecter(lignes: { id; cle: string }[], pieces: { id; cle: string }[], cout: (i, j) => number | null)` → `{ paires: { ligneId; pieceId; cout }[]; coutTotal; unique: boolean }` ; `null` = paire impossible ; matrice rectangulaire acceptée (lignes ou pièces en trop restent seules) ;
   - méthode hongroise en entiers (aucune division) ; les entrées sont d'abord triées par `cle` puis `id` : le résultat ne dépend pas de l'ordre d'entrée ;
   - `unique` : faux s'il existe une autre affectation de même coût total (vérification : pour chaque paire retenue, l'interdire et recalculer ; coût égal → non unique) ;
   - taille au-delà d'un maximum passé en argument → `ErreurAffectation('trop_grand')`.
2. Tests nommés : `t06-2-trois-cafes`, `ordre-d-entree-sans-effet` (3 permutations), `egalite-de-cout-non-unique`, `rectangulaire-plus-de-pieces`, `rectangulaire-plus-de-lignes`, `paire-impossible-respectee`, `jamais-glouton` (cas où le choix glouton du premier minimum coûte plus que l'optimum), `propriete-egale-recherche-exhaustive`.

## Hors périmètre
Calcul du coût (écart de date) et choix des candidats (L02-T32).

## Pièges
Cas limites exigés : listes vides, une seule paire, toutes les paires impossibles (aucune paire, `unique` vrai), coût `NaN`, `Infinity`, négatif ou non entier rendu par `cout` (erreur `cout_invalide`), maximum `NaN` ou nul. Aucun `Math.random` : le test de propriété utilise un générateur à graine écrit dans le test. Sensible (rapprochement). Règles du noyau.

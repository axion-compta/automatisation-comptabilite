## Contexte
Spec 10, fichier 02, règles 1 et 2 : une pièce est une vente si le vendeur lu est la société elle-même (SIREN, nom, n° de TVA du profil), sinon c'est un achat. Nature bien ou service proposée depuis l'habitude du client (E44) et le catalogue appris ; `a_confirmer` sinon (écriture en brouillon). Cas limite : montant négatif sans le mot « avoir » → `avoir`, à confirmer. Fichier 01, règle 6 : l'habitude ne s'applique qu'aux brouillons ; « Effet si je change » liste les pièces non validées touchées, rien n'est modifié avant « Enregistrer ». Ici, seulement des règles écrites en code : aucun appel à un modèle.

## À faire
1. `packages/noyau/src/ventes/reconnaissance.ts` :
   - `sensDeLaPiece(vendeurLu: { siren?; tva?; nom? }, societe: { siren; tva?; nom })` → `'vente' | 'achat' | 'a_verifier'` : SIREN ou TVA égal → vente ; seul le nom normalisé égal (`normaliserNom`, L10-T11) → `a_verifier` ; sinon achat ;
   - `typeProbable({ ttc, texteContientAvoir, texteContientAcompte })` → `{ type; aConfirmer: boolean }` ;
   - `natureProposee(libelle, habitude?: { nature; compteProduit }, catalogue: { motCle; nature; compteProduit }[])` → habitude d'abord, puis premier mot-clé trouvé (mot entier, sans casse ni accents), sinon `a_confirmer` ;
   - `effetSiJeChange(pieces: { id; statut; clientId }[], clientId)` → identifiants des pièces NON validées du client (jamais `validee`, `doublon`, `rejetee`).

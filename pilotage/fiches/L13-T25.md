## Contexte
Spec 13, fichier 05, R02 : un paiement = une ligne d'écart de change ; l'écriture est proposée en BROUILLON. Test MOT93-2 : P1 : D 401000 368,00 / C 512000 360,00 / C 756000 8,00 ; P2 : D 401000 552,00 / D 656000 18,00 / C 512000 570,00 ; ensuite 401000 = 0,00. Les frais bancaires vont à part (627, renvoi `02-banque/09`).

## À faire
1. `packages/noyau/src/change/ecriture-ecart.ts` (types de `../ecritures/modele.js`, sortie de `paiementPartiel` de `./paiement-partiel.js`) :
   - `ecritureReglementFournisseur(resultat (sortie de L13-T24 : partEuros, eurosImputes, ecart), frais, comptes { fournisseur; banque; perte; gain; frais }, ctx { id; date; journal })` donne une écriture `brouillon` : D fournisseur partEuros ; D frais (si non nuls) ; C banque eurosImputes ; D perte si écart positif ; C gain si écart négatif ; aucune ligne d'écart si écart nul ;
   - `soldeTiers(ecritures, compte)` : débits moins crédits.
2. Tests nommés (comptes de la spec passés en argument) : `premier-paiement-gain` (MOT93-2 P1, en centimes), `dernier-paiement-perte` (P2), `fournisseur-solde-apres-deux-paiements` (avec la facture d'achat C 401000 92 000 fournie par le test : solde 0), `avec-frais-ligne-separee`, `ecart-nul-pas-de-ligne`, `toujours-brouillon`, `equilibre-verifie` (chaque écriture passe `verifierEcriture`).

## Hors périmètre
Clients en devise (ventes) : convention de signe à confirmer (LOT-13-PLAN §11), non traitée. Surplus : il devient un acompte à qualifier, pas d'écriture ici.

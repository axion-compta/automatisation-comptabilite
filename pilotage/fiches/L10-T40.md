## Contexte
Spec 10, fichier 05 : `POST /ventes/import` (fichier, profil de colonnes) et `GET /ventes/import/{id}` (importées, rejetées avec raison). Réimport du même fichier = rien créé.

## À faire
1. `ventes-import.ts` : route `importerVentes` (`POST /ventes/import`, corps `{ nomFichier; contenu: string; separateur; separateurDecimal; formatDate; profil }`, `Idempotency-Key` obligatoire) → `{ id; creees; dejaPresentes; rejets: { ligne; raison }[] }` ; route `lireImport` (`GET /ventes/import/{id}`) ; erreurs `IMPORT_INCONNU` 404, `FICHIER_TROP_GRAND` 413, `CSV_MAL_FORME` 400 (avec le numéro de ligne).
2. `ventes-import-service.ts` : en mémoire ; `lireCsv`, `appliquerProfil` (L10-T25), `importer` (L10-T26) par chemin relatif ; les clés déjà présentes viennent des pièces du jeu et des imports précédents de l'instance ; taille maximale lue dans la configuration du serveur (pas une valeur légale, jamais écrite dans le contrat).
3. `registres/lot-10.ts` (contrat) : ajouter `ventesImport` ; régénérer `openapi/lot-10/openapi.json` ; serveur en mémoire branché dans `registres/lot-10.ts` (serveur).
4. Tests nommés : `import-cree-et-rejette`, `reimport-zero-cree`, `idempotence-meme-reponse`, `cle-absente-400`, `csv-mal-forme-400-avec-ligne`, `fichier-trop-grand-413`, `lire-import-404`, `serveur-repond-a-l-import`.

## Hors périmètre
Envoi de fichier binaire (multipart) et stockage chiffré (lot 04, bloqué) : ici, le contenu CSV est du texte dans le corps JSON.

## Pièges
Imports du noyau par chemin relatif (comme L01-T23). Registre du lot 10 seulement : n'ajouter que le domaine de la fiche ; régénérer `openapi/lot-10/openapi.json` par `pnpm contrat:openapi`. `routesEcritureSansEnTete()` reste `[]`. Aucune route de création, de numérotation ni d'envoi de facture (L10-T42). Query : bornes inversées, NaN, non entiers, chaînes trop longues → 400. Données fictives seulement (garde:fictif). Aucune ligne importée n'est jamais validée automatiquement : les pièces créées sont `lue`. Sensible (création de pièces comptables).

## Contexte
Spec 02, fichier 02, règles 2 et 3 : « Détection du format par le CONTENU (signature), jamais par l'extension. Ordre : XML (OFX 2, CAMT.053) → SGML OFX 1 → PDF (texte présent ?) → XLSX → CSV/TSV. » Taille et nombre de lignes bornés. Cas limites : BOM UTF-8, Windows-1252, ISO-8859-1.

## À faire
1. `packages/noyau/src/banque/import/detection.ts` :
   - `detecterFormat(octets: Uint8Array)` → `'camt053' | 'ofx2' | 'ofx1' | 'pdf' | 'xlsx' | 'csv' | 'inconnu'` : `%PDF-` ; `PK\x03\x04` puis présence du nom `[Content_Types].xml` ; XML avec `<Document` et l'espace de noms `camt.053` ; XML avec `<OFX>` ; en-tête `OFXHEADER:` ; sinon texte avec un séparateur constant (`;`, `,`, tabulation) sur les 10 premières lignes non vides ;
   - `detecterEncodage(octets)` → `'utf-8' | 'utf-8-bom' | 'windows-1252'` (UTF-8 valide strict, sinon Windows-1252) ; `decoder(octets, encodage)` → texte (table Windows-1252 pour 0x80 à 0x9F écrite dans le module) ;
   - `verifierLimites(octets, texte, limites: { octetsMax; lignesMax })` → erreur `trop_gros` ou `trop_de_lignes` ;
   - `detecterSeparateur(texte)` → `';' | ',' | '\t'` ou `null`.
2. Tests nommés : `extension-ignoree` (un CSV nommé `.ofx` reste `csv` : le nom n'est jamais lu), `camt-reconnu`, `ofx1-et-ofx2`, `pdf-reconnu`, `xlsx-reconnu`, `csv-point-virgule`, `bom-utf8`, `windows-1252-euro` (octet 0x80 → `€`), `limites-depassees`.

## Hors périmètre
Lecture du contenu (L02-T11 à T16). Lecture effective d'un PDF ou d'un XLSX (L02-T02, T03).

## Pièges
`limites` en argument (pas de 20 Mo en dur). Cas limites exigés : fichier vide (`inconnu`), un seul octet, limites `NaN`, `Infinity`, négatives, non entières (refus), texte binaire aléatoire (`inconnu`, jamais `csv`), CSV dont la 1re ligne est un titre sans séparateur. Règles du noyau.

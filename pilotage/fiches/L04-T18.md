## Contexte
Spec 04, fichier 02 §Liens : `paiement_de` (même fournisseur, même TTC, date de paiement >= date de facture) ; `avoir_de` (n° cité sur l'avoir, sinon même fournisseur et montant <= origine) ; `reemise_de` ; `acompte_de` ; `partie_de` (« le code vérifie la somme au centime »). « Un lien proposé par l'IA reste propose tant qu'une règle en code ne le confirme pas (n° cité, somme exacte) ou qu'une personne ne l'accepte pas. » Cas T-LEC-13.

## À faire
1. `packages/noyau/src/pieces/classement/liens.ts` :
   - `PieceLiee { id: string; type: TypePiece; fournisseurId?: string; numero?: string; numerosCites: string[]; date?: string; datePaiement?: string; ttc: Centimes }` ;
   - `EvaluationLien { sorte: SorteLien; decision: 'confirme' | 'propose' | 'rejete'; regle: string }` ;
   - `evaluerLien(sorte, a, b)` : `paiement_de` (a reçu ou ticket, b facture) confirmé si même fournisseur, même TTC, `a.datePaiement >= b.date` (chaînes ISO) ; sinon rejeté ; `avoir_de` confirmé si `b.numero` (normalisé : blancs, `-`, `/`, `.` retirés, majuscules) est dans `a.numerosCites` ; sinon proposé si même fournisseur et |a.ttc| <= b.ttc ; sinon rejeté ; `reemise_de` (a reemise, b annulee) proposé si même fournisseur, sinon rejeté ; `acompte_de` (a facture, b facture_acompte) confirmé si numéro de b cité dans a, sinon proposé si même fournisseur ; `doublon_de` : rejeté ici (règles dans L04-T23) ;
   - `evaluerPartieDe(globale, parties[])` : confirmé si Σ ttc des parties = globale.ttc au centime, sinon rejeté ;
   - deux pièces de même `id` = rejeté ; dates absentes ou invalides = rejeté pour `paiement_de`.
2. Tests nommés : `paiement-confirme`, `paiement-avant-facture-rejete`, `avoir-numero-cite-confirme` (avoir −120,00 citant F-0099), `avoir-sans-numero-propose`, `avoir-plus-grand-rejete`, `reemise-proposee`, `partie-de-somme-exacte`, `partie-de-un-centime-rejete`, `meme-piece-rejetee`.

Décision d'une personne, stockage du lien (`lien_piece`), effet TVA (lot TVA).

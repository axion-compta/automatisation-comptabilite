## Contexte
Spec 02, fichier 06 : « Petit écart : |écart| ≤ seuil paramétré (défaut 1,00 € ET ≤ 0,5 % du montant) → groupe proposé avec `proposition_ecart` (nature déduite : arrondi si ≤ 0,05 € ; frais bancaires si paiement en devise ou libellé de frais ; escompte si mention sur la facture). Compte proposé, jamais passé seul. » « Au-delà du seuil : paiement partiel ou mauvais candidat. » Trop-perçu (paie 1 210 au lieu de 1 200) → « à rembourser ou avoir à émettre par votre outil », jamais en produit. Test T06-3 : facture 1 200,00 payée 1 199,50 → écart 0,50 proposé, aucune écriture tant que non validé. Les seuils et les comptes sont des RÉGLAGES : en argument.

## À faire
1. `packages/noyau/src/banque/rapprochement/ecarts.ts` :
   - `qualifierEcart(entree: { montantPiece: Centimes; montantPaye: Centimes; enDevise: boolean; libelleFrais: boolean; escompteMentionne: boolean }, reglage: { seuilCentimes; seuilPb; seuilArrondi; comptes: Record<'arrondi' | 'frais_bancaires' | 'escompte', string> })` →
     `{ type: 'aucun' } | { type: 'petit_ecart'; ecart; nature; comptePropose } | { type: 'trop_percu'; ecart } | { type: 'partiel'; reste } ` ;
   - petit écart : les DEUX conditions (`|e| ≤ seuilCentimes` et `|e| × 10 000 ≤ seuilPb × montantPiece`, sans division) ; nature : arrondi si `|e| ≤ seuilArrondi`, sinon frais si devise ou libellé de frais, sinon escompte si mention, sinon `inconnu` (compte non proposé) ;
   - payé > pièce au-delà du seuil → `trop_percu` (aucun compte de produit) ; payé < pièce au-delà du seuil → `partiel` ;
   - aucune fonction de ce module ne crée d'écriture (test : le module n'importe pas `ecritures/`).
2. Tests nommés : `t06-3-cinquante-centimes`, `arrondi-sous-seuil`, `frais-en-devise`, `escompte-mentionne`, `nature-inconnue-sans-compte`, `deux-conditions-du-seuil` (écart sous le seuil en euros mais au-dessus du pourcentage → `partiel`), `trop-percu-jamais-produit`, `aucun-ecart`.

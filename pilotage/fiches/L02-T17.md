## Contexte
Spec 02, fichier 02, règle 8 : « contrôle `solde_ouverture + Σ montants complétés = solde_cloture` au centime. PDF texte : solde faux = import REFUSÉ avec explication. CSV/OFX sans soldes : accepté, `controle_solde = IMPOSSIBLE`. » Règle 9 : seules les lignes `completee` comptent. Tests T02-1 (1 000 000 − 234 567 = 765 433, OK), T02-4 (sans solde : `IMPOSSIBLE`), T02-5 (écart 1 000 → refus).

## À faire
1. `packages/noyau/src/banque/import/soldes.ts` :
   - `controlerSoldes(releve: ReleveLu, politique: { refuserSiEcart: boolean })` → `{ controle: 'OK' | 'ECART' | 'IMPOSSIBLE'; ecart?: Centimes; calcule?: Centimes; refuse: boolean }` ;
   - somme par `ajouter` (argent), lignes `completee` seulement ; `IMPOSSIBLE` si un des deux soldes manque (jamais `OK` par défaut, V3-PRI-007) ; `ecart = soldeCloture − calcule` (signé) ;
   - `refuse` vrai seulement si `controle = 'ECART'` ET `refuserSiEcart`.
2. Tests nommés : `t02-1-solde-ok`, `t02-4-sans-solde-impossible`, `t02-5-pdf-falsifie-refuse` (écart 1 000), `ecart-csv-signale-non-refuse`, `en-attente-exclue-de-la-somme`, `ecart-signe-negatif`, `ordre-des-lignes-sans-effet`.

## Hors périmètre
Chaînage d'un solde courant ligne à ligne (L02-T15). Trous entre relevés (L02-T04).

## Pièges
Cas limites exigés : 0 ligne (`calcule = soldeOuverture`), un seul solde présent, solde `NaN`, `Infinity` ou non entier (erreur `montant_invalide`, jamais `OK`), somme au-delà de l'entier sûr (erreur d'`argent`, propagée). Sensible (argent). Règles du noyau.

## Contexte
PLA-130 : bannière présente sur 100 % des écrans quand l'accès n'est pas actif (T-ABO-6), sans montant. Style de la console (D5) : 14 px, graisse 600 au plus, aucun bleu, thème clair ; jetons de L01-T27 seulement (`var(--…)`). Le composant ne contient AUCUN texte en dur : tout arrive par les propriétés (textes de L07-T23 choisis par l'appelant, L07-T27).

## À faire
1. `BanniereAcces.tsx` : propriétés `{ titre: string; consequence: string; prochaineEtape?: string; lien?: { libelle: string; href: string | null }; resume?: string; gravite: 'info' | 'attention' }` ; rendu `<section role="status" aria-labelledby=…>` (jamais `role="alert"` : la bannière est permanente, pas un événement) ; titre en `<h2>` ; lien rendu en `<a>` seulement si `href` commence par `https:` ; sinon le libellé est rendu en texte simple (pas de lien mort) ; `resume` rendu seulement s'il est non vide.
2. `banniere-acces.css` : variables de L01-T27 seulement ; deux variantes par `data-gravite` ; le sens est porté par le titre, jamais par la couleur seule.
3. Tests nommés (`// @vitest-environment jsdom`) : `role-status-et-titre-relie`, `lien-https-rendu`, `lien-sans-href-valide-texte-simple` (`null`, `javascript:alert(1)`, `http://exemple.invalid` : pas de `<a>`), `resume-vide-non-rendu`, `prochaine-etape-optionnelle`, `aucun-texte-en-dur` (rendu avec des propriétés vides : aucun nœud texte non vide), `css-sans-couleur-en-dur` (lecture du fichier css : aucune couleur littérale, seulement `var(--`).

## Hors périmètre
Pas d'appel au réseau, pas de montage dans la coque (L07-T27).

## Pièges
Ne pas modifier `composants.css` (L01-T29) : la feuille propre est importée par le composant. `garde:textes` refuse les textes en dur dans les `.tsx`. Le composant n'importe pas `packages/textes` (il reste générique).

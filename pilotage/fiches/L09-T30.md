## Contexte
Spec 09, §04 : contrat `profil.v1` : chaque champ porte `valeur`, `origine`, `confiance`, `source`, `date_source`, `statut` ; toute réponse de l'API est validée contre ce schéma en test ; une version 2 se fait par ajout, jamais par renommage. `GET /profil` (état, champs, statut de chaque champ) ; `GET /profil?au=2026-12-31` (lecture à une date). Le contrat fait foi (ADR 0002 et 0003). Emplacement figé par le plan du lot : schémas zod dans `packages/contrat/src/domaines/profil.ts`, JSON Schema dans `openapi.json`. Routes sans préfixe de société (L09-T49, bloquée) et aucune entrée qui porte la société (L13-T36) : le service en mémoire est créé pour UNE société.

## À faire
1. `packages/contrat/src/domaines/profil.ts` : schémas exportés `ChampProfilV1 { cle; valeur: json; origine; confiance; source: { ref; date } | null; statut; effetDebut }`, `ProfilV1 { version: 'profil.v1'; etat; champs: ChampProfilV1[]; manquants: string[]; aConfirmer: string[]; blocages: string[] }` (`blocages` : codes du hors périmètre de la spec §01 règle 6, ex. `commissaire_aux_comptes`, `siege_exclu`, `forme_hors_perimetre`), `ReponseProfil` (enveloppe `{ body: ProfilV1 }`) ; route oRPC `lireProfil` (`GET /profil`, query `au` facultative, date `AAAA-MM-JJ` stricte) ; listes d'énumération recopiées de la spec (le contrat n'importe pas le noyau).
2. `profil-service.ts` : service pur `creerServiceProfil(societeId)` bâti sur `genererProfils()` (L09-T29, import par chemin relatif comme L01-T23) : valeur en vigueur par clé à la date (`au` absente = date du jour passée par l'appelant), état calculé selon la règle de la spec §01 règle 1 et blocages selon la règle 6 (logique minimale, commentée « copie de lecture, la règle fait foi dans le noyau L09-T04 et L09-T07 » ; listes d'exclusion INVENTÉES, prises dans le jeu fictif).
3. `routes.ts` : ajouter `profil: { lireProfil }` au contrat sans toucher aux autres clés ; régénérer `openapi.json`.
4. `apps/serveur/src/domaines/profil.ts` : implémentation ; branchée dans `app.ts` (société fictive par défaut : Lemoine Rénovation).
5. Tests nommés : `profil-valide-contre-le-schema` (chaque réponse passe `ProfilV1.parse`), `lemoine-a-confirmer-p04`, `lecture-a-une-date-p24` (Boulangerie Rivoire : SARL avant, SAS à la date), `au-mal-formee-400` (`2026-02-30`, `31/12/2026`, chaîne vide), `cinq-attributs-par-champ`, `blocage-commissaire-aux-comptes` (un champ `a_commissaire_aux_comptes = oui` dans un service de test : `blocages` le contient, `etat` n'est jamais `complet`), `openapi-contient-lire-profil`, `serveur-repond-au-profil` (Fastify `inject`).

## Contexte
Spec 13, fichier 02, R15 : tout document produit (bilan, compte de résultat, annexe, balance, grand livre, journaux, déclarations préparées, PV, états de rapprochement, rapports de contrôle) passe par un seul rendu qui injecte la mention en en-tête et en pied, plus le validateur quand il existe. R16 : FEC et CSV n'ont pas de zone libre : la mention va dans un fichier compagnon `LISEZMOI.txt` et dans le manifeste, jamais dans le FEC. L03-T03 calcule déjà l'état de la mention (`etatMention`, codes seulement).

## À faire
1. `packages/noyau/src/documents/rendu.ts` (importe le type de sortie de `etatMention` depuis `mention.js` du même dossier) :
   - `FAMILLES_DOCUMENT` : les 10 familles de R15 en codes (`bilan`, `compte_resultat`, `annexe`, `balance`, `grand_livre`, `journaux`, `declaration_preparee`, `pv`, `etat_rapprochement`, `rapport_controles`) ;
   - `rendreDocument({ famille, corps, mention })` donne `{ famille; entete: { mention }; pied: { mention; validation? }; filigrane; corps }` ; famille inconnue : `ErreurRendu('famille_inconnue')` ;
   - `paquetSansZoneLibre({ format (fec ou csv); fichiers: { nom; contenu: Uint8Array }[]; mention })` donne les fichiers INCHANGÉS (mêmes octets), plus `compagnon: { nom: LISEZMOI.txt; mention }` et `manifeste: { mention }` ; fichier déjà nommé `LISEZMOI.txt` (casse ignorée) : `collision_compagnon` ; liste vide : `paquet_vide`.
2. Tests nommés : `dix-familles-exactement`, `mention-en-tete-et-en-pied`, `validateur-dans-le-pied`, `famille-inconnue-refusee`, `fec-octets-intacts-et-compagnon`, `collision-lisezmoi-refusee` (`lisezmoi.TXT`), `filigrane-repris-de-la-mention`.

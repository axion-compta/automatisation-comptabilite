## Contexte
Spec 09, §04 règles 2 à 4 : l'aperçu rend la liste chiffrée des objets touchés : brouillons recalculés (nombre), déclarations non déposées recalculées (périodes), échéances déplacées, écritures validées touchées = TOUJOURS 0 ; rien n'est enregistré sans « Confirmer ». Une date d'effet antérieure à une période dont la TVA est déposée est refusée (`periode_deposee`) : la correction passe par une régularisation proposée. Changement de date de clôture : appliqué à l'exercice suivant, jamais à un exercice dont les dates sont figées. Cas P13 (bascule légale : 0 écriture validée touchée) et P23 (fin d'exercice changée avec une écriture déjà validée : exercice en cours inchangé, exercice suivant proposé).

## À faire
1. `packages/noyau/src/profil/changements.ts` :
   - `Objets { brouillons: { id; date }[]; declarations: { periode: { debut; fin }; deposee: boolean }[]; echeances: { id; date; dependDe: string[] }[]; ecrituresValidees: { id; date }[] }` ;
   - `apercuChangement({ cle, effetDebut }, objets)` → `{ brouillonsRecalcules: number; declarationsRecalculees: { debut; fin }[]; echeancesDeplacees: string[]; ecrituresValideesTouchees: 0; refus?: 'periode_deposee' }` : seuls les objets à partir de `effetDebut` comptent ; une déclaration DÉPOSÉE dont la fin est ≥ `effetDebut` = refus, avec `regularisationProposee: true` ;
   - `changerDateCloture({ exerciceEnCours: { debut; fin; datesFigees: boolean }, nouvelleFinJourMois: string })` → exercice en cours inchangé si figé ; exercice suivant proposé de `fin + 1 jour` à la nouvelle date de fin ; durée hors bornes passées en argument (`dureeMinMois`, `dureeMaxMois`) = `ErreurProfil('duree_exercice_hors_bornes')` ;
   - le type de retour impose `ecrituresValideesTouchees: 0` (littéral de type) ; un test vérifie qu'aucune écriture validée n'apparaît dans les objets recalculés.
2.

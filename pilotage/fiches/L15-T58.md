## Contexte
Spec 15, PR-R4 : `raccourcis.actifs = false` désactive tout raccourci d'une seule touche ; « actifs seulement hors champ de saisie » est une règle de front (tests clavier). PR-R1 : `menu_etat` (`ouvert` 232 px, `reduit` 72 px) mémorisé par type d'appareil. La palette Ctrl+K (L00-T16, L01-T35) n'est pas un raccourci d'une lettre : elle reste active.

## À faire
1. `commandes/lettres.ts` : `installerLettres(cible: Window, { actifs: () => boolean; actions: Record<lettre, () => void> })` → fonction de retrait ; ignore la touche si `actifs()` est faux, si une touche de modification est enfoncée (Ctrl, Alt, Méta), si la cible est un `input`, `textarea`, `select` ou un élément `contenteditable`, ou si un dialogue modal est ouvert ; actions par défaut (proposition) : `c` cloche, `r` recherche ; lettres permises a-z.
2. `Coque.tsx` : installe les lettres avec `usePreference('raccourcis')` (L15-T56) ; bouton « Réduire le menu » qui écrit `menu_etat` ; largeur du menu selon `menu_etat` (classes CSS de `socle.css`).
3. `socle.ts` : textes nouveaux (ne pas renommer les clés existantes).
4. Tests nommés : `lettre-hors-champ-agit`, `lettre-dans-un-champ-ignoree` (input, textarea, contenteditable), `desactives-rien`, `avec-ctrl-ignoree`, `dialogue-ouvert-ignoree`, `retrait-des-ecouteurs`, `menu-reduit-memorise`, `palette-ctrl-k-toujours-active`.

## Hors périmètre
Pas de réaffectation des lettres dans l'écran (le serveur l'accepte déjà ; écran plus tard si Will le veut).

## Pièges
`Coque.tsx` est aussi touché par L15-T53 (dépendance) et par le lot 07 : une seule PR ouverte à la fois sur ce fichier. Les largeurs 232 et 72 px sont des jetons de design existants s'ils existent, sinon des variables CSS de `socle.css`.

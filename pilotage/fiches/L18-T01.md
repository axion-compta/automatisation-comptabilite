## Contexte
bloque_par: V1 : ne pas planifier avant la fin de la V0 (décision de Will, 11/11/2026)
Partie statistique de V3-REP-025 pour la V1 : la part de montants « ronds » dans les écritures d'un exercice repris. Le test de Benford est explicitement reporté en V2 par le critère du registre : il n'est pas fait ici. Existant : seuil de signification et statuts des constats (`packages/noyau/src/agents/reprise.ts`), type `Constat` et propriété par pôle (`packages/noyau/src/agents/hierarchie.ts`), gravités (`packages/noyau/src/chat/types.ts`), montants en centimes (`packages/noyau/src/argent/`).

## À faire
1. Tests d'abord, écritures fictives (comptes et libellés inventés), graine fixe.
2. `montants-ronds.ts` (pur, entiers seulement, aucune division flottante) :
   - `estRond(montant, pas)` : vrai si le montant en centimes est un multiple entier de `pas` (paramètre, jamais une valeur en dur).
   - `analyserMontantsRonds(lignes, p)` où `p = { pas, montantMinimum, effectifMinimum, seuilPdb }` → `{ etat: 'non_evalue'; motif: 'effectif_insuffisant' } | { etat: 'evalue'; effectif; ronds; partPdb; constats: Constat[] }`.
   - Un constat de type `montants_ronds` (gravité `mineur`, jamais `critique`) par compte dont la part de montants ronds dépasse `seuilPdb` ; les lignes sous `montantMinimum` ne comptent pas.
   - Paramètres invalides (pas ≤ 0, points de base hors 0 à 10 000) → `ErreurChat('parametre_invalide')`.
3. Tests nommés : `multiple-du-pas-est-rond`, `effectif-insuffisant-non-evalue`, `part-en-points-de-base-entiers`, `compte-au-dessus-du-seuil-un-constat`, `petits-montants-ignores`, `parametre-invalide-refuse`.

## Hors périmètre
Le constat « par compte » passe par un type local d'entrée défini dans `montants-ronds.ts` (le type `Constat` de `hierarchie.ts` n'a ni compte ni période). Test de Benford (V2), règles apprises (L18-T02), détecteur sémantique par IA, branchement dans le directeur de conformité, écran, textes, routes. Aucune modification de `reprise.ts`, `hierarchie.ts` ni `chat/types.ts`.

## Pièges
Un effectif trop faible donne « non évalué », jamais une part de zéro. Le constat signale, il ne conclut à aucune fraude : le type de constat seul, aucun texte affiché ici.

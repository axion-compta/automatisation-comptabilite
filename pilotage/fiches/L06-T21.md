## Contexte
Spec 06, `10-signalements-et-renvois.md` §1 : SUP-007, durée de conservation des signalements = paramètre daté de type « signalement » avec sa source citée (D45, D31 : jamais en dur, jamais de valeur par défaut) ; purge quotidienne. SUP-008 : l'outil d'erreurs ne reçoit que le code de corrélation, le nom de la route et le code d'erreur, JAMAIS de contenu client ; PLA-108 : 0 montant, 0 nom, 0 IBAN. Cas T-SUP-1 (partie rapport) et T-SUP-2.

## À faire
1. `packages/noyau/src/securite/signalements.ts` :
   - `signalementsAPurger(signalements: { id; creeLe }[], maintenant, dureeConservationMs: number | undefined)` → ids à purger (créés il y a STRICTEMENT plus que la durée) ; durée `undefined` → `ErreurSecurite('argument_invalide')` avec le message « paramètre de conservation absent » (aucune purge, aucune valeur par défaut) ; durée NaN, négative, non entière, `Infinity` → erreur ; `creeLe` invalide → l'id est rendu dans une liste `illisibles` à part (jamais purgé en silence) ;
   - `rapportOutilErreurs(source)` → `{ correlation_id; route; code }` SEULEMENT, quel que soit le contenu de `source` ; `correlation_id` hors forme UUID → `'inconnu'` ; `route` limitée aux caractères `[a-zA-Z0-9/_{}.-]` (le reste retiré) ; `code` limité à `[A-Z_a-z]`.
2. Tests nommés (durée inventée) : `duree-plus-un-jour-purge` (T-SUP-2), `duree-moins-un-jour-present`, `frontiere-exacte-presente`, `duree-absente-refusee`, `duree-invalide-refusee`, `date-illisible-a-part`, `rapport-trois-champs-seulement` (source avec montant, nom de tiers et IBAN fictifs : aucun dans le résultat sérialisé, T-SUP-1), `correlation-mal-formee-inconnu`, `route-nettoyee`.

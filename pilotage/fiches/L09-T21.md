## Contexte
Spec 09, §04 règle 1 : tout changement crée une ligne datée ; au MVP, la consultation « au 31/12/N-1 » lit ces lignes (l'écran de consultation est en V1). Cas P24 : forme SARL puis SAS à une date d'effet : la lecture avant rend SARL, à la date rend SAS ; 0 écriture validée modifiée.

## À faire
1. `packages/noyau/src/profil/profil-au.ts` :
   - `profilAu({ champs, imposition }, societeId, date)` → `{ date; champs: Record<cle, { valeur; statut; origine; confiance; effetDebut }>; imposition: LigneImposition | null }` : pour chaque clé présente, `valeurEnVigueur` (L09-T03) ; `impositionAuJour` (L09-T11) ;
   - clés triées ; une clé sans valeur à la date est ABSENTE (jamais `undefined` dans l'objet) ;
   - résultat gelé (`Object.freeze` profond sur les objets créés) ; les entrées ne sont jamais modifiées.
2. Tests nommés : `forme-changee-p24` (veille de l'effet : SARL ; jour : SAS ; lendemain : SAS), `cle-absente-avant-premier-effet`, `imposition-a-la-date`, `entrees-non-modifiees` (entrées gelées), `resultat-gele`, `societe-voisine-ignoree`, `date-invalide-refusee` (`2026-12-32`, chaîne vide).

## Hors périmètre
Pas de route (`GET /profil?au=`, L09-T30) ; pas d'écran de consultation (V1).

## Pièges
Règles du noyau comme L01-T06. Ne pas recopier la logique de `valeurEnVigueur` : l'importer par chemin relatif.

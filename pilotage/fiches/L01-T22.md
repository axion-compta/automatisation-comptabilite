## Contexte
Les écrans N03 (années comptables), N04 (comptes) et E44 (clients et fournisseurs) tournent sur le faux serveur et le serveur en mémoire. Il faut un jeu comptable fictif unique, à graine fixe (V3-DEM-004), réutilisé par les deux (aucune donnée réelle, V3-PRI-017).

## À faire
1. `packages/donnees-fictives/src/compta.ts` (réutilise `creerAlea` et `GRAINE` de `./generateur.js`, sans modifier ce fichier) :
   - `genererCompta(graine = GRAINE)` → `{ version: 1, societes: SocieteCompta[] }` pour les profils `pleine` et `vide` ;
   - `SocieteCompta { profil; exercices: { id, libelle, debut, fin, statut: 'ouvert' | 'cloture' }[]; plan: { numero, libelle, classe }[]; tiers: { code, nom, type: 'client' | 'fournisseur', email }[]; ecritures: { id, journal, date, statut, lignes: { compte, auxiliaire?, libelle, debitCentimes, creditCentimes }[] }[] }` ;
   - profil `pleine` : 2 exercices (un clos, un ouvert), environ 25 comptes des classes 1 à 7 à libellés génériques, 6 clients `CLI001`… et 6 fournisseurs `FOU001`… aux noms inventés et e-mails `@exemple.fr`, 40 écritures validées équilibrées et 3 brouillons ; profil `vide` : 1 exercice ouvert, plan vide, aucun tiers, aucune écriture ;
   - `serialiserCompta(jeu)` (JSON stable, clés triées).
2. Tests nommés : `meme-graine-meme-empreinte` (SHA-256 de `serialiserCompta` figé dans le test), `ecritures-equilibrees`, `codes-tiers-uniques`, `emails-exemple-fr`, `profil-vide-sans-ecriture`, `un-exercice-clos-un-ouvert`, `comptes-des-ecritures-dans-le-plan`.

## Hors périmètre
Pas de fichier JSON versionné (l'empreinte du test suffit), pas de modification de `generateur.ts` ni de `donnees/v1.json`, pas de pièces.

## Pièges
Aucun montant décimal : centimes entiers. Aucun nom réel, aucun prix réel, aucun IBAN. Dates fictives dans les années 2025 et 2026.

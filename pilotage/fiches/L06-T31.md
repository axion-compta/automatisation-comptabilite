## Contexte
MOD-004, « rien n'est grisé sans raison » : une action refusée reste visible, avec la phrase du serveur. Un bouton `disabled` n'est pas atteignable au clavier et sa raison n'est pas lue : on garde un bouton focalisable `aria-disabled="true"` relié à la phrase par `aria-describedby`.

## À faire
1. `packages/ui/src/composants/ActionAvecRaison.tsx` : props `{ libelle: string; capacite: { permis: true } | { permis: false; raison_texte: string }; onAction: () => void }` ; permis → bouton de base (L01-T29) ; refusé → bouton `aria-disabled="true"`, `onAction` jamais appelé (clic, Entrée, Espace), phrase VISIBLE sous le bouton (pas une infobulle), reliée par `aria-describedby` (id stable par `useId`) ; refusé avec une phrase vide ou absente → le composant lève une erreur (le test rougit plutôt que d'afficher un bouton grisé muet).
2. `packages/ui/src/composants/action-avec-raison.css` : jetons seulement (D5 : 14 px, graisse 600 au plus, aucun bleu).
3. Tests nommés : `permis-appelle-l-action`, `refuse-n-appelle-pas-au-clic`, `refuse-n-appelle-pas-au-clavier`, `refuse-reste-focalisable`, `phrase-visible-et-reliee` (`aria-describedby` pointe vers le texte), `phrase-vide-leve-une-erreur`, `deux-actions-deux-ids`.

## Hors périmètre
Lecture des capacités (L06-T33) ; aucun écran.

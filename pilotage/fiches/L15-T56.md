## Contexte
Spec 15, PR-R1 : le profil serveur est la référence ; le front garde une copie locale ; serveur injoignable : la copie locale s'applique et AUCUN message d'erreur n'est affiché ; au retour, le front rejoue ses écritures (`PUT` idempotent). Clés de disposition par type d'appareil (`bureau`, `mobile`).

## À faire
1. `donnees/preferences.tsx` : `FournisseurPreferences` et `usePreference(cle)` → `[valeur, ecrire]` ; appareil = `mobile` si `matchMedia('(max-width: 767px)')` (même borne que la coque, lue dans le CSS existant ; sinon constante nommée), sinon `bureau` ; lecture `GET /preferences?appareil=` au montage ; copie locale dans `localStorage` (clé `axion.preferences.v1`), valeurs relues par le validateur de L15-T27 avant usage (copie corrompue = ignorée) ; `ecrire` applique tout de suite, met en file `{ cle, valeur, appareil, modifieLeClient, idempotencyKey }` dans `localStorage`, envoie `PUT` ; échec réseau = garde en file, AUCUN message ; rejeu à l'événement `online` et à chaque montage, dans l'ordre, une seule fois par clé d'idempotence.
2. Tests nommés (jsdom, `demarrerNoeud`, panne `x-panne: reseau`) : `lecture-serveur-au-montage`, `copie-locale-si-serveur-injoignable`, `aucun-message-d-erreur`, `ecriture-mise-en-file-si-panne`, `rejeu-au-retour-dans-l-ordre`, `rejeu-une-seule-fois` (même clé d'idempotence), `copie-corrompue-ignoree`, `appareil-mobile-ou-bureau`.

## Hors périmètre
Pas d'écran de réglages (L15-T57), pas de montage dans la coque (L15-T58).

## Pièges
Aucune donnée personnelle dans `localStorage` (préférences d'affichage seulement). Ne pas modifier `api.ts` ni `lecture.tsx`.

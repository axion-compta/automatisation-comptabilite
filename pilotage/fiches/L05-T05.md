## Contexte
Spec 05, fichier 04 §1 : chaque outil déclare nom, niveau, permission `compta-*`, schéma d'entrée, schéma de sortie, codes d'erreur fermés, exigences. Entrées : JSON strict, SANS `tenant_id` ni `societe_id` (pris dans la session), identifiants opaques, montants en centimes entiers, devise ISO 4217 ; paramètre hors schéma = `parametre_invalide`. Le modèle n'a AUCUN outil `appliquer` (fichier 04 §3).

## À faire
1. `outils.json` (lu aussi par la garde L05-T06) : liste `{ nom, niveau, permission, outil_registre, exigences, codes_erreur }` pour les outils des domaines publics : `exercices.lister`, `plan.lister`, `tiers.lister`, `ecritures.lister` (L, `compta-lire`), `vue.ouvrir` (L, navigation), `proposer_validation` (B, `compta-saisir`) ; `outil_registre` = id d'un outil de `registre.json`.
2. `outils.ts` : schémas zod `.strict()` d'entrée et de sortie par nom ; `schemaEntree(nom)` ; `validerEntree(nom, brut)` → `{ ok: true; valeur } | { ok: false; code: 'parametre_invalide' | 'outil_hors_liste' }` ; `NOMS_OUTILS` tiré du JSON.
3. Tests nommés : `chaque-nom-a-ses-schemas`, `aucun-outil-appliquer`, `champ-societe-refuse` (`societe_id`, `tenant_id`, `societeId`), `parametre-en-trop-refuse`, `montant-non-entier-refuse` (1.5, NaN, Infinity, "10"), `devise-invalide-refusee`, `outil-inconnu-hors-liste`, `outil-registre-existe`, `noms-uniques`.

## Hors périmètre
Pas d'exécution des outils (L05-T39), pas de garde (L05-T06).

## Pièges
Fiche sensible (outils du chat). `outils.json` n'est modifié par AUCUNE autre fiche du lot : un outil oublié se déclare dans une fiche de suivi. Aucun outil de niveau I ouvert au chat.

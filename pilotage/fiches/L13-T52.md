## Contexte
Débloquée par les décisions de Will du 07/11/2026 : D43 tranchée (fournisseurs d'IA de l'Union européenne en liste fermée modifiable, passerelle unique) et J3a donné avec quatre conditions (données FICTIVES seulement ; fiche sensible relue par Opus ; aucune mise en production sans le feu vert J10 ; ce qui exige le vrai schéma de la console s'écrit contre une interface et un faux serveur). Ici rien ne touche la console ni un modèle : l'outil est seulement DÉCLARÉ dans le contrat.
Spec 13, fichier 05, R07 : l'outil en lecture seule `change.expliquer_ecart` appelle `GET /ecarts-change/{id}/explication` (route `expliquerEcartChange`, schéma `ExplicationEcart`, erreur `ECART_INCONNU` 404 : L13-T34), la même route que l'écran ; test MOT97-3 : 0 écriture, 0 geste. R04 : entrée sans `societe_id` (la société vient de la session).
Le « registre des outils du chat » est `packages/contrat/src/chat/outils.json` (L05-T05, dont le piège dit qu'un outil oublié se déclare dans une fiche de suivi : c'est celle-ci). L'outil se rattache à l'outil générique `outil_lire` de `packages/contrat/src/actions/registre.json` (niveau L, `chat: "ouvert"`, action `lire`, interrupteur `lecture` déclaré `actif_par_defaut: false`) : `registre.json` n'est PAS modifié, garde:actions et garde:interrupteurs restent vertes sans y toucher.
Symboles réutilisés et LUS : `OUTILS`, `schemaEntree`, `schemaSortie`, `validerEntree` (L05-T05) ; `registre` (L05-T01) ; `genererOpenapi` (L01-T23) ; `ROUTES_EXTERNES` (L13-T36) ; `ROUTES_A_GESTE`, `VERBES_SENSIBLES` (L13-T37) ; `ExplicationEcart` (L13-T34). Aucun fichier commun (`routes.ts`, `app.ts`, `openapi.json`, `openapi.ts`, `registre.json`) n'est modifié.

## Contexte
Spec 04, fichier 02 §Dates et période : « Statut de période calculé par code d'après les dates de la société : avant_depot, formation, entre_immatriculation_et_exercice, dans_exercice, hors_exercice. Toute pièce antérieure au premier exercice va dans la liste "pièces antérieures" avec la décision à prendre ; aucune n'est rangée d'office. » L'exercice est déduit de la date de la pièce ; vide si hors de tout exercice.

## À faire
1. `packages/noyau/src/pieces/classement/periode.ts` :
   - `DatesSociete { depotStatuts?: string; immatriculation?: string; exercices: { id: string; debut: string; fin: string }[] }` (dates ISO `AAAA-MM-JJ`, fin INCLUSE) ;
   - `statutPeriode(datePiece, dates)` → `{ statut: StatutPeriode; exerciceId?: string; anterieure: boolean }` : dans un exercice = `dans_exercice` + id ; avant `depotStatuts` = `avant_depot` ; entre dépôt et immatriculation = `formation` ; entre immatriculation et le début du premier exercice = `entre_immatriculation_et_exercice` ; sinon `hors_exercice` ; `anterieure` = date < début du premier exercice ;
   - date ou bornes au mauvais format, exercice dont `debut > fin`, exercices qui se chevauchent : `ErreurPiece('dates_invalides')` ; exercices reçus dans le désordre : triés avant calcul.
2. Tests nommés (dates inventées) : `dans-exercice`, `borne-de-fin-incluse`, `avant-depot`, `formation`, `entre-immatriculation-et-exercice`, `hors-exercice-apres-le-dernier`, `exercices-dans-le-desordre`, `dates-invalides-refusees` (`2026-02-30`, chaîne vide, chevauchement, début après fin).

## Hors périmètre
Création ou clôture d'exercice (L01-T13).

## Pièges
Comparaison de dates ISO par chaîne seulement après validation du format et de la date réelle. Aucune date littérale dans `src` (garde L01-T02). Règles du noyau comme L04-T00.

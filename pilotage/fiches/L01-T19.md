## Contexte
Spec 12, §01 : résultat d'un contrôle parmi OK, ALERTE, IMPOSSIBLE, NON_APPLICABLE, ECARTE ; « Les contrôles réussis sont aussi écrits. » Chaque règle a un id, une gravité (B, M, m, I), une version, ce qu'elle bloque et ses déclencheurs (arrivée, continu, nocturne, avant TVA, avant export, avant clôture, à la demande). PRI-007 : un contrôle qui n'a pas pu tourner n'est jamais compté OK.

## À faire
1. `packages/noyau/src/controles/moteur.ts` :
   - types `Gravite`, `Declencheur`, `Blocage`, `Resultat = 'OK' | 'ALERTE' | 'IMPOSSIBLE' | 'NON_APPLICABLE' | 'ECARTE'` ;
   - `RegleControle<T> { id; version; gravite; bloque: Blocage[]; declencheurs: Declencheur[]; actif: boolean; evaluer(objet: T): { resultat; valeur?; ecartCentimes? } }` ;
   - `executerControles(regles, objets: { type; id; donnee }[], declencheur, horodatage)` → une `TraceControle` par couple règle × objet : `{ horodatage, declencheur, regleId, versionRegle, objetType, objetId, resultat, valeur?, ecartCentimes? }` ; règle inactive ou hors déclencheur = aucune trace ; `evaluer` qui lève une exception = `IMPOSSIBLE` (jamais OK) ; `declencheur = 'avant_export'` exécute TOUTES les règles actives ;
   - `docs/controles.csv` : en-tête seul `id,exigence,gravite,bloque,declencheurs,phase,test_id,parametres,actif`.
2. Tests nommés : `ok-aussi-trace`, `exception-donne-impossible`, `regle-inactive-ignoree`, `hors-declencheur-ignoree`, `avant-export-tout-le-catalogue`, `une-trace-par-regle-et-objet`, `version-dans-la-trace`.

## Hors périmètre
Pas de règle métier (L01-T21), pas de garde-fou (L01-T20), pas de stockage.

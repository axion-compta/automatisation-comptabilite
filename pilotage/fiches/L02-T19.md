## Contexte
Spec 02, fichier 02, règle 7 : « IBAN lu (comparé au haché) ; sinon solde d'ouverture = solde de clôture d'un relevé connu ; sinon question « Quel compte ? » avec les comptes proposés. Mauvais compte détecté = import bloqué en `a_confirmer`. » Fichier 09 : un relevé est rattaché à UN compte.

## À faire
1. `packages/noyau/src/banque/import/rattachement.ts` :
   - `rattacher(entree: { ibanHache?: string; soldeOuverture?: Centimes; periodeDebut?: string }, comptes: { id; ibanHache?; ferme: boolean; dernierReleve?: { soldeCloture?: Centimes; periodeFin } }[], compteChoisi?: string)` →
     `{ type: 'compte'; compteId; par: 'iban' | 'solde' | 'choix' } | { type: 'question'; comptes: string[] } | { type: 'mauvais_compte'; choisi: string; lu: string }` ;
   - ordre : IBAN haché égal (comptes fermés exclus) ; sinon un SEUL compte dont le dernier solde de clôture égale le solde d'ouverture ET dont la fin précède le début du relevé ; plusieurs : question ; aucun : question avec tous les comptes ouverts ;
   - `compteChoisi` différent du compte trouvé par l'IBAN → `mauvais_compte` ; `compteChoisi` sans IBAN lu → `choix` ;
   - comparaison des hachés par une fonction passée en argument (`memeIban` de L02-T18 en production ; égalité simple dans les tests).
2. Tests nommés : `par-iban`, `par-solde-unique`, `deux-soldes-egaux-question`, `aucun-indice-question-tous-comptes`, `compte-ferme-exclu`, `mauvais-compte-bloque`, `choix-sans-iban-accepte`.

## Hors périmètre
Hachage (L02-T18). Création d'un compte depuis le premier relevé (bloqué : L02-T63).

## Pièges
Cas limites exigés : liste de comptes vide (question avec liste vide), solde d'ouverture `NaN` ou non entier (ignoré pour la règle du solde, jamais égal), `compteChoisi` inconnu (erreur `compte_inconnu`), ordre des comptes sans effet sur le résultat. Règles du noyau.

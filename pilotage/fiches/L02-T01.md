## Contexte
Spec 02, fichier 02, règle 3 : « pdf.js `isEvalSupported=false`, taille max 20 Mo » ; XLSX et PDF texte au MVP. Les deux lectures demandent une bibliothèque : `pdfjs-dist` (texte d'un PDF) et `fflate` (archive d'un XLSX, sans dépendance). Elles vont dans `apps/serveur`, jamais dans le noyau (pur) ni dans `apps/web`.

## À faire
1. `apps/serveur/package.json` : ajouter `pdfjs-dist` et `fflate` en `dependencies`, versions EXACTES ; `pnpm install` met à jour `pnpm-lock.yaml`.
2. `apps/serveur/src/__tests__/dependances-lecture.test.ts` : test `dependances-chargees` : import du point d'entrée Node documenté de `pdfjs-dist` (version « legacy » si la version l'exige) et de `fflate` ; `zipSync` puis `unzipSync` d'un fichier texte de 3 octets rend les mêmes octets.
3. Journal : versions retenues, date de publication, licence, poids installé.

## Hors périmètre
Aucun code de lecture (L02-T02, L02-T03). Aucune autre dépendance.

## Pièges
Sensible (dépendance, `pnpm-lock.yaml`) : le portier refuse toute PR qui touche un `package.json`. Version publiée depuis 14 jours au moins. Vérifier que `pdfjs-dist` n'exige pas de module natif (`canvas`) : s'il l'exige, choisir l'option sans canvas documentée ; sinon arrêter et le noter dans le journal. Licences attendues : Apache-2.0 (pdfjs-dist), MIT (fflate) ; une autre licence = arrêt.

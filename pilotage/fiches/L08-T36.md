## Contexte
Contrat figé par L08-T33. Le service est PUR et en mémoire (comme `fin-contrat-service.ts` de L07-T20) : il sert au serveur en mémoire et au faux serveur (L08-T37). Il assemble les règles du noyau sans les réécrire : échéance et transitions (L08-T22), recherche (L08-T23), décision d'effacement (L08-T25), marques (L08-T26). Réglages : délai de réponse et rappel passés en options (valeurs FICTIVES dans les tests ; les vraies viendront de L08-T02). Conservation : règles fictives du jeu (aucune durée réelle).

## À faire
1. `packages/contrat/src/domaines/personnes-service.ts` : `creerServicePersonnes({ horloge; dateReference; moisReponse; joursRappel; regles; jeu = genererRgpd(...) })` → `{ lister(); enregistrer(cle, corps); rechercher(query); traiter(cle, id, corps); journal() }` :
   - `lister` : demandes triées par échéance puis id ; `en_retard` et `a_rappeler` calculés à la date de l'horloge ; `conserve_jusqu_au` rempli pour un refus de conservation ;
   - `enregistrer` : `nouvelleDemande` (L08-T22) ; id = `dem-` + compteur ;
   - `rechercher` : `rechercherPersonne` (L08-T23) sur le jeu, données marquées `a_effacer` ou `oubliee` EXCLUES (`filtrer` de L08-T26 avec l'usage `affichage`) ;
   - `traiter` : `changerEtat` (L08-T22) ; pour une demande d'effacement, l'issue vient de `deciderEffacement` (L08-T25) et NON du corps si celui-ci la contredit (`ISSUE_NON_PERMISE`) ; `a_effacer` pose la marque (L08-T26) sur les objets trouvés ; aucune suppression ;
   - traduction des codes : `deja_traitee` → `DEJA_TRAITEE`, `transition_interdite` → `TRANSITION_INTERDITE`, `issue_non_permise` → `ISSUE_NON_PERMISE`, `motif_manquant` → `MOTIF_MANQUANT`, `source_manquante` → `SOURCE_MANQUANTE`, `recherche_vide` → `RECHERCHE_VIDE`, `recherche_trop_courte` → `RECHERCHE_TROP_COURTE`, id inconnu → `DEMANDE_INTROUVABLE` ; toute autre erreur → 500 ;
   - idempotence par clé : même clé = même réponse, un seul événement au journal.

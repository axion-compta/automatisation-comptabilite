## Contexte
Spec 06, `02-identite-connexion.md` §2 : lire, déposer, proposer exigent `acr` = « mfa » ; les actions sensibles (ROL-009) exigent en plus une connexion récente (`auth_time`), sinon 401 `reauthentification_requise` ; le délai est celui de la console, le module « ne fixe pas son propre délai ». §4 et point P3 : actions sensibles refusées pendant une période après une récupération du facteur. Cas C14, T-CNX-2, T-CNX-3. Délai et période sont des ARGUMENTS.

## À faire
1. `packages/noyau/src/securite/connexion.ts` : `exigerNiveau(revendications: { acr?: string; authTime?: number }, operation: OperationSensible | 'ordinaire', maintenantMs, reglages: { reauthMaxMs: number; attenteApresRecuperationMs: number }, derniereRecuperationMs?: number)` → `{ ok: true } | { ok: false; raison: 'non_authentifie' | 'mfa_requis' | 'reauthentification_requise' | 'recuperation_recente' }` :
   - revendications absentes → `non_authentifie` ; `acr` différent de `'mfa'` (casse comprise) → `mfa_requis` pour TOUTE opération ;
   - opération sensible et `maintenantMs - authTime*1000 > reauthMaxMs` → `reauthentification_requise` (`authTime` en secondes, comme dans un jeton) ; `authTime` dans le futur → `reauthentification_requise` ;
   - opération sensible et récupération plus récente que `attenteApresRecuperationMs` → `recuperation_recente`.
   - réglages absents, NaN, négatifs, non entiers ou `Infinity` → `ErreurSecurite('argument_invalide')`.
2. Tests nommés (valeurs inventées) : `sans-mfa-aucune-operation` (T-CNX-2), `ordinaire-avec-mfa-permis-meme-vieux`, `sensible-au-dela-du-reglage-refuse` (C14, T-CNX-3), `sensible-en-deca-permis`, `frontiere-exacte-permise`, `auth-time-futur-refuse`, `recuperation-recente-bloque-les-sensibles`, `recuperation-ancienne-sans-effet`, `reglages-invalides-refuses`.

## Contexte
Il n'existe pas de manifeste par écran. La cible compte 84 écrans ; la garde vérifie d'abord les écrans présents dans `apps/web/src/ecrans/`.

## À faire
1. Tests d'abord.
2. `manifeste-ecrans.json` : une ligne par dossier d'écran présent : `{ ecran, route, outil_chat, jeu: "commun" }` ; `outil_chat` est un nom de `packages/contrat/src/chat/outils.json` (à défaut `vue.ouvrir`).
3. `manifeste-ecrans.mjs` : rouge si un dossier d'écran n'a pas de ligne, si une ligne n'a pas de dossier, si `route` ou `outil_chat` manque, si l'outil est inconnu, si `jeu` n'est pas `commun`.
4. Tests nommés : `manifeste-complet-vert`, `ecran-sans-ligne-rouge`, `ligne-sans-ecran-rouge`, `outil-inconnu-rouge`, `jeu-propre-rouge`.

## Hors périmètre
Matrice de parité outil, route et contrôle d'écran (V3-VAL-001, autre plage). Les 84 écrans (le manifeste suit les écrans au fil des lots).

## Pièges
La garde lit `outils.json` sans le modifier. Fiche sensible : relecture Opus, fusion par Will seul. Données fictives seulement (noms inventés, e-mails en @exemple.fr) ; aucune valeur commerciale dans les textes.

## Contexte
Spec 12, `05-traitement-des-doutes`, C5 (V3-CTL-045) : « Action touchant plus de 25 objets ou plus de 1 000,00 € (paramètres réglables) : confirmation renforcée avec récapitulatif chiffré (nombre, total, comptes touchés). Sans confirmation, rien n'est appliqué. » Cas CT-38 (26 objets pour 980,00 : renforcée ; 25 objets pour 1 000,00 : simple ; 3 objets pour 1 000,01 : renforcée). « Plus de » = strictement supérieur.

## À faire
1. `packages/noyau/src/controles/doutes/confirmation.ts` :
   - `recapitulatif(objets: { montant: Centimes; compte: string }[])` → `{ nombre; total: Centimes; comptes: string[] /* triés, sans doublon */ }` ;
   - `niveauConfirmation(recap, seuils: { objets: number; montant: Centimes })` → `'simple' | 'renforcee'` ;
   - `peutAppliquer(niveau, confirmation: { renforceeCochee: boolean; recapitulatifVu?: recap })` → vrai pour `simple` ; pour `renforcee`, seulement si cochée ET récapitulatif vu identique.
2. `packages/noyau/src/controles/doutes/__tests__/confirmation.test.ts`, tests nommés : `CT-38` (3 cas, seuils de TEST 25 et 100 000 centimes), `comptes-sans-doublon`, `renforcee-sans-coche-refusee`, `recapitulatif-different-refuse`, `montants-negatifs-additionnes` (avoir), `liste-vide-simple`, `seuils-invalides` (NaN, −1, 2,5).

## Hors périmètre
Composant d'affichage (L12-T46). Validation d'un lot (L12-T32).

## Pièges
Règles du noyau comme L01-T06 : montants en `Centimes` via `packages/noyau/src/argent`, ni `/`, ni littéral décimal, ni `Math.round`, ni `parseFloat`, ni `toFixed`. Stryker (seuil 80 %) porte sur tout le noyau : chaque branche doit être tuée par un test. Ne pas toucher `packages/noyau/src/index.ts` ni `controles/moteur.ts` (imports par chemin relatif). Aucun taux, seuil, délai ni date légale dans `src` (garde:litteraux, D31) : tout seuil ou tolérance arrive en argument ou dans un `ParametreLu` (L12-T00) ; paramètre absent = `IMPOSSIBLE`, jamais OK (PRI-007). Le noyau ne contient aucun texte affiché : seulement des codes. Montants et seuils des tests INVENTÉS ou repris des cas fictifs de la spec ; noms et SIREN fictifs seulement. Cas limites exigés dans les tests : montant NaN, Infinity, non entier (1,5) et négatif là où il est interdit = exception codée (le moteur la change en `IMPOSSIBLE`) ; liste vide ; objets reçus dans l'ordre inverse (même résultat) ; écart d'exactement un centime de chaque côté de la tolérance. Chaque test doit rougir si l'on casse la branche qu'il couvre (inverser une comparaison, retirer un cas). Sensible (argent).

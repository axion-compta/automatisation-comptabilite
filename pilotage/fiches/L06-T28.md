## Contexte
Spec 06, `03-roles-permissions.md` §3 : « Le serveur expose `GET /api/compta/v1/societes/{s}/moi/capacites` : pour chaque action, `permis` (oui ou non) et, si non, `raison_code` et `raison_texte` (une phrase). […] Le front n'invente aucune raison. » Le préfixe de société attend D29 (fiche bloquée L06-T38) : la route est `/moi/capacites` comme les routes du lot 01. La session réelle attend J3a : `creerApp` reçoit une session SEULEMENT par son option `securite.session`, utilisée par les tests ; sans session → 401.

## À faire
1. `packages/contrat/src/domaines/capacites.ts` : route `GET /moi/capacites`, `operationId: 'lireCapacites'`, erreur déclarée `NON_AUTHENTIFIE` (401) ; schémas EXPORTÉS `Capacite = { action: string; permis: boolean; raison_code?: string; raison_texte?: string }` et `ReponseCapacites = { body: Capacite[] }` (le front les importe, leçon de L01-T47 et L01-T52). Routes sous la constante `PREFIXE_ROUTES_SOCIETE` de `packages/contrat/src/prefixe-routes.ts` (L00-T50 ; valeur par défaut `/api/compta/v1/societes/{s}`, en attente de l'ADR 0060) ; aucun préfixe écrit en dur. Capacités calculées à partir des `permissions` de la `Session` (L00-T50).
2. `packages/contrat/src/routes.ts` : ajouter la clé `capacites` au contrat ; `packages/contrat/openapi.json` : régénéré.
3. `apps/serveur/src/domaines/capacites.ts` : `routesCapacites(options)` ; calcule `capacites(contexte)` (L06-T06) depuis `options.securite.session` (`{ role, permissions, personneId, demande5, separationTaches, mode? }`) ; ajoute `raison_texte` lu dans `packages/textes/src/ecrans/securite.ts` (L06-T30) ; session absente → 401 `NON_AUTHENTIFIE`.
4. `apps/serveur/src/app.ts` : brancher `capacites: routesCapacites(options)` ; `apps/serveur/src/securite/index.ts` : ajouter `session?` au type `OptionsSecurite`.
5. Tests nommés : `contrat-route-get-sans-idempotence`, `schemas-exportes`, `sans-session-401`, `lecture-dix-refus-dix-phrases` (C25), `administrateur-tout-permis-ou-raison`, `chaque-raison-a-une-phrase` (toutes les `RAISONS` de L06-T00 ont un texte non vide), `aucun-en-tete-ne-change-le-role` (envoyer `x-role: administrateur` ne change rien), `ordre-des-actions-stable`.

## Hors périmètre
Faux serveur (L06-T29), front (L06-T33), lecture du jeton (fiche bloquée L06-T36).

## Pièges
Serveur : ne jamais lire un rôle ni une société dans un en-tête de la requête (seule l'option `securite` de `creerApp`, utilisée par les tests, injecte une session). Format d'erreur identique à celui de `packages/faux-serveur/src/handlers.ts` (`{ defined, code, status, message, data? }`). Les tests existants de `apps/serveur` et du faux serveur restent verts. Cas limites obligatoires : en-têtes absents, vides, en double, trop longs ; options absentes (rien ne change) ; réglages NaN, Infinity, négatifs ou non entiers refusés. Chaque test doit rougir si l'on retire la protection qu'il couvre (vérifié à la main, noté au journal). Données fictives seulement. `app.ts` implémente le contrat entier : la route et son handler arrivent dans la même PR. Si un autre lot a modifié `routes.ts` ou `openapi.json` entre-temps, remettre la branche à jour et régénérer `openapi.json`. Fiche sensible (droits).

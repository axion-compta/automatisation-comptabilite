## Contexte
Spec 11, fichier 03 : `d` = distance ANNUELLE professionnelle, par personne et par véhicule (table `cumul_km`). Tant que la ligne de barème de l'année est `a_verifier` : le trajet est enregistré, AUCUN montant (null), aucune écriture. À la validation de la ligne (source citée + contrôle croisé + geste humain), tous les trajets de l'année sont calculés d'un coup et proposés. Point P1 (recommandation suivie) : pas de barème précédent appliqué en provisoire. Cas NF-12.

## À faire
1. `packages/noyau/src/frais/ik-annee.ts` :
   - `calculerAnnee(trajets: readonly { fraisId; personneId; vehiculeId; date; kmRetenusDixiemes; electrique: boolean; puissanceCv }[], bareme: { statut: string; bareme?: BaremeIk; majorationPourcent?: number })` → `{ montants: Map<fraisId, Centimes | null>; cumuls: { personneId; vehiculeId; kmDixiemes; sommeProvisoires: Centimes }[] }` ;
   - statut autre que `valide` → tous les montants `null`, cumuls en km seulement (somme 0) ;
   - ordre de calcul : par date, puis `fraisId` (l'ordre d'entrée n'a aucun effet) ; cumul séparé par couple (personne, véhicule) ;
   - trajets de deux années civiles différentes → `entree_invalide` ; `fraisId` en double → `entree_invalide` ; liste vide → résultat vide.
2. Tests nommés (barème INVENTÉ de L11-T15) : `nf12-bareme-a-verifier-aucun-montant`, `nf12-puis-valide-tout-calcule` (même liste, ligne passée à `valide` : 80 km × 0,500 = 40,00), `ordre-d-entree-sans-effet` (liste inversée → même résultat), `cumul-par-vehicule`, `cumul-par-personne`, `meme-date-tri-par-id`, `deux-annees-refusees`, `id-en-double-refuse`, `somme-des-provisoires-dans-le-cumul`.

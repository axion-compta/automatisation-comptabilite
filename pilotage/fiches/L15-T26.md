## Contexte
Spec 15, RE-R4 : `extrait` = texte ÉCHAPPÉ (HTML) dans lequel seuls les mots trouvés sont entourés de `<mark>` ; tri par score puis date décroissante ; 20 résultats par page, 5 par groupe pour l'omnibarre. Cas limite : un texte lu contenant `<script>` ou `=HYPERLINK(…)` donne un extrait échappé. Recherche vide de résultat : liste vide, jamais une erreur.

## À faire
1. `recherche/extrait.ts` :
   - `echapperHtml(s)` : `&`, `<`, `>`, `"`, `'` ;
   - `extrait(texte, mots, prefixe, longueur)` : fenêtre de `longueur` points de code autour de la première correspondance (début du texte sinon), coupée sur une frontière de mot ; correspondance cherchée sur le texte normalisé (`normaliser` de L15-T25) mais rendu sur le texte d'ORIGINE, échappé morceau par morceau ; seuls `<mark>` et `</mark>` sont produits comme balises ; jamais de `<mark>` imbriqué ;
   - `trier(resultats: { score: number; date: string; id: string }[])` : score décroissant, puis date décroissante, puis id ;
   - `paginer(liste, { limite; curseur? })` → `{ elements; curseurSuivant? }` (curseur opaque, encodé en base64url, invalide = erreur `curseur_invalide`) ; `grouper(liste, parType)` : `parType` premiers par type.
2. Tests nommés : `script-echappe`, `hyperlink-texte-intact-echappe`, `seules-balises-mark` (après retrait de `<mark>` et `</mark>`, l'extrait ne contient plus aucun `<`), `accent-trouve-texte-d-origine-rendu` (« Fact » trouve « Facturé »), `pas-de-mark-imbrique`, `mot-absent-debut-du-texte`, `tri-score-date-id`, `pagination-curseur-et-curseur-invalide`, `groupes-cinq-par-type`.

## Hors périmètre
Pas de droits ni d'isolation (L15-T60), pas d'index (L15-T64), pas de score en base.

## Pièges
Le front ne doit JAMAIS injecter cet extrait comme HTML brut (L15-T54 le découpe sur `<mark>`). Sensible (sécurité : injection) : relecture Opus.

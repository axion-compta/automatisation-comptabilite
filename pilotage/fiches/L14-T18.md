## Contexte
Spec 14, `01` partie A. Règle 1 : toute écriture qui applique une règle légale écrit une ligne `utilisation_parametre` et porte une `version_paquet` non nulle ; sans ligne, la validation est refusée. Règle 4 : le pays fiscal d'une société cliente est un pays de l'Union (liste `pays_ue` en paramètre daté) ; hors Union = refus, 0 ligne créée. Les fournisseurs hors Union restent enregistrables, leurs achats sont « à vérifier » et jamais « cas sûr ». Test R3. Décision D1 de Will : jamais hors Union européenne.

## À faire
1. `packages/parametres/src/pays.ts` (importe `regleAuJour`, `PaquetParametres`, `UtilisationParametre` de `./paquet.js` ; classe locale `ErreurPays`) :
   - `paysDeLUnion(paquet, date)` : lit la clé `pays_ue` (pays `UE`) au jour D, valeur = codes de deux lettres séparés par des virgules ; valeur mal formée = refus `liste_pays_invalide` ;
   - `verifierPaysSociete(pays, paquet, date)` → `{ ok: true; aVerifier: boolean } | { ok: false; code: 'pays_hors_union' }` ;
   - `statutFournisseur(pays, paquet, date)` → `'union' | 'hors_union_a_verifier'` ;
   - `verifierUtilisations(ecriture: { id; appliqueRegleLegale: boolean; versionPaquet: string | null }, utilisations: readonly UtilisationParametre[])` → `{ ok: true } | { ok: false; code: 'version_paquet_absente' | 'utilisation_parametre_absente' }`.
2. Tests nommés (liste INVENTÉE `AA,BB,CC` pour l'Union du test ; aucun vrai code pays dans src) : `r3-societe-hors-union-refusee`, `societe-dans-l-union-acceptee`, `r3-fournisseur-hors-union-a-verifier`, `liste-datee-change-au-jour-d`, `ecriture-sans-version-refusee`, `ecriture-sans-utilisation-refusee`, `ecriture-sans-regle-legale-acceptee-sans-ligne`.

## Hors périmètre
Pas de base ni de validation réelle (L14-T34, bloquée). Pas de « cas sûr » (L14-T22 lit `hors_union_a_verifier`).

## Pièges
Aucun code pays réel dans src (même FR) : tout vient du paquet. Cas limites exigés : pays en minuscules (refus, pas de normalisation silencieuse), pays vide, liste vide (toute société refusée), espaces dans la liste (refus), code en double dans la liste (refus), utilisation d'une autre écriture (ne compte pas).

## Contexte
Spec 01, §04, règles 2 et 3 : « BROUILLON → PROPOSÉ → VALIDÉ (immuable). Aucun retour VALIDÉ → BROUILLON. » « "Valider" crée une demande de validation (échéance = maintenant + délai). Pendant ce délai, "Annuler" remet l'écriture en BROUILLON, aucun numéro consommé. » La durée du délai est un réglage à confirmer : elle est passée en argument, jamais écrite dans le code.

## À faire
1. `packages/noyau/src/ecritures/etats.ts`, fonctions pures (aucune horloge interne, `maintenant` en millisecondes passé par l'appelant) :
   - `proposer(e)` : brouillon → propose ; autre état = `ErreurEcriture('transition_interdite')` ; appelle `verifierEcriture` (L01-T06) ;
   - `demanderValidation(e, maintenant, delaiMs)` → `{ ecritureId, echeance }` ; refus si l'état n'est pas `propose` ; `delaiMs` entier positif sinon `delai_invalide` ;
   - `annulerValidation(demande, maintenant)` → `'annulee'` si `maintenant < echeance`, sinon `ErreurEcriture('delai_depasse')` ;
   - `validationEchue(demande, maintenant)` → booléen (`maintenant >= echeance`) ;
   - `valider(e, numero, validePar, valideLe)` → nouvelle écriture `valide` (copie ; l'entrée n'est jamais modifiée) ; refus si `e.statut !== 'propose'` ;
   - `repasserEnBrouillon(e)` : permis depuis `propose`, refus `transition_interdite` depuis `valide`.
2. Tests nommés : `brouillon-vers-propose`, `valide-vers-brouillon-interdit`, `annuler-avant-echeance` (délai de test 10 000 ms, annulation à 9 000 ms), `annuler-apres-echeance-refuse` (11 000 ms), `validation-ne-modifie-pas-l-entree` (`Object.freeze` sur l'entrée), `delai-invalide-refuse`, `proposer-desequilibree-refuse`.

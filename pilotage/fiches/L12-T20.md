## Contexte
Spec 12, `04-tva-cas-particuliers` (V3-TVA-030) : « Chaque cas est détecté au MVP. Son traitement dépend d'un paramètre daté (statut `valide` seulement après une 2e lecture indépendante). Paramètre `a_verifier` : la ligne est `A_VERIFIER` et la préparation de la TVA est bloquée (CC-T02). » CC-T17 cession (sortie d'une immobilisation avec un prix > 0, paramètre `tva.cession_bien_meuble`) ; CC-T18 acomptes (encaissement « acompte reçu », paiement fournisseur avant facture, facture d'acompte) : B tant que `tva.exigibilite.acompte_bien` n'est pas `valide`, puis M ; CC-T19 créance irrécouvrable (créance passée en perte alors que la TVA a été collectée). Points à trancher Q5 et Q6. Cas CT-31 (machine vendue 1 000,00 HT : B), CT-32 (acompte, paramètre de test `valide` : M à traiter), CT-34 (facture de 1 200,00 passée en perte : B, aucune récupération proposée). Immeuble : toujours B.

## À faire
1. `packages/noyau/src/controles/regles/cas-particuliers.ts` :
   - `Evenement = { type: 'cession'; prix: Centimes; immeuble: boolean } | { type: 'acompte'; sens: 'recu' | 'verse' | 'facture_acompte' } | { type: 'creance_perte'; tvaCollectee: Centimes }` ;
   - `regleCCT17` sur `{ evenement; parametre: ParametreLu }` : id `CC-T17`, version 1, gravité `B`, bloque `tva` ; prix nul = `NON_APPLICABLE` ; immeuble = ALERTE toujours ; paramètre non utilisable = ALERTE ; sinon OK ;
   - `regleCCT18` : id `CC-T18`, gravité `B` ; ALERTE tant que le paramètre n'est pas utilisable ; `regleCCT18M` : id `CC-T18M`, gravité `M` : ALERTE (à traiter par une personne) quand il l'est ;
   - `regleCCT19` : id `CC-T19`, gravité `B` ; TVA collectée nulle = `NON_APPLICABLE` ; sinon ALERTE tant que le paramètre n'est pas utilisable ;
   Déclencheurs : `arrivee`, `continu`, `avant_tva`, `a_la_demande`. `valeur` = clé du paramètre attendu.
2. `packages/noyau/src/controles/regles/__tests__/cas-particuliers.test.ts`, tests nommés : `CT-31 detection`, `CT-32 detection`, `CT-34`, `immeuble-toujours-bloque`, `cession-prix-nul-non-applicable`, `acompte-parametre-absent-bloque`, `acompte-verse-detecte`, `creance-sans-tva-non-applicable`, `aucune-ecriture-produite` (la sortie ne contient aucune ligne d'écriture).

## Hors périmètre
Écritures : cession (L12-T21), acompte versé (L12-T22), acompte reçu (lot 10, L10-T08). Créance irrécouvrable : écriture en V1 (Q6).

## Pièges
Règles du noyau comme L01-T06 : montants en `Centimes` via `packages/noyau/src/argent`, ni `/`, ni littéral décimal, ni `Math.round`, ni `parseFloat`, ni `toFixed`. Stryker (seuil 80 %) porte sur tout le noyau : chaque branche doit être tuée par un test. Ne pas toucher `packages/noyau/src/index.ts` ni `controles/moteur.ts` (imports par chemin relatif). Aucun taux, seuil, délai ni date légale dans `src` (garde:litteraux, D31) : tout seuil ou tolérance arrive en argument ou dans un `ParametreLu` (L12-T00) ; paramètre absent = `IMPOSSIBLE`, jamais OK (PRI-007). Le noyau ne contient aucun texte affiché : seulement des codes. Montants et seuils des tests INVENTÉS ou repris des cas fictifs de la spec ; noms et SIREN fictifs seulement. TVA : chemin sensible (fusion après relecture Opus et double relecture argent). Aucun taux de TVA ni pourcentage légal dans src : taux en points de base et parts déductibles viennent d'un `ParametreLu` ; un paramètre au statut autre que `valide` rend la ligne `A_VERIFIER` (donc CC-T02, L12-T09), jamais une estimation. Comptes (445660, 445800, 275000…) en argument, jamais en dur. Le moteur (L01-T19) a une gravité FIXE par règle : quand la spec donne deux gravités à un même contrôle, la fiche crée deux règles (identifiant suffixé, voir LOT-12-PLAN §7). Le vocabulaire du code (`Blocage` = validation, tva, export, cloture ; `Declencheur` = `a_la_demande`) et celui du CSV (`validation_mois`, `preparation_tva`, `export_officiel`, `cloture`, `aucun` ; `demande`) diffèrent déjà : ne pas les « corriger ». La ligne du catalogue `docs/controles.csv` n'est PAS écrite ici (L12-T26 ou L12-T27) ; le titre du test `CT-nn` doit être exact, `garde:controles` le cherche. Cas limites exigés dans les tests : montant NaN, Infinity, non entier (1,5) et négatif là où il est interdit = exception codée (le moteur la change en `IMPOSSIBLE`) ; liste vide ; objets reçus dans l'ordre inverse (même résultat) ; écart d'exactement un centime de chaque côté de la tolérance. Chaque test doit rougir si l'on casse la branche qu'il couvre (inverser une comparaison, retirer un cas).

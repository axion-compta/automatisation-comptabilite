## Contexte
Spec 02, fichier 02 : XLSX au MVP. Un XLSX est une archive ZIP de fichiers XML : `xl/sharedStrings.xml` et `xl/worksheets/sheet1.xml` suffisent. Le résultat est un tableau de lignes de texte, que le profil d'import (L02-T15) lit comme un CSV.

## À faire
1. `apps/serveur/src/banque/xlsx.ts` :
   - `lireXlsx(octets: Uint8Array, limites: { octetsMax: number; decompresseMax: number; lignesMax: number })` → `string[][]` (première feuille, cellules dans l'ordre des colonnes, cellule absente = `''`) ;
   - `unzipSync` avec filtre : seuls `xl/sharedStrings.xml` et `xl/worksheets/sheet1.xml` ; refus si la taille déclarée OU réelle dépasse `decompresseMax` ;
   - lecture XML : tout `<!DOCTYPE` ou `<!ENTITY` refusé AVANT lecture ; balises `<c r= t=>`, `<v>`, `<si><t>` lues par expressions bornées (pas de retour arrière exponentiel) ;
   - nombres : texte brut de `<v>` gardé tel quel (jamais converti en `number`) ; dates en numéro de série : texte brut (la conversion est faite par le profil) ;
   - classe locale `ErreurXlsx` : `limites_invalides`, `trop_gros`, `archive_invalide`, `feuille_absente`, `decompression_trop_grande`, `trop_de_lignes`, `doctype_refuse`.
2. Tests nommés (classeurs construits dans le test par `zipSync`, données fictives) : `trois-lignes-lues`, `chaines-partagees-resolues`, `cellule-absente-vide`, `nombre-garde-en-texte` (`1234.56` reste `'1234.56'`), `bombe-de-decompression-refusee`, `archive-invalide-refusee`, `doctype-refuse`, `trop-de-lignes-refuse`, `cellules-hors-ordre-remises-dans-l-ordre` (`C1` avant `A1`).

## Hors périmètre
Plusieurs feuilles, formules, styles. Application du profil (L02-T15).

## Pièges
Cas limites exigés : `octets` vide, limites à 0, `NaN`, `Infinity`, non entières (erreur `limites_invalides`), feuille sans ligne (tableau vide). Aucun flottant. Sensible (fichier reçu de l'extérieur).

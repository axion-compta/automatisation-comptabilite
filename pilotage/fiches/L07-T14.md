## Contexte
Le contrat fait foi (ADR 0002) ; serveur en mémoire et faux serveur le suivent. Pour que les domaines de l'abonnement s'implémentent EN PARALLÈLE (L07-T17 à L07-T21) sans toucher les fichiers communs (`routes.ts`, `openapi.json`, `app.ts`), le contrat de chaque domaine est déclaré et figé d'abord, et le serveur branche chaque domaine sur un fichier propre qui répond « non implémenté » (501) en attendant. Routes sans préfixe de société, comme le lot 01 (le préfixe viendra avec l'isolation). Spec 07 : `GET /acces` (PLA-130, aucun montant), `GET /volume` (PLA-155), « Demander le palier supérieur » avec accord (PLA-157). Classe d'action de chaque route déclarée par une étiquette (`tags`) lue plus tard par la garde L07-T22 : `acces:lecture`, `acces:export`, `acces:ecriture`, `acces:agent` ou `acces:compte`.

## À faire
1. `packages/contrat/src/domaines/acces.ts` : schéma de sortie `{ etat: enum des 6 états; banniere: null | { cause: string; consequence: string; prochaine_etape_le: date AAAA-MM-JJ | null; lien: 'portail_abonnement' | 'contacter_axion' }; reprise: null | { pieces_traitees: entier >= 0 } }` ; route `lireAcces` (`GET /acces`, `tags: ['acces:compte']`) ; schéma exporté `ErreurEtatAcces = { etat; raison: 'etat' | 'fonction_non_permise' | 'valeur_inconnue' }` (servira à L07-T22).
2. `volume.ts` : route `lireVolume` (`GET /volume`, `tags: ['acces:lecture']`) → `{ palier: { code; nom_affiche }; compris; utilise; prevision_fin_de_mois; seuils_bps: entier[]; alertes_bps: entier[]; depasse: booléen; proposer_choix: booléen; comportement: 'continuer' | 'attente'; palier_superieur: null | { code; nom_affiche; pieces_par_mois } }` (tous les nombres entiers >= 0).
3. `palier.ts` : route `demanderPalier` (`POST /abonnement/demandes-palier`, `successStatus: 201`, `tags: ['acces:compte']`), en-tête `EnTeteEcriture` (Idempotency-Key), corps `{ code_demande: chaîne non vide; accord: booléen }` → `{ demande: { code_actuel; code_demande; horodatage }; palier_en_vigueur }` ; erreurs déclarées `ACCORD_MANQUANT` 422, `PALIER_INCONNU` 404, `PALIER_IDENTIQUE` 422, `PALIER_NON_SUPERIEUR` 422.
4. `routes.ts` : ajouter `abonnement: { lireAcces, lireVolume, demanderPalier }` sans toucher les autres clés ; `openapi.ts` seulement si la génération ne prend pas les `tags` ; régénérer `openapi.json`.
5. `apps/serveur/src/domaines/options-abonnement.ts` : `type OptionsAbonnement = { horloge?: () => string; scenario?: string | null }` (le texte du scénario est lu par `lireScenario` de L07-T13 dans chaque domaine). `acces.ts`, `volume.ts`, `palier.ts` : chacun exporte UNE fonction de signature figée `implementer<Domaine>(os, options: OptionsAbonnement)` qui rend les handlers du domaine, ici des bouchons qui lèvent `new ORPCError('NOT_IMPLEMENTED')` (501). `app.ts` : branche les 3 domaines dans `creerRouteur` ; `creerApp` accepte en plus un objet d'options `{ abonnement?: OptionsAbonnement }` sans casser les appels existants (si L01-T23 ou L01-T25 ont déjà introduit un objet d'options, y ajouter la clé `abonnement`).
6. Tests nommés : `abonnement-routes-dans-openapi`, `post-avec-idempotency-key` (`routesEcritureSansEnTete()` reste `[]`), `chaque-route-abonnement-a-une-etiquette-acces` (exactement une étiquette `acces:*` valide), `aucun-champ-montant-prix-cout` (parcours des schémas de sortie : aucune clé qui contient `montant`, `prix`, `cout`, `tarif`), `cles-existantes-inchangees` (`ecritures`, `plan`, `tiers` toujours présents), et dans `abonnement-branchement.test.ts` (Fastify `inject`) : `trois-routes-branchees` (statut différent de 404 pour chacune ; ce test ne doit PAS exiger 501, pour rester vert quand les domaines seront implémentés), `post-sans-cle-refuse-400`.

## Hors périmètre
Aucune logique (L07-T17, L07-T18, L07-T19), pas de faux serveur (L07-T16), pas de garde d'état (L07-T22), pas de routes de fin de contrat ni d'acceptation (L07-T15).

## Pièges
Rester sous 400 lignes, `openapi.json` compris : si la génération dépasse, sortir `palier.ts` dans L07-T15 et le noter au journal. Ne pas modifier `contrat.test.ts` ni les clés de `contrat.ecritures`. Les noms de fonctions `implementerAcces`, `implementerVolume`, `implementerPalier` et le type `OptionsAbonnement` sont un CONTRAT entre fiches : ne pas les renommer. Aucun prix, aucun montant dans les schémas.

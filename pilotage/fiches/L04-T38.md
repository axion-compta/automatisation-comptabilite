## Contexte
Spec 04, fichier 03 §2 : « Sortie du lecteur A : JSON strict validé par schéma zod (AGT-002). Chaque champ : valeur, confiance_modele (0 à 100, indicative), citation. Réponse hors schéma = une seconde tentative, puis a_verifier motif sortie_invalide. Le modèle ne fait aucun calcul. » §9 : invite, schéma et modèle versionnés. ## À faire
1. `apps/serveur/src/pieces/schema-lecteur-a.ts` : schéma zod `.strict()` : `{ type_piece: enum TYPES_PIECE, langue: 'fr' | 'en' | 'autre', champs: { nom: string, valeur: string, confiance_modele: entier 0 à 100, citation: string (1 à 300 car.) }[] (100 au plus) }` ; `VERSION_SCHEMA = 1`.
2. `apps/serveur/src/pieces/lecteur-a.ts` :
   - port `ModeleTexte { completer(entree: { invite: string; texte: string; versionInvite: number }): Promise<{ sortie: string; coutMicroCentimes: number }>; estimer(texte): number }` ;
   - `lireAvecModele({ texteTransmissible, jetonsOpaques: Record<string, string>, depenseMicroCentimes, plafondMicroCentimes, versionInvite }, modele)` → `{ champs: ChampLu[] (lecteur A, source `modele`); typePropose; depense; version: { schema, invite } }` ou `{ aVerifier: 'sortie_invalide' | 'plafond_cout'; depense }` ou `{ erreur: 'ia_indisponible'; depense }` ;
   - `texteTransmissible` nul = refus immédiat (`ErreurPiece('appel_interdit')`) : une pièce sensible n'arrive jamais ici ;
   - avant l'envoi : chaque clé de `jetonsOpaques` (nom ou identifiant de la société) remplacée dans le texte par son jeton ; `autoriserAppel` (L04-T06) avant CHAQUE tentative, `constaterApresAppel` après ;
   - `JSON.parse` puis schéma ; échec = une seconde tentative ; second échec = `sortie_invalide` ; exception du port = `ia_indisponible` ;
   - aucun montant calculé : les valeurs restent des chaînes (le code les lira, L04-T11).

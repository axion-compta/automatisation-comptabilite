## Contexte
Spec 03, §05 : `GET /echeances?du=&au=` ; échéance `non_verifie` affichée « date à vérifier » ; mention « Dates indicatives, calculées sur votre année comptable… » (DEC-062, texte dans L03-T39).

## À faire
1. `packages/contrat/src/domaines/echeances.ts` : schéma exporté `Echeance { code; dateLimite; statut: 'a_venir' | 'faite' | 'en_retard'; dateAVerifier: boolean; niveau: 'prepare' | 'alerte' | 'rappel_seul' }`, `ReponseEcheances` (enveloppe) ; route `listerEcheances` (`GET /echeances`, query `du` et `au` au format `AAAA-MM-JJ`, obligatoires ; `au` avant `du` = 400).
2. `echeances-service.ts` sur `genererDeclarations()` (L03-T31) : bornes incluses, tri par date puis code.
3. `routes.ts` : domaine `echeances` ; `openapi.json` régénéré ; `apps/serveur/src/domaines/echeances.ts` branché dans `app.ts`.
4. Tests nommés : `echeances-dans-l-intervalle`, `bornes-incluses`, `au-avant-du-refuse`, `date-mal-formee-refusee`, `serveur-repond-aux-echeances`.

## Hors périmètre
Pas de calcul d'échéance par le serveur (noyau L03-T41 et L03-T42 ; branchement quand le profil de société existera). Pas de route `reporter-rappel` (écriture).

## Pièges
Dernier maillon de la chaîne des fichiers communs du couloir C pour ce lot. Cas limites exigés : `du` = `au` (un jour), intervalle sans échéance (liste vide), 30 février refusé.

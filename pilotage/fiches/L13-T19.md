## Contexte
Spec 13, fichier 04, R07 : la dotation est proposée en BROUILLON, jamais passée sans validation (G01). R08 : l'affectation n'est écrite qu'après la décision d'approbation enregistrée. Bénéfice : D 120000 / C 119000 (apurement des pertes antérieures) / C 106100 (réserve légale) / C 457000 (dividendes à payer) / C 110000 (report créditeur, solde). Perte reportée : D 119000 / C 129000 ; aucun dividende. Tests MOT72-1 (4 500,00 : 225,00 / 3 000,00 / 1 275,00), MOT72-3 (perte 2 000,00), MOT72-6 (4 500,00 : 1 000,00 / 175,00 / 3 325,00).

## À faire
1. `packages/noyau/src/cloture/ecriture-affectation.ts` (types de `../ecritures/modele.js`) :
   - `ecritureAffectation(affectation { resultat; apurementPertes; reserve; dividende }, comptes { resultatBenefice; resultatPerte; reportDebiteur; reserveLegale; dividendesAPayer; reportCrediteur }, ctx { id; date; journal; decisionApprobation?: { date } })` donne une écriture `brouillon` ;
   - sans décision : `ErreurAffectation('decision_approbation_absente')` ;
   - bénéfice : report créditeur = résultat − apurement − réserve − dividende ; négatif : `affectation_incoherente` ; les lignes à montant nul sont omises ;
   - perte (résultat négatif) : D reportDebiteur / C resultatPerte pour la valeur absolue ; dividende non nul : `dividende_sur_perte` ; résultat nul : `resultat_nul`.
2. Tests nommés (comptes de la spec passés en argument) : `benefice-avec-dividende` (MOT72-1, en centimes), `benefice-avec-apurement` (MOT72-6), `perte-reportee` (MOT72-3), `sans-decision-refuse`, `lignes-nulles-omises`, `somme-superieure-au-resultat-refusee`, `dividende-sur-perte-refuse`, `equilibre-verifie` (chaque écriture produite passe `verifierEcriture`).

## Hors périmètre
Calcul de la réserve et du distribuable : L13-T18. PV d'approbation (spec 03-10) et formulaires 2777 / IFU (D5 : rappel seul par défaut) : hors lot.

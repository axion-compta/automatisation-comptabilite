## Contexte
Débloquée par la décision de Will du 09/11/2026 : D42 (démarrage sur le serveur d'Axion IA, avec une base séparée pour la compta) et D29 (avancer sans attendre la réponse de l'équipe console) ; J3a déjà donné le 07/11/2026 avec ses quatre conditions (données FICTIVES seulement ; fiche sensible relue par Opus ; aucune production sans le feu vert J10 ; ce qui exige le vrai service de la console s'écrit contre une INTERFACE et un faux service). Motif d'origine, gardé comme contexte : J3a et D29 (isolation et identité fournies par la console : session, rôles, réauthentification, société courante).

Spec 09, §04 : API sous le préfixe `PREFIXE_ROUTES_SOCIETE` (L00-T50) ; `POST /profil/changements` exige la réauthentification pour forme, régime de TVA, impôt et dates ; §01 : `confirme_par` = personne en session, jamais un agent. Principe d'étanchéité (lot 13) : société prise dans la session ; même réponse 404 pour une société d'autrui.

## À faire
1. Préfixe de société sur les routes du lot (L09-T30 à T35), société prise dans la session et comparée au paramètre de chemin ; 404 au même corps pour une société d'autrui. Identité et session lues par `PortSession` de L00-T50 (personne, organisation, société courante, rôles, permissions, heure de connexion) ; réauthentification par `exigerNouvelleConnexion` (L00-T50) ; tests avec le faux `creerFauxSessions`.
2. Réauthentification exigée (code de la console) pour les clés forme, regime_tva, regime_imposition, exercice_debut, exercice_fin ; refus `REAUTHENTIFICATION_REQUISE` 401.
3. `confirmePar` tiré de la session ; un jeton d'agent est refusé (`CONFIRMATION_PAR_AGENT` 403).
4. Tests nommés : `societe-d-autrui-404-meme-corps`, `sans-session-401`, `reauthentification-requise`, `reauthentification-acceptee`, `agent-ne-confirme-pas`, `confirme-par-personne-de-session`, `cles-non-sensibles-sans-reauthentification`.
5. Règle de séparation (décision de Will du 09/11/2026) : aucune adresse, nom de machine, port, identifiant ni secret de serveur ou de base dans le code, les tests ni les fiches ; tout passe par des réglages lus à un seul endroit, avec des valeurs d'exemple fictives. Tout ce que la console doit fournir s'écrit contre une interface et un faux service ; le vrai service se branchera plus tard sans changer le code appelant. La compta garde sa propre base et ses propres tables.

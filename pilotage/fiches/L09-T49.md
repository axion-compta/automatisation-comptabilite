## Contexte
Débloquée par la décision de Will du 09/11/2026 : D42 (démarrage sur le serveur d'Axion IA, avec une base séparée pour la compta) et D29 (avancer sans attendre la réponse de l'équipe console) ; J3a déjà donné le 07/11/2026 avec ses quatre conditions (données FICTIVES seulement ; fiche sensible relue par Opus ; aucune production sans le feu vert J10 ; ce qui exige le vrai service de la console s'écrit contre une INTERFACE et un faux service). Motif d'origine, gardé comme contexte : J3a et D29 (isolation et identité fournies par la console : session, rôles, réauthentification, société courante).

Spec 09, §04 : API sous le préfixe `PREFIXE_ROUTES_SOCIETE` (L00-T50). Principe d'étanchéité (lot 13) : société prise dans la session ; même réponse 404 pour une société d'autrui.

Découpée par L00-T84 (BLOQUE-L09-T49) : cette fiche pose le préfixe et la session ; la réauthentification et `confirmePar` passent à L09-T52.

## À faire
1. Contrat : chemins de `profil.ts`, `profil-champs.ts`, `profil-changements.ts` sous le préfixe, par `cheminSociete` comme `chat.ts` (`sous`) ; régénérer `openapi.json`.
2. Vrai serveur : la session de route (`versSessionRoute`) perd `societeId` ; `app.ts` ajoute seulement au contexte la session vérifiée par le jeton (`sessionDeRequete`, type `Session` du noyau, lue par `PortSession`), sans changer `session` ni `ContexteSession` des autres domaines. Routes du profil : sans cette session, 401 ; société du chemin comparée à `societeId` ; société d'autrui : 404 au même statut et au même corps qu'une route inconnue (`{ code: 'INTROUVABLE', status: 404 }`).
3. Faux serveur : mêmes handlers aussi servis sous le chemin préfixé (`PREFIXE_ROUTES_SOCIETE` comme `faux-serveur/src/domaines/chat.ts`) ; les chemins sans préfixe restent servis tant que les écrans E45 et E39 (L09-T41 à T43) les lisent.
4. Tests existants adaptés, sans retirer ni affaiblir une assertion : chemin préfixé par une société fictive (`soc-lemoine`), vrai serveur créé avec le jeton et `creerFauxSessions` (`securite: { jeton: { sessions } }`, en-tête `authorization: Bearer` d'un jeton fictif). Contrat : `profil.test.ts` (l. 77-78), `profil-champs.test.ts` (l. 55-56), `profil-changements.test.ts` (l. 69-70) ; serveur : `profil.test.ts`, `profil-champs.test.ts`, `profil-changements.test.ts` ; suites communes `suite-profil.ts`, `suite-profil-ecriture.ts` et leurs cibles « vrai serveur » dans `contrat-commun.test.ts` et `commun-profil-ecriture.test.ts`.
5. Tests nommés : `societe-d-autrui-404-meme-corps`, `sans-session-401` (serveur, `profil-isolation.test.ts`, sur les cinq routes) ; `chemin-profil-sans-prefixe-404` (serveur, même fichier : un chemin `/profil` sans préfixe donne 404 sur le vrai serveur) ; `chemins-prefixes-dans-l-openapi` (contrat, `profil-isolation.test.ts` : plus aucun chemin `/profil`, `/profil/champs*`, `/profil/changements*` sans préfixe).
6. Règle de séparation (décision de Will du 09/11/2026) : aucune adresse, nom de machine, port, identifiant ni secret de serveur ou de base dans le code, les tests ni les fiches ; tout passe par des réglages lus à un seul endroit, avec des valeurs d'exemple fictives. Tout ce que la console doit fournir s'écrit contre une interface et un faux service. La compta garde sa propre base et ses propres tables.

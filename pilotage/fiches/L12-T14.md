## Contexte
Spec 12, `03-controles-tva`, CC-T07 (V3-TVA-022) : « Repas d'affaires justifié (invités ou motif) → selon `tva.repas_affaires` ; hébergement du dirigeant et transport de personnes → selon `tva.hebergement_dirigeant`, `tva.transport_personnes` ; motif absent → `A_VERIFIER`. Sources : CGI et annexe II, article à relever, à vérifier. » M ; via CC-T02 si `A_VERIFIER`. Cas CT-24 (repas 66,00 TTC dont 6,00 de TVA, invités notés, paramètre de TEST valide : 6,00 déduits ; même ticket sans motif : `A_VERIFIER` donc B via CC-T02). Paramètres : L01-T14 (`utilisablePourOfficiel`), passés au noyau sous forme de `ParametreLu` (L12-T00).

## À faire
1. `packages/noyau/src/controles/regles/repas.ts` :
   - `NatureRepas = 'repas_affaires' | 'repas_personnel' | 'hebergement_dirigeant' | 'transport_personnes'` ;
   - `traiterRepas({ nature; tva: Centimes; motif?: string; parametre: ParametreLu })` → `{ code: 'DEDUCTIBLE' | 'NON_DEDUCTIBLE_NATURE' | 'A_VERIFIER'; deduit: Centimes }` : le paramètre porte la part déductible en points de base (`entierParametre`) ; motif absent ou blanc pour un repas d'affaires = `A_VERIFIER` ; paramètre non utilisable = `A_VERIFIER`, 0 déduit ; part nulle = `NON_DEDUCTIBLE_NATURE` ; part en dehors de 0 à 10 000 = exception ;
   - `regleCCT07` : id `CC-T07`, version 1, gravité `M`, bloque `[]`, déclencheurs `arrivee`, `continu`, `a_la_demande` ; `A_VERIFIER` = ALERTE `valeur: 'A_VERIFIER'` ; sinon OK.
2. `packages/noyau/src/controles/regles/__tests__/repas.test.ts`, tests nommés : `CT-24` (part de test 10 000 points : 600 déduits ; sans motif : A_VERIFIER), `parametre-a-verifier-rien-deduit`, `part-nulle-non-deductible`, `part-partielle-arrondie` (arrondi explicite via `pourcentage` de `argent`), `motif-blanc-a-verifier`, `part-hors-bornes-exception` (−1, 10 001, NaN), `repas-personnel`, `transport-et-hebergement`.

## Hors périmètre
Valeurs réelles des paramètres (catalogue daté, « à vérifier » tant que non relues). Notes de frais (lot 11, qui appellera cette fonction).

## Pièges
Règles du noyau comme L01-T06 : montants en `Centimes` via `packages/noyau/src/argent`, ni `/`, ni littéral décimal, ni `Math.round`, ni `parseFloat`, ni `toFixed`. Stryker (seuil 80 %) porte sur tout le noyau : chaque branche doit être tuée par un test. Ne pas toucher `packages/noyau/src/index.ts` ni `controles/moteur.ts` (imports par chemin relatif). Aucun taux, seuil, délai ni date légale dans `src` (garde:litteraux, D31) : tout seuil ou tolérance arrive en argument ou dans un `ParametreLu` (L12-T00) ; paramètre absent = `IMPOSSIBLE`, jamais OK (PRI-007). Le noyau ne contient aucun texte affiché : seulement des codes. Montants et seuils des tests INVENTÉS ou repris des cas fictifs de la spec ; noms et SIREN fictifs seulement. TVA : chemin sensible (fusion après relecture Opus et double relecture argent). Aucun taux de TVA ni pourcentage légal dans src : taux en points de base et parts déductibles viennent d'un `ParametreLu` ; un paramètre au statut autre que `valide` rend la ligne `A_VERIFIER` (donc CC-T02, L12-T09), jamais une estimation. Comptes (445660, 445800, 275000…) en argument, jamais en dur. Le moteur (L01-T19) a une gravité FIXE par règle : quand la spec donne deux gravités à un même contrôle, la fiche crée deux règles (identifiant suffixé, voir LOT-12-PLAN §7). Le vocabulaire du code (`Blocage` = validation, tva, export, cloture ; `Declencheur` = `a_la_demande`) et celui du CSV (`validation_mois`, `preparation_tva`, `export_officiel`, `cloture`, `aucun` ; `demande`) diffèrent déjà : ne pas les « corriger ». La ligne du catalogue `docs/controles.csv` n'est PAS écrite ici (L12-T26 ou L12-T27) ; le titre du test `CT-nn` doit être exact, `garde:controles` le cherche. Cas limites exigés dans les tests : montant NaN, Infinity, non entier (1,5) et négatif là où il est interdit = exception codée (le moteur la change en `IMPOSSIBLE`) ; liste vide ; objets reçus dans l'ordre inverse (même résultat) ; écart d'exactement un centime de chaque côté de la tolérance. Chaque test doit rougir si l'on casse la branche qu'il couvre (inverser une comparaison, retirer un cas). Le registre dit « non déductibles » pour l'hébergement et le transport : ce n'est PAS écrit dans le code, c'est la valeur du paramètre.

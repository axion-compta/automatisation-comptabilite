## Contexte
Spec 15, TB-R5 à TB-R7. Enveloppe commune `{ etat, mot, gravite, periode, donnees, lien }` ; chaque bloc existe en 3 états au moins (`ok`, `vide`, `impossible`) ; un compte neuf rend `vide` avec un mot qui dit quoi faire ; un bloc en panne rend `impossible` et les autres ne sont pas touchés. TB-R3 et décision D4 (point T5) : tant qu'un contrôle TVA-C12 est ouvert (pièce de la période non classée ou en doute), le bloc `tva_impots` rend `impossible` et AUCUN montant, avec le mot « il reste N pièces à regarder ».

## À faire
1. `blocs.ts` :
   - `EnveloppeBloc<T> { code: CodeBloc; etat: EtatBloc; mot: string; gravite?: GraviteAlerte; periode: Periode; donnees?: T; lien?: string }` ;
   - `construireBloc(code, periode, calcul: () => T | undefined)` : exception levée = `impossible`, mot `calcul_impossible`, sans `donnees` ; `undefined` = `vide`, mot `vide_<code>` ; sinon `ok` ;
   - `blocTva(periode, piecesEnDoute: number, calcul)` : `piecesEnDoute > 0` = `impossible`, mot `pieces_a_regarder`, `donnees = { piecesEnDoute }` et AUCUN montant (le calcul n'est même pas appelé) ; `piecesEnDoute` négatif, non entier ou non fini = erreur ;
   - `assemblerTableau(periode, calculs: Partial<Record<CodeBloc, () => unknown>>)` : rend les 8 blocs dans l'ordre de `CODES_BLOC` ; un bloc sans calcul = `vide` ; la panne d'un bloc ne change pas les autres.
2. Tests nommés : `bloc-ok`, `bloc-vide-avec-mot`, `exception-donne-impossible-sans-donnees`, `une-panne-n-atteint-pas-les-autres`, `tva-en-doute-aucun-montant` (le calcul espion n'est pas appelé), `tva-sans-doute-calculee`, `pieces-en-doute-invalides` (`-1`, `0.5`, `NaN`), `huit-blocs-dans-l-ordre`.

## Hors périmètre
Pas de calcul des montants des blocs (L15-T07, L15-T11, lot 03 pour la TVA), pas de délai maximal par bloc (serveur réel, L15-T68).

## Pièges
Le mot « estimée » n'est jamais employé pour la TVA. Codes seulement, aucun texte affiché. Sensible (TVA) : relecture Opus.

## Contexte
Spec 02, fichier 05 : réponse de `GET /banque/lignes/{id}/explication` : `mot`, `score`, `etat`, `passe`, `facteurs` (nom, points, pourquoi), `autres_candidats`, `propose_par`, lien vers l'historique. Principe 3 du bloc : transparence. Le noyau ne contient aucun texte affiché : il rend des CODES et des VALEURS ; la phrase est construite par `packages/textes` (L02-T48).

## À faire
1. `packages/noyau/src/banque/rapprochement/explication.ts` :
   - `expliquer(ligne, lien?, candidats: { pieceId; score }[])` → `{ codeMot: 'rattache' | 'propose' | 'hesite' | 'sans_piece' | 'a_qualifier' | 'neutralisee' | 'ignoree'; score?; etat; passe?; facteurs: { nom; points; code; valeurs: Record<string, string | number> }[]; autresCandidats: { pieceId; score }[]; proposePar? }` ;
   - `valeurs` des facteurs : montants en centimes, nombre de jours, référence lue, alias reconnu (jamais d'IBAN) ;
   - autres candidats triés par score décroissant puis id, au plus un nombre passé en argument ;
   - ligne sans lien : `codeMot` déduit de l'état seul.
2. Tests nommés : `t05-1-cinq-facteurs` (45, 25, 20, 7, 3), `douteuse-deux-candidats`, `sans-lien-code-de-l-etat`, `aucun-iban-dans-les-valeurs`, `candidats-tries-et-bornes`, `facteur-nul-garde`.

## Hors périmètre
Phrases (L02-T48). Historique des états (bloqué : persistance L02-T62).

## Pièges

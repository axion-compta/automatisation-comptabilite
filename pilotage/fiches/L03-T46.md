## Contexte
Liste des écrans : E57 « Ce que le logiciel a vérifié », chemin `/documents/controles`. Spec 12 : les contrôles réussis sont aussi écrits ; un contrôle affiche toujours une valeur chiffrée ; IMPOSSIBLE n'est jamais compté réussi (PRI-007).

## À faire
1. `route.tsx` : `id: 'e57'`, `chemin: '/documents/controles'`, `groupe: 'documents'`.
2. `Ecran.tsx` : `<h1>` ; `useLecture('/exercices/{e}/controles', ReponseTraces)` (schéma importé de `packages/contrat/src/domaines/controles.ts`) ; filtre par résultat (boutons radio accessibles) ; `Tableau` : contrôle (code), résultat (`Pastille` avec mot : réussi, alerte, impossible, non applicable, écarté), valeur, écart (`Montant`), date ; résumé chiffré en tête (« N réussis, N alertes, N impossibles »).
3. `packages/textes/src/ecrans/e57.ts` : textes, vouvoiement.
4. Tests nommés : `liste-non-ok-d-abord`, `filtre-alertes`, `impossible-libelle-distinct-de-reussi`, `resume-chiffre`, `etat-vide`, `titre-h1-unique`.

## Hors périmètre
Pas d'action « écarter » (route d'écriture, plus tard). Pas de libellé client par contrôle (catalogue de la spec 12).

## Pièges
Aucun texte en dur. Pas de `<main>`. Le mot affiché pour IMPOSSIBLE ne doit contenir ni « réussi » ni « OK » (test). Cas limites exigés : écart nul affiché « 0,00 », valeur absente affichée par un tiret accessible (`aria-label`).

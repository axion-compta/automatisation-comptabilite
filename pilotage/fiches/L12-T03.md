## Contexte
Spec 12, `02-controles-coherence` (V3-CTL-023) : CC-K08 « destinataire de la facture d'achat (nom, SIREN, adresse) ≠ société ; ou facture de vente dont l'émetteur ≠ société », M ; la TVA de la pièce passe en `NON_DEDUCTIBLE_NOM` ou `A_VERIFIER` (donc CC-T02). CC-K10 « client d'une vente = personne physique ou tiers inconnu : signalé », m. Cas CT-08 (facture 200,00 HT + 40,00 adressée à « Claire Lemoine », nom fictif : TVA 0,00 déduite tant que non tranché) et CT-10 (vente de 450,00 à un particulier : m, aucune notification).

## À faire
1. `packages/noyau/src/controles/regles/destinataire.ts` :
   - `Societe { nom: string; siren: string; nomsConnus: readonly string[] }` ;
   - `normaliserNom(s)` : minuscules, accents retirés (NFD), ponctuation et formes juridiques courantes passées en argument (`formes: readonly string[]`) retirées, blancs réduits ;
   - `destinataireEstSociete(piece, societe, formes)` → `'oui' | 'non' | 'inconnu'` : SIREN égal = oui ; SIREN différent = non ; sans SIREN, nom normalisé dans `nomsConnus` = oui, sinon non ; destinataire absent = inconnu ;
   - `regleCCK08` : id `CC-K08`, version 1, gravité `M`, bloque `[]`, déclencheurs `arrivee`, `continu`, `a_la_demande` ; achat : regarde `destinataire`, vente : regarde `emetteur` ; `non` = ALERTE `valeur: 'NON_DEDUCTIBLE_NOM'`, `inconnu` = ALERTE `valeur: 'A_VERIFIER'` ;
   - `regleCCK10` : id `CC-K10`, gravité `m`, vente seulement (achat = `NON_APPLICABLE`) ; client sans SIREN ou marqué `personne_physique` = ALERTE.
2. `packages/noyau/src/controles/regles/__tests__/destinataire.test.ts`, tests nommés : `CT-08`, `CT-10`, `siren-egal-l-emporte-sur-le-nom`, `nom-normalise-reconnu` (« LEMOINE  Rénovation » = « lemoine renovation »), `destinataire-absent-a-verifier`, `vente-emetteur-autre`, `achat-non-applicable-pour-k10`, `siren-fictif-seulement` (le jeu de test n'utilise que des SIREN de la liste blanche de garde:fictif).

## Hors périmètre
Effet sur la TVA (code de traitement : L03-T24 ; blocage : L12-T09). Contrôle du numéro de TVA (L12-T04).

Stryker (seuil 80 %) porte sur tout le noyau : chaque branche doit être tuée par un test. Ne pas toucher `packages/noyau/src/index.ts` ni `controles/moteur.ts` (imports par chemin relatif). Aucun taux, seuil, délai ni date légale dans `src` (garde:litteraux, D31) : tout seuil ou tolérance arrive en argument ou dans un `ParametreLu` (L12-T00) ; paramètre absent = `IMPOSSIBLE`, jamais OK (PRI-007). Le noyau ne contient aucun texte affiché : seulement des codes. Montants et seuils des tests INVENTÉS ou repris des cas fictifs de la spec ; noms et SIREN fictifs seulement. Le moteur (L01-T19) a une gravité FIXE par règle : quand la spec donne deux gravités à un même contrôle, la fiche crée deux règles (identifiant suffixé, voir LOT-12-PLAN §7). Chaque test doit rougir si l'on casse la branche qu'il couvre (inverser une comparaison, retirer un cas). Les formes juridiques sont une liste en argument (pas une liste en dur dans src).

## Contexte
Spec 09, §02 : `regime_imposition_societe` historisée, ajout seul, sans chevauchement (`effet_debut`, `effet_fin`) ; impôt `IS` ou `IR`, catégorie `BIC`, `BNC`, `revenus_fonciers`, régime `micro`, `reel_simplifie`, `reel_normal`, `declaration_controlee`. Règle 3 : SARL, SAS, SASU = IS ; EI = IR ; EURL dont l'associé unique est une personne physique = IR ; SCI = IR. Ces défauts sont PROPOSÉS « à confirmer », jamais appliqués seuls. Options IS d'une EI ou d'une EURL, SCI à l'IS : champ prêt, REFUSÉ au MVP avec message. Cas P07.

## À faire
1. `packages/noyau/src/profil/fiscal/imposition.ts` :
   - `LigneImposition { societeId; effetDebut; effetFin: string | null; impot; categorie; regime; motif; statut: 'propose' | 'confirme' }` (`effetFin` EXCLUE) ;
   - `ajouterLigneImposition(historique, nouvelle)` → nouvelle liste ; la ligne ouverte reçoit `effetFin = nouvelle.effetDebut` ; une nouvelle ligne qui commence avant ou le jour d'une ligne existante = `ErreurProfil('chevauchement')` ; ancienne liste jamais modifiée ;
   - `impositionAuJour(historique, societeId, date)` → ligne ou `null` ;
   - `impotParDefaut(matrice, forme, associeUniquePersonnePhysique: boolean | null)` → `{ impot; statut: 'a_confirmer' }` via `regleDeForme(..., 'impot_par_defaut')` (L09-T06) ; pour l'EURL, la matrice porte deux valeurs (`EURL_PP`, `EURL_PM`) ; `null` = `{ impot: null, statut: 'a_confirmer', motif: 'associe_unique_inconnu' }` ;
   - `verifierOptionMvp(forme, impotDemande, impotParDefaut)` : EI ou EURL vers IS, SCI vers IS = `ErreurProfil('option_pas_encore_prise_en_charge')`.
2. Tests nommés (matrice inventée) : `eurl-personne-physique-ir-p07` (statut `a_confirmer`), `sarl-is-p07`, `jamais-confirme-seul` (toute valeur par défaut sort `a_confirmer`), `associe-unique-inconnu`, `ajout-ferme-la-ligne-ouverte`, `chevauchement-refuse` (même jour, jour antérieur), `lecture-a-la-date` (veille, jour, lendemain d'un changement ; fin exclue), `option-is-refusee-mvp` (EI, EURL, SCI), `historique-donne-dans-le-desordre`.

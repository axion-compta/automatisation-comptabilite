## Contexte
Spec 06, `04-isolation-donnees.md` §4 : date comptable = date civile dans le fuseau de la société ; instants en UTC ; aucune date comptable tirée de l'horloge du serveur sans fuseau. Date monotone : si l'horloge recule de plus d'un seuil (réglage), les écritures sont bloquées et une alerte part. Cas T-ISO-3 (31/12 à 23 h 30 heure de Paris, serveur en UTC → 31/12) et T-ISO-5 (horloge reculée de 30 jours → blocage, 1 alerte). Menace M13 (antidater).

## À faire
1. `packages/noyau/src/securite/horloge.ts` :
   - `dateComptable(instantIso, fuseau)` → `'AAAA-MM-JJ'` par `Intl.DateTimeFormat(…, { timeZone: fuseau }).formatToParts` ; fuseau inconnu ou instant invalide → `ErreurSecurite('argument_invalide')` ; le fuseau est un ARGUMENT (aucun fuseau par défaut dans le noyau) ;
   - `observerHorloge(vue: { plusGrandInstantMs: number } | null, maintenantMs, toleranceReculMs)` → `{ bloque: boolean; alerte: boolean; vue }` : recul strictement plus grand que la tolérance → bloqué, alerte, vue inchangée ; sinon vue = maximum ; `vue` nulle = première observation.
2. Tests nommés (années fictives, tolérance inventée) : `paris-23h30-utc-reste-le-31` (T-ISO-3), `utc-minuit-pile`, `changement-d-heure-ete-et-hiver`, `fuseau-inconnu-refuse`, `instant-invalide-refuse` (`''`, `'2026-02-30T00:00:00Z'`, `NaN`), `recul-de-trente-jours-bloque-et-alerte` (T-ISO-5), `recul-egal-a-la-tolerance-accepte`, `avance-normale-met-a-jour`, `tolerance-invalide-refusee` (NaN, négative, non entière, `Infinity`).

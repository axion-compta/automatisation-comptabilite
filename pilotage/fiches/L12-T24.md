## Contexte
Spec 12, `01-socle-catalogue` §Journal (V3-CTL-070) : table `journal_verification` en ajout seul (id, horodatage, déclencheur, règle, version de la règle, objet, résultat, valeur, écart, version des paramètres). « Les contrôles réussis sont aussi écrits. Une requête rend, pour une pièce, la liste de tout ce qui a été vérifié, quand et avec quelle version. » Cas CT-40 (pièce contrôlée à l'arrivée, la nuit et avant export : toutes les lignes présentes, OK compris ; modification refusée). Cette fiche est la version PURE, en mémoire ; la table et son déclencheur SQL attendent la persistance (L12-T48, bloquée).

## À faire
1. `packages/noyau/src/controles/journal.ts` :
   - `LigneJournal extends TraceControle { versionParametres: string }` ;
   - `ajouterAuJournal(journal: readonly LigneJournal[], traces, versionParametres)` → NOUVEAU tableau figé (`Object.freeze` sur chaque ligne et sur le tableau) ; le tableau reçu n'est jamais modifié ; version des paramètres vide = exception ;
   - `historiqueObjet(journal, objetType, objetId)` → lignes de l'objet triées par horodatage puis règle ;
   - `dernierResultat(journal, regleId, objetId)`.

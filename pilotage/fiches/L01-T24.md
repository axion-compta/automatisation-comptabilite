## Contexte
Le faux serveur MSW suit le contrat (L00-T12). La suite commune `suite-contrat.ts` est jouée sur les deux cibles : même entrée, même sortie. Les écrans testés en jsdom (L01-T36 et suivantes) ont besoin d'un faux serveur démarrable côté Node, car `msw` n'est pas une dépendance d'apps/web.

## À faire
1. `packages/faux-serveur/src/domaines/plan.ts` : handlers MSW de `GET /exercices` et `GET /exercices/:exercice/plan`, qui appellent le service `plan-service.ts` du contrat (même code que le serveur en mémoire) ; validation de la query (400 si hors bornes) ; 404 `EXERCICE_INCONNU`.
2. `handlers.ts` : `creerHandlers` ajoute ces handlers (même `base`, même latence, mêmes pannes par `x-panne`).
3. `noeud.ts` : `demarrerNoeud(options)` → `{ fermer }`, démarre `setupServer` de `msw/node` avec `creerHandlers(options)`.
4. `__tests__/suite-plan.ts` : suite commune du plan (enveloppe, tri, filtres, 404, query invalide 400) ; appelée pour les deux cibles dans `contrat-commun.test.ts`.
5. `__tests__/noeud.test.ts`, test `demarrer-noeud-repond` : `fetch` vers `http://localhost:3000/exercices` répond 200 avec `base: 'http://localhost:3000'`.

## Hors périmètre
Pas de tiers (L01-T26), pas d'écran.

## Pièges
Une seule logique : aucun filtrage réécrit dans le faux serveur. `navigateur.ts` reste inchangé (il passe par `creerHandlers`).

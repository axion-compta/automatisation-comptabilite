# Consigne des auteurs cloud (vague 3)

Pour chaque fiche X de ta liste, UNE PAR UNE et dans l'ordre (NN = deux chiffres après la lettre L) :
1. `git fetch origin`, `git checkout -B lot-NN/X origin/main` ; lis (une fois) CLAUDE.md, pilotage/LISEZMOI.md, pilotage/consignes/auteur.md, puis pilotage/fiches/X.md ; si pilotage/ARRET existe sur origin/main, arrête-toi.
2. Tests d'abord (ils doivent échouer si on casse le code ; cas limites NaN, Infinity, non entiers, vides, ordre inversé, tous testés quand la fiche les exige), puis le code. Ne modifie QUE les fichiers_autorises de la fiche. Aucun prix, aucun mot interdit (conforme, sans erreur, garanti, juriste, PDP), données fictives seulement, aucune valeur légale en dur : pas de littéral numérique sur une ligne de taux, seuil ou délai (constante nommée issue d'un paramètre daté). Aucun littéral à forte entropie ni secret, clé ou token en dur dans le code ou les tests (assemble à l'exécution : 'a'.repeat(n), concaténation de morceaux courts), car gitleaks scanne chaque commit. Passe statut à fait dans la fiche et écris pilotage/journal/X.md qui commence par « # Journal X » (10 lignes au plus).
3. Node du cloud 22 alors que le dépôt demande 24 : pnpm install avec npm_config_engine_strict=false, tests ciblés des critères seulement ; la CI complète tourne sur GitHub. Si un test échoue ailleurs que dans ta fiche (par exemple n04), ne touche à rien. stryker ne mute plus que src/argent/**.
4. UN SEUL commit propre par branche, terminé par « Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com> », puis `git push origin lot-NN/X` (branche exacte, jamais de force-push, jamais sur main). Pas de gh : n'ouvre pas de PR.
5. Taille : taille_max_lignes de la fiche est une limite stricte. Mesure avec `git diff --numstat origin/main...HEAD` AVANT de pousser, fiche et journal compris ; écris compact dès le départ (tables de cas, helpers, pas de commentaires superflus). INTERDIT de supprimer un test ou un cas limite exigé pour tenir la limite ; si impossible, sépare en deux commits de code seul puis clôture (statut fait + journal) ou, à défaut, ne pousse pas et réponds « TROP GROS : <lignes> pour <max> ».
6. Si tests_requis est oui, vérifie que fichiers_autorises contient un fichier *.test.ts ou *.spec.ts ; sinon réponds « BLOQUÉE : aucun fichier de test autorisé ». Fiche bloquée (dépendance non faite, fichier hors périmètre nécessaire) : saute-la, note la raison, passe à la suivante.
7. Réponse finale : une ligne par fiche « X POUSSÉE <sha> », « X BLOQUÉE : raison » ou « X TROP GROS : ... ».
